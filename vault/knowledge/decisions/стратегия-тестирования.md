# Стратегия тестирования numerical_solver

## Пирамида тестов (pytest)

### 1. Unit-тесты — один модуль изолированно

**test_pvt.py:**
- `Rs_eq(p_known)` → сравнение с табличным значением (Standing, таблица из Каневской или OPM Manual)
- `Rs_eq(p=0) = 0` — при нулевом давлении газ не растворяется
- `dRs_dp(p) > 0` — газосодержание растёт с давлением
- `Bo(p, Rs=0) ≈ 1` — без газа нефть почти не расширяется
- `Bo(p, Rs) > 1` при Rs > 0 — растворённый газ увеличивает объём
- `dBo_dRs(p, Rs) > 0` — больше газа → больше набухание
- `Bg(p) → ∞` при p → 0 — идеальный газ расширяется
- `dBg_dp(p) < 0` — газ сжимается с ростом давления
- `mu_o(p, Rs=0) = mu_dead_oil` — вязкость мёртвой нефти
- `mu_o(p, Rs) < mu_dead_oil` при Rs > 0 — растворённый газ снижает вязкость
- `rho_o = (rho_o_std + Rs·rho_g_std) / Bo` — проверка формулы
- Ветвление p ≷ pb: Bo(pb-ε) ≈ Bo(pb+ε) — непрерывность на давлении насыщения
- Все функции принимают np.ndarray и возвращают np.ndarray той же формы

**test_relperm.py:**
- `kro(Sg=0) = kro_max`
- `krg(Sg=0) = 0` (Sg < S_gc)
- `krg(Sg=S_gc) = 0` — критическая газонасыщенность
- `kro(Sg=1-S_or) = 0` — остаточная нефтенасыщенность
- `krg(Sg=1-S_or) = krg_max`
- `dkro_dSg(Sg) ≤ 0` — монотонно убывает
- `dkrg_dSg(Sg) ≥ 0` — монотонно возрастает
- `np.clip` в _S_star: Sg < S_gc → S* = 0, Sg > 1-S_or → S* = 1

**test_grid.py:**
- `r_faces[0] = r_w`, `r_faces[N] = R_ext`
- `r_faces` строго возрастает
- `r_centers[j]` ∈ (r_faces[j], r_faces[j+1]) для всех j
- `sum(volumes) ≈ π·h·(R_ext² - r_w²)` с точностью до roundoff
- `trans_internal[j] > 0` для всех j
- `trans_well > 0`, `trans_ext > 0`
- Логарифмический шаг: ln(r_faces[j+1]/r_faces[j]) = const
- N=3 (минимум) — всё вычисляется без ошибок
- N=1000 — производительность приемлема (< 0.1 с)

**test_config.py:**
- Валидный JSON → SimulationConfig без ошибок
- Невалидный porosity=1.5 → ValueError
- Отсутствующее обязательное поле → KeyError или ValueError
- Опциональные поля (output) — defaults

### 2. Граничные тесты — предельные случаи

- `Sg = 0` всюду (однофазный поток): гидро-шаг не создаёт свободного газа при p > pb
- `p = pb` — граница переключения режимов. Неявная проверка непрерывности.
- `dt → 0`: невязки → 0 (член накопления → 0, потоки → 0)
- `p_wf = p0`: нет перепада давления → нет потока → стационар
- Один шаг по времени при dt = dt_init — первый шаг работает
- Расписание с одним интервалом — простейший schedule

### 3. Тесты согласованности — физические инварианты

- `So + Sg = 1` для всех ячеек на каждом шаге
- Баланс массы нефтяного компонента: 
  `sum(V·φ·(1-Sg)/Bo)^{n+1} - sum(V·φ·(1-Sg)/Bo)^n = -dt · (G_o_well - G_o_ext)`
  Глобальный баланс масс должен сходиться до machine precision (консервативная схема).
- Баланс массы газового компонента — аналогично
- `T > 0` (К) на всех шагах
- `0 ≤ Sg ≤ 1 - S_or` на всех шагах
- `0 ≤ Rs ≤ Rs_eq(p)` на всех шагах

### 4. Интеграционные тесты — полный шаг

- Один шаг Ньютона при начальном состоянии (p=p0, Sg=0) с p_wf < pb:
  Ньютон сходится за ≤ 10 итераций
- Результат: Sg > 0 в ячейках вблизи скважины, Sg = 0 далеко
- Температура решается прогонкой без ошибок
- T(r_w) < T0 (охлаждение вблизи скважины за счёт JT и дегазации)

### 5. Валидационные тесты — сравнение с эталоном

**VAL-001: Однофазный стационарный радиальный поток**

Условия: p0 > pb всюду, p_wf > pb, Sg = 0, Rs = Rs0 = const.
Аналитика: p(r) = p_wf + (p0 - p_wf) · ln(r/r_w) / ln(R_ext/r_w).
Допуск: max|p_num - p_analytic| / (p0 - p_wf) < 1e-3 при N = 100.

Для температуры: стационарное решение с JT-эффектом. При постоянных свойствах — аналитическое решение ODE для T(r).

**VAL-003: Buckley-Leverett (без температуры, при наличии двухфазного гидро-солвера)**

Двухфазный поток без капиллярного давления, без температуры. Сравнение профиля Sg(r) с аналитическим решением (касательная Велге). Допуск по положению фронта: |r_front_num - r_front_analytic| / R_ext < 5% при N = 200.

## Порядок реализации тестов

Тесты пишутся **до или одновременно** с модулем. Порядок:
1. test_grid.py — первым (Grid не зависит от других)
2. test_pvt.py, test_relperm.py — вторыми (PVT и ОФП независимы)
3. test_config.py — третьим (чтение JSON)
4. test_fluxes.py — четвёртым (зависит от Grid, PVT, ОФП)
5. test_hydro.py — пятым (аналитическая заглушка + fluxes)
6. test_energy.py — шестым (зависит от Grid, PVT, HydroResult)
7. test_simulator.py — последним (интеграция всех модулей)

Для test_fluxes.py: задавать характеристики (p, Sg, Rs) на отрезках длины, чтобы результат был инвариантен относительно пространственной сетки.

## Fixtures (pytest)

Общие fixtures для тестов:
```python
@pytest.fixture
def default_grid():
    return LogRadialGrid(r_well=0.1, R_ext=500, h=10, N=100, k=1e-13)

@pytest.fixture
def default_pvt():
    return StandingPVT(rho_o_std=850, rho_g_std=1.2, T0=353, Rs0=50, ...)

@pytest.fixture
def default_relperm():
    return CoreyRP(S_or=0.2, S_gc=0.05, n_o=2, n_g=2, kro_max=1, krg_max=0.8)
```

Разместить в `tests/conftest.py`.
