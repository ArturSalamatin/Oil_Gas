## Описание

После BUG-022 (#82) Ньютон прототипа принимает решение, только если выполнены оба условия: абсолютное $\|F\|_\infty \le$ `atol + rtol·scale` и условие по ячейке $\max_c |F_{c,i}|\,\Delta t / V_{p,i} \le$ `cell_tol`. Если решение отвергнуто **только условием ячейки**, отчёт `BlackOilNewtonReport` выглядит как обычный отказ с невязкой ниже абсолютного допуска: «итераций 4, невязка 6.51e-15, не сошлось». Меры ячеек и причины отказа в отчёте нет. Пользователь ищет причину в дроблении шага или в физике, хотя отказ дал порог `numerics.newton_cell_tol` (или его предел округления, DEBT-055).

Приоритет низкий: в примерах дробление шага решает дело, и до сообщения пользователю не доходит. Страдает диагностика: пробы и записи реестра (BUG-025, «Не проверено») не отличают этот отказ от остальных.

## Текущее состояние

**Как возникает отказ.** Проба планирования BUG-022 на сценарии BUG-018 при $N$ = 350 (`vault/issues/bug-022/probes/failing_tests.out.txt`), один вызов адаптера с $\Delta t$ = 86400 с:

```
[pv1e-8] один вызов адаптера, dt = 86400 с: отказ: advance не сошёлся: dt = 8.640e+04 с, t = 0.0000 сут,
итераций 4, невязка 6.51e-15; отказы Ньютона {(1, 'stall'): 1, (2, 'stall'): 1, (3, 'stall'): 1}
```

Механизм (`_newton_fixed_active_set`, `blackoil.py:347-382`): абсолютное условие выполнено, условие ячейки нет. Поэтому итерации продолжаются (`:381`). На пределе округления строгий линейный поиск `merit(ft) < mf` не может уменьшить $\|F\|$ и возвращает отказ (`:379`) с невязкой последнего принятого приближения. В отчёте видно только «отказ, 4 итерации, невязка 6.5e-15». Ни меры ячеек, ни того, что абсолютное условие выполнено, ни причины выхода (линейный поиск) в нём нет.

**Что видит пользователь.**
- Адаптер (`prototype_adapter.py:160-164`) пишет в `HydroConvergenceError` только `dt`, `t`, `iterations`, `residual_inf`.
- `Simulator` ловит ошибку, пишет её в `dev_log.debug` (`simulator.py:253`). Когда дробление исчерпано, он поднимает `RuntimeError(self._failure_message(...)) from exc` (`:255`). В его собственном тексте (`:310-329`) невязки нет, а текст адаптера видно только в цепочке traceback («The above exception was the direct cause…»).
- Когда все ступени отказали, `advance` подменяет поля Ньютона в отчёте полями ступени 1 (DEBT-030, `blackoil.py:432-434`). Для любой новой информации об отказе эту подмену тоже придётся пройти.

**Где формируется отчёт отказа** (на `ccc5ae3`):

|---|---|---|
| `_newton_fixed_active_set` | `:362` | сошлось на старте |
| | `:366` | исключение линейного решателя |
| | `:379` | линейный поиск не уменьшил невязку (**случай задачи**) |
| | `:381` | сошлось |
| | `:382` | исчерпан `max_iter` |

## Целевое состояние

- В отчёте `BlackOilNewtonReport` есть мера условия ячейки $\max_c |F_{c,i}|\,\Delta t/V_{p,i}$. Она считается на той же невязке `f`, по которой судят о сходимости, во всех точках возврата обоих Ньютонов. Подмена DEBT-030 её переносит. При выключенном условии (`cell_tol=None`) — `None`.
- Сообщение адаптера называет меру и порог, а при отказе только по условию ячейки подсказывает про `numerics.newton_cell_tol`. Префикс «advance не сошёлся» сохраняется: по нему матчат тесты.
- Текст отказа `Simulator` при исчерпании дробления называет факты последнего отказа гидродинамики, без чтения цепочки traceback.
- Принятые шаги, истории примеров, `step_log.csv` и эталоны регрессии прототипа (17/17) — побитово прежние. Мера — $O(N)$ на уже вычисленной `f`, на итерации не влияет.

## Анализ вариантов решения

### Вариант 1. Поле меры ячеек в отчёте

- **Суть.** `BlackOilNewtonReport.cell_measure: Optional[float] = None`. Вспомогательный метод возвращает меру (вычисление из `_cells_converged`, `:257`), а `_cells_converged` сравнивает её с порогом. Мера пишется во все точки возврата из таблицы выше (в `_advance_phases:517` — по пересчитанной `r`) и переносится в `replace` DEBT-030. Адаптер дописывает «мера ячеек Y (порог Z)», а при Y > Z — подсказку о `numerics.newton_cell_tol`.
- **Плюсы.** Минимально; поле со значением по умолчанию не ломает подставные отчёты тестов; `None`, а не NaN: сравнение dataclass через `==` остаётся корректным.
- **Минусы.** Адаптер не знает абсолютного допуска `tol = atol + rtol·scale` (scale — начальная невязка решения). Сказать «отказ **только** по условию ячейки» он не может: подсказка при Y > Z появится и тогда, когда не выполнено и абсолютное условие.

### Вариант 2. Вариант 1 + признак абсолютного условия

- **Суть.** В отчёт добавляется ещё `abs_converged: Optional[bool]` (или сам `abs_tol`). Адаптер различает три случая: «только условие ячейки», «оба», «только абсолютное».
- **Плюсы.** Даёт ровно то, что просит реестр: подсказка — только при отказе по условию ячейки. Заодно закрывает пункт «Не проверено» BUG-025 (отказ по абсолютному условию против отказа линейного поиска).
- **Минусы.** Ещё одно поле и его перенос в подмене DEBT-030.

### Вариант 3. Причина выхода из Ньютона

- **Суть.** Поле `exit_reason`: линейный поиск / линейный решатель / `max_iter` / набор фаз / $S_g > 0.98$ / нечисловое / ветвь скважины.
- **Плюсы.** Закрывает весь класс неразличимых отказов. Пересекается с DEBT-061: ступень 4 пишет `iterations = max_iter` и при досрочном выходе.
- **Минусы.** Шире задачи: все точки возврата обоих Ньютонов и `_fallback`, больше тестов. Поглощать ли DEBT-061 — решить при планировании.

### Вариант 4. Мера в адаптере по возвращённому состоянию — отвергнут

При отказе `_advance_phases` возвращает `guess`, начало последнего прохода набора фаз (`:501`), а не последнее приближение Ньютона. После подмены DEBT-030 отчёт относится к ступени 1, а состояние — к последней попытке. Мера описала бы другую точку.

### Вариант 5. Факты отказа в тексте `Simulator`

- **Суть.** В конец `_failure_message` дописать текст последнего `HydroConvergenceError`, чтобы пользователь видел меру и подсказку без цепочки traceback.
- **Ограничение.** Начало текста цитируют README примеров 03, 05, 06, 07, 10 и тесты (`test_simulator.py:559`, `test_prototype_activation_cap.py:230`), поэтому дописывать только в конец.

**Рекомендация: вариант 2 + вариант 5.** Вариант 3 — по решению пользователя: вместе с DEBT-061 или отдельно.

## План решения

1. **Подготовка (baseline).** Быстрый уровень тестов (`-m "not slow"`), их число, регрессия прототипа 17/17. Проба воспроизведения: сценарий `test_first_day_with_cell_tol`, один вызов адаптера с $\Delta t$ = 86400 с, должна повторить «итераций 4, невязка 6.51e-15».
2. **Реализация.**
   1. Поле(я) отчёта и метод меры; `_cells_converged` — через него, поведение побитово.
   2. Заполнение во всех точках возврата `_newton_fixed_active_set`, `_advance_phases:517`, `_newton_switching`.
   3. Перенос в подмене DEBT-030 (`advance:432`).
   4. Текст адаптера, затем конец текста `Simulator`.
   5. `CHANGELOG_1.0.3.md`; формат `step_log.csv` прототипа не меняется.
3. **Верификация.**
   - Unit-тест: мера в отчёте `_newton_fixed_active_set` равна `_measure` теста на возвращённом `z`; при `cell_tol=None` — `None`.
   - Подмена DEBT-030 переносит меру ступени 1.
   - На сценарии воспроизведения сообщение содержит меру > порога и подсказку `numerics.newton_cell_tol`.
   - Сошедшиеся отчёты (`converged`, `iterations`, `residual_inf`) и истории примеров — побитово; регрессия прототипа 17/17; полный прогон тестов.
