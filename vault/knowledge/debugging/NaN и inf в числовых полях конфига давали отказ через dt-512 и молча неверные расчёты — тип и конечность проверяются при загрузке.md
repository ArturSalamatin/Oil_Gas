# NaN и inf в числовых полях конфига давали отказ через dt/512 и молча неверные расчёты — тип и конечность проверяются при загрузке

## Что было

Проверки `_validate` и `_validate_interval` (`numerical_solver/gpn_multiphase_solver/io/config.py`) записаны как `v <= 0`, `v < 0`: сравнение с NaN ложно, литерал JSON `NaN` их проходит, `Infinity` проходит все проверки «снизу». Конечность проверялась только у девяти тепловых параметров ([[DEBT-047]], [[DEBT-049]]).

Красный замер (`vault/issues/debt-051/probes/red_state.py`, вывод `red_state.out.txt`; `configs/baseline.json`, одно поле подменено, 24 ч):
- **молча неверные расчёты:** `numerics.skin` = ±inf, `history.p_wf` = +inf — скважина не добывает ($p$ = 20 МПа везде); `history.min_bhp` = NaN при активном ограничении (1000 м³ст/сут, 15 МПа) — ограничение снято, забой 7.12 МПа, $S_{g,\max}$ = 0.091 (эталон — 15.03 МПа, газа нет);
- **ложный след:** NaN в 13 полях (`porosity`, `p0`, `T0`, `Rs0`, `rho_o_std`, `skin`, `p_wf`, …) — отказ после дробления первого шага до dt/512 с советом увеличить `max_retries`; inf в `rho_o_std`, `T0`, `Rs0` — «Начальное состояние пересыщено газом»;
- **без имени поля:** NaN в геометрии — `invalid radial grid parameters` прототипа; NaN в `dt_integration` — `cannot convert float NaN to integer`; NaN в `duration`/`dt_out` — `round(NaN)` в `load_config`; строка, `null` — `TypeError`; `true` в `permeability` — 1 м².

## Что стало

- `_require_finite_number(value, name)` — число (не строка, `null`, bool) и конечное, иначе `ValueError`: `<имя> должно быть числом, получено …` / `<имя> должно быть конечным числом, получено …`.
- `_check_numeric_fields(obj, where)` — поля с аннотацией `float` и `Optional[float]` (кроме `null`) dataclass-секции, плюс любое значение `float` в поле другого типа (NaN в `grid.N`). Поля выбираются по аннотациям: новое поле проверяется без правки кода. Аннотации — строки (`from __future__ import annotations`); иначе записанная аннотация выпадет из проверки — страж `test_field_list_covers_known_fields`.
- Вызовы: в начале `_validate` по всем секциям, включая `thermal` (цикл конечности DEBT-049 удалён — стал недостижим); в начале `_validate_interval` (имя `history[i].<поле>`); в `_expand_history` для `duration`, `dt_out` до `round`.
- Диапазоны не трогались: геометрия, порода, начальные условия — прежние проверки `_validate`; гидродинамика — прототип (P8 §5).

Зелёный замер (`green_state.out.txt`): все 58 испорченных случаев — `load_config: ValueError` с именем поля; четыре эталонных расчёта — построчно как в красном. Тестов 1493 → 1591 (+98, `TestValidationNumbers`), полный прогон 1591 passed (524 с).

## Что не закрыто

Конечные абсурдные значения параметров скважины — `skin` = 1e6, ±1e300; `p_wf` = 1e12; `min_bhp` = 1e300 — дают тот же расчёт без добычи без сообщения (`vault/issues/debt-051/probes/audit1_finite_extremes.py`). Реалистичный отрицательный скин ($s$ = −0.5, −2) даёт отрицательную проводимость забойной грани $T_w = 2\pi kh/(\ln(r_1/r_w) + s)$ и отказ через dt/512: на сетках примеров $\ln(r_1/r_w)$ = 0.01…0.09. Диапазоны параметров скважины — [[DEBT-056]].
