## Описание

Радиус изобары $p = p_b(R_{s,0})$ — где давление пересекает давление насыщения — считают три функции диагностики примеров. Внутри сетки у всех одна формула: интерполяция $\ln r$ по $p$ между соседними ячейками (`np.searchsorted` по возрастающему $p$). А на краях сетки результаты разные. Это не гипотеза: на примере 11 (`11_degassing_at_boundary`) две функции из трёх дают разные ответы на одну и ту же величину — замкнутое решение рисует и печатает «фронт» в центре последней ячейки, а рисунок $R_s$ линию фронта не рисует вовсе. Задача — одна функция с одним, осознанно выбранным краевым случаем и тестом краёв.

Приоритет низкий. Задача зависит от DEBT-011 (#91): функции переезжают в `gpn_multiphase_solver/diagnostics/`, поэтому править их нужно после переезда.

## Текущее состояние

Три реализации (на `015a297`, все в `numerical_solver/examples/`):

| Функция | Профиль | Газа нет ($p \ge p_b$ всюду) | Газ до края сетки ($p < p_b$ всюду) |
|---|---|---|---|
| `closed_form.py::_front_radius` | замкнутый (стационар) | NaN | центр последней ячейки, `r[p < pb].max()` |
| `two_phase_analytics.py::degassing_front["r_b_interp"]` | численный, последняя запись | NaN | NaN |
| `rs_analytics.py::front_radius` | численный, последняя запись | NaN | NaN |

Кроме краевых случаев, каждая копия заново объясняет в докстринге или комментарии, почему здесь не годится `np.interp`: он требует возрастающих узлов, а $p$ и $\ln r$ монотонны в противоположные стороны. Одно и то же объяснение написано трижды.

### Пример 11: расхождение на деле

Проба `vault/issues/debt-065/probes/edge_cases.py` (вывод — `edge_cases.txt`): пример 11, $N = 50$, $p_0 = 15.05$ МПа, $p_b = 15$ МПа, $r_{N-1} = 46.9873$ м, $R_{ext} = 50$ м.

| Величина | Значение |
|---|---|
| численный профиль, последняя запись | $p < p_b$ во всех 50 ячейках, $p_{N-1} = 14.982$ МПа; $p$ монотонно растёт по $r$ |
| замкнутый профиль на сетке примера | $p < p_b$ во всех 50 ячейках, $p_{N-1} = 14.983$ МПа |
| `closed_form._front_radius`, сетка примера | **46.9873 м**: центр последней ячейки |
| `closed_form._front_radius`, мелкая сетка до $R_{ext}$ (20 001 узел) | **47.7338 м**: опорное значение |
| `degassing_front["r_b_interp"]`, `rs_analytics.front_radius` | **NaN** |

Последствия для вывода примера 11 сейчас:
- `report_closed` печатает `фронт r_b = 46.9873 м (p = pb = 15.000 МПа)`, хотя давление замкнутого решения в этой точке 14.983 МПа. Это центр ячейки, а не изобара, и он на 1.6 % ближе к скважине, чем опорное значение;
- на профилях $p$ и $S_g$ стоит линия «фронт $r_b$ = 46.987 м»;
- на `rs_profiles.png` линии нет: `front_radius` вернул NaN, `_draw_rs` её пропускает;
- `degassing_front` в примере 11 не вызывается — он работает только в 03, 04 и 05.

Внутри сетки интерполяция по центрам ячеек точная: на сетке примера и на мелкой сетке r_b замкнутого решения отличаются на +0.01 % (03, $N = 150$), +0.02 % (04, $N = 50$) и +0.04 % (04a, $N = 150$). Так что дефект — только на краях.

### Синтетические профили (та же проба)

| Профиль | `closed_form` | две другие |
|---|---|---|
| газа нет | NaN | NaN |
| газ до контура | центр последней ячейки | NaN |
| пересечение в первой паре ячеек | одинаково | одинаково |
| в первой ячейке $p = p_b$ ровно | NaN | NaN |
| в последней ячейке $p = p_b$ ровно | $r_{N-1}$ | $r_{N-1}$ |

Ещё один край ни одна функция не обрабатывает: изобара между $r_w$ и первым центром, то есть $p_{wf} < p_b <$ давление в первой ячейке. Все три вернут NaN («газа нет»), хотя у стенки скважины давление ниже $p_b$.

### Предусловие, которое не проверяется

`np.searchsorted` даёт правильный ответ, только если ячейки с $p < p_b$ идут подряд от забоя (образуют префикс). Аудит DEBT-026 (#56) подтвердил это на всех 18 примерах того времени, включая восстановление давления 13b. Сами функции это предусловие не проверяют.

## Целевое состояние

- Одна функция, например `isobar_radius(...)`, в `gpn_multiphase_solver/diagnostics/`; три места вызова переходят на неё.
- Краевой случай один и выбран осознанно. Решение записано в докстринге и в vault.
- Объяснение про `np.interp` — один раз.
- Unit-тесты краёв: газа нет; газ до контура; пересечение в первой паре ячеек; изобара между $r_w$ и первым центром; изобара между последним центром и $R_{ext}$; $p = p_b$ точно в узле; профиль с нарушенным предусловием (префикс).
- Вывод примеров меняется только там, где сейчас срабатывает краевой случай; эти места перечислены до реализации.

## Анализ вариантов решения

### Вариант 1. За краем — NaN (как у двух из трёх)

- **Суть:** общая функция с поведением `rs_analytics.front_radius`.
- **Изменения:** меняется вывод только `closed_form`.
- **Плюсы:** минимальная правка; численные профили не меняются.
- **Минусы:** в примере 11 замкнутое решение перестанет показывать фронт, хотя он в области есть (47.73 м, между последним центром и контуром): `report_closed` напечатает `nan`, линия на $p$ и $S_g$ пропадёт. Информация теряется.

### Вариант 2. За краем — центр последней ячейки (как `closed_form`)

- **Суть:** общая функция с поведением `_front_radius`.
- **Плюсы:** на `rs_profiles.png` примера 11 появится линия.
- **Минусы:** центр ячейки выдаётся за изобару, хотя это лишь нижняя оценка. В примере 11 занижение 1.6 %, и подпись «$p = p_b$» неверна: давление там 14.98 МПа. Ошибка просто распространяется с одной функции на все три.

### Вариант 3. Граничные узлы $(r_w, p_{wf})$ и $(R_{ext}, p_{ext})$ (рекомендуется)

- **Суть:** давления на обеих границах заданы граничными условиями: на контуре — $p_{ext}$, на забое — $p_{wf}$. Добавляем их к профилю как крайние узлы и интерполируем по тем же правилам. NaN остаётся только для случая, когда изобары в области нет: $p_{wf} \ge p_b$ (газа нет) или $p_{ext} < p_b$ (разгазирована вся область вместе с контуром).
- **Изменения:** функции нужны давления на границах. Замкнутое решение их знает. Для численного профиля $p_{ext}$ берётся из конфига, $p_{wf}$ — из последней записи истории.
- **Плюсы:** в примере 11 краевой случай исчезает. Оценка по числам пробы: численный профиль ≈ 47.77 м, замкнутый ≈ 47.73 м при опорном 47.7338 м. Закрывается и неучтённый край между $r_w$ и первым центром. Внутри сетки результаты не меняются.
- **Минусы:** сигнатура шире. При планировании нужно проверить: (а) на контуре давление действительно задаётся условием Дирихле во всех режимах, включая останов; (б) откуда брать $p_{wf}$ при управлении по дебиту. Вывод примера 11 изменится (печать `report_closed`, линии на трёх рисунках), а также тех примеров, где изобара лежит между $r_w$ и первым центром. Их нужно найти до реализации.

### Вариант 4. Для замкнутого решения — корень без сетки

- **Суть:** найти $p(r_b) = p_b$ событием `solve_ivp` при интегрировании уравнения (2) от контура внутрь, без интерполяции по сетке.
- **Плюсы:** значение замкнутого решения перестаёт зависеть от сетки, и пометка «от сетки не зависят» в `grid_convergence.py:110` становится верной буквально.
- **Минусы:** внутри сетки выигрыш ≤ 0.04 % (проба), на краю вариант 3 даёт то же самое. Замкнутое решение уходит от общей функции, и реализаций снова становится две. Не рекомендуется.

**Рекомендация:** вариант 3 — одна функция для всех трёх мест вызова. Окончательный выбор краевого случая — при `/plan-improve`.
