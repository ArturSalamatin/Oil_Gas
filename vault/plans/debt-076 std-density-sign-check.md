# DEBT-076: проверка знака плотностей при стандартных условиях

> **Черновик.** Записаны решения пользователя и замер из сессии 2026-10-15 (обсуждение ввода книгой Excel). Шаги, тестовую стратегию и критерии завершения допишет `/plan-improve DEBT-076`.

## 0. Решения пользователя (2026-10-15)

1. **Отдельная DEBT** для пути JSON — зарегистрирована по решению пользователя, когда при подборе пределов проверок книги Excel ([[feat-033 workbook-input-format|FEAT-033]], раздел 2.6) выяснилось, что у `pvt.rho_o_std`, `pvt.rho_g_std` в программе предела нет.
2. **Книга Excel проверяет плотности на > 0 сама** — проверкой данных Excel и в переводе ([[feat-035 workbook-to-config|FEAT-035]], решение 14), независимо от DEBT-076. Цепочку FEAT-033…036 задача не блокирует.
3. **Значения по умолчанию не трогаем** (FEAT-033, решение 41): умолчание `RockConfig.rho_cp_solid` = 1.25·10⁶ Дж/(м³·К) и значения примеров — вне этой задачи, хотя тоже ниже типичных для минералов.

## 1. Сводка (предварительно)

- **Подтип:** проверка входа (`_validate`). Новых формул нет.
- **Суть:** отказ `load_config` при `rho_o_std` ≤ 0 или `rho_g_std` ≤ 0 — как у остальных физических полей; по варианту 2 — ещё предупреждения о неправдоподобных значениях.
- **Модули:** `numerical_solver/gpn_multiphase_solver/io/config.py` (`_validate`), `tests/test_config.py`, `vault/knowledge/decisions/P8-формат-ввода-json.md` (перечень проверок).

## 2. Контекст

### 2.1. Текущее состояние (на `3899d9b`)

- `_validate` проверяет у плотностей только тип и конечность (`_check_numeric_fields`, [[DEBT-051]]). Пределы есть у `porosity`, `permeability`, `p0`, `T0`, `Rs0`, `rho_cp_solid`, `c_p_oil`, `c_p_gas`, $\lambda$ ([[DEBT-047]]), `compressibility` ([[DEBT-068]]), `skin` ([[DEBT-056]]) — у плотностей нет.
- Фабрика передаёт плотности в PVT (`create_pvt`: `StandingPVT`, `TableFullPVT`, `PrototypePVTAdapter`) без проверки. Гидродинамика табличного пути их не видит (прототип — в стандартных объёмах); плотности входят в энергию: массовые потоки и теплоёмкость флюида, $\rho_o = (\rho_{o,ст} + R_s\rho_{g,ст})/B_o$.

### 2.2. Замер (2026-10-15)

`vault/issues/debt-076/probes/density_sign.py`, вывод — `density_sign.out.txt`. Конфиг примера 18, первые 3 интервала истории (2 сут); значение подменяется в словаре после `json.load`, файлы не создаются. `load_config`, `SimulatorFactory.from_config`, `run` — без отказа и без предупреждения во всех случаях:

| случай | $T(r_w)$ на 2 сут, К | $\Delta T(r_w)$ от $T_0$ = 350 К |
|---|---|---|
| исходный конфиг | 349.7666 | −0.233 |
| `rho_o_std` = −850 | 346.9775 | −3.022 (×13) |
| `rho_o_std` = 0 | 348.8449 | −1.155 (×5) |
| `rho_g_std` = −0.85 | 350.5597 | +0.560 (нагрев вместо охлаждения) |
| `rho_g_std` = 0 | 350.1567 | +0.157 (нагрев) |

Числа правдоподобны — ошибку по ним не заметить.

## 3. Открытые вопросы (к `/plan-improve`)

1. **Вариант:** 1 — только отказ при ≤ 0; 2 — отказ + предупреждения о неправдоподобных значениях.
2. **Пороги предупреждений** (если вариант 2): например $\rho_{g,ст} \ge \rho_{o,ст}$; $\rho_{o,ст}$ вне 600–1100 кг/м³; $\rho_{g,ст}$ вне 0.6–2 кг/м³ — обсудить.
3. **Ссылка в тексте отказа** на смысл поля: плотность при стандартных условиях, кг/м³ (не пластовая).
