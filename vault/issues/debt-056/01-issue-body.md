## Описание

Скин-фактор `numerics.skin` и забойное давление (`p_wf`, `min_bhp`) проверяются только на знак/конечность, но не на физический смысл модели скважины. Два следствия:

1. **Отрицательный скин стимулированной скважины** ($s$ ≈ −0.5…−5 после кислотной обработки или ГРП) на радиальных сетках GPN даёт отказ решателя через 512 подшагов с советом увеличить `max_retries` — ложный след: причина в отрицательной проводимости забойной грани, а не в численных настройках.
2. **Большой положительный скин, `p_wf` или `min_bhp` выше пластового давления** дают правдоподобный расчёт «скважина не работает» без единого сообщения — опечатка в конфиге неотличима от осмысленного режима.

Приоритет средний: реалистичный входной параметр (отрицательный скин) не задаётся и падает с ложным сообщением.

## Текущее состояние

### Формула проводимости забойной грани

`numerics.skin` передаётся прототипу без проверки (`factory.py:433`, `skin=nc.skin`). Прототип вычисляет проводимость забойной грани (`HydroSolverPrototype/Prototype_1.0.3/radial_blackoil/grid.py:20-21`, вызов — `blackoil.py:117`):

$$T_w = \frac{2\pi k h}{\ln(r_1/r_w) + s},$$

где $r_1$ — центр первой ячейки **сетки прототипа**, среднее геометрическое её граней (`grid.py:9-10`). На логарифмической сетке

$$\ln(r_1/r_w) = \frac{\ln(R_{ext}/r_w)}{2N}.$$

При $s = -\ln(r_1/r_w)$ знаменатель обнуляется, при меньших $s$ — $T_w < 0$ (скважина «нагнетает» при $p_{wf} < p$). Эквивалентно: эквивалентный радиус скважины $r_w' = r_w e^{-s}$ выходит за центр первой ячейки, $r_w' \ge r_1$.

У `configs/baseline.json` ($R_{ext}/r_w$ = 500, $N$ = 100) $\ln(r_1/r_w)$ = 0.031; у примеров ($N$ = 50…350) — порядка 0.01…0.09. Чтобы представить $s = -2$, нужно $N < \ln(R_{ext}/r_w)/4 \approx 1.5$ — на рабочих сетках отрицательный скин формулой $T_w$ непредставим.

## Целевое состояние

1. $s \le -\ln(r_1/r_w)$ → `ValueError` до первого шага: допустимый минимум скина для данной сетки ($-\ln(R_{ext}/r_w)/(2N)$) и пояснение — эквивалентный радиус $r_w e^{-s}$ выходит за центр первой ячейки; обход — задать `geometry.r_well` = $r_w e^{-s}$ и `skin` = 0.
2. Скин выше порога (порядок — десятки; порог выбрать при планировании) → предупреждение в журнале, расчёт идёт.
3. `p_wf` / `min_bhp` $\ge p_0$ в интервале истории → предупреждение «скважина в этом интервале не добывает», расчёт идёт (закрытие — законный режим постановки, `eq:bc_pwf_shutin`).
4. P8 §5 дополнен; `problem_statement.tex` — по решению при планировании (скин в постановке сейчас не упоминается).

## Анализ вариантов решения

### А. Отрицательный скин

**Вариант 1 — проверка в фабрике.** После создания `proto_grid` (`factory.py:407`): `s_min = -np.log(proto_grid.centers_m[0] / proto_grid.rw_m)`, при `nc.skin <= s_min` — `ValueError` с именем `numerics.skin`, значением, `s_min`, $N$, $R_{ext}/r_w$ и обходом через `geometry.r_well`.
- ➕ Сообщение в терминах конфига; прототип не меняется.
- ➖ Противоречит P8 §5 («гидро — прототип»); собственный запуск прототипа (`runner.py:112`, параметр `Well skin`) остаётся без защиты; фабрика повторяет знание о формуле $T_w$ прототипа.

**Вариант 2 — проверка в конструкторе прототипа.** `RadialBlackOilModel.__init__` (`blackoil.py:64`): `ln(r_1/r_w) + skin <= 0` → `ValueError` с `s_min` для сетки. Фабрика ничего не дублирует.
- ➕ По P8 §5; одна точка истины рядом с формулой; защищает и `runner.py`. Код прототипа править разрешено.
- ➖ Сообщение прототипа знает только `skin`, не `numerics.skin`; формулировка в единицах и терминах прототипа. Числа прототипа не меняются (эталон регрессии побитовый), но входные файлы прототипа (`Well skin`, xlsx) проверить на допустимость.

**Вариант 3 — запрет $s < 0$ в `_validate`.** Без сетки, рядом с остальными диапазонными проверками.
- ➕ Проще всего, сообщение сразу с обходом через `r_well`.
- ➖ Отвергает и работающее окно $(-\ln(r_1/r_w), 0)$; на сетках с малым $N$ оно шире (при $N$ = 5 — до −0.62).

**Вариант 4 — эквивалентный радиус автоматически** ($r_w' = r_w e^{-s}$, скин = 0, сетка от $r_w'$). Меняет геометрию обеих сеток и точку, где задаётся $T$ забоя; это изменение постановки — отдельная FEAT, не в рамках DEBT.

**Рекомендация:** вариант 2 (или 1, если при планировании решим, что сообщение должно называть поле конфига), с обходом через `geometry.r_well` в тексте ошибки. Вариант 4 — решить при планировании, регистрировать ли FEAT.

### Б. Большой положительный скин

**Вариант 1 — предупреждение в `_validate` при $s >$ порога** (например 50 или 100; по замеру при $s$ = 50 минимум $p$ в пласте 18.46 МПа против 6.095 при $s$ = 0, то есть перепад между первой ячейкой и контуром — около 11 % от базового варианта). Порог — решение пользователя.

**Вариант 2 — предупреждение по доле депрессии на скине** $s / (\ln(R_{ext}/r_w) + s)$ — физичнее (не зависит от $R_{ext}/r_w$), но требует геометрии и сложнее в объяснении.

### В. $p_{wf}$ / `min_bhp` $\ge p_0$

**Вариант 1 — только первый интервал** (как в записи реестра).
**Вариант 2 — любой интервал.** Поскольку $p \le p_0$ при добыче, такой интервал всегда целиком закрыт; закрытия в примерах задаются через `q_oil = 0` — ложных предупреждений не будет.
- Место: `_validate` (знает `p0`) — но после разворачивания истории номер объекта JSON потерян (`config.py:426-428`); либо передать `p0` в `_expand_history`/`_validate_interval` и называть место в JSON. Решить при планировании.

**Рекомендация:** А2 + Б1 + В2, предупреждения через `user_log.warning`, как у `L_degas < 0` и `mu_JT_oil > 0` (`config.py:394-411`).

## План решения

1. **Baseline.** Быстрый уровень тестов; подтвердить, что ни один конфиг `numerical_solver/` (включая `examples/*/config.json`, `configs/*.json`) и входные файлы прототипа не попадают под новые отказы и предупреждения.
2. **Красные тесты.** $s$ = −0.5 → `ValueError` с `s_min` (не `RuntimeError` через dt/512); $s$ чуть выше `s_min` — модель создаётся; $s$ = порог + ε → предупреждение; `p_wf` = $p_0$ и `min_bhp` > $p_0$ → предупреждение; $s$ = 0, `p_wf` < $p_0$ — тишина.
3. **Реализация.** Проверка $T_w > 0$ (место — по выбранному варианту А); предупреждения Б и В в `io/config.py`.
4. **Документы.** P8 §5 — новые проверки; `problem_statement.tex` — по решению; README примеров не меняются.
5. **Верификация.** Полный прогон; проба `skin_range.py` — $s$ = −0.5, −2 дают `ValueError` с именем параметра и минимумом; истории примеров побитово (расчётный код не меняется).
