# Регистрация задачи: контрольный список

## Установление задачи

- [ ] Прочитаны `.agents/project/vault.md`, запрос и относящиеся к нему сохранённые решения. Установлены проблема, границы и ожидаемый результат.
- [ ] Выполнен поиск в соответствующих реестрах и связанных заметках по смыслу, файлам и идентификаторам. Совпадающая существующая задача сообщается пользователю вместо повторной регистрации. Дополнение существующей записи выполняется по запросу.
- [ ] Выбран тип: BUG – дефект, DEBT – технический долг или улучшение, FEAT – новая возможность, VAL – проверка по эталону. Не создавай отдельный тип, которого нет в проекте.
- [ ] Проверенные факты отделены от сообщений пользователя, предположений и неизвестных данных. Сохранены источники, условия и результаты проверок, если они известны.

## Поля по типу

| Тип | Минимум для реестра | Что дополнительно сохранить в черновике |
|---|---|---|
| BUG | Симптом, файл, воспроизведение | Условия, ожидаемое и фактическое поведение, доказательства причины или пометка гипотезы. |
| DEBT | Текущее состояние, мотивация, модули | Ограничения существующего решения, желаемые свойства и границы допустимых изменений. |
| FEAT | Описание, формулы при применимости, модуль | Пользовательский сценарий, предпосылки и зависимости, решения по интерфейсу, если приняты. |
| VAL | Эталон, сценарий, метрика | Происхождение и независимость эталона, условия сравнения, обоснованный допуск или открытый вопрос о нём. |

Незаданные сведения обозначай как неустановленные, а не придумывай. Для `numerical_solver` формульные ссылки ведут к меткам постановки. При неприменимости формул укажи это.

## ID и безопасная вставка

- [ ] Найден максимальный номер соответствующего типа в правильном реестре. BUG и DEBT имеют независимые последовательности в одном файле. Перед записью ID повторно проверен.
- [ ] Черновик с этим ID ещё не существует. Не перезаписывай его при конфликте или повторном вызове.
- [ ] Границы соседних записей определены по заголовкам, включая поля в конце каждой записи. Их полное текущее содержимое сохранено для сравнения до вставки.
- [ ] Добавлена запись по действующему формату реестра с одним статусом `🔴 ОТКРЫТ` и ссылкой на черновик. Поля GitHub, ветки и плана не выдаются за существующие.
- [ ] После вставки соседние записи сравнены целиком, а новая запись проверена на чужие поля и повторные статусы. Для нескольких задач проверь каждую границу. При невозможности сравнения не объявляй проверку выполненной.

## Завершение и частичный сбой

Проверь наличие черновика и записи с одним ID и согласованным содержанием. Сообщи ID, ссылку на реестр, черновик и существенные неизвестные. При прерывании между записями сообщи, что уже сохранено. Повторный вызов начинает с проверки созданного, не создаёт второй ID и не затирает файл. GitHub issue не создаётся, следующий этап – отдельный вызов `issue`.
