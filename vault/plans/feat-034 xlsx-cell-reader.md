# FEAT-034: разбор книги `.xlsx` стандартной библиотекой

> **Черновик.** Записаны решения пользователя из обсуждения 2026-10-14…15 и найденное при нём. Шаги, тестовую стратегию и критерии завершения допишет `/plan-feature FEAT-034`.

Цепочка: [[feat-033 workbook-input-format|FEAT-033]] (формат) → **FEAT-034** (разбор ячеек) → [[feat-035 workbook-to-config|FEAT-035]] (перевод) → [[feat-036 run-from-workbook|FEAT-036]] (расчёт). FEAT-034 от формата не зависит — можно вести параллельно с FEAT-033.

## 0. Решения пользователя

1. **Разбор zip/XML средствами стандартной библиотеки** (2026-10-14), без `openpyxl`: ради чтения нескольких листов новая зависимость поставки в чистом окружении не нужна.
2. **Свой модуль в пакете, не `radial_blackoil.xlsxio`** (предложение 2026-10-14, пользователь выбрал zip/XML; явных возражений против своего модуля не было — подтвердить на планировании).
3. **Типы ячеек** (2026-10-14, пп. 4–7 обсуждения): дата, число строкой («1,5»), формула без сохранённого значения, логическое значение в числовом поле — отказ с адресом ячейки. Отказ применяет перевод [[feat-035 workbook-to-config|FEAT-035]]; разбор обязан эти случаи различать.
4. **`.xls` не поддерживается** (2026-10-14): файл не zip — отказ с подсказкой «сохраните как .xlsx». Возможно, доработаем позже.

## 1. Сводка (предварительно)

- **Суть:** функция чтения книги → для каждого листа ячейки с адресом (A1), значением и типом: число, строка, логическое, ошибка (`#DIV/0!`), пусто; признак даты по формату ячейки; признак формулы и есть ли у неё сохранённое значение.
- **Модуль (предварительно):** `numerical_solver/gpn_multiphase_solver/io/` (имя — при планировании).

## 2. Контекст

### 2.1. Почему не `radial_blackoil.xlsxio` (прочитан 2026-10-15)

`HydroSolverPrototype/Prototype_1.0.3/radial_blackoil/xlsxio.py`, `read_workbook_tables` (55 строк, только стандартная библиотека) возвращает листы как списки строк значений:

- ячейка без `t` с `<v>` → `float`; формат ячейки (`s`, `styles.xml`) не читается — **дата приходит числом** (Excel превращает «1.5» в 1 мая → 46143.0);
- `t="b"` → `float` 1.0 — **логическое значение неотличимо от числа**;
- `<f>` без `<v>` → `None` — **формула без сохранённого значения неотличима от пустой ячейки** (книга, записанная программой и не открытая в Excel, сохранённых значений не имеет);
- `t="e"` → строка `'#DIV/0!'` — различимо;
- адресов нет, неровные строки дополняются `None`.

Плюс это внутренний модуль другого дистрибутива (`radial-blackoil`): зависеть от него ради ввода решателя — связывать формат ввода с прототипом.

### 2.2. Что должен уметь разбор

- общие строки (`sharedStrings.xml`, в том числе форматированный текст из нескольких `<t>`), встроенные (`inlineStr`), строки формул (`t="str"`);
- признак даты: встроенные форматы 14–22, 45–47 и пользовательские с d/m/y/h/s (без кавычек и `[цвет]`) — уточнить при планировании;
- порядок листов и имена — из `workbook.xml` и `_rels/workbook.xml.rels` (как в `xlsxio`);
- пустые хвостовые строки (в черновике руководителя на THERMAL — строка из `None`), неровные строки (SCHEDULE черновика: строки из 3 ячеек при 5 столбцах);
- объединённые ячейки (`mergeCell` на листе COMMENTS черновика) — значение только в первой ячейке; читать как есть.

### 2.3. Средства тестов

XlsxWriter установлен всегда — зависимость прототипа (`HydroSolverPrototype/Prototype_1.0.3/pyproject.toml`, `XlsxWriter>=3.2`; `tests/test_packaging.py`); после [[feat-033 workbook-input-format|FEAT-033]] — явная зависимость пакета. Им в тестах создаются книги с датой, логическим значением, числом строкой, формулой, ошибкой. XlsxWriter пишет у формулы сохранённое значение (0 по умолчанию), поэтому «формула без значения» — правкой XML листа в тесте.
