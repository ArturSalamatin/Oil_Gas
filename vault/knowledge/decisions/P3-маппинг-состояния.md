# P3. Маппинг состояния: прототип ↔ наша библиотека

## Два представления

### Прототип: BlackOilState

```python
BlackOilState:
    pressure_bar: np.ndarray     # [N], бар
    rs_sm3_sm3: np.ndarray       # [N], м³ст/м³ст
    sg: np.ndarray               # [N], безразмерное
    gas_active: np.ndarray       # [N], bool
```

- gas_active=True (режим 1, двухфазная): Sg — свободная переменная, Rs = Rs_sat(p) (восстанавливается из PVT)
- gas_active=False (режим 2, однофазная): Rs — свободная переменная, Sg = 0

### Наша библиотека: SimulationState

```python
SimulationState:
    p: np.ndarray        # [N], Па
    Sg: np.ndarray       # [N]
    Rs: np.ndarray       # [N], м³ст/м³ст
    T: np.ndarray        # [N], К
    regime: np.ndarray   # [N], int (1 или 2)
    t: float             # с
```

Все поля — полные массивы, всегда заполнены.

## Маппинг

### Наш → прототип (шаг 2 Adapter)

```python
proto_state = BlackOilState(
    pressure_bar = state.p / BAR_TO_PA,
    rs_sm3_sm3   = state.Rs.copy(),
    sg           = state.Sg.copy(),
    gas_active   = (state.regime == 1)
)
```

### Прототип → наш (шаг 4 Adapter)

```python
new_state = SimulationState(
    p      = new_proto.pressure_bar * BAR_TO_PA,
    Sg     = new_proto.sg.copy(),
    Rs     = new_proto.rs_sm3_sm3.copy(),
    T      = state.T.copy(),             # гидро не меняет T
    regime = np.where(new_proto.gas_active, 1, 2),
    t      = state.t + dt
)
```

## Проверенные сценарии

### Rs при regime=1 (gas_active=True)

Прототип в `unpack()`: `rs = Rs_sat(p)` — восстанавливает из PVT. В возвращаемом BlackOilState `rs_sm3_sm3` = Rs_sat(p). Adapter копирует это значение. Корректно.

### Sg при regime=2 (gas_active=False)

Прототип в `unpack()`: `sg = 0.0`. Малые отрицательные значения (в пределах sg_switch_tol) зануляются в advance (строка 212). Adapter получает Sg = 0.0 или clamp-нуль. Корректно.

### Переключение режимов между шагами

Прототип определяет режимы самостоятельно через active-set iterations. Начальный mask берётся из state_old.gas_active (= наш regime предыдущего шага), но это только starting guess. Прототип переключит mask если нужно. Adapter не участвует в логике переключения — принимает результат как есть.

### Начальное состояние (t=0)

```python
# Все ячейки однофазные, p > pb
state_0 = SimulationState(
    p      = np.full(N, p0),       # Па
    Sg     = np.zeros(N),
    Rs     = np.full(N, Rs0),
    T      = np.full(N, T0),
    regime = np.full(N, 2, dtype=int),
    t      = 0.0
)
```

Маппинг → `BlackOilState.undersaturated(N, p0_bar, Rs0)`. Совпадает.

### T и t — поля нашего состояния, отсутствующие в прототипе

- T: Adapter копирует из входного state. Гидро не меняет T. EnergySolver обновляет T после гидро-шага.
- t: Adapter вычисляет `state.t + dt`. Прототип не хранит время.

## Подводные камни

### Единственный тонкий момент: согласованность Rs_sat

При gas_active=True прототип вычисляет Rs = Rs_sat(p) через **свой** табличный PVT. Если наш EnergySolver или другой модуль использует **свой** PVT (корреляции), Rs_sat может отличаться.

Это не проблема P3 (маппинга), а проблема **P5 (PVT: табличные vs корреляции)**. В рамках P3 маппинг корректен: мы копируем то, что прототип вычислил, без пересчёта.
