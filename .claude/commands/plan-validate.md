# План валидационного кейса

Пользователь указал задачу: `$ARGUMENTS`

Формат аргумента: `VAL-NNN` или описание кейса.

## Инструкции

### 1. Загрузи контекст

- Прочитай запись в `vault/roadmap/валидационные кейсы.md`.
- Если `$ARGUMENTS` — описание, найди запись или создай через `/issue`.

### 2. Определи эталон

Три варианта:

**Аналитическое решение:**
- Формула из `Refs/` или `moments_method.tex`.
- Конкретные параметры, при которых решение известно.
- Ссылка на источник.

**Предельный случай:**
- Sg=0 (однофазный приток) → формула Дюпюи.
- T=const (изотермический) → 2 PDE вместо 3.
- rb→0 (начальная асимптотика) → автомодельная задача.

**Численный эталон:**
- OPM Flow с радиальной сеткой.
- Конечные разности для PDE-системы (собственная реализация).

### 3. Составь план

Записать в `vault/plans/VAL-NNN <slug>.md`:

```markdown
---
tags: [plan, validation]
date: ГГГГ-ММ-ДД
issue: VAL-NNN
status: черновик
---

# VAL-NNN: Краткое описание

## Эталон
- Источник: ...
- Формула / метод: ...
- Параметры: ...

## Сценарий
- Конфиг: `configs/val_NNN.json` (на основе baseline.json с модификациями)
- Время: ...
- Что варьируется: ...

## Метрика
| Величина | Tolerance | Как сравнивать |
|---|---|---|
| rb(t) | < 5% | относительная ошибка по точкам |
| p(rw,t) | < 1% | ... |
| T(rw,t) | < 2 К | абсолютная ошибка |

## Реализация
- [ ] Создать `configs/val_NNN.json`
- [ ] Реализовать эталон (если нужен код)
- [ ] Тест: `tests/test_solver.py::test_val_NNN`
- [ ] Графики: профили в момент t=...
```

### 4. Запиши результат в vault

После прохождения: `vault/knowledge/validation/VAL-NNN <описание>.md` с графиками и выводами.

### 5. Обнови roadmap

Ссылка на план. Статус → 🟡 В РАБОТЕ или ✅ ПРОЙДЕН.
