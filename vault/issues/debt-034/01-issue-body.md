## Описание

Пример 20 (FEAT-025) переведён с $R_{s,0} = 500$ на $R_{s,0} = 300$ — решение пользователя от 2026-10-03, вариант Б из диагностики BUG-019. При $R_{s,0} = 500$ ($p_b = 46.38$ МПа) задача лежала вне диапазона данных корреляции Стендинга: выше 34.55 МПа $c_{ot} < 0$. Конфиг уже изменён, а README примера, сводная таблица `examples/README.md` и ожидания тестов `TestStandingCoreyCooling` остались от $R_{s,0} = 500$. Тесты примера 20 красные, поэтому baseline любой задачи красный: это блокирует реализацию BUG-019 (#49).

## Анализ вариантов решения

Числа README и тестов меняются в любом варианте. Варианты различаются тем, как класс `TestStandingCoreyCooling` (общий для 19–21) принимает конфиг 20, который нарушает его общий контракт.

**Вариант 1 — параметры примера в `STANDING_COREY_COOLING`.**
- *Суть:* в словарь примера добавить поля для общих сейчас проверок: число интервалов и набор шагов истории, окно $p_0 - p_b$. Для проверок по записям добавить выбор записей, например только суточные.
- *Изменения:* `tests/test_examples.py:2036–2046, 2061–2075, 2079–2093, 2153–2174`.
- *Плюсы:* один класс, правки локальные, 19 и 21 не меняются.
- *Минусы:* докстринги класса описывают уже не общий контракт, словарь разрастается.

**Вариант 2 — отдельный класс для примера 20.**
- *Суть:* убрать 20 из `STANDING_COREY_COOLING` и завести класс с собственными проверками: ступенчатая история, $p_0 - p_b = 2.71$ МПа, окно $\Delta T$ по своим записям.
- *Изменения:* `tests/test_examples.py`, новый класс рядом с `TestStandingCoreyCooling`.
- *Плюсы:* пример самостоятелен, докстринги точны, 19 и 21 не затронуты.
- *Минусы:* около шести тестов дублируются.

**Вариант 3 — вернуть конфиг 20 к общему контракту.**
- *Суть:* 30 × 1 сут и $p_0 - p_b \approx 0.5$ МПа ($p_0 \approx 30.8$ МПа).
- *Плюсы:* тесты меняются только числами.
- *Минусы:* противоречит решению пользователя ($p_0 = 33$ МПа, ступенчатая запись); не рекомендуется без его согласия.

**Рекомендация:** вариант 1. Конфиг 20 отличается от 19 и 21 двумя параметрами (форма истории и окно $p_0 - p_b$), их достаточно вынести в данные примера. Если часовые записи потребуют других проверок первых суток (окно $\Delta T$, монотонность GOR), выбрать вариант 2. Окончательное решение принимается в `/plan-improve` после замера.

**Решения пользователя, нужные для плана:**
1. Откуда $L$ = 170 кДж/кг: Клапейрон для $R_{s,0} = 300$ или выбор пользователя. От ответа зависит раздел «Откуда тепловые параметры» README и докстринг «L по Клапейрону».
2. Зачем `co_undersaturated = 3.3e-9`: README должен это объяснить, в 19 и 21 параметра нет.
3. Имя папки `20_rs300_cooling` — подтвердить (в рабочей копии уже переименовано).
4. Вариант структуры тестов (1 или 2).
