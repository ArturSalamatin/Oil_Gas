## Описание

Три заметки vault описывают `SimulationHistory` и шаг по времени `Simulator` в состоянии до [[DEBT-013]] (балансы в истории) и [[DEBT-015]] (локальное дробление шага). Расхождения найдены при планировании и аудите DEBT-050 (сверка заметки оркестратора с кодом на `81d1474`), план DEBT-050, раздел «Обнаруженные проблемы», пп. 1–3. Код не меняется — правится только vault.

Приоритет низкий: документация, на расчёт не влияет.

## Анализ вариантов решения

### Вариант 1 — переписать все устаревшие разделы по коду

- **Суть.** Во всех трёх заметках заменить устаревший текст текущим: сигнатуры, псевдокод, термины.
- **Изменения.** `контейнер-simulation-history` — разделы «Методы» и «Реализация в фазе 3» переписать (или слить «Методы» с верхом); `архитектура…` — таблицы §§4–6 и псевдокод §6 по коду; `матрица…` — две правки.
- **Плюсы.** Заметки точны.
- **Минусы.** `архитектура…` дублирует `модули-simulator-оркестратор` по схеме шага — два места, которые снова разойдутся при следующей правке `Simulator`. Нарушает исторический характер проектной заметки.

### Вариант 2 — плашки «проектный этап» везде

- **Суть.** В начало каждого устаревшего раздела — плашка «проектный этап; текущее состояние — [[...]]», текст не трогать.
- **Плюсы.** Минимум правок, история решений сохранена.
- **Минусы.** Для `контейнер-simulation-history` не годится: это справочник по контейнеру, верх уже актуален — плашка внутри одной заметки оставит противоречие на месте. Для `матрица…` прогноз о тесте останется неверным утверждением.

Поправить имена функций в «Жизненном цикле».
