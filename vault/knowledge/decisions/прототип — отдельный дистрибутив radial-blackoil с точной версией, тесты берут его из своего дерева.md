# Прототип — отдельный дистрибутив radial-blackoil с точной версией, тесты берут его из своего дерева

**Что было.** У прототипа гидродинамики `radial_blackoil` (`numerical_solver/HydroSolverPrototype/Prototype_1.0.3/`) не было `pyproject.toml`. Ядро GPN импортирует его лениво, и находился он только через вставки пути в `sys.path`: 14 мест в тестах и примерах. Вне репозитория `SimulatorFactory.from_config` падал с `ModuleNotFoundError` (`factory.py:390`). Для поставки заказчику (решение 2026-10-10) так нельзя.

**Решение (DEBT-059, решения пользователя 2026-10-10):**

| Вопрос | Решение | Почему |
|---|---|---|
| Вид поставки | два дистрибутива в одном репозитории: `radial-blackoil` (свой `pyproject.toml`) и `gpn-multiphase-solver`, который требует первый | импорты ядра и тестов прототипа не меняются; у прототипа остаются своя версия, тесты, регрессия против CMG IMEX и граница авторства |
| Версия | `1.0.3+gpn.1` только у дистрибутива — литерал `radial_blackoil.__version__` | `run_regression.py:72` сверяет `prototype_version` и `build_id` из `run_summary.json` с эталонами; их смена — пересъём 17 эталонов. Литерал `setuptools` читает без импорта пакета (в изолированной сборке numpy нет) |
| Зависимость GPN | ровно `radial-blackoil==1.0.3+gpn.1` | совместим только прототип с нашими правками; PyPI не принимает версии с локальной меткой, поэтому чужой пакет с тем же именем зависимость не удовлетворит |
| Как тесты GPN находят прототип | `pythonpath = ["HydroSolverPrototype/Prototype_1.0.3"]` в `[tool.pytest.ini_options]` вместо вставки в `conftest.py` | venv один на основной каталог и все worktree. Установленный прототип указывает на основной каталог, а тесты worktree должны проверять свой код. Установку проверяет приёмка в чистом окружении, а не тесты |
| `PACKAGE_MANIFEST_SHA256.txt` | остаётся записью поставки 2026-08-25 | `Prototype_1.0.3.zip` в git не хранится; манифест — единственная запись исходных сумм |

**Установка** (из `numerical_solver`): `pip install -e HydroSolverPrototype\Prototype_1.0.3 -e ".[dev]"` — одной командой. `pip install -e .` без прототипа даёт `No matching distribution found for radial-blackoil==1.0.3+gpn.1`.

**Сторожа** — `tests/test_packaging.py`:
- версия в `__init__.py` равна требованию GPN;
- версия берётся из литерала;
- в дистрибутив прототипа входит только `radial_blackoil`;
- каждый сторонний импорт обоих пакетов объявлен в их `dependencies`;
- пакеты импортированы из дерева тестов;
- путь к прототипу в `sys.path` никто не вставляет.

**Приёмка:** `vault/issues/debt-059/probes/clean_env_acceptance.py`. Колёса без PyPI и установка с правкой исходников; расчёт примеров 03, 04, 05 побитово равен расчёту из репозитория; `run_workbook` пишет `results.xlsx` и PNG.

**Что осталось открытым:**
- когда менять `+gpn.N` — предложено при каждой поставке, если код прототипа изменился (FEAT-031);
- вставки `numerical_solver/` и `examples/` в `sys.path` — плоские импорты общих модулей (DEBT-011, FEAT-030).
