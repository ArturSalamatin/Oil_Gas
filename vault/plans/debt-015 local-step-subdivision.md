## 1. Текущее состояние (база `cf86aa2`)

### 1.1. Как устроено дробление сейчас

Дробление живёт в двух местах сразу.

1. **Адаптер** — `numerical_solver/gpn_multiphase_solver/hydro/prototype_adapter.py`, `PrototypeHydroAdapter.solve` (строки ~80–204). При `report.converged == False` он пробует `attempt = 0 … max_retries` и каждый раз проходит $2^{attempt}$ **равных** подшагов от исходного состояния. Удачная попытка возвращает один `HydroResult` с полем `n_substeps = 2**attempt`. Исчерпание попыток — `RuntimeError("HydroSolver не сошёлся после {2**max_retries} подшагов …")`. Интегралы потоков через забой и контур (`int_G_*`, DEBT-039) копятся по подшагам удачной попытки.
2. **Simulator** — `numerical_solver/gpn_multiphase_solver/simulator.py`, `_advance` (строки ~198–275). Если `hydro_result.n_substeps > 1`, результат «пробного» шага выбрасывается. Затем интервал проходится заново, рекурсивно, `n_sub` раз по `dt/n_sub` с `allow_subdivision=False`: гидро-подшаги считаются второй раз, теперь вместе с энергией (механизм BUG-010). Если подшаг повторного прохода снова дробится, срабатывает ветка «предел вложенности»: `user_log.warning`, энергия этого подшага не дробится.

Почему энергия обязана идти по подшагам гидро — BUG-010: расщепление «гидро → энергия» имеет порядок $O(\Delta t)$, на интервале, который гидродинамика забраковала, ошибка $T$ достигала 1.39 К (пример 07, $dt$ = 450 с).

### 1.2. Что плохо

- **Двойной счёт.** На останове из развитой газовой зоны A-retry после BUG-020 срабатывает на каждом часе первых суток. 20B ($dt_{int}$ = 3600 с): 1072 принятых вызова `advance` против 540 при локальном дроблении, 376 с против 241 с (раздел 4).
- **Равномерное дробление хрупко при немонотонной сходимости по $\Delta t$** (BUG-019, BUG-020: 60 с ✓, 10 с и 169 с ✗). Сходиться обязан каждый из $2^k$ равных подшагов. Один неудачный подшаг из 512 валит интервал, и `dt_integration` = 1 сут на останове не проходит. Отсюда требование «`dt_integration` ≤ 3600 с при смене режима» в тексте отказа и README.
- **Обратный канал и рекурсия.** Контракт `HydroSolver` («один шаг») нарушен полем `n_substeps`. `_advance` вызывает сам себя с флагом, ветка вложенности недостижима (`02a-comment-decision.md`).

## 2. Целевое состояние

- `HydroSolver.solve` — **один шаг без дробления**. Не сошёлся — `HydroConvergenceError` (подкласс `RuntimeError`, `hydro/base.py`), состояние не меняется.
- `PrototypeHydroAdapter` — один вызов `advance`. Без `max_retries`, без цикла попыток, без `n_substeps`, без пользовательского текста отказа.
- `Simulator(..., max_retries=9)`. `_advance` — локальное дробление G1a (раздел 3.3):
  - отказавший подшаг делится пополам и повторяется из того же состояния;
  - принятый подшаг сразу проходит баланс массы, энергию и обновление состояния;
  - после удачи подшаг удваивается, если пройденная часть шага кратна удвоенному подшагу;
  - наименьший подшаг — $dt/2^{max\_retries}$; не сошлось и на нём — `RuntimeError` с честным текстом.
- Нет повторного прохода, рекурсии, `allow_subdivision`, ветки «предел вложенности», поля `HydroResult.n_substeps`.
- **Истории всех 21 примера побитово равны базе** (проверено пробой при планировании, раздел 4.1).
- На останове из развитой газовой зоны — меньше вызовов `advance` и меньше время. Расчёт проходит и при `dt_integration` = 1 сут: требование «≤ 3600 с» снимается с README и текста отказа (раздел 4.2).

Граф импортов: `simulator.py` начинает импортировать `HydroConvergenceError` из `hydro/base.py` (уже импортирует `HydroSolver` оттуда), `DAY_TO_S` из `units.py` и `dev_log` из `log.py`. Новых модулей и циклов нет.

### 3.2. Политика роста (замер, раздел 4)

- **G0** (без роста до конца шага $dt$) — быстрее там, где проходит. Но застревает на наименьшем подшаге при немонотонной сходимости: 19B и 20A при 1 сут падают.
- **G1** (×2 после удачи, `min(2h, остаток)`) — устойчивее G0, но порождает подшаги не вида $dt/2^k$ (548 с, 928 с при $dt$ = 1 сут) и стык через остаток. 20B при 1 сут и `max_retries` 9 падает.
- **G1a** (×2 с выравниванием) — выбран. Проходит все 5 сценариев останова при штатном `max_retries` = 9.

### 3.3. Алгоритм G1a

Шаг $dt$ меряется в единицах наименьшего подшага: `n_units = 2**max_retries`. Состояние цикла — два целых: `done` (пройдено единиц) и `size` (текущий подшаг в единицах, всегда степень двойки).

```
size = n_units; done = 0
пока done < n_units:
    h = dt / (n_units // size)          # деление на степень двойки — точно
    гидро(h): отказ → если size == 1: RuntimeError; иначе size //= 2; повторить
    принят → баланс массы, энергия(h), состояние; done += size
    если done < n_units и done % (2*size) == 0: size *= 2
```

- **Целочисленный учёт** исключает накопление ошибки округления в «остатке» (с `t_left -= h` в float подшаг на конце мог выйти $10^{-13}$ с).
- **Выравнивание.** Удвоение разрешено, только если граница кратна удвоенному подшагу. Тогда `n_units − done` кратно `2*size` и удвоенный подшаг не выходит за конец шага: `min` не нужен, подшаги — только $dt/2^k$.
- **Побитовость при глубине 1** (пример 10): `dt` ✗ → `size = n_units/2`, `h = dt/2` ✓ → `done = n_units/2`, рост не разрешён (`n_units/2 % n_units ≠ 0`) → `h = dt/2` ✓. Прежний повторный проход делал те же два вызова `advance(dt/2)` и `energy(dt/2)`, в том же порядке. Прототип между вызовами `advance` состояния не хранит (`02a-comment-decision.md`), поэтому результат побитово тот же.
- **Лимит не меняет путь решения.** Последовательность $h$ не зависит от `max_retries`, пока глубина ≤ лимита: условие роста `done % (2*size) == 0` эквивалентно «граница кратна $2h$», в секундах. Замер: 20B при 1 сут — `max_retries` 9 и 11 дают одну и ту же последовательность (348/187). Поэтому метод «минимальный `max_retries` = наибольшая глубина одного прогона» (`vault/knowledge/numerics/минимальный max_retries измеряется одним прогоном…`) сохраняется.

        """Один шаг advance без дробления; не сошёлся — HydroConvergenceError (DEBT-015)."""
        from radial_blackoil.state import BlackOilState

        # ── Шаг 2: SimulationState (Па) → BlackOilState (бар) ──
        proto_state = BlackOilState(
            pressure_bar=state.p / BAR_TO_PA,
            rs_sm3_sm3=state.Rs.copy(),
            sg=state.Sg.copy(),

        new_proto, report = self._model.advance(proto_state, dt)
        if not report.converged:

                f"невязка {report.residual_inf:.2e}")

        # ── Шаг 4: BlackOilState (бар) → SimulationState (Па) ──
        new_state = SimulationState(
            p=new_proto.pressure_bar * BAR_TO_PA,
            Sg=new_proto.sg.copy(),

        # (DEBT-039). Потоки — на новом состоянии, как в невязке Ньютона

                       int_G_o_ext=dt * f['oil_outer'],
                       int_G_g_well=dt * (-f['gas_component_well']),

```python
    def _advance(self, state: SimulationState, dt: float,
                 bc: BoundaryConditions,
                 balance: EnergyBalanceAccumulator,
                 mass: MassBalanceAccumulator | None
                 ) -> tuple[SimulationState, HydroResult]:
        """Шаг dt: подшаги гидро → энергия; не сошедшийся подшаг делится пополам (DEBT-015)."""
        # ── Локальное дробление (DEBT-015) ──
        # Подшаг, на котором гидродинамика не сошлась (HydroConvergenceError),
        # делится пополам и повторяется из того же состояния; принятый сразу
        # проходит балансы и энергию. После удачи подшаг удваивается, если
        # пройденная часть шага кратна удвоенному подшагу: подшаги остаются
        # вида dt/2**k и стыкуются без остатка. Наименьший подшаг —
        # dt/2**max_retries; не сошлось и на нём — RuntimeError.
        #
        # Энергия идёт ровно по подшагам гидро — BUG-010: расщепление
        # «гидро → энергия» имеет порядок O(dt) и применимо лишь там, где
        # устойчивы обе половины (замерено −1.39 К против −0.06 К при
        # дроблении, пример 07 при dt = 450 с).
        #
        # Накопители (EnergyBalanceAccumulator, MassBalanceAccumulator) —
        # кумулятивные сумматоры без отката. Откатывать нечего: отказ
        # гидродинамики случается до энергии, в накопители попадают только
        # принятые подшаги. Допущение «гидродинамика не зависит от T» не
        # нужно: каждый подшаг гидро видит T, обновлённое предыдущими.
        #
        # Равномерное дробление (A-retry адаптера до DEBT-015) требовало,
        # чтобы сходился каждый из 2**k равных подшагов: при немонотонной
        # сходимости по dt (BUG-019, BUG-020) один неудачный подшаг из 512
        # валил шаг, и останов из развитой газовой зоны при dt_integration =
        # 1 сут не проходил. Локальное дробление выбирает подшаг на каждом
        # участке отдельно.

        # Шаг dt в единицах наименьшего подшага: пройденная часть и
        # текущий подшаг — целые, ошибка округления не копится.
        n_units = 2 ** self._max_retries
        done = 0              # пройдено единиц
        size = n_units        # текущий подшаг, единиц; всегда степень двойки
        n_ok = n_fail = 0
        h_min_ok = dt
        while done < n_units:
            # Деление на степень двойки точно: при глубине 1 подшаг побитово
            # равен dt/2 прежнего A-retry, и истории примеров не меняются.
            h = dt / (n_units // size)

            # 1. Гидродинамика → p, Sg, Rs + потоки на конце подшага
            try:
                hydro_result = self._hydro.solve(state, h, bc)
            except HydroConvergenceError as exc:
                # Ловим только отказ сходимости: ошибка кода в гидро
                # (иной RuntimeError) дроблением не маскируется.
                n_fail += 1
                dev_log.debug(f"  подшаг {h:.3e} с не сошёлся: {exc}")
                if size == 1:
                    raise RuntimeError(self._failure_message(state, dt)) from exc
                size //= 2
                continue

            # Баланс массы (DEBT-039): только принятый подшаг.
            if mass is not None:
                mass.add_step(hydro_result)

            # 2. Температура на замороженных p, Sg, Rs подшага.
            # Решатель попутно отдаёт накопителю коэффициенты, которые
            # уходят в СЛАУ, — баланс считается по тем же величинам,
            # что и схема (DEBT-013).
            T_new = self._energy.solve(
                hydro_result, state, h, bc, collect=balance)

            # 3. Обновить состояние (splitting: T из energy, остальное из hydro)
            state = SimulationState(
                p=hydro_result.state.p,
                Sg=hydro_result.state.Sg,
                Rs=hydro_result.state.Rs,
                T=T_new,
                regime=hydro_result.state.regime,
                t=hydro_result.state.t,
            )
            n_ok += 1
            h_min_ok = min(h_min_ok, h)
            done += size
            # Рост ×2 после удачи — только с выравниванием: граница кратна
            # удвоенному подшагу, поэтому n_units − done кратно 2·size и
            # удвоенный подшаг не выходит за конец шага. Без выравнивания
            # появляются подшаги не вида dt/2**k (замер при планировании:
            # 548 и 928 с при dt = 1 сут) и стык через остаток, а останов
            # 20B при 1 сут не проходит.
            if done < n_units and done % (2 * size) == 0:
                size *= 2

        if n_fail > 0:
            # Видимо сказывается на времени расчёта — сообщаем, как прежде
            # сообщал адаптер.
            user_log.info(
                f"Шаг {dt:.3g} с раздроблен: подшагов {n_ok}, наименьший "
                f"{h_min_ok:.3g} с, отказов гидродинамики {n_fail}")
        return state, hydro_result

    def _failure_message(self, state: SimulationState, dt: float) -> str:
        """Текст отказа: факты подшага, на котором исчерпано дробление (BUG-018, DEBT-015)."""
        # Факты, а не догадка о причине: отказ бывает из-за величины шага
        # (DEBT-007, BUG-003 — помогает дробление глубже) и не из-за неё
        # (BUG-017, BUG-018 до исправления, BUG-019 — шаг не сходится и при
        # мелких подшагах). Различить их здесь нельзя. Начало текста
        # цитируют README примеров 03, 05, 06, 07, 10 и тесты — менять
        # вместе с ними.
        n_units = 2 ** self._max_retries
        n_two = int(np.count_nonzero(state.regime == 1))
        return (
            f"HydroSolver не сошёлся при дроблении шага до dt/{n_units} = "
            f"{dt / n_units:.2e} с на подшаге с t = {state.t / DAY_TO_S:.4f} сут: "
            f"двухфазных ячеек {n_two} из {state.p.size}, "
            f"max S_g = {float(np.max(state.Sg)):.3f}. "
            f"Наименьший подшаг — time.dt_integration / 2**numerics.max_retries "
            f"(сейчас max_retries = {self._max_retries}, допустимо до 20). "
            f"Если отказ вызван величиной шага, поможет больший "
            f"numerics.max_retries или меньший time.dt_integration; если шаг "
            f"не сходится и при мелких подшагах, причина не в его величине.")
```
