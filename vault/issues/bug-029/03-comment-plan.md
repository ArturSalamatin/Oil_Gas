### План готов

**Файл:** `vault/plans/bug-029 skin-zone-throttling-temperature.md` (2026-10-15, база `a7b0dc0`)

**Решение пользователя (2026-10-14):** только вариант 1 — уведомить пользователя, что скин в тепловой модели не учитывается. Проба $\Delta T_s$ и варианты 2 (поправка вывода $T_{wf}$), 3 (вклад скин-перепада в схему) не делаются; расчётный код не меняется. Рекомендация тела issue «сначала проба» снята этим решением.

**Что делается (5 шагов):**
- `io/config.py`: `_warn_skin_not_in_energy` — предупреждение при $s > 0$ после `_validate`, рядом с `_warn_large_skin`: скин учитывается только в гидродинамике, дросселирование и разгазирование на перепаде скин-зоны в температуру не входят, $T_{wf}$ их не содержит. В сообщении — доля депрессии на скин-зоне в установившемся однофазном притоке $s/(\ln(R_{ext}/r_w) + s)$. При $s > 50$ — два предупреждения: о доле притока (DEBT-056, текст прежний) и о температуре.
- Тесты `TestValidationWell` (`tests/test_config.py`): `test_skin_up_to_threshold_silent` заменён — он фиксировал молчание при $0 < s \le 50$, то есть сам дефект; `test_large_skin_warns` ждёт два сообщения; сообщения различаются по признакам, а не по порядку. 22 → 24 теста, всего 1987 → 1989.
- Комментарии `NumericsConfig.skin`, `WellData.T_wf`; проба видимости предупреждения в свежем процессе (резервный обработчик `logging`, без `caplog`).
- vault: P8 §5, схема конфига, заметка о температуре ячейки 0.

**Не трогается:** `problem_statement.tex` (фраза о скин-зоне уже есть в `ssec:bc_disc` после BUG-015) и `energy/tridiag.py` — этот раздел и докстринг `compute_jt` переписывает DEBT-070 (#119). README пакета (FEAT-031) вне git — заметка к FEAT-031.

**Численно:** побитово — во всех конфигах проекта $s = 0$, расчётный код не меняется.
