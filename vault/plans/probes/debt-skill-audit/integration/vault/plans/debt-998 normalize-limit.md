# План DEBT-998: убрать дублирование чтения лимита

## Основание

Реестр, тестовый issue `vault/issues/debt-998/issue-fixture.md` и `00-draft.md` требуют сохранить явные ложные значения. В `src/config.py` две функции содержат выражение `data.get("limit", 5)`.

## Шаг 1: зафиксировать поведение тестом

Создать `tests/test_limits.py` и проверить обе функции для отсутствующего ключа, `0`, `None`, `False` и `""`. Ожидания: соответственно `5`, `0`, `None`, `False`, `""`. Для `False` проверить тождество, для `0` – значение и тип `int`, чтобы различить `0` и `False`. До изменения кода выполнить тесты.

## Шаг 2: выделить общую функцию

В `src/config.py` добавить `normalize_limit(data)`, возвращающую `data.get("limit", 5)`. Обе функции `read_limit` и `read_other_limit` должны вызывать её. Ожидаемое поведение совпадает с исходным: отсутствие ключа даёт `5`, явные `0`, `None`, `False`, `""` сохраняются.

## Проверка после шагов

Из корня фикстуры выполнить интерпретатором `numerical_solver/.venv/Scripts/python.exe` из корня Oil_Gas команду `-m pytest tests/test_limits.py`. Повторить тест после выделения функции.

## Критерии

Обе функции вызывают общий код, тесты проходят, обработка значений не меняется. После сохранения плана запустить `audit-plan` через субагента до реализации.
