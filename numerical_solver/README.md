# gpn-multiphase-solver — неизотермический приток газированной нефти к скважине

Библиотека решает одномерную осесимметричную задачу для призабойной зоны
пласта: фильтрацию нефти с растворённым газом и свободного газа (модель
Black Oil, вода отсутствует) совместно с расчётом температуры пласта.
В уравнении энергии учтены конвекция, теплопроводность, адиабатический
эффект, эффект Джоуля–Томсона и скрытая теплота разгазирования.
Гидродинамическую часть задачи (давление, газонасыщенность и газосодержание)
решает модуль `radial_blackoil`, уравнение энергии (температуру) —
собственный решатель библиотеки. Уравнения дискретизованы методом конечных
объёмов на логарифмической сетке по радиусу.

Постановка задачи и дискретные уравнения — [doc/problem_statement.tex](doc/problem_statement.tex).

## Начало работы

Решатель передаётся в одном из двух видов. Ниже – что делать с
полученными файлами, по шагам. Команды – PowerShell, с полными путями;
`X.Y.Z` – номер выпуска, его нужно подставить; папка `D:\gpn` – пример.
Нужны Python 3.10 или новее и доступ к PyPI или к его зеркалу.

| Поставка | Что получено | Для чего |
|---|---|---|
| для разработки | архив `gpn-multiphase-solver-X.Y.Z.zip` | изменение и развитие кода: исходный код решателя и прототипа, тесты, примеры, собранные HTML-документация и PDF постановки |
| для расчётов | папка `release-X.Y.Z` с пятью файлами: `gpn_multiphase_solver-X.Y.Z-py3-none-any.whl`, `radial_blackoil-1.0.3+gpn.N-py3-none-any.whl`, `examples-vX.Y.Z.zip`, `README.md` (этот файл), `docs-vX.Y.Z.zip` | расчёты без изменения кода |

## Ограничения

Модель и её реализация (подробно — постановка, раздел «Область и допущения»):

- задача одномерная осесимметричная: горизонтальный однородный пласт
  постоянной толщины, вертикальная скважина; все величины осреднены по
  толщине, сила тяжести не учитывается;
- две фазы — нефть с растворённым газом и свободный газ; воды нет; нефтяной
  компонент в газовую фазу не испаряется;
- фазовое равновесие мгновенное: кинетика разгазирования не учитывается;
- капиллярное давление не учитывается — давление фаз одно;
- теплообмен с кровлей и подошвой пласта не учитывается;
- гидродинамика от температуры не зависит: свойства флюидов в балансах масс
  берутся при пластовой температуре, температура входит только в уравнение
  энергии;
- теплоёмкости, коэффициенты Джоуля–Томсона и теплота разгазирования —
  постоянные из файла конфигурации;
- на контуре питания поддерживаются начальные давление, температура и
  газосодержание, приток однофазный; начальное состояние однородное, нефть
  недонасыщенная;
- скин-фактор не меньше нуля и учитывается только в гидродинамике: в
  уравнении энергии его нет, при положительном скине выводится
  предупреждение;
- скважина только добывающая: заданное забойное давление или дебит нефти с
  нижним пределом забойного давления; останов — дебит 0. Отрицательный
  дебит отвергается при чтении конфигурации; при забойном давлении выше
  давления у забоя скважина останавливается (дебит 0), нагнетания нет;
- погрешность по времени не контролируется: схема первого порядка, шаг
  задаёт пользователь (`time.dt_integration`, интервалы `time.history`,
  нарастающий шаг после смены режима);
- `setup.bat` — только для Windows; файлы EMF создаются только при
  установленном Inkscape.

## 1. Установка

Требуется Python 3.10 или новее (проверено на Python 3.13 под Windows).
Пакеты numpy, scipy, matplotlib и XlsxWriter устанавливаются автоматически
как зависимости.

Решатель и прототип — два отдельных пакета, и устанавливать их нужно
**вместе, одной командой**: решатель требует строго определённую версию
прототипа `radial-blackoil` (номер — литерал `__version__` в
[`radial_blackoil/__init__.py`](HydroSolverPrototype/Prototype_1.0.3/radial_blackoil/__init__.py)),
и без прототипа `pip install .` завершится ошибкой «No matching
distribution found for radial-blackoil». Команды ниже, кроме установки из
выпуска, выполняются из каталога `numerical_solver`.

**Для разработки, скриптом (Windows).** [setup.bat](setup.bat) находит
Python 3.10 или новее (`py -3`, затем `python`), создаёт `.venv` рядом с
собой, если её нет, устанавливает в неё оба пакета в режиме разработки с
вариантом `[dev]` и проверяет команду расчёта. Запускать можно из любого
каталога — по полному пути к скрипту; из каталога с этим README:

```powershell
.\setup.bat
```

Python скрипт не устанавливает; нужен доступ к PyPI или к его зеркалу.
Повторный запуск доустанавливает пакеты в существующую `.venv`. После
переноса каталога `numerical_solver` скрипт нужно запустить заново:
установка в режиме разработки запоминает пути.

**Для разработки, вручную** (изменения исходного кода действуют сразу, без переустановки):

```powershell
cd numerical_solver
python -m venv .venv
.venv\Scripts\python -m pip install -e HydroSolverPrototype\Prototype_1.0.3 -e ".[dev]"
```

Вариант `[dev]` дополнительно устанавливает pytest и Sphinx (сборка
документации, §7). Задавать `PYTHONPATH` не нужно.

**Только для расчётов** (без изменения кода) — та же команда без ключей `-e`:

```powershell
.venv\Scripts\python -m pip install HydroSolverPrototype\Prototype_1.0.3 .
```

**Из выпуска** (пакеты без исходного кода, для расчётов). Выпуски
публикуются в разделе Releases репозитория `ArturSalamatin/Oil_Gas`; состав
выпуска – таблица раздела «Начало работы» (в выпусках до 1.0.2 включительно
нет `README.md` и `docs-vX.Y.Z.zip`). При доступе к репозиторию выпуск
скачивается GitHub CLI, авторизованным командой `gh auth login`:

```powershell
mkdir D:\gpn -Force
cd D:\gpn
gh release download vX.Y.Z --repo ArturSalamatin/Oil_Gas --dir D:\gpn\release-X.Y.Z
```

Дальше – раздел «Начало работы», «Поставка для расчётов», с шага 1.

**На компьютере без доступа к PyPI.** На компьютере, где доступ есть,
соберите в каталог `wheels` установочные файлы (формат wheel, `.whl`)
решателя, прототипа и всех их зависимостей, перенесите этот каталог на
целевой компьютер и установите пакеты из него. Версия Python, операционная
система и её разрядность на обоих компьютерах должны совпадать: numpy и
scipy собраны под конкретную платформу.

```powershell
# на компьютере с доступом к PyPI
.venv\Scripts\python -m pip wheel -w wheels HydroSolverPrototype\Prototype_1.0.3 .
# на целевом компьютере
python -m venv .venv
.venv\Scripts\python -m pip install --no-index --find-links wheels gpn-multiphase-solver
```

Проверка установки:

```powershell
.venv\Scripts\python -m gpn_multiphase_solver run --help
```

Номер установленной версии решателя печатает
`.venv\Scripts\python -m gpn_multiphase_solver --version`; изменения между
версиями и правило номеров — в [CHANGELOG.md](CHANGELOG.md).

**Inkscape (необязательно).** Помимо PNG, каждый рисунок сохраняется в
`output/emf/` в форматах SVG и EMF (EMF — для вставки в Word). EMF
получается из SVG с помощью внешней программы Inkscape. Если она не
установлена, расчёт выполняется полностью: выводится одно предупреждение,
файлы SVG сохраняются, EMF не создаются. Путь к `inkscape.com` можно задать
переменной окружения `INKSCAPE`; значение `GPN_EXAMPLES_EMF=0` отключает
вывод SVG и EMF — остаются только PNG.

## 2. Запуск примеров

Обзор примеров и рекомендуемый порядок знакомства с ними — [examples/README.md](examples/README.md).
Каждый пример запускается своим скриптом `main.py` или командой пакета
с файлом конфигурации примера:

```powershell
cd numerical_solver
.venv\Scripts\python examples\06_table_corey_rp\main.py
.venv\Scripts\python -m gpn_multiphase_solver run examples\06_table_corey_rp\config.json

# все 24 примера подряд, около 12 мин
.venv\Scripts\python examples\run_all.py
```

В 18 примерах `main.py` только вызывает эту команду (в примере 22 — с книгой
Excel вместо файла конфигурации). В примерах 01–05
(кроме 04a) и 18 `main.py` после штатного расчёта выполняет дополнительную обработку, которой
нет в команде: аналитическое решение Дюпюи и решение ОДУ для температуры
(01, 02), сводку проверок стационарного режима (03–05), сверку с прототипом
и CMG IMEX (18).

Результаты записываются в `examples\<пример>\output\` (в репозиторий этот
каталог не входит). Пояснения к рисункам и контрольным значениям — в README
каждого примера.

## 3. Расчёт собственного варианта

Вариант задаётся файлом конфигурации JSON в единицах СИ (3.1–3.5) или книгой
Excel в инженерных единицах (3.6). Книга переводится в такой же файл
конфигурации, и дальше расчёт идёт одинаково.

### 3.1. Файл конфигурации

Расчёт полностью определяется файлом конфигурации в формате JSON. Проще всего
скопировать файл конфигурации наиболее близкого примера (вместе с его
таблицами CSV, если они есть) или [configs/baseline.json](configs/baseline.json)
и изменить нужные значения. **Все величины задаются в СИ:** Па, К, м, с, м²,
Па·с; дебит — м³ст/с.

| Раздел | Поле | Единицы | По умолчанию | Описание |
|---|---|---|---|---|
| `geometry` | `r_well` | м | — | радиус скважины $r_w$ |
| | `R_ext` | м | — | радиус контура питания $r_e$ |
| | `h` | м | — | толщина пласта |
| `grid` | `N` | — | — | число ячеек логарифмической сетки между $r_w$ и $r_e$ |
| | `type` | — | `"log_radial"` | тип сетки; других вариантов нет |
| `rock` | `porosity` | — | — | пористость $\phi$ при давлении $p_0$ |
| | `permeability` | м² | — | абсолютная проницаемость $k$ (1 мД ≈ 9,869·10⁻¹⁶ м²) |
| | `compressibility` | 1/Па | 0 | сжимаемость породы $c_r$ |
| | `rho_cp_solid` | Дж/(м³·К) | 1,25·10⁶ | объёмная теплоёмкость скелета $(\rho c_p)_s$ |
| | `lambda_solid`, `lambda_oil`, `lambda_gas` | Вт/(м·К) | 1,5; 0,14; 0,04 | теплопроводность скелета, нефти и газа |
| `pvt` | `model` | — | — | `"standing"` (корреляции Стендинга) или `"table"` (таблицы CSV) |
| | `rho_o_std`, `rho_g_std` | кг/м³ | — | плотности нефти и газа в стандартных условиях |
| | `co_undersaturated` | 1/Па | 0 | для корреляций Стендинга: сжимаемость недонасыщенной нефти $c_o \ge 0$; при $p \ge p_b(R_s)$ объёмный коэффициент $B_o = B_o(p_b)\,e^{-c_o (p - p_b)}$, при $c_o = 0$ $B_o$ зависит только от $R_s$. При табличном PVT допустимо только 0 |
| | `mu_o_undersaturated` | — | `"none"` | для корреляций Стендинга: вязкость нефти при $p > p_b(R_s)$. `"none"` — вязкость по Беггсу–Робинсону, зависит только от $R_s$; `"beal"` — к ней добавляется линейная по давлению поправка Била–Стендинга: $\mu_o = \mu_{ob} + (\partial \mu_o / \partial p)\,(p - p_b)$, наклон зависит от $\mu_{ob}$. При табличном PVT допустимо только `"none"` |
| | `oil_pvt_file`, `gas_pvt_file` | — | — | для таблиц: имена файлов CSV относительно каталога файла конфигурации (см. п. 3.3) |
| `relperm` | `model` | — | — | `"corey"` (модель Кори) или `"table"` (таблица CSV) |
| | `S_or`, `S_gc`, `n_o`, `n_g`, `kro_max`, `krg_max` | — | 0,2; 0,05; 2; 2; 1; 0,8 | модель Кори: остаточная нефтенасыщенность, критическая газонасыщенность, показатели степени, максимальные значения ОФП нефти и газа |
| | `file` | — | — | таблица ОФП: имя файла CSV относительно каталога файла конфигурации |
| `thermal` | `c_p_oil`, `c_p_gas` | Дж/(кг·К) | 2000; 1000 | удельные теплоёмкости нефти и газа |
| | `mu_JT_oil`, `mu_JT_gas` | К/Па | 0; 0 | коэффициенты Джоуля–Томсона нефти и газа (у нефти обычно < 0, у газа > 0) |
| | `L_degas` | Дж/кг газа | 0 | удельная теплота разгазирования |
| `initial_conditions` | `p0`, `T0`, `Rs0` | Па, К, м³ст/м³ст | — | однородное начальное состояние пласта; эти же значения поддерживаются на контуре питания |
| `time` | `dt_integration` | с | — | шаг интегрирования по времени |
| | `history` | — | — | режим работы скважины по этапам (см. п. 3.2) |
| | `dt_after_control_change` | с | `null` | первый подшаг после смены режима работы скважины, далее шаг удваивается; `null` — выключено; в примерах останова 16 и 17 — 0,11 с (README примера 16: газосодержание у забоя после останова задают первые доли секунды) |
| `numerics` | `skin` | — | 0 | скин-фактор скважины (≥ 0); учитывается только в гидродинамике — в уравнении энергии его нет, при значении больше нуля выводится предупреждение |
| | `max_retries` | — | 9 | наибольшее число делений шага пополам при несходимости метода Ньютона; наименьший подшаг — `dt_integration / 2**max_retries` |
| | прочие | — | см. код | ограничения и допуски метода Ньютона, `jacobian_mode`, `linear_solver`; изменять их не требуется |
| `output` | `title`, `n_profiles`, `steady_state`, `closed_form_overlays`, `log_level` | — | см. п. 3.5 | состав выводимых результатов; на расчёт не влияют |

Полный перечень полей и проверок их значений — [gpn_multiphase_solver/io/config.py](gpn_multiphase_solver/io/config.py).
Если в имени поля опечатка, значение недопустимо или обязательное поле
отсутствует, `load_config` отклоняет конфигурацию с сообщением, в котором
указано это поле.

**Граничные условия.** На контуре питания $r_e$ поддерживаются начальные
значения: давление $p_0$, температура $T_0$ и газосодержание притекающей
нефти $R_{s,0}$; приток однофазный. На забое задаётся режим работы скважины
из `time.history`.

**Начальное состояние.** Нефть в начальном состоянии должна быть
недонасыщенной: $R_{s,0} \le R_s^{eq}(p_0)$, то есть $p_0$ не ниже давления
насыщения нефти с газосодержанием $R_{s,0}$. Иначе конфигурация отклоняется;
в сообщении приводится значение $p_b(R_{s,0})$.

### 3.2. Режим работы скважины (`time.history`)

Список этапов; для каждого задаются режим работы скважины и
продолжительность. Результаты записываются в конце каждого интервала,
поэтому частота записи определяется только этим списком. Продолжительность
задаётся в одной из трёх форм:

```json
"history": [
  {"duration": 864000, "dt_out": 86400, "control": "pressure", "p_wf": 8.0e6},
  {"dt": 3600, "repeat": 24, "control": "pressure", "p_wf": 6.0e6},
  {"dt": 86400, "control": "rate", "q_oil": 0.0, "min_bhp": 5.0e6}
]
```

Здесь: 10 сут при забойном давлении 8 МПа с записью раз в сутки, затем
1 сут при 6 МПа с записью раз в час, затем 1 сут останова скважины.

- `duration` и `dt_out` — этап продолжительностью `duration` с записью через
  каждые `dt_out` (значение `duration` должно быть кратно `dt_out`);
- `dt` и `repeat` — `repeat` одинаковых интервалов длиной `dt`;
- `dt` — один интервал.

Режим (`control`): `"pressure"` — заданное забойное давление `p_wf`, Па;
`"rate"` — заданный дебит **нефти** в стандартных условиях `q_oil`, м³ст/с
(50 м³ст/сут = 5,787·10⁻⁴ м³ст/с), с обязательным нижним пределом забойного
давления `min_bhp`, Па. Останов скважины задаётся режимом `"rate"` с
`q_oil = 0`.

### 3.3. Табличные PVT и ОФП

Имена файлов CSV задаются полями `pvt.oil_pvt_file`, `pvt.gas_pvt_file`,
`relperm.file` относительно каталога файла конфигурации. Разделитель полей —
запятая, десятичный разделитель — точка; первая строка — заголовок строго
следующего вида:

| Файл | Заголовок | Содержание |
|---|---|---|
| нефть | `Rs_sm3_sm3,pressure_Pa,Bo,mu_o_Pa_s` | таблица в формате PVTO: ветви $R_s$ = const; на каждой — $B_o(p)$ и $\mu_o(p)$ от давления насыщения и выше |
| газ | `pressure_Pa,Bg,mu_g_Pa_s` | $B_g(p)$, $\mu_g(p)$ |
| ОФП | `Sg,kro,krg` | $k_{ro}(S_g)$, $k_{rg}(S_g)$ |

Образцы файлов — [examples/04_table_table/](examples/04_table_table/). При
табличном задании PVT корреляции не используются; значение $R_{s,0}$ должно
лежать в пределах таблицы. Несогласованные таблицы (немонотонные
зависимости, отрицательная сжимаемость) при построении решателя отклоняются
либо сопровождаются предупреждением.

### 3.4. Запуск

```powershell
.venv\Scripts\python -m gpn_multiphase_solver run путь\к\config.json [--output КАТАЛОГ] [--title ЗАГОЛОВОК] [--profiles N]
gpn-solver run путь\к\config.json          # то же при активированном виртуальном окружении
```

Команду можно запускать из любого каталога. Результаты записываются в
каталог, указанный ключом `--output`, по умолчанию — в каталог `output`
рядом с файлом конфигурации.

> **После успешного расчёта каталог вывода полностью очищается** и только
> затем заполняется результатами. Не указывайте каталог, в котором хранятся
> другие файлы. Если внутри каталога вывода находится сам файл конфигурации
> или его таблицы CSV, команда завершается с ошибкой ещё до расчёта.
> Так же до расчёта отвергается путь `--output`, по которому лежит файл
> (например, `well_history.csv` вместо каталога) или который проходит
> через файл, и путь на несуществующем диске — и при расчёте по книге.
> При расчёте по книге Excel каталог очищается до расчёта (3.6).
>
> Если файл каталога вывода открыт в другой программе (например, CSV в
> Excel) или в этом каталоге стоит консоль, каталог не удаётся очистить:
> команда завершается с ошибкой до расчёта (код 2), каталог не меняется —
> файл нужно закрыть и повторить расчёт. Если файл открыли уже во время
> расчёта, результаты записываются в соседний каталог с датой и временем в
> имени, например `output_2026-10-18_15-30-12`; об этом выводится
> предупреждение, прежний каталог не меняется.

Коды возврата: 0 — расчёт выполнен; 1 — решатель не смог выполнить шаг по
времени (сообщение решателя выводится в консоль; при расчёте по файлу
конфигурации прежние результаты в каталоге вывода сохраняются, по книге — в
каталоге остаётся только перевод книги, 3.6); 2 — ошибка в аргументах или
файле конфигурации либо занятый каталог вывода, расчёт не начинался.

Если решатель не сходится, обычно помогает уменьшить `time.dt_integration`
или увеличить `numerics.max_retries`; при резкой смене режима работы
скважины — задать `time.dt_after_control_change` (в примерах останова 16 и
17 — 0,11 с).

### 3.5. Результаты расчёта

| Файл | Содержание |
|---|---|
| `well_history.csv` | по строке на каждую запись: время (с и сут), дебиты нефти и газа (м³ст/с, кг/с), забойные давление и температура, газовый фактор |
| `profiles.csv` | по строке на каждую ячейку в каждой записи: `step, time_s, r_m, p_Pa, T_K, Sg, Rs` |
| `pressure_profiles.png`, `temperature_profiles.png`, `saturation_profiles.png`, `rs_profiles.png` | профили $p$, $T$, $S_g$, $R_s$ по радиусу в несколько моментов времени |
| `well_rates.png`, `wellbore_dynamics.png` | изменение дебитов во времени; изменение давления, температуры и газонасыщенности у забоя во времени |
| `relperm.png`, `pvt.png` | использованные в расчёте ОФП и PVT-свойства с отмеченным рабочим диапазоном |
| `energy_balance.png`, `mass_balance.png` | балансы энергии и массы компонентов — контроль разностной схемы |
| `versions.txt` | версии решателя, прототипа, Python, numpy и scipy, которыми получены результаты: по строке «имя номер» |

В консоль выводятся: перед расчётом — путь к файлу конфигурации (или к книге) и версии
(те же, что в `versions.txt`); после расчёта — сводка (давление и
температура у забоя и дебиты на конец расчёта), невязки балансов энергии и
массы, проверка равновесия $R_s$ и сводка PVT. Дебиты при добыче
положительны. Время на всех графиках — в сутках.

Состав выводимых результатов задаёт раздел `output` файла конфигурации;
ключи командной строки `--title` и `--profiles` имеют приоритет над ним.

| Поле | По умолчанию | Назначение |
|---|---|---|
| `title` | имя каталога файла конфигурации; у книги — имя книги без расширения | заголовок рисунков и сводки в консоли |
| `n_profiles` | 4 момента, выбранные по номерам записей | число моментов времени на графиках профилей, равномерно распределённых по времени (не менее 2) |
| `steady_state` | `false` | сравнение со стационарным режимом: аналитическое решение на графиках профилей $p$ и $S_g$, сверка с ним в консоли и асимптотика температуры |
| `closed_form_overlays` | `["p", "Sg"]` | на графики каких профилей наносить аналитическое решение при `steady_state = true` |
| `log_level` | `"INFO"` | уровень подробности журнала решателя: от `DEBUG` до `CRITICAL` |

Сравнение со стационарным режимом имеет смысл включать, только если скважина
весь расчёт работает в одном режиме и течение успело стать стационарным:
аналитическое решение (газовый фактор $= R_{s,0}$) и асимптотика температуры —
это пределы при $t \to \infty$. Иначе сверка покажет расхождение, не
связанное с точностью расчёта.

### 3.6. Книга ввода Excel

Вместо файла конфигурации расчёт можно задать книгой Excel (`.xlsx`):
величины — в инженерных единицах (бар, мД, сП, м³ст/сут, сутки, часы),
у числовых ячеек — проверка допустимых значений. Одна книга — один расчёт.

1. Получить шаблон с демонстрационными значениями:

   ```powershell
   .venv\Scripts\python -m gpn_multiphase_solver template my_case.xlsx
   ```

   Существующий файл команда не перезаписывает.
2. Заполнить книгу: на листах MODEL, THERMAL, NUMERICS — столбец Value
   (значение нужно в каждой строке), таблицы режима скважины SCHEDULE и
   свойств OIL_PVT, GAS_PVT, RELPERM. Единицы фиксированы и проверяются
   при чтении. Правила листов — на листе COMMENTS книги. Книга сохраняется
   в формате «Книга Excel (*.xlsx)».
3. Рассчитать:

   ```powershell
   .venv\Scripts\python -m gpn_multiphase_solver run my_case.xlsx [--output КАТАЛОГ] [--title ЗАГОЛОВОК] [--profiles N]
   ```

Результаты — те же, что у расчёта по файлу конфигурации (3.5), по
умолчанию в каталоге `output` рядом с книгой; заголовок рисунков — имя
книги без расширения. В `output\input\` сохраняется вход расчёта: книга,
переведённая в файл конфигурации `config.json` и таблицы CSV в единицах
СИ. По нему расчёт повторяется без книги (команда — из папки книги):

```powershell
.venv\Scripts\python -m gpn_multiphase_solver run output\input\config.json --output другой_каталог
```

Без `--output` результаты повтора легли бы в `output\input\output\` —
внутрь каталога, который следующий расчёт по книге очистит.

> **При расчёте по книге каталог вывода очищается до расчёта** — сразу
> после проверки книги. Если в книге ошибка, каталог не меняется. Если
> ошибку находит проверка файла конфигурации или таблиц либо решатель не
> может выполнить шаг по времени, в каталоге остаётся только `input\` —
> вход, на котором расчёт остановился; прежних результатов нет. Книга
> внутри каталога вывода — отказ до расчёта. Если файл каталога вывода
> открыт в другой программе (например, CSV в Excel) или в каталоге стоит
> консоль, каталог не удаётся очистить: команда завершается с ошибкой до
> расчёта, каталог не меняется — файл нужно закрыть и повторить расчёт.

Ошибки книги выводятся все сразу, с листом и ячейкой: `NUMERICS!C2 (Grid
cells (N)): 20.5 — нужно целое число ≥ 1`. Ошибки, которые находит проверка
файла конфигурации и таблиц, называют поле конфигурации — оно совпадает с
ключом строки книги (столбец Key), например `initial_conditions.Rs0`. Коды
возврата — как в 3.4; код 2 — также ошибка книги.

Перевести книгу без расчёта (посмотреть, какие значения в СИ получит
расчёт) — команда `convert`; каталог — новый или пустой:

```powershell
.venv\Scripts\python -m gpn_multiphase_solver convert my_case.xlsx каталог
```

Пример расчёта по книге — [examples/22_workbook_input](examples/22_workbook_input/README.md).

## 4. Использование из Python

Решатель вызывается из скриптов другого проекта. Пакет ставится в окружение
этого проекта: из выпуска – шаг 5 раздела «Поставка для расчётов» (интерпретатором окружения этого проекта), из исходного
кода — команды §1. Исходные данные — файл конфигурации с таблицами CSV
(3.1–3.3) или книга Excel (3.6); проще всего скопировать папку подходящего
примера, например `examples\06_table_corey_rp` под именем `my_case`.
Относительные пути в скриптах ниже отсчитываются от папки, из которой
запускается скрипт; все величины — в СИ.

**Штатный набор результатов с доступом к данным расчёта** — файл
`my_script.py`:

```python
from gpn_multiphase_solver.cli import configure_batch_run
from gpn_multiphase_solver.report.pipeline import run_case

# Рисунки — в файлы, без окон; русские буквы в консоли — без ошибок
configure_batch_run()

# Расчёт: файлы результатов — в my_case/output, сводка — в консоль
result = run_case("my_case/config.json", "my_case/output", title="Скважина 1")

# Данные расчёта для своей обработки
history = result.history
last_state = history.states[-1]      # пласт на последней записи
last_well = history.well_data[-1]    # скважина на последней записи

print("Забойное давление, МПа:", last_well.p_wf / 1e6)
print("Забойная температура, К:", last_well.T_wf)
print("Дебит нефти, м³ст/сут:", last_well.q_o_std * 86400)
print("Наибольшая газонасыщенность:", last_state.Sg.max())
```

Запуск — из папки проекта:

```powershell
.venv\Scripts\python my_script.py
```

`configure_batch_run()` вызывается первой строкой собственного скрипта: она
переключает matplotlib в режим без вывода окон и устанавливает для консоли
кодировку UTF-8 — так же, как это делает команда. Без неё вывод в файл или
канал может прерваться ошибкой кодировки на знаках вроде «м³».

`run_case` записывает файлы и выводит сводку в консоль так же, как команда.
Первым аргументом можно передать и книгу Excel (3.6): `run_case("my_case.xlsx")`.
Аргументы `title`, `n_profiles`, `steady_state` имеют приоритет над разделом
`output`; аргумент `overlays` добавляет собственные кривые на графики
профилей: словарь `{"p" | "T" | "Sg" | "Rs": функция(ax, history, grid, simulator)}`,
пример — функция `overlay_temperature` в
[examples/03_standing_corey/main.py](examples/03_standing_corey/main.py).
Ошибка в файле конфигурации, таблицах или книге — исключение
`CaseConfigError` (наследник `ValueError`), расчёт не начинался; отказ
решателя на шаге по времени — `CaseRunError` (наследник `RuntimeError`).
Оба класса — в `gpn_multiphase_solver.report.pipeline`; текст исключения
называет причину, у ошибок конфигурации — поле.

**Только расчёт**, без записи файлов и сводки в консоли — например, для
серии расчётов:

```python
from gpn_multiphase_solver.cli import configure_batch_run
from gpn_multiphase_solver.io.config import load_config
from gpn_multiphase_solver.factory import SimulatorFactory

configure_batch_run()

config = load_config("my_case/config.json")                      # прочитать и проверить
simulator, initial_state = SimulatorFactory.from_config(config)  # собрать решатель
history = simulator.run(initial_state)                           # рассчитать

# Таблица по моментам записи: время, забойные давление и температура, дебит
for t, well in zip(history.times, history.well_data):
    print(f"{t / 86400:8.3f} сут  {well.p_wf / 1e6:7.3f} МПа  "
          f"{well.T_wf:8.3f} К  {well.q_o_std * 86400:8.2f} м³ст/сут")

# Профиль по радиусу на последней записи
r = simulator.grid.r_centers         # центры ячеек, м
T = history.states[-1].T             # температура в ячейках, К
print("ячеек:", len(r), " T у забоя:", T[0], " T у контура:", T[-1])
```

Строки журнала решателя (`[INFO] …`) выводятся и здесь; уровень подробности
задаёт поле `output.log_level` файла конфигурации, например `"WARNING"`.
Ошибки в файле конфигурации или таблицах — исключения `load_config` и
`SimulatorFactory.from_config`: обычно `ValueError`; `OSError` — файл не
читается, `TypeError` и `KeyError` — лишний или пропущенный ключ. Отказ
решателя — `RuntimeError` (`simulator.run`). В `run_case` все они сведены к
`CaseConfigError` и `CaseRunError`.

Содержимое истории расчёта: `history.times` — моменты записей, с;
`history.states[i]` — поля `p` (Па), `T` (К), `Sg`, `Rs` (м³ст/м³ст) по
ячейкам; `history.well_data[i]` — `q_o_std`, `q_g_std` (м³ст/с), `m_o_well`,
`m_g_well` (кг/с), `p_wf` (Па), `T_wf` (К). Индекс 0 у полей `states[i]` —
ячейка у забоя; `states[i].p[0]` — давление в её центре, а забойное
давление — `well_data[i].p_wf`. Сетка, PVT-модель и ОФП доступны
как свойства `simulator.grid`, `simulator.pvt`, `simulator.relperm`; без
расчёта PVT-модель и ОФП создают функции `factory.create_pvt(config)` и
`factory.create_relperm(config)`.

Номер версии пакета — строка `gpn_multiphase_solver.__version__` (форма
PEP 440; правило номеров — [CHANGELOG.md](CHANGELOG.md)).

Полезные модули:

| Модуль | Назначение |
|---|---|
| `gpn_multiphase_solver.io.output` | `save_csv`, `save_well_csv`, `save_npz`; построение графиков на заданных осях matplotlib: `plot_profiles`, `plot_well_rate`, `plot_wellbore_dynamics`, `plot_pvt_properties`, `plot_relperm_curves` |
| `gpn_multiphase_solver.io.figures` | `save_figure` (PNG и SVG), `export_emf` |
| `gpn_multiphase_solver.energy.balance`, `gpn_multiphase_solver.mass_balance` | `compute_energy_balance(history)`, `compute_mass_balance(history)` — временные ряды балансов и невязки |
| `gpn_multiphase_solver.diagnostics` | аналитическое стационарное решение, проверка равновесия $R_s$, однофазная асимптотика $T$ — без вывода в консоль и рисунков |
| `gpn_multiphase_solver.report` | вывод проверок в консоль и построение рисунков с записью PNG — части, из которых собран штатный набор |

## 6. Тесты

Из каталога `numerical_solver`:

```powershell
.venv\Scripts\python -m pytest tests/ -m "not slow" -q   # быстрый уровень, 1–2 мин
.venv\Scripts\python -m pytest tests/ -q                 # полный, ~10 мин
```

Меткой `slow` отмечены тесты, рассчитывающие примеры по их штатным файлам
конфигурации. pytest подключает прототип из этого же дерева каталогов
(параметр `pythonpath` в [pyproject.toml](pyproject.toml)). У прототипа
собственные тесты и регрессионная проверка по эталону, сверенному с
CMG IMEX, — команды запуска приведены в его README. После изменения кода
прототипа их нужно запускать отдельно: тесты решателя отклонение прототипа
от эталона не обнаружат.

Сборку HTML-документации без предупреждений проверяет тест с меткой `slow`
(`tests/test_docs.py`); там же проверяется, что докстринги публичного
интерфейса (перечень — `doc/source/api.rst`) написаны в стиле NumPy с
разделами параметров и результата.
