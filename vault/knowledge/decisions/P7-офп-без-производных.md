# P7. ОФП без производных

## Суть

Прототип использует `TabulatedRelPerm` — табличная интерполяция kro(Sg), krg(Sg) через `np.interp`. Производных dkro/dSg, dkrg/dSg нет (конечно-разностный якобиан прототипа в них не нуждается).

Наш ABC `RelPermModel` предоставляет default-реализацию производных через конечные разности. Достаточно обернуть TabulatedRelPerm в Adapter.

## Решение: PrototypeRPAdapter

```python
from radial_blackoil.relperm import TabulatedRelPerm

class PrototypeRPAdapter(RelPermModel):
    """Обёртка TabulatedRelPerm прототипа → наш RelPermModel.

    kro, krg — делегируются прототипу.
    dkro_dSg, dkrg_dSg — наследуются из RelPermModel (конечные разности).
    Конвертация единиц не нужна (всё безразмерное).
    """

    def __init__(self, proto_rp: TabulatedRelPerm):
        self._rp = proto_rp

    def kro(self, Sg):
        return self._rp.kro(np.asarray(Sg, float))

    def krg(self, Sg):
        return self._rp.krg(np.asarray(Sg, float))

    # dkro_dSg, dkrg_dSg — default из RelPermModel:
    # (f(Sg+eps) - f(Sg-eps)) / (2*eps)
```

## Почему Adapter, а не duck typing

TabulatedRelPerm имеет методы `kro(sg)` и `krg(sg)`, совместимые по сигнатуре. Но:
- Не наследует RelPermModel → `isinstance` проверка не пройдёт
- Не имеет dkro_dSg, dkrg_dSg → если какой-то модуль вызовет — AttributeError

Adapter решает обе проблемы.

## Граничные значения

`np.interp` при Sg вне диапазона таблицы делает clamp к крайним значениям. Это поведение прототипа, наш Adapter его наследует. Дополнительных проверок не нужно.
