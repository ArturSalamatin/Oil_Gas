## Описание

`compute_fluxes` (`gpn_multiphase_solver/fluxes.py`) — второй, нерабочий путь вычисления потоков через грани. Рабочий расчёт его не вызывает: потоки компонентов даёт прототип, а `PrototypeHydroAdapter._build_result` досчитывает $Q_\alpha$, $u_\alpha$, $m_\alpha$ со своим выбором ячейки выше по потоку. `compute_fluxes` вызывают только тесты и тестовый двойник.

Три проблемы:

1. **На забое `compute_fluxes` расходится с постановкой.** При $p_{wf} > p[0]$ он считает втекание через забой ($G^o_{1/2} > 0$) и возвращает `HydroResult.p_wf` = уставке. Постановка (`eq:bc_pwf_shutin`) и прототип в этом случае закрывают скважину: потоки через забой нулевые, фактическое $p_{wf} = p[0]$.
2. **Эталон тестов проверяет не ту модель.** Двухфазная фикстура `test_fluxes.py` построена именно на втекании ($p[0] = 8$ МПа, $p_{wf} = 10$ МПа) — на ней стоят 82 теста.
3. **Логика выбора ячейки выше по потоку записана дважды** (в `compute_fluxes` и в адаптере) — и третий раз в прототипе. DEBT-009 (#29) и DEBT-017 (#34) уже исправляли расхождения этих копий на контурной грани.

Рабочий расчёт расхождение на забое не затрагивает. Критичность — низкая-средняя.

## Текущее состояние

### Забой: втекание вместо закрытия

`fluxes.py:112-129`:

```python
dp_w = p_wf - p[0]
up_w = 0
G_o[0] = grid.trans_well * mob_o[up_w] * dp_w
```

Знак `dp_w` не проверяется: при $p_{wf} > p[0]$ получаем $G^o_{1/2} > 0$ (закачка), а свойства берутся из ячейки 0 — то есть из ячейки **ниже** по потоку. В конце (`fluxes.py:177`) возвращается `p_wf=p_wf` — уставка, а не фактическое давление.

Постановка, `problem_statement.tex`:
- `eq:bc_pwf_shutin` (стр. 689-705) — условие дополнительности $q_{o,ст} \ge 0$, $p(r_w) \le p_{wf}$, $q_{o,ст}\,[p_{wf} - p(r_w)] = 0$;
- дискретная форма (стр. 1736-1747) — при $p_0 \le p_{wf}$ потоки через забой нулевые, фактическое $p_{wf} = p_0$ ($p_0$ — давление в ячейке 0).

Прототип делает ровно это: `blackoil.py:116-131`, ветвь `'shut'` → `bhp=p0; qow=0.0; qgfw=0.0`. Адаптер забирает фактическое $p_{wf}$ из `well_rates` (`prototype_adapter.py:252`).

Последствие для энергии: `HydroResult.p_wf` идёт в решатель энергии (`energy/tridiag.py:120`, давление на забойной грани). Тесты энергии на `compute_fluxes` при $p_{wf} > p[0]$ получили бы уставку вместо $p[0]$.

### Дублирование выбора ячейки выше по потоку

| Место | Правило на внутренней грани |
|---|---|
| прототип, `blackoil.py:160` | `left = dp >= 0` (по перепаду давления) |
| `fluxes.py:86-90` | `dp >= 0 → f-1`, иначе `f` (по перепаду давления) |
| адаптер, `prototype_adapter.py:204` | `up = f if G_o[f] < 0 else f - 1` (**по знаку $G^o$**) |

**Наблюдение по коду (замером не проверено):** правило адаптера не совпадает с прототипом, когда в ячейке выше по потоку $k_{ro} = 0$ ($S_g \ge 1 - S_{or}$). Тогда при $dp < 0$ прототип берёт ячейку $f$, $G^o_f = 0$, а адаптер по условию `G_o[f] < 0` берёт $f-1$ — ячейку ниже по потоку. Следствие: $Q_g$ и $u_g$ на грани считаются с $B_g$ не той ячейки. $m_g$ не страдает: $\rho_g B_g = \rho_{g,ст}$ (`pvt/base.py:74`), так что $m_g = \rho_{g,ст} G^{св.газ}$ при любом выборе. В рабочих примерах, по замерам BUG-018 (#48), в решении ячеек с $S_g \ge 1 - S_{or}$ нет — на опубликованные результаты это, вероятно, не влияет; проверить в плане.

На контурной грани правила адаптера и прототипа совпадают: $k_{ro}(S_{g,ext} = 0) > 0$, поэтому знак $G^o_N$ совпадает со знаком перепада.

## Целевое состояние

- `compute_fluxes` на забое следует `eq:bc_pwf_shutin`: при $p[0] \le p_{wf}$ потоки через забой нулевые, `HydroResult.p_wf = p[0]`.
- Двухфазная фикстура — при $p_{wf} < p[0]$ (добыча); проверка закрытия скважины — отдельным тестом.
- Выбор ячейки выше по потоку на внутренних гранях одинаков во всех трёх местах (по перепаду давления, как в прототипе).
- Устаревшие ссылки на неисполненный план DEBT-019 в тестах исправлены.

## Анализ вариантов решения

### Вариант 1. Закрытие скважины в `compute_fluxes` + фикстура на добычу

**Суть.** В `fluxes.py` на забое: если $p[0] \le p_{wf}$ — все потоки грани 0 нулевые, `p_wf = p[0]`; иначе — как сейчас. Двухфазную фикстуру перевести на $p_{wf} = 6$ МПа (отдельная константа, `P_WF` нужен однофазной фикстуре). Добавить тест закрытия: $p_{wf} > p[0]$ → нулевые потоки на грани 0, `p_wf == p[0]`, остальные грани не изменились.

**Изменения.** `fluxes.py:112-129, 177`; `test_fluxes.py:346-350` + новый тест; ссылка на `eq:bc_pwf_shutin` в комментарии.

**Плюсы.** Тестовый путь совпадает с постановкой и прототипом. Объём малый. Проба DEBT-019 (`vault/issues/debt-019/probes/test_round2_fixture_2ph_fix.py`): при $p_{wf} = 6$ МПа все поля на всех гранях совпадают с эталоном, значения грани 1 (`TestTwoPhaseConcreteValues`) не меняются.

**Минусы.** Дублирование выбора ячейки выше по потоку остаётся. Эталон `_compute_reference_face` для грани 0 тоже должен знать про закрытие — иначе тест закрытия сверяет с собой.

### Вариант 2. Запрет втекания в `compute_fluxes` (`ValueError`)

**Суть.** При $p_{wf} > p[0]$ — исключение; фикстура — как в варианте 1.

**Плюсы.** Минимум кода, ошибка видна сразу.

**Минусы.** Закрытая скважина — штатный режим постановки (FEAT-023, пример 13б, переключение $p_{wf}$), а не ошибка. Тестовый путь перестаёт его покрывать: тесты энергии на закрытой скважине на `compute_fluxes` не построить. Расходится с прототипом, который этот режим считает.

### Вариант 3. Единое правило выбора ячейки выше по потоку для обоих путей

**Суть.** Вынести выбор индекса ячейки выше по потоку на внутренних гранях (и набор свойств на контуре) в одну функцию; вызывать её из `compute_fluxes` и `_build_result`. Правило — по перепаду давления (`dp >= 0 → f-1`), как в прототипе.

**Изменения.** Новая функция (в `fluxes.py` или отдельном модуле), `fluxes.py:77-164`, `prototype_adapter.py:202-241`.

**Плюсы.** Одно правило в пакете вместо двух; убирает расхождение адаптера с прототипом при $k_{ro} = 0$. Класс ошибок DEBT-009 / DEBT-017 / DEBT-021 закрывается на уровне устройства.

**Минусы.** Затрагивает рабочий путь → нужна побитовая сверка историй примеров (механизм есть с DEBT-033). Пути различаются по входу: `compute_fluxes` строит $G$ из подвижностей, адаптер получает $G$ от прототипа и делит на $B$ — общая часть только индекс ячейки и свойства контура. Сам по себе забой не исправляет. Копия правила в прототипе остаётся (другой пакет).

### Рекомендация

**Вариант 1 + узкая часть варианта 3:** в адаптере заменить условие `G_o[f] < 0` на выбор по перепаду давления, как в прототипе (одна строка). Выносить ли общую функцию — решить в плане по объёму изменений. Перед правкой адаптера — тест, воспроизводящий расхождение при $S_g \ge 1 - S_{or}$; после — побитовая сверка историй примеров (ожидание: без изменений, если в решениях нет ячеек с $k_{ro} = 0$).

## План решения

1. **Подготовка (baseline).** Быстрый уровень тестов (`-m "not slow"`), число тестов. Замер: есть ли в историях примеров ячейки с $S_g \ge 1 - S_{or}$ (подтверждает или опровергает влияние на результаты). Тест-проба: состояние с $k_{ro} = 0$ в ячейке выше по потоку → `_build_result` против `compute_fluxes` по $Q_g$, $u_g$.
2. **Реализация.**
   - `compute_fluxes`: закрытие скважины по `eq:bc_pwf_shutin`, `p_wf = p[0]` при закрытии; эталон `_compute_reference_face` — то же.

   - Устаревшие ссылки на DEBT-019 (`test_energy.py:1392-1394`, `test_energy_matrix_examples.py:212`), docstring «72 проверки».
3. **Верификация.** Быстрый уровень после каждого шага, полный в конце; побитовая сверка историй примеров после правки адаптера.
