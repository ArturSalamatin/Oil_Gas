# vault/issues/

Каталог хранит локальные черновики задач, тексты для GitHub issue и
проверочные пробы.

## Зачем хранить

Тексты для GitHub передаются через `--body-file`. Файлы находятся в проекте,
чтобы сохранить отправленный текст и воспроизводимые пробы вместе с задачей.

Текст, отправленный в issue, остаётся в репозитории –
видно, что именно было опубликовано и когда, без обращения к GitHub.

## Структура

```
vault/issues/<id-lowercase>/
├── 00-draft.md           # локальный контекст регистрации (/draft)
├── 01-issue-body.md      # тело issue (/issue)
├── 02-comment-open.md    # «Контекст при открытии» (/issue)
├── 03-comment-plan.md    # «План готов» (/plan-*)
├── audit-r<N>.md         # полный отчёт раунда аудита (/audit-plan)
├── 04-comment-audit.md   # «Аудит плана» (/audit-plan)
├── 05-comment-done.md    # результат реализации (/implement)
└── probes/               # диагностические скрипты – см. PROBES.md
```

`00-draft.md` остаётся локальным черновиком и не публикуется как комментарий.
Файлы с `01` по `05` сохраняют тексты соответствующих публикаций. Отчёты
`audit-r<N>.md` содержат находки и хеш проверенной версии плана. Каждый
раунд сохраняется отдельно. Не все файлы обязательны: у старой задачи
может не быть черновика или плана.

При `implement` подготовленные материалы текущей задачи включаются в
предварительный коммит базовой ветки. Файлы, созданные во время реализации,
включаются в коммиты ветки задачи. Общий реестр может попасть в коммит со
ссылкой на незакоммиченный черновик другой задачи. Такой черновик не
добавляется автоматически и до своего коммита отсутствует в истории Git.
Создание issue и комментария через `gh` изменяет GitHub сразу. Push ветки
задачи и базовой ветки выполняется при `merge`.

## probes/

Скрипты воспроизводят замеры из расследований. Подробности, состав и
ограничения – `PROBES.md`.

Правила хранения задаются актуальными навыками проекта и `AGENTS.md`.
