# Grid — пространственная дискретизация

## ABC Grid

```python
class Grid(ABC):
    """Абстрактная сетка с проводимостями.

    Хранит геометрию (грани, центры, объёмы) и проводимости
    (включая граничные). Проводимости содержат k и h — они постоянны
    и вычисляются один раз в конструкторе.
    """

    @property
    @abstractmethod
    def N(self) -> int:
        """Число ячеек."""
        ...

    @property
    @abstractmethod
    def r_faces(self) -> np.ndarray:
        """Грани r_{j+1/2}. Массив [N+1]. r_faces[0]=r_w, r_faces[N]=R_ext."""
        ...

    @property
    @abstractmethod
    def r_centers(self) -> np.ndarray:
        """Центры ячеек r_j. Массив [N]."""
        ...

    @property
    @abstractmethod
    def volumes(self) -> np.ndarray:
        """Объёмы ячеек V_j. Массив [N]."""
        ...

    @property
    @abstractmethod
    def trans_internal(self) -> np.ndarray:
        """Проводимости внутренних граней T_{j+1/2}. Массив [N-1]."""
        ...

    @property
    @abstractmethod
    def trans_well(self) -> float:
        """Проводимость левой граничной грани T_{1/2}."""
        ...

    @property
    @abstractmethod
    def trans_ext(self) -> float:
        """Проводимость правой граничной грани T_{N+1/2}."""
        ...

    @abstractmethod
    def log_weights(self) -> tuple[np.ndarray, np.ndarray]:
        """Логарифмические веса для гармонической интерполяции на грани.

        Возвращает (w_left[N-1], w_right[N-1]):
        w_left[j] = ln(r_{j+1/2} / r_j)
        w_right[j] = ln(r_{j+1} / r_{j+1/2})

        Для интерполяции скалярного свойства A на грань j+1/2:
        A_{j+1/2} = (w_left[j] + w_right[j]) / (w_left[j]/A_j + w_right[j]/A_{j+1})
        """
        ...
```

## Конкретная реализация: LogRadialGrid

Формулы из problem_statement.tex §4.1.

### Грани (eq. 10)

```
r_{j+1/2} = r_w · (R_ext / r_w)^{j/N},   j = 0, 1, ..., N
```
r_faces[0] = r_w, r_faces[N] = R_ext.

Логарифмический шаг: `ln(r_{j+1/2}/r_{j-1/2}) = const = ln(R_ext/r_w)/N`.

### Центры ячеек (`eq:cell_center`)

```
r_j = √(r_{j-1/2} · r_{j+1/2})        (середина ячейки по ln r)
```

Те же центры у RadialGrid прототипа (DEBT-063, [#98](https://github.com/ArturSalamatin/Oil_Gas/issues/98)): одна сетка для гидродинамики, энергии и вывода; совпадение побитово проверяет `tests/test_prototype_adapter.py::TestGridsMatchPrototype`. Профиль Дюпюи воспроизводится в центрах точно при любом центре — это свойство логарифмической проводимости грани. До DEBT-063 — exp⟨ln r⟩ по площади слоя (в заметках ошибочно «центр масс», DEBT-060); замер точности обоих центров — `vault/issues/debt-063/probes/center_accuracy.py`: в нестационарном однофазном притоке оба второго порядка, равномерно лучшего нет.

На логарифмической сетке логарифмические веса интерполяции равны: w_L = w_R = ½ ln(r_{j+1}/r_j).

### Объёмы (eq. 13)

```
V_j = π · h · (r_{j+1/2}² - r_{j-1/2}²)
```

### Проводимости внутренних граней (eq. 19)

```
T_{j+1/2} = 2π · h · k / ln(r_{j+1}/r_j)
```

Делитель — `ln(r_{j+1}/r_j)`, расстояние между **центрами** в логарифмической метрике. Это следствие точного решения для радиального потока.

### Проводимости граничных граней

```
T_{1/2} = 2π · h · k / ln(r_0 / r_w)
T_{N+1/2} = 2π · h · k / ln(R_ext / r_{N-1})
```

Расстояние от центра граничной ячейки до границы области.

### Логарифмические веса для интерполяции (eq. 21)

```
w_left[j] = ln(r_{j+1/2} / r_j)
w_right[j] = ln(r_{j+1} / r_{j+1/2})
```

Гармоническое среднее с логарифмическими весами корректно для радиальной геометрии (аналогия с последовательными сопротивлениями в кольцевых слоях).

### Кондуктивная проводимость грани (для теплопроводности)

```
Q^T_{j+1/2} = 2π · h · λ_{eff}^{j+1/2} / ln(r_{j+1}/r_j)
```

где λ_{eff}^{j+1/2} = (w_left[j] + w_right[j]) / (w_left[j]/λ_j + w_right[j]/λ_{j+1}) — гармоническое среднее с нормированными весами (`eq:face_interp`; w_left + w_right = ln(r_{j+1}/r_j)). Без множителя в числителе — двойной ln ([[BUG-002]], [[BUG-027]]).

Это НЕ хранится в Grid: зависит от λ_eff, которая зависит от Sg (переменная). Вычисляется в EnergySolver на каждом шаге.

## Решение: Grid хранит k и h

Grid при создании получает:
- r_well, R_ext, N — геометрия
- k — абсолютная проницаемость
- h — мощность пласта

Проводимости вычисляются в конструкторе. k и h постоянны — пересчёт не нужен.

Альтернатива (Grid — чистая геометрия, проводимости — снаружи) отвергнута: усложняет код, нет выигрыша при постоянных k и h.

## Единая Grid для всех модулей

Один объект LogRadialGrid создаётся в Factory и передаётся **по ссылке** в оба модуля (гидро и энергия). В Python все переменные — ссылки (аналог shared_ptr в C++). Оба модуля работают с одним и тем же объектом.

**Grid — immutable после создания.** Конструктор вычисляет грани, центры, объёмы, проводимости. После — только чтение. Модули не модифицируют Grid.

### Согласование с прототипом

**Решено DEBT-063** (2026-10-11, [#98](https://github.com/ArturSalamatin/Oil_Gas/issues/98)): `LogRadialGrid` берёт центры прототипа √ (вариант A1, решение пользователя), сетки совпадают побитово — `test_prototype_adapter.py::TestGridsMatchPrototype`. Прежние задачи «изменить формулу центров в прототипе» (отменена — согласовано в обратную сторону) и «передать единый Grid в прототип» (не нужна) в реестр так и не вносились. До DEBT-063 центры двух сеток расходились на ≈ h²/6 по ln r (h = ln(R_ext/r_w)/N), граничные проводимости — на ≈ h/3; давление прототипа в выводе относилось к чужим точкам.
