# Навык issue: создание и регистрация задачи

Навык преобразует запись реестра vault или произвольное описание проблемы в опубликованное GitHub issue с предварительным анализом кода, фиксацией контекста и синхронизацией с реестрами проекта.

## Правила проекта

1. **Субагенты запрещены:** вся работа выполняется последовательно в основном контексте разговора без запуска дочерних агентов.
2. **Тире:** только среднее «–» (U+2013) во всех формируемых текстах.
3. **Хранение артефактов:** все тексты тел задач и комментариев сохраняются строго в каталоге `vault/issues/<id-lowercase>/` (никаких временных каталогов или scratchpad).
4. **Язык и терминология:** русский язык, исключение неоправданных англицизмов по словарю CLAUDE.md.
5. **Git:** коммиты не создаются, пользователь фиксирует изменения самостоятельно.

---

## Порядок выполнения

### 1. Анализ входных параметров и выбор режима

- **Флаг `--dry`:** если запрос содержит `--dry`, включается режим предпросмотра (dry-run). Все шаги анализа выполняются, файлы в `vault/issues/` генерируются, но обращение к GitHub (`gh`) и модификация реестров vault не производятся.
- **Режим existing:** если передан идентификатор вида `BUG-NNN`, `DEBT-NNN`, `FEAT-NNN` или `VAL-NNN`.
- **Режим new:** если передан произвольный текст с описанием проблемы или идеи.

### 2. Сбор контекста и определение идентификатора

**Для режима existing:**
1. Проверить наличие дубликатов на GitHub:
   ```powershell
   python .agents/skills/issue/scripts/issue_helper.py check-duplicate <ID>
   ```
   Если задача уже открыта, сообщить пользователю URL и запросить подтверждение продолжения.
2. Открыть соответствующий реестр в `vault/roadmap/` (согласно [conventions.md](references/conventions.md)) и извлечь секцию с указанным ID.
3. Если есть ссылка на заметку в `knowledge/`, прочитать ее для получения контекста.

**Для режима new:**
1. Определить тип задачи (`BUG`, `DEBT`, `FEAT`, `VAL`) и получить следующий свободный номер:
   ```powershell
   python .agents/skills/issue/scripts/issue_helper.py next-id <TYPE>
   ```
2. Задать пользователю недостающие вопросы единым блоком (симптомы, затронутые модули, формулы или эталоны).
3. Добавить базовую секцию с новым ID в соответствующий файл реестра vault.

### 3. Анализ кода и вариантов решения

*(Для задач типа VAL данный шаг пропускается)*

1. Для файлов, упомянутых в записи:
   - проверить их наличие в репозитории.
   - найти точные строки ключевых функций.
   - проверить связанные тесты.
2. Сформулировать варианты решения с оценкой достоинств и недостатков каждого варианта.
3. Подготовить пошаговый план решения (минимальное исправление → архитектурное решение → верификация).

### 4. Определение ветки и меток

1. Сформировать имя ветки в формате `<prefix>/<id-lowercase>/<slug>` по правилам из [conventions.md](references/conventions.md).
2. Проверить уникальность ветки:
   ```powershell
   python .agents/skills/issue/scripts/issue_helper.py check-branch <имя-ветки>
   ```
3. Определить список меток (labels) на основе типа задачи и маркеров статуса (🔴 critical, 🟡 workaround, блокирующие зависимости) по [conventions.md](references/conventions.md).

### 5. Подготовка документов в vault

1. Создать каталог `vault/issues/<id-lowercase>/`.
2. Загрузить соответствующий шаблон из `references/templates/`:
   - `BUG` → [templates/bug.md](references/templates/bug.md)
   - `DEBT` → [templates/debt.md](references/templates/debt.md)
   - `FEAT` → [templates/feat.md](references/templates/feat.md)
   - `VAL` → [templates/val.md](references/templates/val.md)
3. Записать заполненное тело задачи в `vault/issues/<id-lowercase>/01-issue-body.md`.
4. Записать комментарий с контекстом при открытии в `vault/issues/<id-lowercase>/02-comment-open.md`.

### 6. Публикация на GitHub

Если активен режим `--dry`:
- вывести предпросмотр (заголовок, метки, имя ветки, первые 20 строк тела задачи).
- завершить работу без изменения внешних систем.

В штатном режиме выполнить публикацию через `gh`:
```powershell
gh issue create --repo ArturSalamatin/Oil_Gas `
  --title "<ID>: <краткое описание>" `
  --body-file "vault/issues/<id-lowercase>/01-issue-body.md" `
  --label "<labels>" `
  --assignee "@me"

gh issue comment <номер> --repo ArturSalamatin/Oil_Gas `
  --body-file "vault/issues/<id-lowercase>/02-comment-open.md"
```

### 7. Синхронизация с vault

Обновить реестр задач и заметку знаний:
```powershell
python .agents/skills/issue/scripts/issue_helper.py update-vault <ID> --issue-url "<URL>" --branch "<имя-ветки>"
```

### 8. Отчет и предложение следующего шага

1. Начать отчет с ответа на вопрос о сути задачи: два–четыре связных предложения своими словами без списков (текущий дефект или недостаток, практическая важность, ожидаемый результат после решения).
2. Привести технические данные: URL созданного issue, назначенные метки, имя ветки.
3. Предложить переход к следующему шагу планирования:
   - `BUG-*` → `/plan-fix <ID>`
   - `DEBT-*` → `/plan-improve <ID>`
   - `FEAT-*` → `/plan-feature <ID>`
   - `VAL-*` → `/plan-validate <ID>`
