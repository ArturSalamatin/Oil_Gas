## Описание

Заметка vault `vault/knowledge/decisions/модули-simulator-оркестратор.md` — справочник по оркестратору `Simulator` — описывает цикл по времени в том виде, каким он был до DEBT-015 (#61). DEBT-015 перенёс дробление шага из гидро-адаптера в `Simulator._advance` (локальное дробление подшага пополам при `HydroConvergenceError`), добавил параметр конструктора `max_retries` и поменял сигнатуру вызова `EnergySolver.solve`, но эту заметку не тронул. Читатель получает устаревшую схему шага. Код не меняется — задача только по vault.

## Целевое состояние

- Сигнатура `__init__` и вызов в фабрике — с `max_retries`.
- Псевдокод `run` — внешний цикл по интервалам, внутренний — `_advance`, запись на конце интервала.
- Псевдокод `_advance` — цикл локального дробления в целых единицах `dt/2**max_retries`: гидро → баланс массы → энергия по подшагу `h` → `_check_temperature` → новое состояние; отказ на наименьшем подшаге → `RuntimeError(_failure_message(...))`.
- Без «пробного шага»; пункт о накопителе массы — «только принятый подшаг».
- Ссылки на [[P4-адаптивный-шаг]] и [[локальное дробление шага проходит останов при суточном dt_integration — равномерное падает на одном подшаге из 512]].

## Анализ вариантов решения

**Вариант 1 — точечная правка перечисленных мест.**
Суть: заменить сигнатуру, вызов в фабрике, псевдокод `run`, убрать «пробный шаг».
Плюсы: минимум правок, строго в рамках записи реестра.
Минусы: раздел `SimulationHistory` (`:155-165`) остаётся устаревшим — следующий читатель найдёт то же расхождение.

**Вариант 2 — псевдокод заменить ссылками на код.**
Суть: вместо псевдокода `run`/`_advance` — краткое словесное описание и ссылки `simulator.py:<строки>`.
Плюсы: меньше поводов для будущих расхождений.
Минусы: заметка теряет самодостаточность; номера строк в ссылках устаревают так же, как псевдокод.

**Вариант 3 (рекомендуемый) — вариант 1 + раздел `SimulationHistory`.**
Суть: псевдокод `run` и сокращённый псевдокод `_advance` (цикл дробления, без журналирования), сигнатура с `max_retries`, «пробный шаг» убрать, `:62` и `:155-165` привести к `state.py`, добавить ссылки на P4 и заметку о локальном дроблении.
Плюсы: заметка целиком соответствует коду; объём правки — один файл vault.
Минусы: чуть шире записи реестра — решить при планировании.
