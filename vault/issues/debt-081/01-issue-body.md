## Описание

`_validate` (`io/config.py`) проверяет у `grid.N` только условие `N < 1`, а не то, что это целое число. Из пяти полей конфига с аннотацией `int` только у `grid.N` нет проверки на целое: у `numerics.max_retries`, `newton_max_iter`, `max_active_set_iter`, `output.n_profiles` и `history[i].repeat` она есть, причём `bool` исключён явно. Самое опасное следствие — `"N": true` даёт расчёт на сетке из одной ячейки без единого сообщения.

Приоритет — средний: опечатку в JSON, набранном вручную, решатель молча превращает в неверный расчёт. Конфиг — канонический вход команды расчёта (FEAT-030) и результат перевода книги Excel (FEAT-035). Перевод пишет `grid.N` целым (`test_integer_fields_written_as_int`) и дефекта не задевает, но конфиг, набранный вручную, сейчас ничем не защищён.

## Текущее состояние

Воспроизведение на `4b67213` (код `io/config.py` и `grid/log_radial.py` с замера в реестре на `55868a6` не менялся): берём конфиг `examples/01_single_phase_no_jt/config.json`, подменяем `grid.N` и вызываем `load_config`.

| `grid.N` | `load_config` | `LogRadialGrid` (сборка решателя) | Итог |
|---|---|---|---|
| `true` | проходит, `cfg.grid.N = True` | проходит: `isinstance(True, int)` истинно, `N = 1` | **расчёт на одной ячейке, молча** |
| `"100"` | `TypeError: '<' not supported between instances of 'str' and 'int'` | — | не `ValueError`, в сообщении нет имени поля |
| `100.0` | проходит, `cfg.grid.N = 100.0` | `ValueError: N must be an integer >= 1, got 100.0` | отказ по-английски, без узла JSON, уже после загрузки |
| `100.5` | проходит | тот же отказ | то же |
| `NaN` | `ValueError: grid.N должно быть конечным…` | — | корректно (DEBT-051) |
| `0` | `ValueError: N должен быть ≥ 1, получено 0` | — | корректно, но в сообщении нет префикса `grid.` |

Почему так:
- `_check_numeric_fields` (DEBT-051) проверяет поле на число и конечность, только если аннотация `float`/`Optional[float]` или значение — `float`. Поле с аннотацией `int` и значением `True` или `"100"` эту проверку минует, значение `100.0` проходит её как конечное.
- Проверка диапазона `cfg.grid.N < 1` для `True` ложна (`True == 1`), для строки бросает `TypeError`, а `100.0` и `100.5` пропускает.
- `LogRadialGrid.__init__` проверяет `isinstance(N, int)`, но `bool` — подкласс `int`, поэтому `True` проходит и здесь.

## Целевое состояние

- `grid.N` — целое ≥ 1, `bool` исключён. Любое другое значение даёт `ValueError` из `_validate` с узлом JSON в сообщении: `grid.N должен быть целым ≥ 1, получено …` — в том же виде, что у `numerics.newton_max_iter`.
- Отказ происходит при загрузке конфига, до сборки решателя.
- Проверку в `LogRadialGrid` оставляем как внутренний предохранитель класса сетки: он вызывается и в обход конфига (тесты, прототип).
- Все существующие тесты остаются зелёными, расчёты не меняются: во всех конфигах примеров и тестов `grid.N` — целое.

## Анализ вариантов решения

### Вариант 1. Проверка на целое в `_validate` (рекомендуется)

- **Суть:** заменить условие в строках 520–521 на `isinstance(N, bool) or not isinstance(N, int) or N < 1` → `ValueError(f"grid.N должен быть целым ≥ 1, получено {N!r}")`.
- **Изменения:** `io/config.py` — одна проверка и комментарий со ссылкой на DEBT-081 и замер; `tests/test_config.py` — параметризованный тест на `true`, `false`, `"100"`, `100.0`, `100.5`, `0`, `-1`.
- **Плюсы:** минимальная правка, тот же код, что у пяти других целых полей; `test_N_zero` (`match="N"`) остаётся зелёным.
- **Минусы:** у будущего целого поля проверку опять придётся писать руками. Сейчас таких полей нет, а страж `test_field_list_covers_known_fields` о новых полях напомнит.

### Вариант 2. Общая проверка целых полей в `_check_numeric_fields`

- **Суть:** по аналогии с `float` распознавать аннотации `int` и `Optional[int]` и в одном месте проверять, что значение целое и не `bool`; проверки диапазона оставить на местах.
- **Изменения:** `_check_numeric_fields` плюс сокращение проверок типа у `max_retries`, `newton_max_iter`, `max_active_set_iter`, `n_profiles`; `history[i].repeat` идёт отдельным путём (`_validate_interval`) и общей проверкой не охватывается.
- **Плюсы:** одно место для всех целых полей dataclass-секций; новое поле защищено автоматически.
- **Минусы:** правка шире задачи. Меняются сообщения четырёх полей, на которые завязаны тесты (`match=` на «должен быть целым»), а `repeat` всё равно остаётся отдельно. Это обобщение сверх задачи (CLAUDE.md, «Файлы и код»).

### Вариант 3. Приводить `100.0` к `100`

- **Суть:** принимать `float` с целым значением.
- **Минусы:** молчаливое приведение типа, которое DEBT-051 для строк уже отверг; в JSON целое пишется без точки; перевод книги пишет `int`. **Отклонён.**

### Вариант 4. Исправить только `LogRadialGrid`

- **Суть:** исключить `bool` и перевести сообщение на русский.
- **Минусы:** `TypeError` на строке возникает раньше, в `_validate`; узел JSON сетке неизвестен; отказ остаётся отложенным до сборки решателя. **Отклонён.**

**Рекомендация:** вариант 1.
