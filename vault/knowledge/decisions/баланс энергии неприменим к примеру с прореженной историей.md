# Баланс энергии неприменим к примеру с прореженной историей

`examples/energy_balance.compute_balance` **бросает `ValueError`** при
`save_every != 1` (явная защита, `energy_balance.py:124`), а не считает
приближённо. Причина: баланс суммирует **приращения** по сохранённым шагам,
и пропуск шагов делает сумму неполной — не менее точной, а просто неверной.

## Как это проявилось

Пример `04a_high_gas_saturation` (FEAT-015) — первый в наборе с
`save_every = 12`. Его добавление в `ALL_EXAMPLES` уронило бы три теста
`TestSharedChecks` (FEAT-016), которые идут по этому списку и считают
`compute_balance` для каждого имени. Причём уронило бы **исключением**,
а не превышением порога невязки — по сообщению об ошибке причина читалась
бы не сразу.

Проверено прогоном, а не рассуждением: `examples/04a_high_gas_saturation/diag_save_every.py`.

## Решение

Списки в `tests/test_examples.py` строятся **по конфигам**, а не
перечислением имён:

```python
BALANCE_EXAMPLES = [
    name for name in ALL_EXAMPLES
    if load_config(EXAMPLES_DIR / name / "config.json").output.save_every == 1
]

TABLE_PVT = [
    name for name in ALL_EXAMPLES
    if load_config(EXAMPLES_DIR / name / "config.json").pvt.model == "table"
]
```

`TABLE_PVT` попал сюда за компанию по той же причине: перечисление имён
отнесло бы 04a (табличный PVT) к аналитическим, и `test_nodes_none_for_analytical_pvt`
упал бы с сообщением «у корреляции узлов быть не может» — про PVT, хотя
дело в устаревшем списке.

## Почему именно так

Перечисление имён — скрытая связь между списком и содержимым конфигов.
Она рвётся молча при каждом новом примере, и падает не тот тест, который
описывает нарушенное свойство. Вывод списка из конфига делает связь явной
и самоподдерживающейся.

**Обратная сторона:** баланс энергии у 04a не проверяется автоматически.
Это осознанная цена — [[BUG-004]] жил незамеченным именно на табличном
PVT, то есть в том же классе задач.

Но сама физика проверена разово, и результат хороший: тот же сценарий,
прогнанный с `save_every = 1` (865 состояний), даёт относительную невязку
**$9.98\cdot10^{-4}$** — на порядок ниже порога $10^{-2}$. Значит решатель
на 04a энергию сохраняет, и проверка отключена **исключительно** из-за
формата вывода, а не из-за дефекта. Опасение, записанное в плане FEAT-015
(§6.2, риск со стороны BUG-004), не подтвердилось.

При появлении второго примера с прореживанием к вопросу стоит вернуться:
разовый прогон не ловит регрессию.
