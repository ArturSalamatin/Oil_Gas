# Передача заказчику — срез метки выпуска с документацией Sphinx и приёмкой на распакованной копии

**GitHub issue:** [#114](https://github.com/ArturSalamatin/Oil_Gas/issues/114) · план [[feat-031 customer-delivery-kit]] · выпуск — [[выпуск решателя — одна команда, push только после самопроверки сборки из метки]]

**Что было.** Решатель ставился из исходного дерева и выпусками для испытаний (FEAT-038), но комплекта для заказчика не было: README не описывал установку скриптом и ограничения модели, докстринги публичного интерфейса не имели разделов параметров и результата (ни одного из 120 объектов), HTML-документации не было, приёмку на чужой машине повторить было нечем.

**Решение (FEAT-031, решения пользователя 2026-10-17…18).** Получатель — команда разработки заказчика: она развивает код и сама готовит поставку инженерам. Передаётся срез `numerical_solver/` из метки выпуска без истории git, с собранными PDF постановки и HTML-документацией; номер не важен — важна финальная версия со всеми изменениями. Одна команда из корня: `numerical_solver\.venv\Scripts\python tools\handover.py v<X.Y.Z>`.

| Вопрос | Решение | Почему |
|---|---|---|
| Что в срезе | файлы `numerical_solver/` под git на метке (`git archive`) + `doc/problem_statement.pdf` + `doc/build/html/` | неотслеживаемые черновики (книга руководителя, `deliverables/`) и `vault/` не попадают сами; перечни задач заказчику не передаются |
| Документация | Sphinx: README (MyST), техническое описание — докстринги пакета и подпакетов, публичный интерфейс — `doc/source/api.rst` | один источник для HTML и для `help()`; прототип и примеры не входят |
| Заголовки докстрингов | русские, синонимы стандартных в `napoleon_custom_sections`; «Примечания» и подразделы обзора — простыми строками | `numpydoc` знает только английские; синоним Notes вышел бы рубрикой «Заметки», необъявленный подраздел — заголовком страницы (пробы плана) |
| Ссылки на уравнения | в докстрингах — метки; в HTML — номера по `doc/source/eq_numbers.json` (`tools/eq_numbers.py` из `.aux`); метки нет в таблице — предупреждение, при `-W` отказ | номера сдвигаются при правке постановки; LaTeX для сборки HTML не нужен |
| Ссылки README на файлы | README ради HTML не правится; предупреждения `myst.xref_missing` подавлены, существование файлов проверяет `test_readme_links_exist` | README читают и как файл рядом с кодом, там ссылки работают |
| Страж правила | `tests/test_docs.py`: перечень из `api.rst`, разделы «Параметры» = сигнатура, «Возвращает», «Атрибуты» = поля dataclass, без ID задач и `vault/`, заголовки модулей объявлены; сборка `-W` — тест `slow` | правило без проверки разошлось бы с кодом при первой правке сигнатуры |
| Перечень интерфейса | README §4, `tests/test_public_api.py`, всё, что импортируют скрипты примеров, абстрактные классы PVT, ОФП, сетки, режима скважины | пример — образец работы с пакетом: всё, что он вызывает, описано; тест сверяет импорты примеров с перечнем |
| Установка | `setup.bat` (Windows): Python ≥ 3.10 (`py -3`, затем `python`), `.venv`, `pip install -e` обоих пакетов с `[dev]`, проверка `run --help`; `.gitattributes` — `*.bat text eol=crlf` | без прогона тестов (решение пользователя); `goto` по метке в LF-файле cmd ненадёжен |
| Sphinx | в группе `[dev]`, границы `sphinx>=7.2`, `myst-parser>=2.0` не проверялись | одна команда установки; на Python 3.10 свежих версий нет |
| Приёмка | `numerical_solver/tools/acceptance.py` на свежей копии: `setup.bat` → версии → полный прогон тестов (пропуски — только известные причины) → `sphinx -W` → расчёт по книге и по конфигурации из постороннего каталога | числа сверяют тесты (результаты примеров против README с допусками): эталон не хранится и не устаревает; на версиях с PyPI, отличных от общего venv, полный прогон среза зелёный (замер плана) |
| Где скрипты | `tools/handover.py` — в корне репозитория (работает с git, у заказчика бесполезен); `acceptance.py`, `eq_numbers.py` — в `numerical_solver/tools/` (в срезе) | срез — поддерево `numerical_solver/` |
| Манифест прототипа | `PACKAGE_MANIFEST_SHA256.txt`, `VERSION.txt` не меняются | запись поставки 2026-08-25 (DEBT-059); регрессия прототипа сверяет `build_info` с эталоном |

**Следствия.**
- Новые публичные функции пишутся сразу в стиле NumPy и вносятся в `api.rst`; новый импорт пакета в примере без строки в `api.rst` роняет `test_api_covers_required_names`.
- После правки `problem_statement.tex`: PDF (два прохода `pdflatex`) → `tools/eq_numbers.py`; иначе `tools/handover.py` откажет на сверке таблицы.
- Причина пропуска теста, которой нет в `ALLOWED_SKIPS` приёмки, роняет приёмку у заказчика; тексты сверяет `tests/test_acceptance_script.py`.
- Фикстура класса в форме метода экземпляра (pytest 10 её удаляет) — переписана классовым методом в `tests/test_val002.py`.
