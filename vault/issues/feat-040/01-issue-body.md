## Описание

README пакета (раздел «Начало работы», случай «Папка с кодом без установки») описывает работу прямо из папки с исходным кодом: пакеты `gpn-multiphase-solver` и `radial-blackoil` через pip не ставятся, в окружении только numpy, scipy, matplotlib и XlsxWriter. Готового примера для этого случая нет: шаг 2 README предлагает скопировать папку примера 06 и написать свой скрипт с двумя строками `sys.path.insert`.

Задача – новый пример `numerical_solver/examples/23_<имя>/`: книга Excel, `main.py`, README. `main.py` сам находит решатель и прототип по своему расположению в дереве папки и считает по книге. Запуск – одной командой в окружении без пакетов решателя:

```powershell
D:\gpn\.venv\Scripts\python D:\gpn\solver\examples\23_<имя>\main.py
```

README пакета ссылается на пример как на демонстрацию работы с библиотекой без установки (решение пользователя 2026-10-22).

## Мотивация

- Случай «Папка с кодом без установки» – один из трёх случаев «Начала работы» в README для заказчика. Без примера инженер собирает скрипт по фрагменту README и узнаёт об ошибке в путях только по `ModuleNotFoundError: No module named 'radial_blackoil'`.
- Ручная проверка 2026-10-20 на копии дерева (`git archive`) в окружении без пакетов решателя (Python 3.13.3; numpy 2.5.4, scipy 1.18.1, matplotlib 3.11.2, XlsxWriter 3.2.9):
  - без путей: `python -m gpn_multiphase_solver --version` – код 0, `run` примера 06 – `ModuleNotFoundError: radial_blackoil`;
  - `PYTHONPATH` на обе папки: `run` примера 06 – код 0, `T(r_w)` в конце 351.509 К;
  - скрипт вне папки со вставкой обеих папок в `sys.path` и вызовом `run_case` – код 0, `__file__` обоих пакетов – из копии, те же числа;
  - быстрый уровень тестов из папки копии (`pip install pytest`) – 2328 passed, 3 skipped.
- В тестах этот путь не проверяется: в venv разработки оба пакета установлены в режиме `-e` из тех же папок, поэтому запуск примера там не отличает работу без установки от работы с установкой.
- Фаза: примеры и демонстрация, поставка заказчику (FEAT-031, #114).

## Предлагаемый API

Новых имён в пакете нет. `main.py` примера вызывает функции, которые README §4 и случай «Папка с кодом без установки» уже описывают: `configure_batch_run` (`gpn_multiphase_solver/cli.py:36`) и `run_case` (`gpn_multiphase_solver/report/pipeline.py:116`). Набросок из черновика плана:

```python
import sys
from pathlib import Path

# Папка с исходным кодом – на два уровня выше этого файла (examples\23_…\main.py);
# прототип – в её подпапке HydroSolverPrototype\Prototype_1.0.3
ROOT = Path(__file__).resolve().parents[2]
sys.path.insert(0, str(ROOT))
sys.path.insert(0, str(ROOT / "HydroSolverPrototype" / "Prototype_1.0.3"))

import gpn_multiphase_solver, radial_blackoil  # noqa: E402
from gpn_multiphase_solver.cli import configure_batch_run  # noqa: E402
from gpn_multiphase_solver.report.pipeline import run_case  # noqa: E402
```

Код пакета не обращается к `importlib.metadata`: номера версий берутся из литералов `__version__`, поэтому расчёт без записей pip в окружении не отличается от расчёта после установки.

### Как пример находит пакеты

**A. `sys.path.insert` в `main.py`, пути от `Path(__file__)`.**
- Плюсы: пример работает из любой копии папки без правки и запускается одной командой. Он показывает тот же приём, что шаг 2 README.
- Минусы: вставка нарушает сторож DEBT-059 (`tests/test_packaging.py:181`, `TestNoPrototypePathInsertion`), и для этого файла нужно узкое исключение. Кроме того, `pathlib` и `parents[2]` сложнее двух строк с полными путями в README (решение пользователя о простоте) и требуют комментариев.

**B. `PYTHONPATH` в `.bat` рядом с примером (`%~dp0..\..`).**
- Плюсы: `main.py` без служебных строк, сторож не изменяется.
- Минусы: появляется второй файл, и пример запускается не через `python main.py`, хотя `examples/run_all.py` вызывает `main.py` напрямую. Приём шага 2 README пример не показывает.

**C. Файл `.pth` в `site-packages` окружения.**
- Минусы: путь в `.pth` абсолютный и записывается в окружение, а не в пример: копия папки в другом месте его не получает. Папки из `.pth` встают в конец `sys.path`, и установленный пакет того же имени их перекрывает. Для примера способ не подходит, а вопрос о том, вносить ли его в README пакета, решается отдельно.

**Рекомендация:** A с узким исключением в стороже и проверкой, что исключённый файл существует.

### Как проверить работу без установки в тестах

**A. Подпроцесс `python -S main.py` с `PYTHONPATH` = `site-packages` venv.** С `-S` модуль `site` не загружается и файлы `.pth` не обрабатываются, поэтому поисковики editable-установки (`__editable__.*.pth`) не включаются. Numpy и прочие зависимости находятся через `PYTHONPATH`, а решатель и прототип – только если пример добавил их сам. Утверждения: код 0, файлы результатов на месте, напечатанные `__file__` обоих пакетов – из дерева. **Не проверено:** импортируются ли numpy, scipy, matplotlib под `-S` – проба при планировании.

**B. Шаг `tools/acceptance.py`:** до `setup.bat` – окружение только с зависимостями и запуск примера. Проверка настоящая, но медленная, нужен PyPI и идёт вне pytest.

**C. Разбор `main.py` (AST):** обе вставки вычисляются от `__file__`, папки существуют. Быстро, но импорт фактически не проверяется.

**Рекомендация:** A + C, а B остаётся запасным вариантом на случай, если A не работает.

## План реализации

1. **Пробы:** запуск с `-S` и `PYTHONPATH` на `site-packages` (импортируются ли numpy, scipy, matplotlib и остаются ли выключены editable-поисковики), время расчёта книги, числа README примера. Решения пользователя по вопросам ниже.
2. **Папка примера:** книга, `main.py`, README.
3. **Тесты:** списки примеров, класс теста примера (состав папки, перевод книги, числа README), исключение сторожа DEBT-059 с проверкой существования файла, запуск без установки.
4. **Документы:** README пакета (ссылка на пример), `examples/README.md`, CHANGELOG, `tools/release.py`.
5. **Верификация:** быстрый и полный прогон тестов.

### Открыто к планированию

1. `main.py` – вызов функций (`run_case`, печать результатов из `result.history`) или обёртка команды `run`, как у примера 22. Предложение – функции: случай «Папка с кодом без установки» описывает вызов функций из своих скриптов.
2. Книга – шаблон без изменений (расчёт совпадёт с примером 22) или свои значения – например, короткое расписание, чтобы тесты шли быстрее. Примеры самостоятельны, сравнения с примером 22 нет.
3. Пути в `main.py` через `pathlib` с комментариями – допустимо ли при решении о простоте.
4. Проверка без установки – подпроцесс с `-S` или шаг приёмки.
5. Имя папки: предложение – `23_workbook_without_install`.
6. Вносить ли способ `.pth` в README пакета.
