Три раунда запускались последовательно в отдельных контекстах на искусственной задаче DEBT-999. Реестры и код фикстуры не относятся к рабочим задачам проекта. Содержимое плана между раундами изменялось, поэтому в сохранённой фикстуре находится только версия третьего раунда.

В каждом раунде основной агент сопоставил хеш в сводке с `Get-FileHash -Algorithm SHA256` проверяемого файла. Субагенты не изменяли план и не обращались к GitHub. Отчёты сохранены в `fixture/vault/issues/debt-999/`. Запуск раундов организован вручную. Автоматический переход из настоящего `plan-improve` не проверен.

После уточнения шаблона отчёта отдельно запущен дополнительный тест аудитора с номером 4. Это отдельный тест, а не четвёртый автоматический раунд одного вызова планирования. Аудитор явно записал нулевые счётчики, вердикт «готов» и хеш версии из раунда 3. При этом `git status` в том запуске сообщил о недоступности временного каталога `skill-work/pytest-reg/`. Поэтому полный статус общей рабочей копии в этом тесте не подтверждён. Отчёт сохранён как `audit-r4.md`.

Аудитор подтвердил исправления и вернул вердикт «готов» для SHA-256 `3d128b68f0c5711df002242c4e846e4593c6d09e73292219be4c71b6b8ade980`. Хеш подтверждён командой `Get-FileHash -Algorithm SHA256`.

Файлы плана, реестра, черновика и отчётов сохранены в `integration/vault/`. Ответ GitHub заменён локальным файлом. Подготовка плана и вызовы аудитора выполнены основной сессией по инструкциям навыков. Отдельный запуск настоящего `plan-improve` в пользовательской сессии не выполнялся. Во второй сводке путь отчёта возвращён ссылкой Markdown. Контракт `audit-plan` уточнён: основной агент извлекает целевой путь и сверяет его с ожидаемым.

## Git

Команда из корня проекта:

```powershell
python -X utf8 vault/plans/probes/debt-skill-audit/git_cycle_check.py
```

Результат: `PASS: local base, worktree, branch push, merge, base push and draft preservation`. Скрипт создаёт каталог `git-cycle` рядом с собой, в нём – самостоятельные локальный и удалённый репозитории. Он завершится с ошибкой, если каталог уже существует. Команда не затрагивает рабочий `.git` и настоящий GitHub. После просмотра тестовые каталоги можно удалить по правилам проекта.

Проверены порядок Git и сохранность черновика другой задачи. Навыки `implement` и `merge` как инструкции агенту скрипт не исполняет.
