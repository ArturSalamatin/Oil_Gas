# DEBT-048: после двух шагов, решённых ступенью 4, шаг останова решается сразу ею — память в адаптере

## Кратко

- **Что не так.** Останов скважины после добычи с развитой газовой зоной: почти каждый шаг решает только ступень 4 `advance` прототипа (Ньютон с переключением фаз, BUG-020). Перед ней каждый раз проходят ступени 1–3, а они здесь не сходятся. После DEBT-015 (локальное дробление шага) около 40 % вызовов `advance` на останове — отказы попыток роста шага, и каждый стоит всех четырёх ступеней. Итог замера на коде `9a4669e`: на непринятые решения уходит 82–84 % итераций Ньютона на останове.
- **Что делаем.**
  - Прототип: ступень 4 выносится в публичный метод `advance_fourth_stage`. `advance` вызывает его же, поэтому его поведение не меняется.
  - Адаптер `PrototypeHydroAdapter` помнит серию: после **двух** принятых подряд шагов, решённых ступенью 4, при том же управлении скважиной и на продолжении той же траектории следующий шаг идёт сразу в `advance_fourth_stage`.
  - Её отказ — отказ шага без ступеней 1–3: `Simulator` делит подшаг пополам. После **двух** её отказов подряд память сбрасывается, и следующая попытка проходит все четыре ступени.
  - В замерах этот вариант назван m2s.
- **Эффект** (замер 1.2, код `9a4669e`, текущий допуск Ньютона):
  - итераций Ньютона на останове −42…−51 % в сценариях конфига 20, −45 % в примере 17;
  - счёт сквозного расчёта 20A 276 → 177 с, 20B 287 → 205 с (18 расчётов одновременно);
  - 21 пример из 22 побитово, включая 16. Пример 17 меняется на $|\Delta p| \le 1.2\cdot10^{-4}$ бар, $|\Delta T| \le 3.5\cdot10^{-5}$ К. При текущем допуске ломается один его тест (`test_examples.py:2749`, $R_s(r_w)$) — причина в BUG-022, а не в памяти (1.5).
- **Порядок.** Сначала влить BUG-022 (допуск Ньютона по газу), потом этот план — решение пользователя. BUG-022 влит (`7b47ac8`); аудит 1 перемерил план на базе после него (`f466cc4`, раздел 1.8).
- **Текущая база — после BUG-024** (`d7528d4`, аудит 2, раздел 1.9). BUG-024 ограничил шаг $R_s$ в ступени 4. Отказов на останове конфига 20 больше нет, ступень 4 сходится за 8–16 итераций, суточный останов снова проходит при штатном `max_retries`. Перемер:
  - доля итераций, потраченных впустую, на останове 20B при 3600 с — по-прежнему ~80 % (2727 из 3398);
  - с памятью m2s итераций 3398 → 695 (−80 %), счёт 37 → 15 с, **история побитово та же**;
  - 22 примера из 23 побитово (16 и новый 18 тоже); пример 17 — итераций 10107 → 3176 (−69 %), история сдвигается на $1.3\cdot10^{-9}$ бар;
  - тесты с эмуляцией памяти проходят: классы 16 и 17, VAL-004 (`test_val004.py`), суточный тест BUG-024 — 29 passed.

  Шаг 0 повторяет замер, только если расчётный код ушёл от `d7528d4`.

### 1.5 Причина сдвига $R_s(r_w)$ — допуск Ньютона по газу (BUG-022; `tolerance17.out.txt`, `tolerance17_records.out.txt`)

В базе $R_s(r_w)$ примера 17 на сутках 20–30 немонотонен: 79.5345 → 79.5096 → 79.5326 → … → 79.5125, 6 убываний, до −0.018 за сутки. При $q_{oil} = 0$ так быть не может: недонасыщенная забойная ячейка получает нефть только из ячейки 1 ($R_s$ = 87.2). Оценка:
- допуск по газу $300 \cdot 10^{-11}$ м³ст/с (`gas_residual_scale` = 300, `blackoil.py:225`) — $1.08\cdot10^{-5}$ м³ст за шаг 3600 с;
- в ячейке $4.1\cdot10^{-3}$ м³ст нефти это $2.6\cdot10^{-3}$ по $R_s$ за шаг;
- за сутки — блуждание ~0.013.

### 2.3 Варианты

**Что помнить** — измерено восемь вариантов (1.2). Три оси:
- **M** — сколько принятых подряд шагов ступени 4 включают память. M = 1 меняет пример 16: там ступень 4 решает один шаг, а следующий решила бы ступень 1. M = 2 оставляет 16 побитовым, а выигрыш теряет только один шаг на серию (m1 и m2 — один отпечаток).
- **Сброс при отказе полного перебора** («r»). Сохраняет побитовость сценариев конфига 20, но в режиме роста G1a (удача — удвоение — отказ) почти не даёт памяти включиться: m2r −3…−5 %.
- **Строгий** («s»). Пропуск ступеней 1–3 после отказа ступени 4 по памяти даёт главный выигрыш (m2 −25…−34 % → m2s −42…−51 %). Риск: шаг, который решили бы только ступени 1–3, отдаётся дроблению. Замер — 0 таких из 2486. Страховка — сброс после 2 отказов подряд: тогда следующий, вдвое меньший подшаг проходит все ступени. Неверного результата риск не даёт: в худшем случае лишний отказ и меньший подшаг.

Выбран **m2s** (решение 1). Он меняет сценарии конфига 20 (1.7) и пример 17 (1.4) в пределах допуска Ньютона, 21 пример побитово.

**Где хранить память:**
- **В адаптере (выбрано, решение 2).**
  - Плюсы:
    - `advance` остаётся функцией (состояние, шаг, управление);
    - тесты, вызывающие `model.advance` на общей модели (фикстура `shutin_start` с `scope="module"`, `test_prototype_phase_switching.py:47`), не зависят от порядка;
    - ключ продолжения траектории — время $t$, которое адаптер видит точно.
  - Минусы:
    - новый публичный метод прототипа (запись в CHANGELOG);
    - адаптер хранит состояние между вызовами `solve`.
- **Внутри прототипа (отклонено).** Память в `advance`, адаптер не меняется. Минусы:
  - проверка «продолжение той же траектории» — только по $S_g$, $R_s$ и набору фаз: давление после перевода бар → Па → бар у 14 % значений побитово не возвращается (проверено на $10^6$ случайных значений), поэтому его сравнить нельзя;

Тест `:109` переключает управление на BHP и обнуляет серию, но два следующих при $q_{oil} = 0$ (`:123`, `:144`) набирают её до двух — память включилась бы и при M = 2.

**Где хранить параметры M и F:** модульные константы адаптера. M — ещё и параметр конструктора: тестам нужна память, выключенная для сравнения (`stage4_memory=None`). В конфиг не выносятся: это внутренняя стратегия решателя, не параметр задачи.

def _fake_stages(model, monkeypatch, outcomes):
    """Подменить advance и advance_fourth_stage; outcomes — (сошёлся, решила ступень 4) по вызовам.

    Журнал: "все" — advance (ступени 1-4 по порядку), "4" — advance_fourth_stage.
    Состояние возвращается прежним: адаптеру для потоков и забойного давления
    нужно корректное состояние, новое не нужно.
    """
    calls, queue = [], list(outcomes)

    def make(kind):
        def fake(proto_state, dt, *args, **kwargs):
            calls.append(kind)
            converged, stage4 = queue.pop(0)
            return proto_state, SimpleNamespace(
                converged=converged, phase_switching=stage4, iterations=3, residual_inf=1.0)
        return fake

    monkeypatch.setattr(model, "advance", make("все"))
    monkeypatch.setattr(model, "advance_fourth_stage", make("4"))
    return calls


def _solve(adapter, state, bc, ok=True):
    """Один вызов solve. ok=False — ждём отказ и возвращаем то же состояние: повтор, как у Simulator."""
    if ok:
        return adapter.solve(state, DT, bc).state
    with pytest.raises(HydroConvergenceError, match="advance не сошёлся"):
        adapter.solve(state, DT, bc)
    return state
