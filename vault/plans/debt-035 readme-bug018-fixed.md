## Контекст

**BUG-018** (#48, влит `f2dfd4c`, 2026-10-03). При пуске ячейки у забоя переходят в двухфазный режим со стартовой газонасыщенностью «закрытого сосуда»
$$S_g^{закр} = \frac{d\,B_g}{B_o + d\,B_g},\qquad d = R_{s,0} - R_s(p_{wf}).$$
Если $S_g^{закр} > 1 - S_{or}$, начальная точка лежит там, где ОФП Кори на полках: $k_{ro} = 0$, $k_{rg} = k_{rg}^{max}$ (`CoreyRP`, `numerical_solver/gpn_multiphase_solver/pvt/relperm.py:32-42`: $S^* = (S_g - S_{gc})/(1 - S_{or} - S_{gc})$ обрезается до 1). Ньютон из такой начальной точки до решения не доходит — это замерено (обрезка стартовой $S_g$: cap 0.79 — сходимость, 0.81 — отказ при $1 - S_{or} = 0.80$). **Почему не доходит — не проверено** (заметка ниже, раздел «Почему Ньютон не выходит из этой области»): нулевые производные потоков по $S_g$ на полках — правдоподобное объяснение, не факт. Поэтому README не должен подавать полки как причину отказа. До исправления первый шаг не сходился при любом дроблении. Исправление: стартовая $S_g$ ограничивается наибольшим узлом таблицы ОФП с $k_{ro} > 0$ (`_sg_activation_cap`, `numerical_solver/HydroSolverPrototype/Prototype_1.0.3/radial_blackoil/blackoil.py:32-37`). Таблица — потому что прототип принимает ОФП только таблицей: Кори табулирует фабрика на 101 узле, $S_g$ = 0, 0.01, …, 1 (`_get_or_create_proto_rp`, `numerical_solver/gpn_multiphase_solver/factory.py:353-366`). Узел ограничения (проверено аудитом вызовом этих функций, $S_{gc} = 0.1$, $n_o = 2$, $n_g = 3$): 0.94 при $S_{or} = 0.05$, 0.84 при 0.15, 0.79 при 0.2, 0.77 при 0.22. Итоговая заметка: [[начальное Sg закрытого сосуда выше 1 − S_or не даёт Ньютону дойти до решения — ограничение по таблице ОФП снимает отказ]].
