## Описание

Плотности нефти и газа при стандартных условиях `pvt.rho_o_std`, `pvt.rho_g_std` не проверяются на знак. Нулевое или отрицательное значение (опечатка, пропущенная цифра) проходит `load_config`, а дальше всё зависит от модели PVT:

- **таблица PVT** (`pvt.model = "table"`) — расчёт идёт до конца без отказа и без предупреждения, температура у забоя молча неверна;
- **корреляции Стендинга** (`pvt.model = "standing"`) — отказ фабрики, но сообщение не называет плотность: «начальное состояние пересыщено газом» или `ZeroDivisionError`.

Остальные физические поля конфига проверяются в `_validate` на допустимый диапазон (DEBT-047, DEBT-068, DEBT-056); плотности — исключение. Книга ввода Excel (FEAT-033, FEAT-035) проверяет плотности на > 0 сама, путь JSON — нет: у одного поля разные правила на двух входах.

Приоритет низкий: в примерах плотности верные, вредит только опечатка.

## Текущее состояние

`_validate` (`io/config.py`) секцию `pvt` не проверяет вовсе. У плотностей — только тип и конечность (`_check_numeric_fields`, DEBT-051). Фабрика передаёт их в PVT без проверки (`create_pvt`: `StandingFullPVT`, `PrototypePVTAdapter` → `TableFullPVT`).

Куда входят плотности:

| путь | где | что |
|---|---|---|
| оба | `pvt/base.py:70`, `:74` | $\rho_o = (\rho_{o,ст} + R_s\rho_{g,ст})/B_o$, $\rho_g = \rho_{g,ст}/B_g$ — теплоёмкость флюида в энергии |
| оба | `fluxes.py:100-101`, `simulator.py:249-250` | массовые потоки фаз и дебиты на забое |
| оба | `energy/tridiag.py:545-570` | интенсивность разгазирования $\dot m$ — источник $Q_{deg} = -L\dot m$ |
| Стендинг | `pvt/standing.py:58-60` (`_api_gravity`, `_gas_specific_gravity`) | $\gamma_{API} = 141.5/(\rho_{o,ст}/\rho_w) - 131.5$, $\gamma_g = \rho_{g,ст}/\rho_{возд}$ — вход корреляций $R_s$, $B_o$, $\mu_o$ |

Гидродинамика табличного пути плотностей не видит (прототип работает в стандартных объёмах), поэтому на этом пути отказа нет нигде.

`load_config` отвергает `rho_o_std` ≤ 0 и `rho_g_std` ≤ 0 с `ValueError`, в тексте — полное имя поля и смысл: плотность при стандартных условиях, кг/м³ (не пластовая). Отказ одинаков для обоих путей PVT и наступает до фабрики. Перечень проверок в `P8-формат-ввода-json.md` дополнен.

## Анализ вариантов решения

### Вариант 1 — отказ в `_validate` при ≤ 0

- **Суть:** проверка `0 < v` для `pvt.rho_o_std`, `pvt.rho_g_std` (NaN и inf уже отвергнуты `_check_numeric_fields`).
- **Изменения:** `config.py` — отдельный блок «PVT» в `_validate` (цикл тепловых параметров не подходит по смыслу: плотности — свойства флюида, не тепловые); `test_config.py` — параметризованный тест на 4 случая + проверка текста.
- **Плюсы:** как у остальных физических полей (DEBT-047, DEBT-068); одинаково для обоих путей PVT; отказ до фабрики с именем поля вместо «пересыщено газом». Истории примеров не меняются — все плотности в них > 0.
- **Минусы:** правдоподобную, но неверную плотность (850 → 85, 0.85 → 8.5) не ловит.

### Вариант 2 — вариант 1 + предупреждения о неправдоподобных значениях

- **Суть:** в журнал — предупреждение (не отказ), расчёт идёт: $\rho_{g,ст} \ge \rho_{o,ст}$; $\rho_{o,ст}$ или $\rho_{g,ст}$ вне диапазона.
- **Пороги — решить при планировании.** Черновик плана: $\rho_{o,ст}$ ∈ 600–1100 кг/м³, $\rho_{g,ст}$ ∈ 0.6–2 кг/м³. Для пути Стендинга естественный диапазон — область данных корреляции; по распространённым сводкам API 16.5–63.8 ($\rho_{o,ст} \approx$ 725–956 кг/м³) и $\gamma_g$ 0.59–0.95 — **по памяти, сверить с первоисточником** до использования.
- **Плюсы:** ловит пропущенную или лишнюю цифру.
- **Минусы:** пороги условны; предупреждение на законной тяжёлой нефти или жирном газе — шум; книга Excel (FEAT-035) такие предупреждения не выдаёт — опять разные правила на двух входах.

### Вариант 3 — проверка в конструкторах PVT

- **Суть:** `ValueError` в `StandingFullPVT.__init__` и `PrototypePVTAdapter.__init__`.
- **Плюсы:** ловит и конфиг, собранный в коде.
- **Минусы:** противоречит принятому правилу «проверки — только на пути JSON → `load_config` → `from_config`» (P8, строка 228); два места вместо одного; отказ после чтения таблиц.

**Рекомендация: вариант 1.** Вариант 2 — только если пользователь выберет пороги; его можно отложить в отдельную задачу, не задерживая отказ при ≤ 0.

## План решения

1. **Подготовка.** Число тестов (`pytest tests/ --collect-only -q`); пробы `density_sign.py`, `density_sign_standing.py` на базе — воспроизвести замеры 1 и 2.
2. **Реализация.** Блок проверки в `_validate`; параметризованный тест в `test_config.py` (4 случая: ноль и минус для каждой плотности; совпадение `pvt.rho_o_std` / `pvt.rho_g_std` в тексте отказа) + тест, что пример с верными плотностями проходит; строка в `P8-формат-ввода-json.md`. При варианте 2 — предупреждения и тесты на журнал.
3. **Верификация.** Пробы на ветке: оба пути — отказ `load_config` с именем поля. Быстрый уровень, затем полный (`pytest tests/ -q`); истории примеров не меняются (все плотности в них > 0) — регрессия по `test_examples.py`.
