# Выпуск решателя — одна команда, push только после самопроверки сборки из метки

**GitHub issue:** [#137](https://github.com/ArturSalamatin/Oil_Gas/issues/137) · план [[feat-038 team-releases-script]] · номер и журнал — [[номер версии решателя — литерал __version__, журнал сводится при выпуске]]

**Что было.** Пакет ставился только из исходного дерева (`pip install -e`), меток и выпусков не было. Испытатель, которому нужен установленный пакет и регулярные обновления, должен был копировать дерево.

**Решение (FEAT-038, решения пользователя 2026-10-18).** Выпуск — в Releases самого `Oil_Gas`: два колеса (`gpn_multiphase_solver-X.Y.Z-py3-none-any.whl`, `radial_blackoil-1.0.3+gpn.N-py3-none-any.whl`) и архив примеров `examples-vX.Y.Z.zip`. Вручную — только текст раздела «Не выпущено» журнала (закоммитить до запуска); всё остальное — `numerical_solver\.venv\Scripts\python tools\release.py X.Y.Z` из корня, на `numerical_scheme/implementation` основного каталога. Порядок — в докстринге скрипта.

| Вопрос | Решение | Почему |
|---|---|---|
| Когда push | последним: коммит выпуска, метка, сборка из метки, самопроверка, коммит `.dev0` — локально; затем один `git push --atomic` ветки и метки; затем `gh release create` | отказ сборки после push оставил бы на `origin` метку без выпуска, а опубликованный выпуск и его номер не меняются |
| Отказ до push | автооткат: `git restore` четырёх файлов скрипта → `git tag -d` → `git reset --keep` к исходному коммиту | `--keep`, не `--hard`: незакоммиченные файлы vault основного каталога остаются (проба на учебном репозитории) |
| Отказ после push | только печать команды `gh release create …` для повтора | ветка и метка уже на `origin` |
| Откуда собирать | `git archive` метки в `dist/vX.Y.Z/src` | из рабочего каталога в колесо попали бы неотслеживаемые `.py` пакета и устаревший `build/` |
| Проверка «нет правок» | только отслеживаемые файлы `numerical_solver/` | неотслеживаемые черновики (книга руководителя, `deliverables/`) в сборку из метки не попадают |
| Коммиты скрипта | по именам четырёх файлов (`__init__.py` решателя и прототипа, `pyproject.toml`, `CHANGELOG.md`), тип `release` | в основном каталоге обычно лежат незакоммиченные общие файлы vault |
| `+gpn.N` | повышается, если с прошлой метки (у первого выпуска — с `29a1ffa`, DEBT-059) изменились `radial_blackoil/` или `pyproject.toml` прототипа | всё, из чего собирается колесо прототипа |
| Самопроверка | `tests/test_packaging.py` дерева метки (11 тестов при FEAT-038; с DEBT-086 – 29) и рабочего каталога после `.dev0`; пропуск теста = отказ; имена колёс | тесты сверяют литерал прототипа с требованием решателя, раздел журнала с номером, а с DEBT-086 – и форму пунктов раздела выпуска: пункт не по форме останавливает выпуск до публикации, с откатом; на Python 3.10 тесты `pyproject.toml` пропускаются (нет `tomllib`) |
| Описание выпуска | раздел выпуска журнала, строки каждого абзаца склеены в одну (`release_notes`, DEBT-086), затем `NOTES_TAIL` | GitHub показывает перенос строки в описании выпуска как `<br>`: пункт v1.0.6, перенесённый по ~76 знаков, вышел 14 рваными строками |
| Пример 18 | в архив не входит; строка в заметках выпуска | читает книги и эталон CMG IMEX из дерева прототипа |
| Установка | `gh release download`, архив — в каталог своего выпуска, `pip install` по путям колёс (README §1 «Из выпуска») | по имени с `--find-links` pip может взять одноимённый пакет с PyPI; `Expand-Archive` в непустой каталог отказывает |
| Тесты скрипта | не пишутся | решение пользователя; проверка — самопроверка, проба функций `vault/issues/feat-038/probes/plan_check.py`, первый выпуск в другом каталоге |

**Ловушки:**
- Рабочее дерево — с CRLF (`core.autocrlf=true`): скрипт читает и пишет литералы и журнал байтами, регулярные выражения — с `(?=\r?$)`. METADATA колеса, собранного setuptools на Windows, тоже с CRLF — сверять по строкам.
- Вывод в канал или файл без `PYTHONIOENCODING` идёт в cp1251: `print('→')` даёт `UnicodeEncodeError`. Скрипт делает `reconfigure(errors="replace")` потоков вывода. В сессии Claude переменная задана (`utf-8`), поэтому пробы этого не видят — проверять вызовом с очищенным окружением.
- `+` в имени файла выпуска GitHub сохраняет и при загрузке, и при скачивании (проверено на черновике 2026-10-18; в URL — `%2B`). Черновик выпуска метки не создаёт — поэтому `preflight` проверяет имя и через `gh release view`.
- Изолированная сборка колёс скачивает `setuptools>=68` (в venv его нет) — нужен PyPI или кеш pip.
- `reset --keep` снимает индексирование с чужих файлов; содержимое сохраняется.
- Не запускать, пока другая сессия вливает ветку: скрипт коммитит в базовую ветку; push уносит и прежние локальные коммиты базы.
