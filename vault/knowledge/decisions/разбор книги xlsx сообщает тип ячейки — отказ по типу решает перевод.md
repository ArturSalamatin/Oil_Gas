# Разбор книги xlsx сообщает тип ячейки — отказ по типу решает перевод

Книгу ввода ([[книга ввода Excel версии 1 — все параметры явно, единицы фиксированы]]) читает `numerical_solver/gpn_multiphase_solver/io/xlsx_reader.py` — только стандартная библиотека (`zipfile`, `xml.etree.ElementTree`), без `openpyxl`. Разбор ничего не запрещает: он сообщает, **что лежит в ячейке**. Что допустимо в поле книги — дата, текст «1,5», логическое значение, формула без значения в числовом поле, — решает перевод [[FEAT-035]]: только он знает, какое поле ждёт число. План и решения пользователя — [[feat-034 xlsx-cell-reader]].

## Что отдаёт разбор

`read_workbook(path) → Workbook`:

- `Workbook.sheets` — листы в порядке книги (скрытые — как обычные); `Workbook.recalc_on_open` — пометка книги «пересчитать при открытии» (`fullCalcOnLoad`);
- `Sheet.cell(row, col)` — ячейка; не записанная в книге — пустая; `Sheet.max_row` — последняя строка с непустой ячейкой;
- `Cell`: `kind` — `number` (значение `float`: Excel хранит все числа вещественными), `string` (как в книге, пробелы не срезаются), `bool`, `error` (`#DIV/0!` …), `empty`; `is_date` — число с форматом даты или времени; `formula` — текст без «=» («» — ячейка общей формулы); `formula_without_value`; `ref` — `MODEL!C5` для сообщений.

Внутренний код, не публичный интерфейс пакета: в README §4 и `tests/test_public_api.py` его нет, докстринги — однострочные.

## Правила

| Что | Как | Почему |
|---|---|---|
| Формула в книге с `fullCalcOnLoad` | значения нет: `formula_without_value` | пометку ставят XlsxWriter и (по документации) openpyxl; XlsxWriter у формулы без значения пишет `<v>0</v>` — нуль неотличим от настоящего. Excel при сохранении пометку снимает — проверено на книге генератора, сохранённой Excel |
| Признак даты | встроенные форматы 14–22, 45–47, 27–36, 50–58; код формата — буквы d, m, y, h, s в первом разделе вне кавычек, `[…]` (кроме `[h]`, `[mm]`, `[ss]`) и символов после `\`, `_`, `*` | как у Excel: экранированная буква — литерал. Формат книг IMEX `\y\y\y\y\-\m\m\m\-…` — не дата. Правило «любая буква» дало бы ложные отказы на числах с подписью в формате |
| Стилизованная пустая ячейка | не хранится | `max_row` не продлевается оформлением; в черновике руководителя таких 80 |
| Строки | `_xHHHH_` раскодируется, фонетика `<rPh>` не читается | так ECMA-376 записывает управляющие символы |
| `<v></v>` без типа | значения нет | так XlsxWriter пишет формулу со значением `""` |
| Пути частей | связь `officeDocument` из `_rels/.rels`; абсолютные и относительные цели | прототип пишет `/xl/…`, Excel — от каталога части |

**Исключения.** Любой отказ из-за содержимого файла — `WorkbookError` (подкласс `ValueError`) с путём файла, частью или адресом ячейки и подсказкой «Сохраните книгу в Excel как «Книга Excel (*.xlsx)»»: составной файл OLE (`.xls` и книга с паролем на открытие начинаются одинаково), не zip, zip без книги Excel (`.ods`, `.docx`), `.xlsb`, строгий формат Open XML (без проверки — ноль листов молча), повреждённый XML, испорченная ячейка или служебный атрибут (`r`, `s`, `numFmtId`). Ошибки файловой системы — `OSError` как есть. Командная строка ловит только свои исключения и печатает прочее с трассировкой как ошибку кода, поэтому [[FEAT-036]] должен ловить `WorkbookError` и `OSError` явно.

## Книги, на которых проверен

Книги в git записаны тремя программами, у каждой свой XML:

| Программа | Книги | Особенности |
|---|---|---|
| прототип (.NET) | 23: `INPUT_TEMPLATE.xlsx`, `regression/inputs/`, `regression/evidence/`, `tests/fixtures/` | теги с префиксом `x:`, текст — `t="str"` без формулы, общих строк нет, абсолютные пути частей |
| Microsoft Excel | 22: `regression/reference_imex_xlsx/` | формулы `DATE(…) + TIME(…)` с сохранёнными значениями, формат 164 с экранированными буквами, `calcId="191029"` |
| XlsxWriter | книга генератора `configs/INPUT_TEMPLATE_v1.xlsx` | `fullCalcOnLoad="1"`; в `docProps` подписывается «Microsoft Excel» — признак программы `calcPr`, не `docProps` |

На 45 книгах прототипа значения совпадают с `radial_blackoil.xlsxio` — там, где тот прав (`xlsxio` дату отдаёт числом, логическое — 1.0, формулу без значения — как пустую ячейку; адресов нет). Книга генератора совпадает с помощником тестов `tests/_xlsx.py`.

Фикстуры настоящего Excel — `numerical_solver/tests/data/feat034_excel/`, сохранены пользователем 2026-10-18 в Excel 16 с **английскими настройками** (десятичная точка): `traps.xlsx` — «1,5» и «01.05.2026» остаются текстом, `ИСТИНА`/`TRUE` — `bool`, время 10:30 — дата (встроенный формат 20), формулы `0.11/3600`, `1/0`, `ROW()`; `template_saved.xlsx` — книга генератора после Excel: пометки пересчёта нет, `=0.2/2` со значением 0.1. Ловушка Excel **с русскими настройками** — ввод «1.5» становится 1 мая — в фикстурах не воспроизведена; её проверяют книги XlsxWriter с форматами 14 и 16.

## Чем разбор не занимается

Защита листов, выпадающие списки, проверки данных Excel — не читаются: проверку данных обходит вставка из буфера обмена, поэтому все проверки повторяет перевод. Даты в числа дней не переводятся — только признак (система дат 1904 безразлична). Числа не округляются: Excel пишет до 17 значащих цифр, `float` читает их точно; XlsxWriter пишет 16 — свойство записи, а не разбора.
