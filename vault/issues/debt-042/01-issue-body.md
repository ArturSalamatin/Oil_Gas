## Описание

CSV-ридеры фабрики (`model = "table"` для PVT и ОФП) молча пропускают строку, которую не удалось разобрать в числа, и строку, в которой меньше столбцов, чем нужно. Лишние столбцы отбрасываются. Опечатка в числе удаляет строку таблицы без сообщения, а десятичная запятая сдвигает значения на столбец. У ОФП столбцы могут разойтись по длине. Тогда отказ наступает только во время счёта, и сообщение `np.interp` не называет ни файла, ни строки.

Приоритет низкий: все 47 CSV-таблиц проекта (16 `oil_pvt.csv`, 16 `gas_pvt.csv`, 15 `relperm.csv`) разбираются без пропусков, число столбцов совпадает с заголовком (проверено 2026-10-07). Заголовки одинаковы во всех файлах одного типа.

## Текущее состояние

Три ридера в `factory.py` устроены одинаково: заголовок пропускается через `next(reader)`, затем для каждой строки:
- `if len(line) < N: continue` — короткая строка пропускается (N = 4 у нефти, 3 у газа и ОФП). Пустая строка (`[]`) пропускается этим же условием;
- `float(...)` в `try`, `except ValueError: continue` — нечисловая строка пропускается;
- столбцы после N-го не читаются.

`float()` принимает `nan` и `inf`.

У `_read_relperm_csv` (`factory.py:495-500`) значения дописываются в три списка по одному. При ошибке во 2-м или 3-м столбце `Sg` уже дописан, а `kro`/`krg` нет: столбцы разной длины. `TabulatedRelPerm.__init__` (`relperm.py:3-6` прототипа) проверяет монотонность `Sg` и знак ОФП, но не длины.

Что происходит с ошибкой в таблице:

| Ошибка | Поведение | Сигнал пользователю |
|---|---|---|
| Опечатка в числе (`15OOOOOO`) | Строка пропущена. У нефти ветвь PVTO теряет точку, у газа и ОФП пропадает узел интерполяции | Нет. `_check_pvto_branches` (DEBT-038) сработает, только если в ветви осталась одна строка |
| Десятичная запятая без кавычек (`30.0,15000000,1,20,0.0015`) | Пять полей вместо четырёх, значения сдвигаются: $B_o$ = 1, $\mu_o$ = 20 Па·с вместо 1.5 мПа·с | Нет |
| Пропущено значение (строка короче заголовка) | Строка пропущена | Нет |
| Ошибка во 2-м или 3-м столбце ОФП | Столбцы `Sg`, `kro`, `krg` разной длины | `ValueError: fp and xp are not of the same length` из `np.interp` при первом вычислении ОФП (проверено 2026-10-07 вызовом `TabulatedRelPerm([0, 0.4, 0.8], [1, 0], [0, 0.8]).kro(0.5)`) |
| `nan` или `inf` в ячейке | Принимается | Нет. Сравнения с NaN ложны, поэтому давление `nan` проходит правила DEBT-038 (замечание аудита плана DEBT-038) |
| Разделитель `;` с десятичной запятой (CSV из Excel в русской локали) | Ни одна строка не разбирается | Нефть: `ValueError` DEBT-038 «нет ни одной числовой строки» с именем файла. Газ, ОФП: исключение прототипа о монотонности (`pvt.py:32`, `relperm.py:5`) или `np.interp` о длинах, без имени файла и без причины |

Строки 1–3 и 5–6 таблицы выведены из кода, не запускались.

XLSX-ридер прототипа тоже пропускает нечисловые строки (`input_reader.py:56-58`, `68-70`, `76-78`: `except (TypeError, ValueError, IndexError): continue`). Эталона строгости разбора строк в проекте нет.

## Целевое состояние

Непустая строка, которая не разбирается в конечные числа или у которой число столбцов не совпадает с заголовком, даёт `ValueError` с именем файла и номером строки. Пустые строки по-прежнему пропускаются (`test_oil_csv_skips_blank_lines`). Корректные таблицы разбираются в те же значения, результаты примеров не меняются.

## Анализ вариантов решения

### Вариант 1 — точечная правка трёх ридеров

**Суть.** В каждом ридере: `continue` → `ValueError(f"{csv_path.name}, строка {reader.line_num}: ...")`; `len(line) < N` → `len(line) != N`; пустая строка (все поля пустые или из пробелов) пропускается явно; после `float` — проверка `np.isfinite`. В `_read_relperm_csv` строка сначала разбирается в кортеж, потом дописывается.

**Изменения.** `factory.py:440-450`, `467-476`, `492-500`; тесты в `TestCSVReaders`.

**Плюсы:** минимальная правка, структура ридеров прежняя.
**Минусы:** одни и те же правила и сообщения в трёх копиях, три набора одинаковых тестов. Число столбцов задано константой в коде, а не заголовком файла.

### Вариант 2 — общий разборщик строк

**Суть.** Функция `_read_numeric_csv(csv_path, columns) -> list[tuple[float, ...]]`:
- существование файла (сообщение «не найден» сохраняется — его проверяют тесты);
- заголовок: число столбцов (и, по решению в плане, имена) сверяется с ожидаемым;
- строки: пустые пропускаются; число полей = числу столбцов заголовка; каждое поле — `float`, затем `np.isfinite`; при нарушении `ValueError` с именем файла, номером строки (`reader.line_num`), столбцом и исходным текстом ячейки.

Три ридера становятся обёртками: перевод единиц (Па → бар, Па·с → сП) и раскладка по кортежам. У ОФП — `zip(*rows)`, столбцы одной длины по построению. Сигнатуры и типы возврата не меняются: `TestCSVReaders` проходит без правок.

**Изменения.** `factory.py:425-501` — новая функция + упрощение трёх ридеров; новые тесты разборщика.

**Плюсы:** правила в одном месте, один набор тестов на правила разбора. Рассинхрон столбцов ОФП невозможен по построению. Сообщения единообразны.
**Минусы:** на одну функцию больше; ридеры переписываются целиком (около 75 строк).

### Вариант 3 — вариант 2 + проверки значений как у XLSX-ридера

**Суть.** Добавить на CSV-путь проверки значений, которые есть в XLSX-ридере и которых нет в конструкторах прототипа: $B_g > 0$, $\mu_g > 0$ (`input_reader.py:73`), $S_g \in [0, 1]$ (`:81`). Монотонность давления газа, монотонность $S_g$ и $k_r \ge 0$ уже проверяют конструкторы прототипа (`pvt.py:32`, `relperm.py:5-6`), но без имени файла. $B_o > 0$, $\mu_o > 0$ не проверяет ни один путь.

**Плюсы:** CSV-путь не слабее XLSX; сообщения с именем файла вместо исключений прототипа.
**Минусы:** выходит за формулировку DEBT-042 (разбор строк, а не допустимость значений). Вопрос — включать сюда или регистрировать отдельной записью.

### Рекомендация

Вариант 2. Вариант 3 — решить в плане явно, без расширения задачи по умолчанию.

### Вопросы для плана

1. **Лишнее пустое поле в конце строки** (`0.0,5000000,1.05,0.003,` — бывает при экспорте из табличных редакторов). Сейчас принимается. Правило «число полей = числу столбцов заголовка» его отвергнет. В 47 таблицах проекта такого нет. Рекомендация — отвергать: сообщение называет лишний столбец, и тот же текст ловит десятичную запятую.
2. **Строка из пробелов** — считать пустой (сейчас `['   ']` пропускается условием длины).
3. **Имена столбцов заголовка.** Столбцы читаются по позиции: перестановка `Bo` и `mu_o_Pa_s` сейчас проходит молча. Заголовки всех 47 файлов одинаковы в пределах типа (проверено 2026-10-07), поэтому сверку имён можно ввести без правки таблиц. Если сверять имена — читать файл в `encoding="utf-8-sig"`, иначе BOM попадёт в имя первого столбца.
