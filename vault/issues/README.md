# vault/issues/

Тексты, которые уходят в GitHub через `gh issue create --body-file` и
`gh issue comment --body-file`.

## Зачем хранить

`gh` принимает многострочный markdown только файлом: передавать его
аргументом в PowerShell нельзя — спецсимволы и кириллица ломаются.
Раньше такие файлы складывались во временный каталог, что противоречит
CLAUDE.md («Все новые файлы — только в папке проекта»). Теперь они
лежат здесь.

Побочная польза: текст, отправленный в issue, остаётся в репозитории —
видно, что именно было опубликовано и когда, без обращения к GitHub.

## Структура

```
vault/issues/<id-lowercase>/
├── 01-issue-body.md      # тело issue (/issue)
├── 02-comment-open.md    # «Контекст при открытии» (/issue)
├── 03-comment-plan.md    # «План готов» (/plan-*)
├── 04-comment-audit.md   # «Аудит плана» (/audit-plan)
├── 05-comment-done.md    # результат реализации (/implement)
└── probes/               # диагностические скрипты — см. PROBES.md
```

Нумерация — порядок публикации. Имена отражают назначение, не команду.
Не все файлы обязательны: у задачи может быть только issue без плана.

## probes/

Скрипты, воспроизводящие замеры из расследований. Раньше уходили
в временные каталоги и терялись; 23 таких скрипта спасены 2026-09-20.
Подробности, состав и ограничения — `PROBES.md`.

## Где ещё правится это правило

Инструкции команд исправлены 2026-09-20: `/issue`, `/audit-plan`,
`/implement`, `/plan-fix`, `/plan-improve`, `/plan-feature`,
`/plan-validate` — все 14 упоминаний scratchpad заменены на пути
внутри `vault/issues/`.
