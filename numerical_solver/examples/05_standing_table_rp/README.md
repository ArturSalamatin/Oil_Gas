# 05 — Смешанная комбинация: PVT Стендинга + табличные ОФП (комбинация C)

**Частая ситуация на практике:** PVT считается по корреляциям
(лабораторного исследования разгазирования нет), а кривые ОФП измерены
на керне.

## Описание

Двухфазный сценарий с разгазированием: $R_{s,0} = 50$, $p_b = 9.43$ МПа,
$p_{wf} = 8$ МПа. PVT — корреляции Стендинга, ОФП — таблица
`relperm.csv`.

Смысл примера — показать, что **модули комбинируются независимо**.
PVT и ОФП — разные абстракции (`HydroPVT` и `RelPermModel`), библиотека
не требует, чтобы обе были табличными или обе аналитическими.

## Комбинация модулей (C: Standing + Table ОФП)

| Модуль | Класс | Ключ конфига | Внешние файлы |
|---|---|---|---|
| Сетка | `LogRadialGrid` | `grid.N = 50` | — |
| PVT (гидро) | `StandingFullPVT` | `pvt.model = "standing"` | **нет** |
| ОФП | `PrototypeRPAdapter` | `relperm.model = "table"` | **`relperm.csv`** |
| Гидродинамика | `PrototypeHydroAdapter` | (единственный) | — |
| Энергия | `TridiagEnergySolver` | (единственный) | — |
| Управление | `PressureControl` | `control = "pressure"` | — |

Как это задаётся — секции независимы:

```json
"pvt": {"model": "standing", "rho_o_std": 850.0, "rho_g_std": 0.85},
"relperm": {"model": "table", "file": "relperm.csv"}
```

Обратите внимание: в папке лежит **только `relperm.csv`**.
Файлы `oil_pvt.csv` и `gas_pvt.csv` не нужны — PVT считается корреляциями.
Ключи `pvt.oil_pvt_file` / `pvt.gas_pvt_file` в конфиге отсутствуют.

## Ключевые параметры

| Параметр | Значение |
|---|---|
| $R_{s,0}$ | 50 м³ст/м³ст |
| $p_b$ | 9.4262 МПа (по Стендингу) |
| $p_0$ / $p_{wf}$ | 20 / 8 МПа |
| $\mu_{JT,o}$ / $\mu_{JT,g}$ | $-4\times10^{-7}$ / $4\times10^{-6}$ К/Па |
| $L$ | 168000 Дж/кг |
| $\lambda_s$ / $\lambda_o$ / $\lambda_g$ | 1.5 / 0.14 / 0.04 Вт/(м·К) |

## Ожидаемое поведение

| Величина | Значение |
|---|---|
| $S_g^{max}$ | 0.01400 |
| $R_s^{min}$ | 41.997 м³ст/м³ст |
| $p(r_w)$ финал | 8.132 МПа |
| $T(r_w)$ финал | 352.790 К (за 3 сут; нагрев на 2.8 К) |
| $q_o$ финал | $1.0909 \times 10^{-2}$ м³ст/с |
| $q_g$ финал | $5.4543 \times 10^{-1}$ м³ст/с |
| фронт разгазирования $r_b$ | 0.2034 м |
| двухфазных ячеек | 6 из 50 |

За 3 суток гидродинамика стационарна, а температура — нет.

### Что определяет ОФП

Насыщенность задаёт уравнение замыкания (п. 1 «Аналитики»):

$$\frac{k_{rg}(S_g)}{k_{ro}(S_g)} = \bigl[R_{s,0}-R_s(p)\bigr]\frac{\mu_g B_g}{\mu_o B_o}$$

**Правая часть не содержит ОФП** — только PVT и давление. Требуемое
отношение подвижностей задано извне, а ОФП определяет лишь, при какой
$S_g$ оно достигается: на забое отношение $1.44\times10^{-3}$ достигается
при $S_g = 0.014$. Газа мало, $k_{ro} \approx 1$, и течению нефти он почти
не мешает — поэтому дебит и температура от вида ОФП почти не зависят.

**Вывод для практики:** уточнение кривых ОФП меняет насыщенность, а не
температуру или дебит. Смотреть надо `saturation_profiles.png`. Обратное
тоже верно: настраивать ОФП по замеру забойного давления или дебита в
таком режиме бессмысленно — эти величины почти не несут информации о виде
$k_r(S_g)$.

## Аналитика

Проверки печатаются при запуске `main.py`. Замкнутое решение для $p$ и
$S_g$ и равновесие $R_s$ ставит общий модуль (`../closed_form.py`,
`../rs_analytics.py`); ниже — то, что специфично для этого примера.

### 1. Замыкание по насыщенности выполняется

При подстановке численного давления в уравнение замыкания расхождение
составляет $\max|\Delta S_g| = 1.1\times10^{-12}$ (0.000 %) во всех шести
двухфазных ячейках. Причина — вид ОФП: табличная $k_{rg}$ растёт от нуля
**линейно**, производная $d(k_{rg}/k_{ro})/dS_g$ конечна, и обращение
хорошо обусловлено.

### 2. Газовый фактор, фронт, Дюпюи

| Проверка | Результат |
|---|---|
| GOR на забое и контуре | $50.0000$, отклонение от $R_{s,0}$: $6\times10^{-10}$ |
| $G^{своб}=\|G^o\|(R_{s,0}-R_s)$ | max отн. откл. $1.1\times10^{-10}$ |
| фронт $r_b$: интерполяция vs формула | 0.20337 м vs 0.20337 м (0.00 %) |
| ячейки без газа: пересыщенных / ниже $p_b$ | 0 / 0 |
| Дюпюи, 44 однофазных ячейки | $\max\|p-\text{Дюпюи}\| = 1.3\times10^{-8}$ Па |
| наклон: из профиля vs из $G^o$ | отн. разность $9.7\times10^{-16}$ |
| $R_s = R_s^{eq}(p)$ в ячейках с газом | $\max\|\Delta R_s\| = 0$, побитово (6 ячеек) |

Наклон Дюпюи предсказывается **независимо**, из потока
$|G^o|\mu_oB_o/(2\pi kh)$ — это проверка согласованности PVT
с гидродинамикой, а не только самой гидродинамики.

### 3. Температура

Аналитической проверки температуры в двухфазной зоне нет. Схема
проверяется сверкой матрицы с постановкой
(`tests/test_energy_matrix_examples.py`, `rtol=1e-13`) и балансом энергии
(п. 4). В однофазной зоне на `temperature_profiles.png` нанесена
асимптотика $T = T_{ext} + \mu_{JT}(p - p_{ext})$.

### 4. Баланс энергии

| Компонент | Значение, Дж |
|---|---|
| $\Delta E$ (накопление) | $+2.90\times10^{9}$ |
| адиабатика | $-5.89\times10^{9}$ |
| конвекция | $-1.19\times10^{10}$ |
| Джоуль–Томсон | $+2.39\times10^{10}$ |
| скрытая теплота | $-3.23\times10^{9}$ |
| теплопроводность | $+4.30\times10^{5}$ |
| **невязка** | $+2.1\times10^{-5}$ ($4.5\cdot10^{-16}$) |

Невязка на уровне округлений: баланс проверяет самосогласованность
дискретных уравнений, а не точность решения — см.
[[невязка баланса энергии не есть ошибка расщепления]]. Скрипт
`energy_balance_convergence.py` при $\Delta t$ = 3600 / 900 / 360 с даёт
относительную невязку $4.5\cdot10^{-16}$ / $1.2\cdot10^{-15}$ /
$3.4\cdot10^{-15}$ — ниже порога $10^{-12}$ (до DEBT-043, пока СЛАУ
решалась в абсолютной температуре, было $6.1\cdot10^{-13}$ /
$2.9\cdot10^{-12}$ / $6.8\cdot10^{-12}$). Невязка отнесена к сумме
модулей всех членов баланса.

## Как модифицировать

### Что менять безопасно

| Параметр | Секция JSON | Эффект |
|---|---|---|
| содержимое `relperm.csv` | — | свои керновые данные (главный сценарий) |
| $R_e$ | `geometry.R_ext` | шире область; фронт $r_b$ растёт |
| $h$, $k$, $\varphi$ | `geometry`, `rock` | дебит |
| $N$ | `grid.N` | детальность профилей |
| длительность | `time.history[0].duration` | гидродинамика стационарна через 1–2 ч; $T$ за 3 сут не устанавливается |
| частота записи | `time.history[0].dt_out` | запись раз в `dt_out` на этапе `duration`: 259 200 / 3600 → 72 интервала, 73 шага; `duration` должна делиться на `dt_out` |
| тепловые скаляры | `thermal` | только $T$; гидродинамика не меняется (расщепление) |

Чтобы перейти к комбинации A (без CSV вообще) — заменить секцию `relperm`
на модель Кори, например
`{"model": "corey", "S_or": 0.2, "S_gc": 0.05, "n_o": 2.0, "n_g": 2.0, "kro_max": 1.0, "krg_max": 0.8}`.

### Что требует осторожности — $p_{wf}$

**Сверху:** при $p_{wf} > p_b = 9.43$ МПа разгазирования не будет,
сценарий молча станет однофазным.

**Снизу:** на всём диапазоне $p_{wf}$ = 8…2 МПа расчёт идёт без дробления
шага (замер 2026-10-07 через 1 МПа, DEBT-041). Раньше первый шаг дробился
на 2 подшага в двух точках: при 5 МПа — до BUG-020 (четвёртая ступень
`advance`), при 4 МПа — до BUG-021 (Ньютон сходился на последней, 15-й
итерации, а записывался отказом). При отказе
`RuntimeError: HydroSolver не сошёлся при дроблении шага до dt/N …` увеличить
`"max_retries"` в секции `numerics` (по умолчанию 9).

### Не трогать

`grid.type` — только `"log_radial"`: иное значение отвергается при загрузке конфига.
