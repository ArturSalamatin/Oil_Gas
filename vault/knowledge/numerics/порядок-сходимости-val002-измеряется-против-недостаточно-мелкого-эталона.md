# test_convergence_order_ge_1 измеряет порядок против слишком грубого эталона

Обнаружено при реализации [[debt-017 upstream-properties-outer-boundary]],
шаг 6. Тест `tests/test_val002.py::TestCaseC_MeshConvergence::test_convergence_order_ge_1`
после правки DEBT-017 даёт порядок **0.85** вместо требуемого ≥ 1.0.

## Это не регресс правки — схема сходится с первым порядком

Порядок сходимости самой $T_0$ **по Рунге**, без обращения к эталону
(три последовательные сетки, отношение приращений):

| Тройка сеток | p |
|---|---|
| 25, 50, 100 | 1.081 |
| 50, 100, 200 | 1.043 |
| 100, 200, 400 | 1.022 |
| 200, 400, 800 | 1.011 |

Схема даёт честный первый порядок, как и заявлено в докстринге теста
(«upstream-конвекция на log-сетке даёт ~1, не 2»).

## Причина — методика измерения

Тест берёт за «точное» решение прогон на `N_REF = 400` и считает RMS
отклонения сеток `N_LIST = [10, 20, 50, 100]`. Но погрешность самого
эталона сравнима с измеряемой ошибкой:

| N | T[0] | отклонение от N=800 |
|---|---|---|
| 100 | 351.49006123 | 6.7e-3 |
| 200 | 351.49392772 | 2.8e-3 |
| **400 (эталон)** | 351.49583185 | **9.4e-4** |
| 800 | 351.49677663 | 0 |

Ошибка сетки N=100 (6.7e-3) лишь в 7 раз больше погрешности эталона
(9.4e-4). Разность двух приближений искажает наклон: измеренный порядок
против N=800 составляет 0.50 → 0.51 → 0.66 → 1.03 при N = 10…200 —
он «растёт» просто потому, что вклад погрешности эталона убывает.

## Почему всплыло только сейчас

До DEBT-017 **100 % ошибки** приходилось на приконтурную ячейку:
RMS 5.7e-2, из них 5.68e-2 в ячейке N−1. Эта ошибка (свойства из ячейки
N−1 вместо ГУ при втекании) на порядок превышала погрешность эталона,
поэтому наклон измерялся по ней и давал 1.28.

После правки RMS упала в **27 раз** (4.8e-3 → 1.7e-4), ошибка в ячейке
N−1 — в **660 раз** (4.77e-3 → 7.2e-6), и обнажилась погрешность
методики. То есть правка улучшила решение, а тест начал падать.

Остаточная ошибка теперь на **100 % сосредоточена в ячейке 0** (забой) —
зона максимального градиента $dp/dr$ на логарифмической сетке. Это
обычная погрешность аппроксимации: проверено, что дефект [[DEBT-019]]
здесь **не активен** ($\Phi^+_0 = 0$, поток направлен к скважине,
`T = 0 K` не подставляется).

## ✅ Решено: тест переписан на метод Рунге (2026-09-20)

Пользователь выбрал вариант с методом Рунге. Реализовано:
`N_RUNGE = (50, 100, 200)`, порядок считается как
`p = log2(|T_a − T_b| / |T_b − T_c|)` по T на забое, порог ≥ 1.0
сохранён. Эталон `N_REF = 400` остался только у `test_error_decreases`,
где погрешность эталона монотонности не нарушает.

Фактический результат: **854 passed** (851 baseline + 3 новых теста
DEBT-017), тест сходимости зелёный.

### Что выяснилось про чувствительность теста (инъекции ошибок)

| Инъекция | Изменила решение | Порядок | Поймана |
|---|---|---|---|
| `T_new += 3·sqrt(h)` | да | **0.497** | ✅ да |
| линейное расстояние вместо ln в `Q_T` | да | 1.04 | ❌ нет (поймал DEBT-016) |
| `Q_T · (1 + 3·sqrt(h))` | да | 1.05 | ❌ нет |
| `Phi · (1 + 3·sqrt(h))` | да | 1.08 | ❌ нет |
| возмущение `cap ~ sqrt(h)` | **нет** | 1.04 | — (в стационаре cap выпадает) |
| осреднение ρ вместо значения против потока | **нет** | 1.04 | — (ρ однородна при Sg=0) |

Вывод: тест ловит **появление в решении члена меньшего порядка** — ровно
то, для чего метод Рунге и предназначен. Ошибки в *значении*
коэффициентов он не ловит и не должен: они меняют предел, а не скорость
сходимости, и их предмет — эталон DEBT-016 (ту же инъекцию с линейным
расстоянием он поймал).

Аналитическая проверка формулы: для `T_h = T* + A·h + B·sqrt(h)` при
A = 1 порядок падает как 1.000 / 0.965 / 0.786 / 0.559 при
B = 0 / 0.03 / 0.3 / 3 — чувствительность есть, просто множитель
на коэффициенте почти сокращается в стационарном балансе и потому
не создаёт нужного вида возмущения.

Формула проверена на синтетике: восстанавливает заданный p = 0.5, 1.0,
2.0 с машинной точностью.

## Что предлагалось (история)

Сдвинуть сетки в асимптотический режим и отодвинуть эталон:
`N_LIST = [25, 50, 100, 200]`, `N_REF = 800`. Тогда порядок на последней
паре = 1.03, порог ≥ 1.0 сохраняется без ослабления. Цена — прогон
примерно в 3 раза дольше (сетка 800 вместо 400).

Альтернатива, более правильная методически: измерять порядок **по Рунге**
по трём последовательным сеткам, вообще без эталона. Тогда тест не
зависит от того, насколько мелок `N_REF`, и даёт 1.01…1.08. Требует
переписать тело теста.

Решение не принято — вынесено пользователю.
