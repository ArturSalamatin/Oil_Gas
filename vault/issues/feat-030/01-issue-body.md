## Описание

Команда расчёта по конфигу из установленного пакета: инженер или аналитик заказчика запускает свой сценарий одной командой вида

```
python -m gpn_multiphase_solver run config.json --output <каталог>
```

(точная форма — при планировании) и получает то же, что сейчас даёт `examples/example_runner.run_example`:

- расчёт, историю скважины и профилей в CSV;
- штатные рисунки: профили $p$, $T$, $S_g$, $R_s$; дебиты; динамика на забое; ОФП; PVT; балансы энергии и массы;
- печать проверок: сводка, $R_s = \min(R_{s,eq}(p), R_{s,0})$, замкнутое решение стационара, PVT, асимптотика температуры.

Конвейер `run_example` и экспорт рисунков `figure_io` переходят в пакет. Примеры становятся конфигом, README и собственными скриптами конкретного примера там, где они есть (сходимость, асимптота 02, наложение $T$ в 03 и т. п.).

Решение пользователя 2026-10-10 — модель запуска «Б». Модель «скопировать папку примера и править» отклонена: она размножает код конвейера по отделам заказчика, и исправления (как BUG-020, BUG-022) до копий не доходят. Внутри репозитория с копиями уже боролись DEBT-037 и DEBT-046.

## Мотивация

- **Фаза:** поставка заказчику. Порядок: DEBT-059 (влит) → DEBT-011 (реализуется) → **FEAT-030** → FEAT-031 (комплект поставки).
- Сейчас посчитать свой сценарий со штатными рисунками и проверками можно только изнутри репозитория: `main.py` примера вставляет `examples/` в `sys.path`, конвейер импортирует соседние модули по плоскому имени (`from relperm_plot import ...`). В дистрибутив `examples/` не входит (`pyproject.toml:28-30`, `include = ["gpn_multiphase_solver*"]`).
- У пакета нет точки входа: ни `__main__.py`, ни `[project.scripts]`.
- FEAT-031 (приёмочная проверка в чистом окружении: «расчёт примера из постороннего каталога → совпадение с эталонным выводом») без команды не формулируется.

## Физическое/математическое обоснование

Новых формул нет. Команда воспроизводит существующие проверки; физика входит в задачу через **условия их применимости**, которые сейчас решает автор `main.py`, а в команде придётся решать по конфигу или по результату:

| проверка | предел / условие | кто сейчас отключает |
|---|---|---|
| замкнутое решение $p(r)$, $S_g(r)$ (`closed_form`) | $t \to \infty$ при одном режиме скважины, замыкание GOR = $R_{s,0}$ | `steady_state=False`: 13b, 14, 16, 17, 18, 19, 20, 21; наложения `{"Sg": None}` — 13a, `{"p": None, "Sg": None}` — 15 |
| асимптотика $T = T_{ext} + \mu_{JT,o}(p - p_{ext})$ | однофазная зона, $t \to \infty$ | тот же флаг |
| $R_s = \min(R_{s,eq}(p), R_{s,0})$ | любой сценарий с газом | не отключается |
| балансы энергии и массы | всегда | не отключаются |

Отключение — по **результату**, а не только по конфигу. Пример 14 — один режим скважины, но GOR = 149.2 < $R_{s,0}$ = 150 (отличие 0.5 %), а численная $S_g$ = 0.091 в ячейке у фронта меньше $S_{gc}$ = 0.1, которого требует замыкание. Пример 19 — один режим, GOR = 128.7 < 150 и растёт. Автоматический критерий «GOR близок к $R_{s,0}$» на 14 ошибся бы. Это главный открытый вопрос проектирования (вариант 2 ниже).

## Предлагаемый API

Эскиз, уточняется при планировании:

```python
# gpn_multiphase_solver/<модуль конвейера>.py
def run_case(config_path, output_dir, *, title=None, n_profiles=None,
             steady_state=..., overlays=None, emf=False) -> CaseResult: ...

@dataclass
class CaseResult:
    elapsed: float
    simulator: Simulator      # тот, что считал задачу: main.py 01–05 больше
    history: SimulationHistory  # не собирают второй Simulator ради PVT
    grid: Grid
    config: SimulationConfig

# gpn_multiphase_solver/cli.py
def main(argv=None) -> int: ...   # коды возврата: 0 — успех, 2 — ошибка конфига/аргументов, 1 — отказ расчёта
```

```
python -m gpn_multiphase_solver run config.json --output out/ [--title ...] [--profiles N] [--emf]
```

Протокол наложений `(ax, history, grid, simulator)` становится публичным: им пользуется 03 (наложение $T$), и он нужен заказчику для своих кривых.

## Анализ вариантов решения

### 1. Форма команды

- **А. `python -m gpn_multiphase_solver run …`** (`__main__.py`). Работает тем интерпретатором, в который установлен пакет, без `PATH`. Длиннее.
- **Б. Команда в `[project.scripts]`** (`gpn-solver run …`). Коротко, но на Windows без активированного venv `gpn-solver.exe` не найдётся — частая ошибка у неразработчиков.
- **Рекомендация:** обе, одна функция `cli.main(argv)`; в инструкциях FEAT-031 — форма А как основная.

### 2. Где живут параметры примера: заголовок, число профилей, стационарная аналитика

- **А. Новые поля секции `output` конфига** (`title`, `n_profiles`, `steady_state`). Пример = конфиг + README, команда воспроизводит его без флагов; тип и значения проверяет `_validate` (DEBT-051). Минус: параметры оформления в конфиге расчёта; меняются 23 конфига.
- **Б. Аргументы командной строки.** Конфиги не меняются, но пример больше не воспроизводится «голой» командой — нужен `main.py` или строка в README с флагами, которая расходится с ним молча.
- **В. Автоматический выбор стационарной аналитики по результату** (один режим и GOR ≈ $R_{s,0}$). На примере 14 ошибся бы (см. «обоснование»); неверно включённое наложение выглядит как ошибка решателя.
- **Рекомендация:** А + переопределение флагами Б. Значение `steady_state` по умолчанию для чужих сценариев — решение пользователя: `true` (как сейчас) показывает замкнутое решение там, где стационар не достигнут; `false` прячет проверку, которая на 01–12 работает.

### 3. Своя логика примеров (01, 02, 03, 04, 05, 18)

- **А.** Публичная функция `run_case` с наложениями и `CaseResult`; `main.py` этих примеров — её вызов плюс своя часть. Команда — тонкая обёртка над той же функцией. Снимает второй `Simulator` в 01–05.
- **Б.** Перенести своё в команду флагами. Раздувает команду под шесть демонстраций.
- **Рекомендация:** А. Судьба 15 тривиальных `main.py` (удалить или оставить однострочником) — при планировании; от неё зависит тест структуры `test_examples.py:153`.

### 4. Каталог вывода

`run_example` удаляет `output_dir` целиком (`shutil.rmtree`) — чтобы не оставались рисунки прошлых прогонов (например `rs_profiles.png` после перехода примера на однофазный режим). С путём пользователя это опасно: `--output .` или `--output D:\Расчёты` уничтожит чужие файлы.

- **А.** Удалять только файлы, которые команда сама пишет (известный список + `emf/`). Устаревший `rs_profiles.png` удалится, чужое — нет.
- **Б.** Метка каталога (файл-признак): очищать только каталог с меткой прошлого прогона; непустой каталог без метки — отказ с сообщением, `--overwrite` — явно.
- **В.** Каждый раз новый подкаталог с меткой времени. Безопасно, но ломает сравнение с эталоном FEAT-031 и `examples/*/output/`.
- **Рекомендация:** Б (возможно, вместе с А).

### 5. EMF

Сейчас включён по умолчанию (`GPN_EXAMPLES_EMF` ≠ "0"); без Inkscape — сообщение, SVG остаются. Поведение на машине без Inkscape не проверено. Для команды: выключен по умолчанию, флаг `--emf` — или как сейчас. Решение пользователя.
