## Описание

Новый пример `numerical_solver/examples/12_<имя>/` — повтор примера 11 (`11_degassing_at_boundary`) на области дренирования в 4 раза больше. Меняются ровно два параметра конфига:

| Параметр | Пример 11 | Пример 12 |
|---|---|---|
| `geometry.R_ext` | 50 м | **200 м** |
| `initial_conditions.p0` (оно же давление на контуре) | 15.05 МПа | **15.5 МПа** |

Остальное совпадает: `grid.N = 50`, табличные PVT и ОФП, $p_{wf} = 6$ МПа, 72 × 3600 с. **Пример 11 не меняется.**

## Мотивация

Показать, как размер области дренирования влияет на дебит, температуру на забое и газонасыщенность при прочих равных. Такого сравнения в наборе примеров нет: все 12 сценариев считаются при $R_{ext} = 50$ м.

Режим «фронт разгазирования в последней ячейке», ради которого создан пример 11 (DEBT-009), здесь **намеренно исключён** запасом по давлению — см. следующий раздел.

Фаза roadmap: примеры и демонстрация.

## Физическое обоснование

### Почему в примере 11 «разгазирование у контура» — сеточный эффект

Давление на контуре задано на **грани** $r = R_{ext}$ (`eq:bc_p_ext`, `problem_statement.tex:656`), а неизвестные решателя — в **центрах** ячеек. В непрерывной задаче на контуре $p = p_0 > p_b$, нефть недонасыщена, и `eq:bc_Sg_ext` ($S_g = 0$, $R_s = R_s^0$) с этим согласовано.

В примере 11 фронт $p = p_b$ лежит при $r_b \approx 47.8$ м — внутри последней ячейки (44.16–50 м), а её центр 47.11 м оказывается по двухфазную сторону: перепад на полуячейке 68 кПа больше запаса $p_0 - p_b = 50$ кПа. Сгущение сетки (R = 50 м, 72 ч):

| N | центр $r_{N-1}$, м | $p_{ext} - p_{N-1}$, кПа | $p_{N-1} - p_b$, кПа | $S_{g,N-1}$ |
|---|---|---|---|---|
| 50 | 47.11 | 68.0 | −18.0 | $5.3\cdot10^{-6}$ |
| 60 | 47.56 | 56.5 | −6.5 | 0 |
| 70 | 47.89 | 48.4 | +1.6 | 0 |
| 100 | 48.50 | 33.8 | +16.2 | 0 |

$p_{ext} - p_{N-1} \propto 1/N$; при $N \ge 70$ последняя ячейка однофазна, фронт стоит на месте.

### Почему поднято $p_0$

При $R = 200$ м и $p_0 = 15.05$ МПа попадание контурной ячейки в двухфазное состояние решается сеткой, а не размером области: при $N = 50$ — с 62 ч, при $N = 61$ (тот же $\Delta\ln r$, что в 11) — с 84 ч. Сравнение 11 ↔ 12 смешало бы эффект $R$ с эффектом разрешения фронта. Запас $p_0 - p_b = 0.5$ МПа в ~6 раз больше перепада на полуячейке и исключает это.

### Почему $N = 50$

Число ячеек совпадает с примером 11. Шаг у забоя грубее на 24 % (0.0164 против 0.0132 м), но влияние на забойные величины измерено и мало (R = 200 м, $p_0$ = 15.05 МПа, N = 50 против 61): $q_o$ — 0.1 %, $T_w$ — 6 мК.

### Ожидаемый результат

Прогон в памяти, 72 ч, $N = 50$ (2026-09-25):

| | Контроль: R = 50 м, $p_0$ = 15.5 МПа | **Пример 12:** R = 200 м, $p_0$ = 15.5 МПа |
|---|---|---|
| сходимость / время счёта | да / 40 с | да / 15 с |
| $\min p_{N-1} - p_b$ | +419 кПа | +426 кПа |
| $\max S_{g,N-1}$ | 0 | 0 |
| $\max\lvert R_{s,N-1} - R_s^0\rvert$ | $6.0\cdot10^{-14}$ | $2.8\cdot10^{-14}$ |
| внешняя граница зоны $S_g > 0$ | 28.7 м | 117.9 м |
| $q_o$ (24 / 48 / 72 ч), $10^{-3}$ м³ст/с | 3.9386 / 4.0477 / 4.0398 | 3.2352 / 3.1271 / 3.0916 |
| $T(r_w)$, 72 ч | 345.069 К | 345.936 К |
| $S_g(r_w)$, 72 ч | 0.0192 | 0.0433 |

Эффект размера области при равном $p_0$: $q_o$ −23.5 %, $T_w$ +0.87 К, $S_g(r_w)$ ×2.3.

### Нестационарность — оговорка для README

При R = 200 м к 72 ч процесс не установился: $q_o$ за третьи сутки −1.1 %, зона $S_g > 0$ занимает 118 м из 200. Стационарные наложения `make_overlay_pressure` / `make_overlay_saturation` (замыкание GOR = $R_s^0$), которые `example_runner` рисует всем двухфазным примерам, разойдутся с расчётом — README обязан это объяснить. Длительность остаётся 72 ч, выход на стационар не добиваемся.

Новых формул нет: `numerical_solver/doc/problem_statement.tex`, `eq:bc_p_ext`, `eq:bc_Sg_ext`.

Код библиотеки не меняется. Новая папка примера:

```
examples/12_<имя>/
├── config.json      # копия 11 с R_ext = 200, p0 = 15.5e6

├── gas_pvt.csv
├── relperm.csv
```

`check_boundary_upstream.py` не переносится: дефекту DEBT-009 на этом сценарии нечего показать ($\lvert\Delta R_s\rvert \sim 10^{-14}$, как в примере 10).

## Анализ вариантов решения

**1. PVT/ОФП: копии CSV или ссылка на файлы примера 11.**
- Копии (прецедент 04a): каждая папка самодостаточна, как обещает `examples/README.md`. Минус — три дубликата.
- Относительный путь `../11_degassing_at_boundary/*.csv`: без дублей, но пример перестаёт быть самодостаточным, правка 11 молча меняет 12.
- **Рекомендация:** копии.

**2. Тест «11 и 12 отличаются ровно двумя полями».**
- Отдельная функция с копией `flatten`: не трогает существующий тест, но дублирует код.
- Вынести `flatten` в хелпер модуля и параметризовать пары `(01, 02, {mu_JT_oil})`, `(11, 12, {R_ext, p0})`: без дублей, но правка существующего теста.
- **Рекомендация:** параметризация — решить на `/plan-feature`.

**3. Контрольный вариант (R = 50 м, $p_0$ = 15.5 МПа).**
- Только числа в README: минимум кода, но числа невоспроизводимы одной командой.
- Скрипт в папке примера (по образцу `check_boundary_upstream.py` у 11): прогоняет 12 и контроль (конфиг 12 с `R_ext = 50` в памяти), печатает таблицу сравнения. +40 с на контрольный прогон.
- **Рекомендация:** скрипт — числа README воспроизводимы.

## План реализации

1. **Проектирование:** имя папки (рабочий вариант `12_large_drainage_radius`); решения по вариантам 1–3; объём правки `examples/README.md`.
2. **Реализация:** папка примера — `config.json`, CSV, `main.py`; прогон `main.py`, сверка чисел с таблицей выше.

4. **Документация:** `README.md` примера (сравнение с контролем, оговорка о нестационарности, разделы «Как модифицировать» и «Как увеличить газонасыщенность», классы модулей); `examples/README.md`.
5. **Верификация:** полный прогон тестов; баланс энергии примера 12 в пределах порога.
