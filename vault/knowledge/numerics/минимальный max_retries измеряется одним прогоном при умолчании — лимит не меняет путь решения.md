# Минимальный `max_retries` измеряется одним прогоном при умолчании — лимит не меняет путь решения

**Метод.** Адаптер (`PrototypeHydroAdapter.solve`) при отказе Newton повторяет шаг с $2^a$ равными подшагами, $a = 0, 1, \dots, $ `max_retries`. Первая сошедшаяся попытка от лимита не зависит. Поэтому при лимите $m$ прогон идёт побитно как при умолчании 9, пока какому-то вызову не понадобится $a > m$; на этом вызове — `RuntimeError`. Минимально достаточный лимит для всего расчёта:

$$k = \max_{\text{вызовы hydro.solve}} \log_2 n_{substeps}.$$

Учитывать нужно **все** вызовы, а не только первый шаг: после дробления симулятор проходит интервал заново подшагами (BUG-010, `simulator.py:229-242`), и каждый такой вызов может дробиться сам с тем же лимитом. Контроль: при $k - 1$ прогон падает, при $k$ конечное $p$ побитно совпадает с умолчанием. Так было во всех проверенных точках.

**Условие.** $k$ зависит от шага первого вызова, то есть от `time.dt_integration`. Таблицы README 03 и 04 сняты при 3600 с, и это теперь написано рядом с числами.

**Замер** (DEBT-041, `299d6a7`, BUG-020 влит; `vault/issues/debt-041/probes/`):

| пример | точка | $k$ | где дробится |
|---|---|---|---|
| 03, $N = 150$ | $p_{wf}$ = 8…5 МПа | 0 | нигде |
| 03 | 4 / 2 / 0.5 МПа | 1 / 4 / 3 | только первый шаг |
| 03, 8 МПа | $N$ = 50…200 | 0 | нигде |
| 04, $N = 50$ | 14 … 0.5 МПа | максимум 5 (12 МПа), при 0.5 МПа — 0 | только первый шаг |
| 04a | $N$ = 80…500 | 0 | нигде (первый шаг) |
| 05 | 8…2 МПа | 0 | нигде |

**Что изменила четвёртая ступень `advance` (BUG-020).** Ступень — запасной путь BUG-014 с Ньютоном, переключающим набор фаз после каждой итерации. Она вызывается только после отказа первых трёх и снимает часть дробления первого шага при глубокой депрессии. Выключение ступени возвращает ровно прежние числа README (`audit4_stage4_off.txt`):

| точка | без ступени 4 | со ступенью 4 |
|---|---|---|
| 03, 0.5 МПа | 16 подшагов | 8 |
| 04a, $N$ = 300 / 500 | 2 / 8 | 1 / 1 |
| 05, 5 МПа | 2 | 1 |

Записи «без дробления» ступень 4 изменить не может: где первые три ступени сходятся, она не вызывается.

**Умолчание 9** — запас, а не порог: сценарии, где 9 удвоений были нужны (03 при $N = 75$, 6 МПа — до BUG-014; 04a при $N = 80$ — до BUG-016), теперь не дробятся. Обоснование — комментарий `NumericsConfig.max_retries`.

**Скрипты.** `max_retries_probe.py` — пример 03 с контролем $k-1$/$k$; `audit_claims.py` — пример 04 и сценарии из комментария; `audit4_other_readmes.py` — примеры 04a и 05. Запуск из `numerical_solver` того дерева, чей код меряется: скрипты берут пакет из `Path.cwd()` и печатают пути пакета и прототипа.
