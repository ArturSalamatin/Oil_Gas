# Реализация плана

Принимай ID задачи или путь плана. `/implement` разрешает предусмотренные ниже коммиты, но не push и не слияние. Работай по плану и правилам `AGENTS.md`. Сначала прочитай `.agents/project/overview.md` для команд и их побочных действий. Порядок Git и проверок – [references/worktree.md](references/worktree.md).

## Предусловия

1. Найди план и задачу, установи ID, базовую ветку, ветку задачи, issue и worktree. Для `numerical_solver` база – `numerical_scheme/implementation`. Проверь наличие каталога решателя в дереве базы. Не используй `master` как базу решателя. Прочитай относящиеся к плану материалы и решения, включая `00-draft.md` при наличии.
2. Проверь обязательный аудит: последний полный отчёт относится к текущим байтам плана по SHA-256, обязательные проверки выполнены, блокирующие находки устранены и перепроверены. Сверь отчёт и фактический файл до изменения статуса плана. При отсутствии хеша у старого отчёта или изменении содержательного плана сначала выполни актуальный `audit-plan`. Условные ограничения оцени по отчёту, не скрывай их.
3. Проверь состояние основного каталога, индекс, ветку, зарегистрированные worktree и перекрытие файлов с другими сессиями. Сохраняй чужие изменения. Если ветка или worktree уже существуют, установи, относится ли это к возобновлению задачи. Не создавай дубль и не затирай работу.

## Работа

1. В базовой ветке предварительно закоммить подготовленные материалы текущей задачи и предусмотренные общие файлы vault по явным путям. Реестры и `vault/00-home/index.md` коммить целиком по правилам проекта. Чужой незакоммиченный черновик не включай автоматически и не останавливай коммит реестра только из-за ссылки на него.
2. Создай `.worktrees/<id-lowercase>` от проверенной базы с веткой задачи и проверь наличие предварительного коммита и материалов. Работай в этом worktree. До окончания шагов не изменяй проверенные байты плана только ради статуса: состояние работы фиксируй в реестре или отдельной заметке. Для возобновления прочитай состояние ветки и план из существующего worktree.
3. До правок выполни исходную проверку по плану на этом дереве. Для решателя соблюдай быстрый уровень после шагов и полный в конце по `AGENTS.md`. Для прототипа добавь его отдельные тесты. Для инструментов и документов проверяй затронутый инструмент и тексты. Запиши команды и результаты.
4. Выполняй шаги последовательно: сверяй контекст, вноси правки, запускай предусмотренные проверки, записывай результат. Не подменяй ожидаемый результат фактическим без обоснования. При регрессии выясни причину и исправь её. Не коммить сломанное состояние как завершённое.
5. Коммить связанные изменения на ветке задачи по явным путям, не захватывая заранее добавленные файлы других сессий. Vault коммить отдельно от кода. Новые проблемы регистрируй локально через `draft` в базовом vault и фиксируй предусмотренным отдельным коммитом базы по правилам проекта. Issue автоматически не создавай.
6. Выполни итоговые проверки и критерии плана, обнови документацию и журнал изменений по области задачи. В плане и реестре укажи фактические результаты и состояние «реализовано, не влито». Сохрани `vault/issues/<id-lowercase>/05-comment-done.md` в worktree, закоммить vault и опубликуй комментарий при наличии issue по процессу задачи.
7. Сообщи ветку, путь worktree, коммиты, проверки и ограничения. Слияние – только по отдельному запросу `/merge` или «мерж».
