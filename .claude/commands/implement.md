# Реализация плана из vault

Пользователь указал план: `$ARGUMENTS`

Формат аргумента: `FEAT-NNN`, `BUG-NNN`, `VAL-NNN` или имя файла плана.

## Инструкции

### Фаза 1: Загрузка

- Найди план в `vault/plans/`. Прочитай.
- Если плана нет — предложи создать через `/plan-feature`, `/plan-fix` или `/plan-validate`.
- Проверь зависимости: все ли предшествующие FEAT готовы?

### Фаза 2: Baseline

- Запусти полный набор тестов:
  ```powershell
  cd d:\Lessons\Grants\2026\GPN\Oil_Gas\method_of_moments
  python -m pytest tests/ -v
  ```
- Запомни количество pass/fail. Это baseline для проверки регрессий.

### Фаза 3: Реализация

Для каждого шага плана:
1. Прочитай формулу из `.tex` (offset + limit по нужной секции).
2. Реализуй функцию. Docstring — одна строка + ссылка на уравнение:
   ```python
   def compute_Cp(p, T, Sg, fluid, rock):
       """Коэффициент ёмкости C_p. Ур. (eq:Cp) moments_method.tex."""
   ```
3. Напиши тест **до** или **сразу после** реализации.
4. Запусти тест: `python -m pytest tests/test_module.py::test_name -v`.
5. Если падает — исправь. Не двигайся дальше, пока тест не проходит.

### Фаза 4: Полная проверка

- Запусти все тесты: `python -m pytest tests/ -v`.
- Сравни с baseline. Новых падений быть не должно.
- Если есть регрессии — исправь до завершения.

### Фаза 5: Обновление vault

- Обнови статус в roadmap: ✅ ГОТОВО + дата.
- Обнови план: `status: реализован`.
- Если в процессе обнаружены баги или открытые вопросы — создай записи BUG/DEBT.
- Если реализация выявила расхождение с формулой из `.tex` — создай карточку в `vault/knowledge/science/` через `/card`.

### Ограничения

- Не трогай `.tex` файлы — только Python.
- Не меняй интерфейсы уже реализованных модулей без обсуждения.
- Один FEAT/BUG за вызов. Не объединяй несколько задач.
