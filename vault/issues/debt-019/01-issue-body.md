## Описание

Забойная грань `f = 0` обработана в предположении, что поток всегда направлен **к скважине**. Предположение нигде не проверяется и не документируется как ограничение. При $p_{wf} > p_0$ (закачка либо численный переброс на переходном шаге) втекающая энергия учитывается при температуре **нуль кельвинов**, а свойства флюида берутся из пласта вместо закачиваемого.

Дефект **латентный**: на всех штатных конфигах $\mathcal{Q}_\alpha[0] < 0$, эффект тождественно нулевой. Опасность — в отсутствии диагностики: NaN не возникает, итерации сходятся, поле $T$ просто оказывается искажённым.

Решение пользователя (2026-09-19): **вариант 1** — зафиксировать ограничение валидацией, физику закачки не реализовывать.

## Текущее состояние

**1. Выбор ячейки выше по потоку жёстко зафиксирован** (`energy/tridiag.py:225-227`):

```python
# Забой (f=0): upstream = ячейка 0
Phi_o[0] = rho_o[0] * c_p_o[0] * Q_o[0]
Phi_g[0] = rho_g[0] * c_p_g[0] * Q_g[0]
```

Знак $\mathcal{Q}_\alpha[0]$ не разбирается — в отличие от внутренних граней, где upstream выбирается по знаку потока.

**2. Асимметрия матрицы.** В диагональ строки $j = 0$ входит член $\Phi^+_0$ (`energy/tridiag.py:426-427`):

```python
b[0] = (cap[0] + Q_T_R0
        + Phi_plus[1] - Phi_minus[0] + Phi_plus[0])
d[0] = cap[0] * T_old[0] + J_jt[0] + V[0] * (Q_ad[0] + Q_deg[0])
```

Симметричного вклада в правую часть **нет**. Поток через забойную грань есть $E_0 = \Phi^+_0 T_{-1} + \Phi^-_0 T_0$, где $T_{-1}$ — температура среды за гранью (ствол скважины). Фиктивной ячейки нет, код фактически подставляет $T_{-1} = 0$, сохранив коэффициент $\Phi^+_0$ в матрице.

Сравнение с контуром показывает асимметрию прямо — там втекающий вклад выписан явно (`energy/tridiag.py:439`):

```python
+ (-Phi_minus[N]) * T_ext
```

На забое аналога $(-\Phi^+_0)\,T_{wf}$ не существует.

**3. Когда срабатывает.** Знак потока на забое определяется единственной величиной $\Delta p_w = p_{wf} - p[0]$ (`fluxes.py:105-116`): обе фазы считаются через один перепад и подвижности $\lambda_\alpha \geqslant 0$ из одной ячейки 0, поэтому $\mathcal{Q}_o[0]$ и $\mathcal{Q}_g[0]$ **всегда одного знака** — противоток на этой грани структурно невозможен.

| Режим | $\Delta p_w$ | $\Phi^+_0$ | Результат |
|---|---|---|---|
| Добыча (штатный) | $< 0$ | $\equiv 0$ | **Правильный.** Член `+ Phi_plus[0]` — тождественный ноль, выбор ячейки 0 как upstream верен |
| Закачка / переброс | $> 0$ | $\neq 0$ | **Молча неверный.** Свойства из пласта вместо закачиваемого флюида + энтальпия при $T = 0$ K |

**4. Ограничения нет нигде.** `PressureControl.__init__` (`bc.py:38-41`) валидирует только `p_wf > 0`:

```python
def __init__(self, p_wf: float):
    if p_wf <= 0:
        raise ValueError(f"p_wf должно быть > 0, получено {p_wf}")
```

Ограничения $p_{wf} < p_0$ нет ни в конфиге, ни в решателе.

**5. Входной величины для варианта 2 нет вообще.** В отличие от DEBT-017 (#34), где всё нужное уже лежало в `BoundaryConditions`, здесь нет данных: `BoundaryConditions` (`state.py:95-106`) несёт `p_ext`, `T_ext`, `Rs_ext`, `Sg_ext` — только для контура; для забоя есть лишь `well: WellControl`, то есть давление либо дебит, без термической характеристики. Поле `WellData.T_wf` (`state.py:90`) не годится: это выходная диагностика, `T_wf = state.T[0]` (`simulator.py:173`, `simulator.py:268`) — температура ячейки 0, а не заданная температура закачки.

**6. Соответствие постановке.** `doc/problem_statement.tex:1421-1423` (`ssec:bc_disc`):

> При $p_0 > \pwf$ потоки отрицательны — направлены к скважине. Подвижности берутся из ячейки $j = 0$ (против потока: поток направлен к скважине).

Постановка предполагает добычной режим ровно так же неявно, как код: $p_0 > p_{wf}$ записано как констатация типичного случая, а не как ограничение применимости. Расхождения кода с постановкой нет — есть общее для обоих неявное предположение.

## Целевое состояние

Неявное предположение «поток через забой направлен к скважине» переведено из подразумеваемого в **явное и проверяемое**: нарушение даёт остановку с диагностикой, а не молча неверное поле $T$. Физика закачки не реализуется.

## Анализ вариантов решения

### Вариант 1 (выбран) — зафиксировать ограничение валидацией

**Суть.** Отказ с диагностикой при $\Delta p_w \geqslant 0$; комментарии, объясняющие, почему жёсткий upstream и непарный $\Phi^+_0$ корректны.

**Изменения.**
1. Проверка знака $\Delta p_w$ в `fluxes.py` рядом со стр. 108 — там, где $\Delta p_w$ уже вычислен. Не в `PressureControl.__init__`: там доступно только $p_{wf}$, а $p[0]$ меняется на каждом шаге. Не в конкретной стратегии управления: проверка должна покрывать `TotalRateControl` и прочие будущие реализации `WellControl`.
2. Комментарий у члена `+ Phi_plus[0]` (`tridiag.py:427`): слагаемое тождественно нулевое в силу гарантированного ограничения; при снятии ограничения требует парного вклада $(-\Phi^+_0)\,T_{wf}^{\text{зак}}$ в `d[0]`.
3. Комментарий у выбора upstream на забое (`tridiag.py:225-227`): жёсткий `upstream = ячейка 0` корректен именно благодаря ограничению из п. 1.
4. Тест: конфиг с $p_{wf} > p_0$ падает с ожидаемым `ValueError` (`pytest.raises`).

**Плюсы.** Малая правка; численный результат не меняется нигде; граница применимости становится явной; член `+ Phi_plus[0]` перестаёт выглядеть случайным, а его нулевое значение на всех конфигах — совпадением.

**Минусы.** Закачка остаётся неподдержанной. Численный переброс на переходном шаге (если он физически допустим и временный) будет обрывать расчёт — при планировании оценить, возможен ли такой переброс в сходящихся итерациях, и не нужен ли допуск по величине $\Delta p_w$ вместо строгого нуля.

### Вариант 2 (отклонён, не закрыт) — поддержать закачку физически

**Суть.** Ввести температуру и состав закачиваемого флюида в контракт ГУ по образцу `T_ext` / `Rs_ext`.

**Изменения.** Расширить `BoundaryConditions`; разобрать знак $\mathcal{Q}_\alpha[0]$ в `compute_convective_coefficients`; добавить в `d[0]` член $(-\Phi^+_0)\,T_{wf}^{\text{зак}}$; согласованно поправить `compute_jt` (`J_face[0]`, `tridiag.py:320-322`) и `compute_degassing` (`R_conv[0]`, `tridiag.py:376-377`).

**Основание отклонения.** Закачка не входит в постановку задачи (ПЗП нефтедобывающей скважины). Если постановка расширится — открывать отдельной записью. Вариант 1 вариант 2 не блокирует, а лишь делает границу применимости явной.

## План решения

**Этап 1. Baseline.**
- Зафиксировать текущее число зелёных тестов и вывод эталонного конфига.
- Проверить, достижимо ли $\Delta p_w \geqslant 0$ на переходном шаге в сходящихся итерациях — от этого зависит, нужен ли допуск вместо строгого нуля.
- Определить точное место проверки: единая точка после вычисления `dp_w`, покрывающая все реализации `WellControl`.

**Этап 2. Реализация.**
- Проверка знака $\Delta p_w$ с `ValueError`: в тексте названы обе величины ($p_{wf}$ и $p[0]$), причина отказа и ссылка на DEBT-019.
- Комментарий у `+ Phi_plus[0]` в `assemble_tridiag`.
- Комментарий у выбора upstream в `compute_convective_coefficients`.
- Опционально: явная формулировка ограничения в `doc/problem_statement.tex` (`ssec:bc_disc`) — сейчас добычной режим там тоже предполагается неявно.

**Этап 3. Верификация.**
- Новый тест: конфиг с $p_{wf} > p_0$ → `pytest.raises(ValueError)`.
- Все существующие тесты зелёные, численный результат не изменился ни на одном примере.
- Регрессий не ожидается: на штатных конфигах вычисления не трогаются.

Отдельного теста на ветку $\mathcal{Q}_\alpha[0] > 0$ в наборе нет и после правки не появится — она эту ветку **запрещает**, а не покрывает. Ср. родственное замечание DEBT-018 о непокрытой ветке `up = f - 1` на внутренних гранях: та ветка остаётся достижимой и теста по-прежнему требует.
