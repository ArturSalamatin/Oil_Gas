## Описание

Эталон сверки матрицы температурной задачи (`tests/test_energy_matrix_examples.py`) неверно считает вклад Джоуля—Томсона на левой грани ячейки. Для внутренней грани $j-1/2$ эталон берёт давление «за гранью» $p_j$ вместо $p_{j-1}$, перепад `dp_left = p[j] - p[j]` тождественно равен нулю, и слагаемое $\mu_{JT}\,\Phi^+_{j-1/2}\,(p_j - p_{j-1})$ из eq:QJT_disc в эталоне пропадает.

Дефект только в тесте: решатель (`TridiagEnergySolver.compute_jt`) считает этот член верно. Но сверка матрицы перестаёт проверять ветку $\Phi^+ > 0$ (течение от скважины через внутреннюю грань: нагнетание, перетоки при останове), а на конфиге примера 18 из плана VAL-005 тест падает.

**Критичность:** блокирует VAL-005 — пример 18 роняет `test_matrix_matches_reference` в полном прогоне.

## Симптомы

- Аудит плана VAL-005 (2026-10-10, копия `vault/issues/val-005/probes/impl/` после `apply_plan.py`):
  `test_matrix_matches_reference[18_prototype_input]` → «вызов 0, dt=60 с, правая часть d: max |d - d_ref| / допуск = nan в ячейке 69».
- В ячейке 68 решатель даёт $d$ = 1.18e-26 Вт, эталон — 0, и сумма модулей слагаемых эталона тоже 0. Допуск $10^{-12}\cdot(|d^{эт}| + \text{масштаб}) = 0$, шум 1e-26 Вт его превышает. На вызове 1 — ячейка 97, 2.95e-27 Вт.
- Синтетика: $N = 4$, $p$ = 10, 20, 30, 40, $\Phi^+$ = 2 на всех внутренних гранях, $\mu_{JT}$ = 0.5. Эталон даёт $J$ = [0, 0, 0, 0], по eq:QJT_disc должно быть [0, 10, 10, 10].

## Корневая причина

`_ref_jt` обрабатывает обе грани ячейки $j$ одной функцией `_ref_jt_face(f, …)`:

```python
p_left,  mu_o_l, mu_g_l = _ref_jt_face(j,     …)   # левая грань j-1/2
p_right, mu_o_r, mu_g_r = _ref_jt_face(j + 1, …)   # правая грань j+1/2
dp_left  = p[j] - p_left
dp_right = p_right - p[j]
```

Для внутренней грани $0 < f < N$ функция возвращает `p[f]` — давление ячейки справа от грани (docstring: «со стороны, противоположной ячейке-владельцу», владелец — ячейка $f-1$). Для правой грани ячейки $j$ ($f = j+1$) это $p_{j+1}$ — верно. Для левой ($f = j$) — $p_j$, а нужно $p_{j-1}$. На забое ($f = 0$, `p_wf`) и контуре ($f = N$, `p_ext`) ошибки нет: там значение за гранью одно.

Решатель строит два массива: `p_left = concat([p_wf], p)`, `p_right = concat(p, [p_ext])`. Для левой грани ячейки $j$ он берёт `p_left[j]` $= p_{j-1}$ (`tridiag.py:389-390, 423`).

**Почему не проявлялось.** На всех 22 примерах $Q_\alpha < 0$ на внутренних гранях, $\Phi^+ \equiv 0$, и потерянное слагаемое умножается на ноль. Docstring `_ref_convective` это прямо фиксирует (`:184-185`). У примера 18 ($k$ = 1 мД, $c_r$ = 4.5e-5 1/бар) на фронте волны давления расход нефти через грань — шум Ньютона +2.5e-18 м³/с (от скважины). Значит, $\Phi^+ > 0$, а $p_{j-1}$ уже чуть ниже $p_j = p_0$. Физически вклад нулевой (1e-26 Вт), но ветка $\Phi^+$ впервые включается в сверке.

**Пробел покрытия.** Ветку $\Phi^+ > 0$ на внутренних гранях в `compute_jt` независимо не проверяет ни один тест. `test_energy.py:1288` (однородное $p$) от ветки не зависит: перепады нулевые. Тест `:1419` проверяет только забойную грань. Тест `:1326` проверяет сборку $a, b, c$, а не JT-вклад.

## Анализ вариантов решения

### Вариант 1 — точечная правка в `_ref_jt`

- **Суть:** в цикле `_ref_jt` для левой грани при $j > 0$ брать `p[j - 1]`, `_ref_jt_face` оставить как есть.
- **Изменения:** `test_energy_matrix_examples.py:399` — одна строка.
- **Плюсы:** минимальная правка.
- **Минусы:** `_ref_jt_face` по-прежнему возвращает «давление за гранью» относительно неявного владельца $f-1$: из-за этой двусмысленности ошибка и возникла. Для забоя и внутренних граней левый перепад считается по-разному, единой обработки граней, о которой говорит комментарий `:389-391`, нет.

### Вариант 2 — давления по обе стороны грани (рекомендуется)

- **Суть:** `_ref_jt_face` возвращает пару $(p^{слева}, p^{справа})$: $(p_{wf}, p_0)$ на забое, $(p_{f-1}, p_f)$ на внутренней грани, $(p_{N-1}, p_{ext})$ на контуре. `_ref_jt` для обеих граней берёт $\Delta p_f = p^{справа} - p^{слева}$.
- **Изменения:** `test_energy_matrix_examples.py:320-344` (возврат и docstring), `:392-400` (распаковка и перепады).
- **Плюсы:** перепад — свойство грани, а не пары «ячейка + грань»: это и есть $\Delta p_{j\mp1/2}$ из eq:QJT_disc. Все три типа граней обрабатываются одинаково. Эталон остаётся независимым от решателя: цикл по граням, без копии векторной записи `compute_jt`. Проверен при аудите VAL-005 (`audit_bug023_fix.py`): синтетика даёт [0, 10, 10, 10], на копии с примером 18 — 25 passed (`audit_bug023_matrix.out.txt`).
- **Минусы:** меняется контракт вспомогательной функции. Вызывает её только `_ref_jt` (grep по `*.py` проекта). Сигнатура и результат `_ref_jt` не меняются, поэтому пробы, которые его импортируют (`val-005/probes/audit_matrix_d.py`, `debt-043/probes/audit3_planned_tests.py`), не затрагиваются.

### Вариант 3 — модульный тест эталона на синтетике (дополнение к 1 или 2)

- **Суть:** тест `_ref_jt` на данных с $\Phi^+ > 0$ на внутренних гранях. Ожидание задаётся двумя способами:
  - значениями, посчитанными вручную по eq:QJT_disc ([0, 10, 10, 10] — не через другую реализацию);
  - совпадением с `TridiagEnergySolver.compute_jt` на тех же данных.
- **Изменения:** новый тест (в `test_energy_matrix_examples.py` или `test_energy.py`, решить при планировании), быстрый уровень, без метки `slow`.
- **Плюсы:** закрывает пробел покрытия ветки $\Phi^+$ сразу для эталона и решателя. Сейчас ошибка эталона ловится только случайно, через шум Ньютона на одном конфиге. Ручные значения не дают двум реализациям ошибиться одинаково.
- **Минусы:** нет.

### Вариант 4 — диагностика сверки $d$ при нулевом допуске (дополнение, решить при планировании)

- **Суть:** при `d_lim = 0` отношение `d_err / d_lim` даёт `inf` (ячейка 68) и `nan` (0/0, ячейка 69). `np.max` возвращает `nan`, `np.argmax` указывает на первый `nan`, и сообщение называет не ту ячейку. Печатать первую ячейку с `d_err > d_lim` и сами `d`, `d_ref`, `d_lim`.
- **Изменения:** `test_energy_matrix_examples.py:727-729`.
- **Плюсы:** следующий такой отказ сразу укажет ячейку и величины, без отдельной пробы.
- **Минусы:** правка вне корневой причины, расширяет задачу.

### Отклонено — нижний порог допуска (`atol`) в сверке $d$

С порогом вроде `atol = 1e-20` Вт тест на примере 18 прошёл бы, но потерянное слагаемое в эталоне осталось бы. Это маскировка дефекта: сверка продолжала бы пропускать ошибки решателя в ветке $\Phi^+$ любого масштаба ниже порога.

**Рекомендация:** вариант 2 + вариант 3. Вариант 4 — по решению при планировании. Вместе с правкой обновить docstring `_ref_convective` (`:184-185`) и `_ref_jt_face` (`:321-336`).

## План решения

1. **Минимальный фикс.** Вариант 2: `_ref_jt_face` возвращает давления по обе стороны грани, `_ref_jt` берёт $\Delta p = p^{справа} - p^{слева}$. Красное состояние до правки — синтетика [0, 0, 0, 0].
2. **Архитектурное исправление.** Вариант 3: модульный тест эталона и `compute_jt` на синтетике с $\Phi^+ > 0$ (ручные значения + совпадение с решателем). Docstring `_ref_convective`, `_ref_jt_face`. Вариант 4 — если принят.
3. **Верификация.**
   - Быстрый уровень (`-m "not slow"`): новый тест зелёный.
   - Полный прогон: `test_matrix_matches_reference` на 22 штатных примерах не меняется ($\Phi^+ \equiv 0$, левый вклад нулевой в обоих вариантах).
   - Пример 18 — в рамках VAL-005 после влития этой задачи; на копии аудита уже 25 passed.
