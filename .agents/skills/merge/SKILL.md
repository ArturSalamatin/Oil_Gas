# Влитие задачи

Запускай только по `/merge <ID>` или слову «мерж» после реализации задачи в текущей сессии. Вызов включает предусмотренные коммиты и два push. Не используй `--force`, не удаляй ветку задачи и не уничтожай незакоммиченные данные. Перед реализацией шагов прочитай [references/checks.md](references/checks.md).

## Подготовка

1. Найди план в worktree задачи или основном каталоге, определи ID, базу, ветку, issue и worktree. Установи, что задача реализована и не влита. Для решателя база – `numerical_scheme/implementation`. Не подменяй её `master` или `main`.
2. Проверь состояние основного каталога и индекса, чистоту worktree, ветку и пересечение изменений с незакоммиченными и неотслеживаемыми файлами. Сохрани чужую работу. Предусмотренные общие реестры и `vault/00-home/index.md` при пересечении коммить целиком по правилам проекта. Чужой черновик автоматически не добавляй и не считай его отсутствие препятствием для коммита реестра.
3. Проверь, что результаты и пробы, нужные после задачи, сохранены. Игнорируемые файлы не считаются закоммиченными. Определи изменения базы после ветвления и необходимые проверки итогового дерева, включая влияющие конфигурации, тесты и прототип.
4. Сообщи ветку, базу, точку ветвления, состав общих файлов и необходимые проверки.

## Слияние

1. Выполни `git push -u origin <branch>` без `--force`, затем `git merge --no-ff --no-edit <branch>` в основном каталоге на базе. Сохрани хеш мержа и его первого родителя.
2. Разрешай конфликты по правилам проекта, сохраняя данные обеих сторон. Для конфликта с неоднозначным содержанием или чужими правками не выполняй разрушительные действия. Не объявляй незавершённый мерж успешным.
3. Если база после ветвления изменилась в затронутых областях или зависимостях, проверь итоговое дерево мержа в изолированном worktree с нужными тестами. Для прототипа учитывай его отдельные проверки. Не отправляй базу при непрошедшей обязательной проверке.
4. Проверь чистоту worktree и сохранность нужных результатов. Перед удалением проверь абсолютный путь внутри проекта и выйди из каталога worktree. Удали worktree средствами Git без `--force`, сохрани ветку. Не удаляй незакоммиченные материалы.
5. Отметь хеш, дату и результаты в плане и реестре, при необходимости обнови индекс vault. Закоммить изменения vault отдельно по явным путям. Покажи список коммитов, которые попадут на сервер, и выполни `git push origin <base>` без `--force`.
6. После успешной отправки базы закрой issue при наличии и сообщи пользователю хеш мержа, проверки, состояние worktree, сохранённую ветку и результат двух push.
