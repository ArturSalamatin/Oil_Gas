# Отказ Ньютона только по условию ячейки выглядел обычным — отчёт называет допуск, меру и причину выхода

## Что было

После [[BUG-022]] решение Ньютона прототипа принимается при двух условиях:
- **абсолютном** $\|F\|_\infty \le$ `atol + rtol·max(‖F₀‖∞, 1e-9)`;
- **по ячейке** $\max_c |F_{c,i}|\,\Delta t/V_{p,i} \le$ `numerics.newton_cell_tol` (1e-8).

Отказ «только по условию ячейки» отчёт `BlackOilNewtonReport` показывал как любой другой. Пример — первые сутки сценария BUG-018 при $N$ = 350: «итераций 4, невязка 6.51e-15». Невязка была на 8 порядков ниже допуска 5.4e-7, но ни допуска, ни меры ячеек, ни причины выхода в отчёте не было. Причина выхода там — линейный поиск, вставший на пределе округления.

Отказ ступени 4 писал `iterations = max_iter` (40) и при досрочном обрыве ([[DEBT-061]]).

## Что стало

Отчёт несёт три новых поля:
- `residual_tol` — допуск абсолютного условия;
- `cell_measure` — мера условия по ячейке на той же невязке, что `residual_inf`;
- `exit_reason` — `converged`, `line_search`, `linear_solver`, `max_iter`, `nonfinite`, `active_set`, `sg_bound`, `branch`.

Поля заполняются во всех точках возврата обоих Ньютонов. Подмена [[DEBT-030]] переносит их вместе с прочими полями ступени 1.

Адаптер печатает прежний текст и хвост: допуск, меру с порогом `numerics.newton_cell_tol`, причину выхода, какое условие не выполнено и чьи это числа. «Какое условие не выполнено» — те же сравнения, что в Ньютоне, то есть факт, а не догадка. `Simulator` дописывает этот текст в конец своего `RuntimeError`.

```
advance не сошёлся: dt = 8.640e+04 с, t = 0.0000 сут, итераций 4, невязка 6.51e-15 (допуск 5.35e-07), мера ячеек 2.60e-08 (порог numerics.newton_cell_tol = 1e-08), выход: линейный поиск не принял ни одной точки — не выполнено только условие по ячейке; числа — Ньютона ступени 1
```

## Метрики

Перепись отказов: `vault/issues/debt-054/probes/failure_census.py`, сверка «до/после» — `histories.py`.

| Сценарий | Отказов | «Только по ячейке» | Причина выхода |
|---|---|---|---|
| BUG-018, $N$ = 350, первые сутки | 2 | 2 | линейный поиск (мера 2.60e-8 при 86400 с, 1.17e-8 при 43200 с) |
| пример 14 | 1 | 1 | линейный поиск (мера 1.14e-8) |
| примеры 16, 17 | 0 | — | — |
| суточный останов rs300 | 7 | 2 (ступень 4 по памяти) | лимит 40 при невязке 8e-16, мера 1.25–1.29e-8 |

- Истории пяти сценариев и последовательность вызовов гидродинамики побитово прежние; новый текст каждого отказа начинается с прежнего.
- Регрессия прототипа 17/17 PASS побитово.
- В сценарии BUG-018 мера пропорциональна шагу ($\approx 3\cdot10^{-13}\,\Delta t$): дробление снимает отказ само. Механизм установлен в [[DEBT-055]]: это предел округления, мера вектора $|J|\,\mathrm{ulp}(z)$ (`eq:newton_cell_floor`). Он растёт как $\Delta t$, Ньютон встаёт на 0.23–0.40 предела; с DEBT-055 отчёт несёт его (`cell_floor`), а текст отказа говорит «мера не выше предела округления». Подшага, на котором условие не выполняется ни при каком дроблении, при пороге по умолчанию в замерах не нашлось. С [[DEBT-067]] решение на пределе принимается (строка по своему пределу): сутки BUG-018 при $N$ = 350 — одним вызовом; тесты отчёта отказа воспроизводят его с выключенным пределом (`CELL_FLOOR_KAPPA = 0`).

## Замечания

- **Невязка и мера отказа ступени 4 вычисляются при удержанных ячейках «выше по потоку».** До `finally` они ещё удерживаются, то есть числа относятся к той же схеме, что решал Ньютон. Проба, пересчитавшая меру после выхода по исходной схеме, получила 5.89 вместо 3.91. Для отброшенного шага это не важно, но пересчитанные пробой числа с отчётом не совпадут.
- **`iterations` отказа у двух Ньютонов считается по-разному.** `_newton_fixed_active_set` пишет номер итерации, на которой отказал (её строки — в `step_log.csv` эталона регрессии). `_newton_switching` пишет число проходов минус один, как у своего сошедшегося решения.
