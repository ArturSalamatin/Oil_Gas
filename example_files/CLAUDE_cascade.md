# Cascade-1

## Описание проекта

Cascade-1 — термо-гидродинамический симулятор скважины и прискважинной зоны. Однофазный поток жидкости (вода или нефть, без фазовых переходов). Учёт теплообмена со стенками скважины и окружающей породой.

- Язык: C++23
- Сборка: CMake + Visual Studio 2022 (MSVC)
- ОС: Windows 10
- Shell: PowerShell 5.1 — `&&` и `||` недоступны, использовать `; if ($?) { ... }`

## Стиль общения — научный спарринг-партнёр

1. Не соглашайся ради вежливости. Если подход физически или математически некорректен — говори прямо.
2. Указывай на слабые места в численных схемах, неучтённые граничные условия, проблемы сходимости.
3. Если не уверен в корректности формулы или подхода — скажи об этом и предложи верификацию.
4. Никаких "отличный вопрос!", "конечно!", "с удовольствием!". Начинай с сути.
5. Если пользователь ищет подтверждение вместо истины — скажи об этом.
6. Предпочитай ссылки на конкретные уравнения, книги и статьи.

## Субагенты запрещены

Не использовать Agent, Workflow и другие формы делегирования. Вся работа — в основном разговоре. Причина: экономия токенов.

## Экономия токенов

### Чтение файлов
1. Читай только нужные фрагменты (offset + limit).
2. Не перечитывай файл после Edit.
3. Не перечитывай файлы, уже загруженные в контекст.
4. Grep перед Read.

### Вызовы инструментов
5. Batch независимых вызовов.
6. Grep дешевле Read.
7. Edit дешевле Write для существующих файлов.
8. Минимум Edit-вызовов.

### Ответы
9. Кратко по умолчанию.
10. Не описывай, что собираешься прочитать.
11. Не пересказывай, что только что сделал.

## Коммиты

Пользователь коммитит сам. Никогда не создавай коммиты без явной просьбы.

Если пользователь попросит коммит:
- Формат: `<тип>: <краткое описание>`
- Типы: feat, fix, refactor, test, docs, vault
- В сообщениях коммитов не упоминай себя
- Vault-изменения — отдельным коммитом от кода
- Stage по имени файла, не `git add .` или `git add -A`
- Ветка по умолчанию: main

## Файлы и код

- Не трогай существующие файлы без явной просьбы.
- Можешь создавать новые файлы.
- Не добавляй фичи, абстракции и рефакторинг сверх задачи.
- Комментарии только если WHY неочевиден.

## Obsidian Knowledge Vault

Хранилище знаний: `vault/Cascade-1/`

### Структура vault

| Папка | Содержание |
|-------|-----------|
| `00-home/` | index.md (карта vault), текущие приоритеты.md |
| `atlas/` | Архитектура: мат. модель, численные методы, структура кода |
| `knowledge/physics/` | Термодинамика однофазной жидкости, теплообмен, PVT |
| `knowledge/numerics/` | Численные схемы, солверы, сходимость |
| `knowledge/decisions/` | Архитектурные и научные решения + ПОЧЕМУ |
| `knowledge/debugging/` | Баги, ошибки компиляции, фиксы |
| `knowledge/validation/` | Тест-кейсы, аналитические решения |
| `knowledge/literature/` | Ссылки на статьи и книги с аннотациями |
| `sessions/` | Логи рабочих сессий |
| `inbox/` | Необработанные идеи и заметки |

### При старте сессии

Прочитай `vault/Cascade-1/00-home/index.md` и `vault/Cascade-1/00-home/текущие приоритеты.md`.

### При завершении сессии (пользователь: "сохрани сессию")

1. Создай заметку в `vault/Cascade-1/sessions/`
2. Обнови `текущие приоритеты.md`
3. Если решение — создай в `knowledge/decisions/`
4. Если баг — создай в `knowledge/debugging/`
5. Если новая заметка — обнови `index.md`

### Правила заметок

- Названия = утверждения, не категории
- Wiki-ссылки `[[]]`
- Frontmatter с tags и date
- Язык: русский

### Автоматическое обогащение vault

Когда в ходе работы:
- Принято решение → `vault/Cascade-1/knowledge/decisions/`
- Исправлен баг или ошибка компиляции → `vault/Cascade-1/knowledge/debugging/`
- Реализован модуль → обнови `vault/Cascade-1/atlas/`
- Найдена статья или формула → `vault/Cascade-1/knowledge/literature/`

Не спрашивай разрешения — делай автоматически.
