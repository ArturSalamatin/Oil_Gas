# Порядок реализации модулей

## Принцип

Снизу вверх по графу зависимостей: сначала модули без зависимостей, потом — зависящие от готовых.

## Граф зависимостей

```
SimulatorFactory
    └── Simulator
            ├── HydroSolver ──┬── Grid
            │                 ├── HydroPVT
            │                 ├── RelPermModel
            │                 ├── fluxes ──┬── Grid, PVT, ОФП
            │                 └── bc ──────── WellControl (ABC)
            ├── EnergySolver ─┬── Grid
            │                 ├── ThermalPVT
            │                 ├── RockConfig
            │                 └── fluxes (для Q_o, Q_g)
            ├── TimeSchedule ── HistoryInterval + WellControl
            ├── BoundaryConditions
            ├── SimulationState
            └── log (user_log, dev_log)

config.py (чтение JSON) ── используется всеми через Factory
fluxes.py ── общая логика upstream + вычисление G, Q, u, m
bc.py ── ABC WellControl + PressureControl
log.py ── настройка logging (user + dev уровни)
```

## Фазы реализации

### Фаза 0. Каркас проекта
- `pyproject.toml`
- Структура директорий `src/`, `tests/`, `configs/`
- `conftest.py` с fixtures
- Пустые `__init__.py`

**Результат:** `pytest` запускается (0 тестов, 0 ошибок).

### Фаза 1. Grid (без зависимостей)
- `src/grid/base.py` — ABC Grid
- `src/grid/log_radial.py` — LogRadialGrid
- `tests/test_grid.py` — unit-тесты

**Результат:** Grid создаётся, grани/центры/объёмы/проводимости вычислены и протестированы.

### Фаза 2. PVT + ОФП (без зависимостей)
- `src/pvt/base.py` — ABC HydroPVT, ThermalPVT, RelPermModel
- `src/pvt/standing.py` — StandingPVT (из correlations.py, vectorized)
- `src/pvt/relperm.py` — CoreyRP
- `src/pvt/thermal.py` — скалярная реализация ThermalPVT (μ_JT, L, c_p)
- `tests/test_pvt.py` — unit-тесты
- `tests/test_relperm.py` — unit-тесты

**Результат:** все PVT-функции и производные протестированы, vectorized.

### Фаза 3. Инфраструктура: state, config, bc, log, fluxes
- `src/state.py` — SimulationState, WellData, HydroResult, EnergyResult, BoundaryConditions, SimulationHistory
- `src/bc.py` — ABC WellControl, PressureControl
- `src/log.py` — setup_logging, user_log, dev_log
- `src/fluxes.py` — compute_fluxes (G, Q, u, m + upstream)
- `src/io/config.py` — dataclasses + load_config
- `configs/baseline.json` — эталонный конфиг
- `tests/test_config.py` — чтение, валидация
- `tests/test_fluxes.py` — потоки на стационарном профиле давления

**Результат:** JSON читается, потоки вычисляются, логирование работает.

### Фаза 4. HydroSolver — ABC + аналитическая заглушка
- `src/hydro/base.py` — ABC HydroSolver
- `src/hydro/analytical.py` — AnalyticalHydroSolver (использует fluxes.py)
- `tests/test_hydro.py` — unit-тесты для заглушки

Конкретный Newton-солвер **не реализуем** — ожидаем модуль коллеги. Для тестирования EnergySolver и Simulator нужна заглушка, возвращающая аналитические поля p(r), Sg(r), u_o(r), u_g(r).

AnalyticalHydroSolver — упрощённая реализация:
- p(r) = логарифмический профиль (стационарный однофазный поток)
- Sg(r) = 0 (без дегазации) или заданный профиль
- u_o(r) из закона Дарси при известном p(r)
- u_g = 0 (однофазный) или пропорционален krg/mu_g · dp/dr

Этого достаточно, чтобы:
1. Протестировать EnergySolver на реалистичных полях
2. Протестировать Simulator (полный цикл)
3. Валидировать T(r) при известном аналитическом p(r) (VAL-001)

Когда модуль коллеги поступит — написать AdapterHydroSolver.

**Результат:** ABC определён, заглушка работает, можно тестировать остальные модули.

### Фаза 5. EnergySolver
- `src/energy/base.py` — ABC EnergySolver
- `src/energy/tridiag.py` — TridiagEnergySolver
- `tests/test_energy.py` — unit + интеграционные

Подзадачи:
1. Вычисление конвективных потоков (upstream по фазе)
2. Кондуктивные потоки (гармоническое среднее)
3. JT-вклад, адиабатика, дегазация
4. Сборка трёхдиагональной СЛАУ
5. Решение (scipy.linalg.solve_banded)
6. Граничные условия

**Результат:** температура решается при известных p, Sg, Rs.

### Фаза 6. Simulator + Factory
- `src/simulator.py` — Simulator (цикл по времени, адаптация dt)
- `src/factory.py` — SimulatorFactory.from_json
- `tests/test_simulator.py` — интеграционные

**Результат:** полная симуляция из JSON-конфига.

### Фаза 7. I/O + визуализация
- `src/io/output.py` — save_npz, save_csv, plot_profiles, plot_wellbore_dynamics, plot_well_rate, plot_2d_map
- Эталонный запуск с baseline.json → результаты в `results/`

**Результат:** полный pipeline JSON → расчёт → графики.

### Фаза 8. Валидация
- VAL-001: однофазный стационарный поток (аналитическое решение)
- VAL-003: Buckley-Leverett (при наличии двухфазного гидро-солвера)

### Фаза 9 (отложена). Adapter для внешнего модуля
- `src/hydro/adapter.py` — шаблон AdapterHydroSolver
- Реализация при получении модуля коллеги

## Оценка трудоёмкости

| 0 | Каркас | 0.5 сессии |
| 1 | Grid | 1 сессия |
| 2 | PVT + ОФП | 2 сессии |
| 3 | State + config + bc + log + fluxes | 2 сессии |
| 4 | HydroSolver ABC + аналитическая заглушка | 1 сессия |
| 5 | EnergySolver | 2 сессии |
| 6 | Simulator + Factory | 1 сессия |
| 7 | I/O + визуализация | 1 сессия |
| 8 | Валидация (VAL-001 как минимум) | 1 сессия |
| 9 | Adapter (при получении модуля коллеги) | 1-2 сессии |

**Итого до получения внешнего модуля:** ~11-12 сессий.
**С Newton-реализацией (если понадобится):** +3-4 сессии.

- Правка problem_statement.tex (знаки) — отдельная сессия
