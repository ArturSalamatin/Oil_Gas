# 10 — Глубокое разгазирование: полная модель при $p_{wf} = 6$ МПа

**Стресс-тест.** Самая сильная депрессия среди примеров с табличными PVT
и ОФП.

## Описание

Полная физическая модель: табличные PVT и ОФП, все тепловые эффекты
включены ($\mu_{JT} > 0$, $L > 0$). Отличия от примера
[04](../04_table_table/): забойное давление снижено с 8 до **6 МПа**
(депрессия выросла с 12 до 14 МПа) и заданы физические теплопроводности
1.5 / 0.14 / 0.04 Вт/(м·К) вместо нулевых.

Смысл: показать, как ведёт себя модель при сильном разгазировании,
и проверить устойчивость расчёта у нижней границы рабочего диапазона.

## Комбинация модулей (B: Table + Table)

| Модуль | Класс | Ключ конфига | Внешние файлы |
|---|---|---|---|
| Сетка | `LogRadialGrid` | `grid.N = 50` | — |
| PVT (гидро) | `TableFullPVT` | `pvt.model = "table"` | `oil_pvt.csv`, `gas_pvt.csv` |
| ОФП | `PrototypeRPAdapter` | `relperm.model = "table"` | `relperm.csv` |
| Гидродинамика | `PrototypeHydroAdapter` | (единственный) | — |
| Энергия | `TridiagEnergySolver` | (единственный) | — |

Полная термика:

```json
"thermal": {
    "c_p_oil": 2000.0, "c_p_gas": 1000.0,
    "mu_JT_oil": 4.0e-7, "mu_JT_gas": -4.0e-6,
    "L_degas": 168000.0
}
```

## Ключевые параметры

| Параметр | Значение | У примера 04 |
|---|---|---|
| $R_{s,0}$ | 30 м³ст/м³ст | то же |
| $p_b$ | 15 МПа | то же |
| $p_0$ | 20 МПа | то же |
| $p_{wf}$ | **6 МПа** | 8 МПа |
| депрессия | **14 МПа** | 12 МПа |
| $\lambda_s$ / $\lambda_o$ / $\lambda_g$ | **1.5 / 0.14 / 0.04** Вт/(м·К) | 0 |

## Ожидаемое поведение

| Величина | 04 ($p_{wf} = 8$) | **10** ($p_{wf} = 6$) |
|---|---|---|
| $S_g^{max}$ | 0.0147 | **0.0191** (+30 %) |
| $R_s^{min}$ | 9.5 | **3.6** (газа вышло больше) |
| $r_b$, м | 2.64 | **3.58** (фронт продвинулся) |
| $T(r_w)$, К | 344.203 | **343.072** |
| $q_o$, м³ст/с | $5.876\times10^{-3}$ | $6.555\times10^{-3}$ (+12 %) |

Все величины — на момент $t = 3$ сут.

Что видно:

- **Фронт разгазирования расширился** с 2.64 до 3.58 м — зона двухфазного
  течения захватила больше пласта.
- **$R_s$ упал до 3.6** против 9.5: нефть у забоя почти полностью
  дегазирована.
- **Забой холоднее на 1.13 К**: 343.07 К против 344.20 К, охлаждение
  относительно $T_0 = 350$ К — 6.9 К против 5.8 К.
- **Насыщенность выросла только на 30 %** при росте депрессии на 17 %.
  Депрессия — слабый рычаг для $S_g$ (см. раздел ниже).

## Как увеличить газонасыщенность

Даже при депрессии 14 МПа $S_g^{max} \approx 1.9\,\%$. Это показывает, что
**депрессия — не тот рычаг**.

Причина: в стационаре GOR всегда равен $R_{s,0} = 30$ — весь газ,
поступающий с контура, уходит в скважину. $S_g$ определяется тем, какая
насыщенность нужна, чтобы вынести этот поток. Демонстрационная
`relperm.csv` даёт $k_{rg} = 0.01$ уже при $S_g = 0.1$ — газ слишком
подвижен, чтобы накапливаться.

Сравнение рычагов (измерено на конфиге 04):

| Рычаг | Диапазон | $S_g^{max}$ |
|---|---|---|
| депрессия $p_{wf}$ | 14 → 8 → 4 МПа | 0.0018 → 0.0147 → 0.0219 |
| газосодержание $R_{s,0}$ | 10 → 20 → 30 | 0.0005 → 0.0077 → 0.0147 |
| **подвижность газа (ОФП)** | таблица → Кори (секция ниже) | **0.0147 → 0.165** |

Решающий рычаг — ОФП. Заменить секцию `relperm` на:

```json
"relperm": {"model": "corey", "S_or": 0.2, "S_gc": 0.05,
            "n_o": 2.0, "n_g": 3.0, "kro_max": 1.0, "krg_max": 0.3}
```

Контринтуитивно: **менее подвижный газ даёт бо́льшую насыщенность**,
потому что для выноса того же расхода нужно накопить больше газовой фазы.
Подробный разбор — в README примера [04](../04_table_table/).

С этой секцией пример 10 ($p_{wf} = 6$ МПа) считается с настройками по
умолчанию и даёт $S_g^{max} = 0.175$. При отказе `RuntimeError:
HydroSolver не сошёлся после N подшагов` увеличить `"max_retries"` в
секции `numerics` (по умолчанию 9).

## Как модифицировать

### Что менять безопасно

| Параметр | Секция JSON | Эффект |
|---|---|---|
| параметры ОФП | `relperm` | главный рычаг для $S_g$ |
| тепловые скаляры | `thermal` | только $T$; гидродинамика не меняется (расщепление) |
| $R_e$ | `geometry.R_ext` | шире область; фронт $r_b$ растёт |
| $h$, $k$, $\varphi$ | `geometry`, `rock` | дебит |
| $N$ | `grid.N` | детальность профилей |
| длительность | `time.history[].dt` | ⚠️ стационар за 8–12 ч |
| частота записи | `time.history[]` | число интервалов = число записей; 72 по 3600 с → 73 шага |

### Что требует осторожности — $p_{wf}$

**Сверху:** при $p_{wf} > p_b = 15$ МПа разгазирования не будет.
**Снизу:** при $p_{wf} = 3$ МПа расчёт проходит с настройками по
умолчанию: $S_g^{max} = 0.022$, $R_s^{min} = 0$ — нефть у забоя
полностью дегазирована. При отказе Newton — увеличить глубину дробления
шага в секции `numerics`:

```json
"numerics": { "max_retries": 11 }
```

Лимит `max_retries` ограничивает
число удвоений подшага в `PrototypeHydroAdapter` ($2^{max\_retries}$
подшагов); по умолчанию 9. Уменьшение `dt_integration` — не всегда
замена: A-retry уже дробит шаг внутри с тем же лимитом.

### Не трогать

`grid.type` и `output.format` — объявлены в `io/config.py`, но не читаются.
