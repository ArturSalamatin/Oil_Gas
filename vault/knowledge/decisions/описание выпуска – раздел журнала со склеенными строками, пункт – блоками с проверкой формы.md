# Описание выпуска – раздел журнала со склеенными строками, пункт – блоками с проверкой формы

**GitHub issue:** [#143](https://github.com/ArturSalamatin/Oil_Gas/issues/143) · план [[debt-086 release-notes-format]] · выпуск – [[выпуск решателя — одна команда, push только после самопроверки сборки из метки]] · журнал – [[номер версии решателя — литерал __version__, журнал сводится при выпуске]]

**Что было.** `tools/release.py` переносил раздел выпуска из `numerical_solver/CHANGELOG.md` в описание выпуска на GitHub без изменений. Строки пунктов журнала перенесены по ~76 знаков. В файле `.md` такой перенос мягкий, но в описании выпуска (как и в комментариях к issue) GitHub отображает каждый перенос строки как `<br>`: пункт FEAT-039 в v1.0.6 вышел 14 строками, оборванными посреди фраз (`gh api repos/ArturSalamatin/Oil_Gas/releases/tags/v1.0.6`, поле `body_html`). Пункт по прежнему шаблону `/implement` 4.1 – один абзац из 3–8 предложений, границы «задача – решение – результат» и изменившиеся числа в нём не видны.

**Причина `<br>` проверяется без публикации.** `gh api markdown -f mode=gfm` отрисовывает текст так же, как описание выпуска: `- **A.** one⏎two` → `one<br>two`. Проба `vault/issues/debt-086/probes/p1_unwrap_render.py` на всех восьми разделах журнала: `<br>` 14/13/6/4/4/10/26/42 → 0 после склейки, последовательность слов та же.

**Решение – разделение работы.**

| Что | Кто | Почему там |
|---|---|---|
| Склейка строк абзаца | `tools/release.py`: `unwrap_paragraphs`, `release_notes` (в `build`) | механическая правка; устраняет особенность отображения описаний выпусков для любых пунктов, в том числе старых разделов; журнал остаётся перенесённым и читаемым в редакторе и в передаче заказчику |
| Деление пункта на блоки | `/implement` 4.1 (шаблон, разметка, таблица содержания блоков, образец); правки без задачи – Claude при выпуске (докстринг `release.py`) | смысловое: где кончается «было» и начинается «стало», скрипт по тексту не определит |
| Соответствие формы | `tests/test_packaging.py`, `TestChangelogFormat` (группа `-k changelog`) | её запускают `/implement` 4.1 и быстрый уровень `/merge`; в дереве метки проверяется раздел выпуска, поэтому пункт не по форме останавливает и самопроверку выпуска – до публикации, с откатом |
| Знаки шапки журнала (вступление, правило номеров) | `tests/test_packaging.py`, `test_changelog_header_symbols` (DEBT-087) | длинное тире и десятичная запятая вне `…`; граница шапки – первый заголовок раздела выпуска (`## Не выпущено` или `## X.Y.Z — <дата>`), поэтому проверка действует и в самопроверке выпуска |

**Форма пункта.** `- **<ID>.** <суть одной фразой>.`, затем абзацы с отступом 2 пробела через пустую строку: `*Было.*`, `*Стало.*` и, если при тех же исходных данных изменяются результаты, `*Числа.*` со вложенным списком «величина было → стало». На GitHub: `<li>` с отдельными `<p>`, номер – `<strong>`, метки – `<em>`, числа – вложенный `<ul>`.

**Решения пользователя (2026-10-22).**
- Одна задача на всё оформление – команды, скрипт, проверка; правка команд `.claude` – тоже через задачу.
- Метки блоков – курсивом (номер задачи остаётся единственным жирным).
- Разделы 1.0.0–1.0.6 журнала не переписываются; проверка формы читает только текущий раздел, знаки – ещё и шапку (DEBT-087).
- Пункт без номера задачи – область жирным: `- **README.** …`, те же блоки.
- Пункт FEAT-040, лежавший в «Не выпущено» в старой форме, переведён: текст дословно, новая – только суть.
- Тест склейки – `numerical_solver/tests/test_release_notes.py`; в срезе заказчика `tools/` нет, тест пропускается, причина – в `ALLOWED_SKIPS` `tools/acceptance.py`. В `test_packaging.py` он не лежит: самопроверка выпуска запускает этот файл в дереве метки и считает пропуск отказом.
- Вывод программ цитируется дословно в обратных кавычках; длинное тире и запятая между цифрами внутри `…` проверкой не отвергаются (в строковых литералах пакета «—» встречается 177 раз).

**Проверено.** Эмуляция на копии с настоящими `pyproject.toml` и `conftest.py`: дерево метки 1.0.7 (номер и раздел – функциями `release.py`) – 18 passed, с пунктом без жирного номера – 1 failed, после `.dev0` с пустым «Не выпущено» – 18 passed. Отрисовка «Не выпущено» ветки (`p4_verify_tree.py`): пункты FEAT-040 и DEBT-086, `<br>` 0, по два `<em>Было.</em>` и `<em>Стало.</em>`.

**Следствие.** Задача, начатая до влития DEBT-086, исполняет 4.1 по загруженному тексту команды – старому шаблону; её пункт после влития DEBT-086 отвергнет быстрый уровень `/merge`. Пункт тогда переводится в новую форму так же, как FEAT-040 (текст дословно, новая – суть), с показом пользователю до коммита. На 2026-10-22 так реализуется DEBT-085.
