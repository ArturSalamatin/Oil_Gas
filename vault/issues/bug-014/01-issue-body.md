## Описание

Решатель гидродинамики (прототип `radial_blackoil`) не сходится, когда забойное давление $p_{wf}$ скачком поднимают выше давления в ячейке у забоя $p[0]$. Физически сценарий корректен: скважина «только добыча» закрывается (обратный клапан, $q = 0$), в ПЗП идёт восстановление давления, при $p[0] > p_{wf}$ скважина снова открывается. Численно шаг падает даже после дробления на 512 подшагов.

Критичность: блокирует пример 13б (FEAT-023) и любой сценарий с ростом $p_{wf}$ — останов скважины, восстановление давления (FEAT-019), реальную историю работы скважины. Снижение $p_{wf}$ (пример 13а) не затронуто.

## Корневая причина

Установлена частично. Два независимых механизма.

**1. Ветка «открыта / закрыта» выбирается по текущей итерации внутри Ньютона.** Дебит скважины (`blackoil.py:83-87`):

$$q = WI\,\lambda\,\max(p[0] - p_{wf},\,0).$$

Оба условия — заданное $p_{wf}$ и непротекание $q = 0$ — гладкие; излом ($\partial q/\partial p[0]$: $0 \to WI\,\lambda$) возникает только из-за переключения. Сам излом — не приговор: полугладкий Ньютон на кусочно-гладких функциях локально сходится. Проблема в том, что ветку выбирает текущая итерация, а не внешний цикл ограничений.

Цепочка: `PrototypeHydroAdapter.solve` → `RadialBlackOilModel.advance` (внешний цикл набора активных ограничений по фазам) → `_newton_fixed_active_set` → `residual` → `_well_fluxes`. Начальная итерация $p[0] = 6.13 < p_{wf}$ — ветка «закрыта»: $\partial q/\partial p[0] = 0$, линейная модель скважины не видит и ведёт к восстановлению давления без отбора. При dt = 3600 с у этой ветки нет согласованного решения: с отбором $p[0] = 10.784 > p_{wf}$, без отбора давление ещё выше — противоречие условию «закрыта ⇒ $p[0] \le p_{wf}$».

Подтверждение: при ветке «открыта», зафиксированной на всё время решения и без ограничения знака дебита, шаг 3600 с сходится за 11 итераций, $p[0] = 10.784$ МПа $> p_{wf}$, дебит положителен — ответ согласован. Решение шага существует и регулярно; отказывает путь итераций.

**2. Исчезновение газа в ячейке у забоя.** При ветке «закрыта», зафиксированной на всё время решения, Ньютон не сходится уже при dt = 60 с: давление в ячейке 0 растёт, свободный газ растворяется целиком, все 44 пробные точки линейного поиска отвергнуты `_trial_is_reasonable` ($S_g[0] < -0.05$). Переключение ячейки в однофазный режим (`advance`, строка 209) выполняется только **после** сходимости Ньютона — до него не доходит. Ослабление границы (−1 вместо −0.05) не помогает. Зеркально BUG-008 (там — массовое появление газа).

## Анализ вариантов решения

### Вариант 1. Состояние скважины — во внешний цикл активных ограничений

**Суть.** Состояние скважины (открыта / закрыта) фиксируется на время Ньютона так же, как набор фаз. «Открыта» — $q = WI\,\lambda\,(p[0] - p_{wf})$ без проверки знака; «закрыта» — $q = 0$. После сходимости в `advance` проверяется согласованность: открыта и $q < 0$ → закрыть; закрыта и $p[0] > p_{wf}$ → открыть; шаг пересчитывается. Начальное состояние — «открыта».

**Изменения.** `blackoil.py`: `_well_fluxes` (52-90) — принудительная ветка; `advance` (202-219) — проверка согласованности и переключение, счётчик переключений в отчёте. Без принудительной ветки `_well_fluxes` работает как сейчас — `well_rates` на статическом состоянии и `test_producer_only.py` не меняются.

**Плюсы.** Бьёт прямо в механизм 1; замер подтверждает, что с ветки «открыта» шаг 3600 с сходится. Ожидается не больше одного переключения за шаг: закачка только поднимает $p[0]$, поэтому если «открыта» дала $q < 0$, то при «закрыта» $p[0]$ ещё ниже и условие $p[0] \le p_{wf}$ выполнено (монотонность — ожидание, не доказано). Для примеров с непрерывно работающей скважиной путь итераций не меняется — ожидаются побитово те же результаты (проверить).

**Минусы.** Механизм 2 не устраняет: когда верна ветка «закрыта» (короткий шаг, длительный останов), растворение газа у забоя по-прежнему роняет Ньютон. Лишнее решение Ньютона при переключении. Управление по дебиту с нижней границей $p_{wf}$ (56-77) выбирает ветку тем же способом — относится к FEAT-020, в объём не входит.

### Вариант 2. Исчезновение фазы внутри Ньютона

**Суть.** Смена переменных $S_g \leftrightarrow R_s$ на каждой итерации Ньютона или ограничение приращения насыщенности (Appleyard chop, как в OPM Flow).

**Изменения.** `blackoil.py`: `_newton_fixed_active_set` (186-201), `_trial_is_reasonable` (180-185), логика переключения из `advance` (208-217).

**Плюсы.** Устраняет механизм 2 и, вероятно, BUG-008 (зеркальный случай).

**Минусы.** Глубокая правка Ньютона: меняет путь итераций во всех примерах, где есть переходы фаз, — риск регрессии результатов. Требует отдельного плана вместе с BUG-008.

### Вариант 3. Неравномерное дробление в адаптере

**Суть.** Малый первый подшаг, затем рост, вместо $2^k$ равных.

**Изменения.** `prototype_adapter.py` (67-134).

**Плюсы.** Прототип не трогается.

**Минусы.** Лечит симптом: платим мелкими шагами за выбор ветки. Меняет контракт `HydroResult.n_substeps` — энергия обязана пройти те же подшаги (BUG-010).

**Рекомендация:** вариант 1 первым (закрывает механизм 1, подтверждён замером), затем вариант 2 совместно с BUG-008. Вариант 3 — нет.
