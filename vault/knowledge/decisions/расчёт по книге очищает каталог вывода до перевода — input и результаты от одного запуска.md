# Расчёт по книге очищает каталог вывода до перевода — input и результаты от одного запуска

`run_case` (`numerical_solver/gpn_multiphase_solver/report/pipeline.py`) принимает вход по расширению: `.xlsx`, `.xlsm`, `.xls`, `.xlsb` без учёта регистра (`EXCEL_SUFFIXES`) — книга ввода Excel, прочее — JSON-конфиг, как прежде. Команда `gpn-solver run книга.xlsx` — тот же `run_case`. Перевод книги — [[перевод книги в конфиг проверяет только книгу — моменты SCHEDULE в целых мс]] (FEAT-035). План и решения пользователя 1–29 — [[feat-036 run-from-workbook]].

## Порядок для книги

1. Явный `n_profiles` проверяется первым — ошибка аргумента в скрипте не стирает вывод.
2. Книга внутри каталога вывода (сама или в подкаталоге) — `CaseConfigError` до чтения: очистка удалила бы её.
3. `workbook_to_config(read_workbook(книга))` — перевод **в памяти**. Книга с ошибкой (не `.xlsx`, значения ячеек, нет файла) — `CaseConfigError`, каталог вывода не тронут.
4. Очистка каталога вывода — **до** расчёта (решение пользователя 2026-10-18), переименованием (`_clear_output`, [[DEBT-082]]): каталог занят (файл открыт в Excel, консоль в каталоге) — `CaseConfigError` «каталог вывода … не удаётся очистить (<причина>): файл в нём открыт в другой программе …», ни один файл не удалён, расчёт не начат. До DEBT-082 прямой `rmtree` успевал удалить часть файлов ([[каталог вывода очищается переименованием — занятый каталог не удаляется частично]]).
5. `write_files(output/input, …)` — `config.json` и `oil_pvt.csv`, `gas_pvt.csv`, `relperm.csv` в СИ.
6. Расчёт по `output/input/config.json`, как по любому конфигу, но без защиты входных файлов (перевод лежит в каталоге вывода по замыслу) и без второй очистки после расчёта.

Печать — «Книга: <путь>» вместо «Конфиг: …»; ошибки `load_config` и фабрики по переводу — с путём книги. Ключ строки книги равен пути поля JSON, поэтому отказ `_validate` («`initial_conditions.Rs0` …») находят в книге. Командная строка: при входе-книге код 2 — «Ошибка книги: …». Заголовок рисунков — имя книги без расширения (перевод пишет `output.title`); `--title`, `--profiles` действуют.

## Цена и почему так

У конфига каталог вывода очищается **после** расчёта (FEAT-030, решение 2026-10-13): при отказе решателя прежние результаты целы. У книги это правило отменено: при ошибке конфига или таблиц и при отказе решателя прежних результатов нет, в каталоге — только `input/`, вход, на котором расчёт остановился. Взамен `input/` и результаты всегда от одного запуска.

| Вариант | Почему не принят |
|---|---|
| А. Перевод во временный каталог, копия в `output/input/` после успеха | правило FEAT-030 сохранялось бы, но при отказе нового входа для разбора нет, печать и ошибки называли бы временный файл; пользователь выбрал Г |
| В. Перевод в `output/input/` до расчёта, `run_case` бережёт `input/` при очистке | при отказе решателя в каталоге — старые результаты рядом с новым входом |
| Только в командной строке, `run_case` без книги | скрипт на Python книгу не считает; печать «Конфиг: output/input/config.json» |
| **Г. Очистка до перевода** (с переводом в памяти до очистки) | принят |

Повтор по `output/input/config.json` без `--output` пишет в `output/input/output/` — внутрь каталога, который следующий расчёт по книге очистит; README §3.6 и строка «Run» листа COMMENTS советуют `--output`.

У расчёта по конфигу открытый файл каталога вывода ломал очистку **после** расчёта — трассировка, результаты не записаны. Решено в [[DEBT-082]]: занятый каталог — отказ до расчёта, занятый во время расчёта — результаты в соседнем каталоге.
