# FEAT-035: перевод книги в конфиг — `gpn-solver convert`

> **Черновик.** Записаны решения пользователя из обсуждения 2026-10-14…15 и найденное при нём. Шаги, тестовую стратегию и критерии завершения допишет `/plan-feature FEAT-035`.

Цепочка: [[feat-033 workbook-input-format|FEAT-033]] (формат, таблица полей) → [[feat-034 xlsx-cell-reader|FEAT-034]] (разбор ячеек) → **FEAT-035** (перевод) → [[feat-036 run-from-workbook|FEAT-036]] (расчёт).

## 0. Решения пользователя

1. **JSON — канонический формат, книга переводится в него** (2026-10-14).
2. **Перевод — в файлы** (предложение 2026-10-14, принято решением 1): `config.json` + `oil_pvt.csv`, `gas_pvt.csv`, `relperm.csv`; дальше обычный `load_config(path)`. Вход расчёта сохраняется (пункт 17 обсуждения, согласовано) — у [[feat-036 run-from-workbook|FEAT-036]] это `output/input/`.
3. **Единицы инженерные, фиксированные, столбец единиц сверяется точно** (2026-10-14).
4. **Сообщения:** физические ошибки — пока по узлам JSON (2026-10-14). Ошибки самой книги (тип ячейки, единица, неизвестный ключ, порядок времён) возникают до JSON — с листом и ячейкой (предложение).
5. **Интервал истории округляется до 1 мс** (2026-10-15), как в конвертере примера 18 (`examples/18_prototype_input/prototype_input.py`: `round((t_b − t_a)·DAY, 3)`). Без округления 10 с, записанные в книге как $1.157\ldots\cdot10^{-4}$ сут, дают интервал 10.0000000000x с. Нулевой интервал после округления — отказ.
6. **Типы ячеек** (2026-10-14): целые поля — из вещественных (350.0 → 350, 350.5 — отказ); дата, число строкой, логическое в числовом поле, формула без значения — отказ с адресом; пустое обязательное значение — отказ; слово «выключено» — `null` (`newton_cell_tol`, `dt_after_control_change`; само слово — `none`, решение 12).
7. **Конвертер примера 18 и тесты [[VAL-005]] не меняются** (2026-10-15).
8. **Смысл SCHEDULE** ([[feat-033 workbook-input-format|FEAT-033]], решения 9, 32): строка $k$ — момент $t_k$ и режим на $[t_k, t_{k+1}]$; последняя строка — только момент завершения расчёта (2026-10-15), её режим не используется, заполненный — молча пропускается (FEAT-033, решение 40); общее время расчёта отдельно не задаётся. Каждая строка — момент записи, столбца «шаг записи» нет (решение 30). Шаги `dt_integration`, `dt_after_control_change` — в часах (решение 31).
9. **Тест «шаблон читается»** (2026-10-15): `numerical_solver/configs/INPUT_TEMPLATE_v1.xlsx` ([[feat-033 workbook-input-format|FEAT-033]], решение 38) переводится в конфиг, и `load_config` его принимает. Не сравнение книг: снимок генератора отстаёт от таблицы полей при её изменении — новое обязательное поле, переименованный ключ, другая единица, другой `format_version` дают отказ перевода; тест ловит это у нас, а не у заказчика. ~~Тихий случай — в снимке нет новой необязательной строки — допустим (значение по умолчанию).~~ Отменено решением 15: нет строки — отказ, тихого случая нет. Актуальную книгу всегда даёт `gpn-solver template`.
10. **Умолчания перевода** (предложены 2026-10-15 как «решу при `/plan-feature`, если не возразите» — возражений не было): `convert` в непустой каталог — отказ; одна строка SCHEDULE — один интервал `{"dt": …}` (без сжатия в `{dt, repeat}`); неизвестный ключ на листе — отказ; лишние листы — пропускаются.
11. **Листа OUTPUT нет** ([[feat-033 workbook-input-format|FEAT-033]] решение 44): секцию `output` перевод не заполняет, кроме заголовка — имя книги ([[feat-036 run-from-workbook|FEAT-036]]); остальное — умолчания конфига.
12. **Выключено — `none`** (FEAT-033 решение 36) → `null` в JSON (`dt_after_control_change`, `newton_cell_tol`); без учёта регистра — решить при планировании.
13. **Сообщения — русские**, подписи и ячейки в них — как в книге (FEAT-033 решение 34).
14. **Пара пористости и плотности при ст. у.** (FEAT-033 решения 49, 54): $\varphi_0 = \varphi_{ref}\,e^{c_r(p_0 - p_{ref})}$; плотности проверяются на > 0 переводом, независимо от [[DEBT-076]].
15. **Все параметры обязательны** ([[feat-033 workbook-input-format|FEAT-033]] решение 57, 2026-10-17): на MODEL, THERMAL, NUMERICS нет строки ключа — отказ; пустая Value — отказ с адресом для любого поля, не только для полей без умолчания (уточняет решение 6); «выключено» — только `none`. Умолчания `io/config.py` перевод не подставляет: в `config.json` — каждое поле книги явно. Книга с `format_version` ≠ 1 — отказ.
16. **SCHEDULE: ячейки чужого режима не читаются** ([[feat-033 workbook-input-format|FEAT-033]] решение 61, 2026-10-17): строка BHP — только BHP target, строка OIL_RATE — Oil-rate target и Minimum BHP; остальные заполненные ячейки молча пропускаются, как режим последней строки (решение 8). Из плана FEAT-033 (П6): единицы → СИ — `gpn_multiphase_solver/io/workbook_format.UNIT_TO_SI`; поля вне книги — `NOT_FROM_WORKBOOK`, вычисляемые — `DERIVED`; проверка значения строки — `Param.accepts`. Из аудита 1 FEAT-033: первая строка SCHEDULE — $t = 0$ (раскладка FEAT-033, раздел 2.5; проверка Excel `A2 = 0`), иное — отказ с адресом ячейки; XlsxWriter пишет числа с 16 значащими цифрами (К16 плана FEAT-033), поэтому демо-числа генератора — с 15 цифрами ([[feat-033 workbook-input-format|FEAT-033]] решение 63): ячейка книги генератора равна литералу `workbook_template.DEMO_*` бит в бит, и CSV перевода шаблона — переводу литералов в СИ. Сам перевод не округляет: в ячейках — то, что хранит Excel.

## 1. Сводка (предварительно)

- **Суть:** книга → словарь конфига в СИ + три CSV в каталог; подкоманда `gpn-solver convert книга.xlsx каталог`.
- **Модули (предварительно):** `gpn_multiphase_solver/io/` (перевод по таблице полей FEAT-033), `cli.py` (подкоманда `convert`).

## 2. Контекст

### 2.1. Как конфиг и таблицы проверяются сейчас (на `546e9f2`)

- `load_config` (`io/config.py`): `json.load` → словарь; на словаре — только структура: обязательные секции, удалённые ключи ([[DEBT-008]]), формы `history` (`_expand_history`, [[FEAT-018]]). Словарь → dataclass-секции: неизвестный ключ — ошибка распаковки. Типы, конечность, пределы — `_validate` на `SimulationConfig` ([[DEBT-051]], [[DEBT-056]]).
- Таблицы: в конфиге — имена файлов (`pvt.oil_pvt_file`, `pvt.gas_pvt_file`, `relperm.file`) относительно папки конфига; `load_config` их не открывает. Читает и проверяет фабрика при сборке решателя: `create_pvt` → `_read_numeric_csv` (столбцы, числа, пределы — [[DEBT-044]]) → `_check_pvto_branches` ([[DEBT-038]]), `_check_gas_pvt_table`, `_check_rs0_in_table`; `create_relperm` → `_check_relperm_table`; затем согласованность PVT ([[BUG-019]]) и недонасыщенный старт ([[BUG-017]]).
- Перевод в файлы проходит оба этапа без изменений — ни одна проверка не дублируется и не обходится. Рефакторинг загрузчика (`config_from_dict`, таблицы в памяти) **не нужен** — он понадобился бы, только если бы таблицы шли в решатель из памяти.

### 2.2. Столбцы CSV, которые ждёт фабрика

| Файл | Столбцы (СИ) | Из книги |
|---|---|---|
| `oil_pvt.csv` | `Rs_sm3_sm3, pressure_Pa, Bo, mu_o_Pa_s` | OIL_PVT: бар × 1e5, сП × 1e-3 |
| `gas_pvt.csv` | `pressure_Pa, Bg, mu_g_Pa_s` | GAS_PVT: бар × 1e5, сП × 1e-3 |
| `relperm.csv` | `Sg, kro, krg` | RELPERM: без перевода |

В конфиг: `pvt.model = "table"`, `relperm.model = "table"`, имена файлов.

### 2.3. Множители единиц

`gpn_multiphase_solver/units.py`: `BAR_TO_PA` = 1e5, `MD_TO_M2` = 9.869233e-16, `CP_TO_PA_S` = 1e-3, `DAY_TO_S` = 86400, `MIN_TO_S` = 60. Кроме них: 1/бар → 1/Па (× 1e-5), К/МПа → К/Па (× 1e-6), кДж/кг → Дж/кг (× 1e3), м³ст/сут → м³ст/с (÷ 86400), **часы → с (× 3600) для `dt_integration` и `dt_after_control_change`** (решение пользователя 2026-10-15, [[feat-033 workbook-input-format|FEAT-033]] решение 18). $(\rho c_p)_s = \rho_s c_s$.

Составные поля ([[feat-033 workbook-input-format|FEAT-033]], решения 33, 49): `rock.rho_cp_solid` = $\rho_{ma}c_{ma}$; `rock.porosity` = $\varphi_{ref}\,e^{c_r(p_0 - p_{ref})}$ — $c_r$ в 1/Па, давления в Па, после перевода единиц.

Проверки чисел книги (FEAT-033 раздел 2.6, решение 50) перевод повторяет сам: при вставке через буфер обмена Excel их не запускает. Пределы те же, что у `_validate`, кроме плотностей при ст. у.: у программы предела нет, в книге — > 0.

Перевод не точен в последнем разряде: в конфиге примера 18 `rock.compressibility` = 4.5000000000000005e-10 (4.5e-5 1/бар × 1e-5); $h_0$ = 0.11 с из часов — 0.10999999999999999 или 0.11000000000000001 с. На расчёт не влияет ($h_0$ округляется вниз до $dt/2^m$).

### 2.4. Точность

Числа в JSON и CSV — через `repr` (у Python точное обратное чтение). Значения в инженерных единицах после перевода в СИ не обязаны быть «круглыми» (1 мД = 9.869233e-16 м²) — побитовое совпадение с конфигами примеров, заданными в СИ, не гарантируется и не требуется (примеры независимы).
