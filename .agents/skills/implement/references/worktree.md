# Работа в worktree

- Основной каталог остаётся на базовой ветке. Проверка точной базы выполняется до предварительного коммита и создания ветки. Пути для Git передаются явно, без `git add .` и `git add -A`. При коммите указывай те же пути, чтобы не захватить чужой индекс.
- Общие файлы vault – реестры `vault/roadmap/*.md` и `vault/00-home/index.md`. Их предусмотренный предварительный коммит включает файл целиком. Планы, заметки и материалы других задач не включаются автоматически. Чужой черновик, на который ссылается реестр, не блокирует этот коммит и остаётся незакоммиченным до своей очереди.
- Пробы текущей задачи запускай из её worktree, проверяя пути импортированных модулей. Воспроизводимые скрипты хранятся в `vault/issues/<id-lowercase>/probes/`. Игнорируемые `.npz` и графики не попадают в Git и могут исчезнуть при удалении worktree.
- Не используй общий `git stash` как средство изоляции сессий. Не выполняй `reset`, `checkout --`, очистку или удаление пользовательских изменений без соответствующего разрешения.
- При возобновлении сверяй план, статус, ветку, журнал коммитов и фактические незакоммиченные файлы. Отмечай уже выполненные проверки и повторяй только те, на которые повлияли последующие изменения или есть иные обоснованные причины.
- Проверочные команды решателя, прототипа, документации и эффект очистки результатов берутся из `.agents/project/overview.md` и плана. Тесты оболочки не заменяют тесты изменённого прототипа.
