## Описание

Инженеры заказчика будут задавать параметры расчёта книгой `.xlsx`: одна книга — один расчёт. JSON остаётся каноническим форматом, книгу в него переводит FEAT-035. Задача FEAT-033 — **формат книги версии 1**: листы, строки, ключи, единицы, правила пустых ячеек, смысл строк SCHEDULE. Сюда же входят **таблица полей в пакете**, общая для генератора шаблона и для перевода, команда **`gpn-solver template путь.xlsx`** и книга генератора с демонстрационными значениями `numerical_solver/configs/INPUT_TEMPLATE_v1.xlsx`.

Исходный материал — черновик руководителя `numerical_solver/configs/INPUT_TEMPLATE_THERMAL_v1_14.10.2026.xlsx`: книга прототипа `INPUT_TEMPLATE.xlsx` (листы MODEL, SCHEDULE, OIL_PVT, GAS_PVT, RELPERM, COMMENTS) плюс лист THERMAL. Черновик не окончательный: формат дорабатываем и исправляем сами (решение пользователя 2026-10-15). Черновик в git не коммитится (решение 56), его значения уже перенесены в план.

## Мотивация

Поставка заказчику (FEAT-031, #114) ждёт цепочку ввода книгой: **FEAT-033** (формат, шаблон) → FEAT-034 (разбор ячеек) → FEAT-035 (перевод в конфиг) → FEAT-036 (расчёт по книге). Без таблицы полей FEAT-035 не знает, какие строки, единицы и пределы ждать. Без генератора у инженера нет актуального шаблона.

## Физическое/математическое обоснование

Новых формул в решателе нет. Перевод книги считает два поля конфига из пар значений книги:

- **Пористость при p₀** — точно для закона решателя φ(p) = φ₀·exp(c_r(p − p₀)):
  φ₀ = φ_ref·exp(c_r·(p₀ − p_ref)) → `rock.porosity`. Формула — из сообщения `_REMOVED_KEYS["rock"]["p_ref"]` (`io/config.py`). Условие φ₀ ≤ 1 проверяет `_validate`.
- **Объёмная теплоёмкость скелета** — (ρc_p)_s = ρ_ma·c_ma → `rock.rho_cp_solid`; определение под `eq:main_rhocpeff` (`problem_statement.tex`). Множитель (1 − φ₀) — в решателе, книга задаёт свойства минерального скелета (`eq:main_rhocpeff`, `eq:lambda_eff`).

Множители единиц в СИ: mD × `MD_TO_M2` (`units.py`); bar × 10⁵; 1/bar × 10⁻⁵; K/MPa × 10⁻⁶; kJ/kg × 10³; h × 3600.

Проверка демонстрационных значений (пересчитана при открытии issue):

- Теплоёмкость α-кварца по формуле Шомейта NIST (A = −6.076591, B = 251.6755, C = −324.7964, D = 168.5604, E = 0.002548; t = T/1000; M = 0.060084 кг/моль): 44.57 Дж/(моль·К) = 742 Дж/(кг·К) при 298 К, 49.47 Дж/(моль·К) = 823 Дж/(кг·К) при 350 К. Взято 820.
- μ_JT,o = v(αT − 1)/c_p (`eq:muJT_def`) при ρ_o ≈ (800 + 50·0.727)/1.139 ≈ 734 кг/м³, α ≈ 10⁻³ 1/К, T = 350 К, c_p = 2365 Дж/(кг·К): −0.37 К/МПа. Это согласуется с −0.4 черновика в трактовке К/МПа.
- λ_eff = (1 − φ₀)λ_s + φ₀(…) (`eq:lambda_eff`) — среднее арифметическое, верхняя оценка. С λ_s = 2.5 Вт/(м·К) λ_eff ≈ 2.0 Вт/(м·К). С теплопроводностью кварца 7.7 вышло бы ≈ 6.2 против измеряемых 2–4 у насыщенного песчаника. Поэтому Comment у λ_ma объясняет, какое значение вводить.
- Ветвь R_s = 60 из `regression/inputs/T08c.xlsx` прототипа (сверена авторами прототипа с CMG IMEX) продолжает ряд p_b = 24.5, 45.5, 82.8, 116.9, 149.1, 180 → 210.85 бар. Условие «p_b растёт с R_s» (`_check_pvto_branches`, DEBT-038) выполнено.

## Предлагаемый API

Имена модулей и функций — предварительные, утверждаются при `/plan-feature`.

- **Таблица полей** — модуль в `gpn_multiphase_solver/io/` (например `workbook_format.py`):
  - `FORMAT_VERSION = 1`;
  - строка поля: лист, ключ (путь поля конфига, `rock.permeability`), подпись «Название (символ)», единица (ASCII), множитель или функция перевода в СИ, обязательность или умолчание, проверка Excel (тип, пределы), демонстрационное значение, Comment;
  - описание табличных листов: заголовки столбцов с единицами (`Rs, Sm3/Sm3`, `Pressure, bar(a)`, …), столбцы CSV в СИ;
  - список полей конфига «не из книги» с причиной.
- **Генератор** — `write_template(path)`. Использует XlsxWriter: листы, столбцы **Key | Parameter | Value | Unit | Comment**, защита листа без пароля (Key и Unit заблокированы), выпадающие списки (Control mode, Jacobian mode, Linear solver), проверки данных на числовые ячейки с пределами программы (раздел 2.6 плана), демонстрационные значения, лист COMMENTS.
- **Команда** `gpn-solver template путь.xlsx` (и `python -m gpn_multiphase_solver template …`) — подкоманда в `cli.py`. Импорт решателя, scipy и прототипа ей не нужен.

Раскладка листов версии 1 (утверждена 2026-10-15, решение 16):

- **MODEL** (14 строк): `format_version`, r_w, R_ext, h, k, φ_ref, p_ref, c_r, ρ_o,sc, ρ_g,sc, p_i, R_si, T_i, skin.
- **THERMAL** (10 строк): ρ_ma, c_ma, λ_ma, λ_o, λ_g, c_p,o, c_p,g, μ_JT,o, μ_JT,g, L.
- **NUMERICS** — все численные поля: N, Δt (h), h₀ (h, `none` — выкл.), `max_retries`, `newton_max_iter`, `max_active_set_iter`, `newton_cell_tol` (`none` — выкл.), `rs_switch_tol`, `sg_switch_tol`, `jacobian_mode`, `linear_solver`.
- **SCHEDULE**: `Time, day` | `Control mode` (BHP / OIL_RATE) | `BHP target, bar(a)` | `Oil-rate target, Sm3/day` | `Minimum BHP, bar(a)`. Строка k задаёт режим на [t_k, t_{k+1}]. Последняя строка — только момент завершения: заполненный режим в ней молча пропускается.
- **OIL_PVT**, **GAS_PVT**, **RELPERM** — заголовки черновика, сверяются точно.
- **COMMENTS** — как получить шаблон, заполнить и запустить.
- Листа OUTPUT нет: секция `output` — умолчания, заголовок — имя книги (FEAT-036).

### Найдено при открытии

1. **Удаление строки и защита листа противоречат друг другу.** По разделу 2.5 плана строку поля с умолчанием можно удалить, тогда действует умолчание. Но Key и Unit заблокированы (решение 37), а пользователь меняет только значения (решение 46). В Excel строку с заблокированной ячейкой на защищённом листе удалить нельзя, даже при разрешении «Удаление строк». Это проверить пробой при планировании. Тогда остаётся вопрос, что значит **пустая ячейка Value у поля с умолчанием**: умолчание или отказ. Решение 26 определяет пустую ячейку только для обязательных полей (отказ) и для полей с `null` (`none`).
2. **Поля конфига вне книги** — для теста «каждое поле — в таблице полей или помечено „не из книги“»: `grid.type`, `pvt.model`, `pvt.co_undersaturated`, `pvt.mu_o_undersaturated`, `pvt.oil_pvt_file`, `pvt.gas_pvt_file`, `relperm.model`, параметры Кори (`S_or`, `S_gc`, `n_o`, `n_g`, `kro_max`, `krg_max`), `relperm.file`, вся секция `output`. Поля `time.history` (из SCHEDULE), `rock.porosity` и `rock.rho_cp_solid` вычисляются из нескольких ячеек.
3. **Перезапись файла командой `template`.** Решение 53 говорит, что `gpn-solver template` перезаписывает книгу генератора в `configs/`. Для инженера та же команда может молча затереть заполненную книгу. Отказ при существующем файле (с ключом перезаписи) или перезапись — решить при планировании.
4. **Защита на SCHEDULE и табличных листах** не определена: строки там добавляет пользователь. Решение 37 касается листов «параметр–значение».
