## Описание

Поставка для расчётов в выпусках GitHub Releases (FEAT-038, DEBT-089) сейчас выкладывается пятью отдельными файлами: два колеса (`gpn_multiphase_solver-*.whl`, `radial_blackoil-*.whl`), два архива (`examples-vX.Y.Z.zip`, `docs-vX.Y.Z.zip`) и `README.md`. В то же время поставка для разработки (DEBT-089) оформлена как единый самодостаточный архив `gpn-multiphase-solver-X.Y.Z.zip`.

Такая асимметрия создаёт неудобства для пользователей расчётной поставки: после скачивания им приходится вручную распаковывать несколько вложенных zip-архивов (примеры и документацию). Кроме того, список ассетов в Releases перегружен отдельными файлами.

Решения пользователя (2026-11-03):
1. Объединить материалы поставки для расчётов в единый архив `gpn-multiphase-solver-wheels-X.Y.Z.zip`.
2. Внутри архива расчётов разместить:
   - `wheels/` – оба wheel-пакета;
   - `examples/` – расчётные примеры в уже распакованном виде (без примеров 18 и 23);
   - `docs/` – HTML-документацию Sphinx в уже распакованном виде (с `index.html`);
   - `README.md` – руководство пользователя в корне архива.
3. Сохранить текущее имя `gpn-multiphase-solver-X.Y.Z.zip` для архива поставки разработки.
4. Файл `README.md` оставить отдельным файлом рядом в Releases (для быстрого чтения в браузере) и вложить в каждый из обоих архивов.
5. Итоговый состав ассетов GitHub Release: ровно 3 файла проекта (`gpn-multiphase-solver-X.Y.Z.zip`, `gpn-multiphase-solver-wheels-X.Y.Z.zip`, `README.md`) плюс автоматические архивы исходников GitHub.

## Текущее состояние

Скрипт `tools/release.py` публикует в Releases шесть файлов (DEBT-089):
- `gpn-multiphase-solver-X.Y.Z.zip` – поставка для разработки (срез репозитория из метки через `tools/handover.py`);
- `gpn_multiphase_solver-X.Y.Z-py3-none-any.whl` – колесо решателя;
- `radial_blackoil-1.0.3+gpn.N-py3-none-any.whl` – колесо прототипа;
- `examples-vX.Y.Z.zip` – архив примеров;
- `docs-vX.Y.Z.zip` – архив HTML-документации;
- `README.md` – руководство.

Что плохо:
- расчётчик скачивает папку выпуска и должен выполнять несколько `Expand-Archive` (отдельно для примеров, отдельно для документации);
- в списке ассетов выпуска нет симметрии: разработка представлена одним архивом, а расчёты – пятью разрозненными файлами.

## Целевое состояние

1. `tools/release.py` формирует и загружает в Releases ровно 3 целевых файла:
   - `gpn-multiphase-solver-X.Y.Z.zip` – архив поставки для разработки (собирается `tools/handover.py`);
   - `gpn-multiphase-solver-wheels-X.Y.Z.zip` – архив поставки для расчётов с подкаталогами `wheels/`, `examples/`, `docs/` и файлом `README.md`;
   - `README.md` – отдельный файл руководства для чтения на GitHub.
2. Пользователь поставки для расчётов распаковывает один архив и сразу получает готовое рабочее место:
   - установка: `pip install (Get-ChildItem ...\wheels\*.whl).FullName`;
   - примеры и документация уже распакованы и готовы к использованию.
3. `numerical_solver/README.md` обновлён: шаги раздела «Поставка для расчётов» избавлены от промежуточных распаковок архивов.
4. Тесты упаковки (`tests/test_packaging.py`) проверяют новую структуру архива и соглашения выпуска.
