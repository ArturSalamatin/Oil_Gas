### План готов

План: `vault/plans/feat-020 oil-rate-control.md`. Ветка: `feat/feat-020/oil-rate-control`. Шагов: 14. Подтип: режим (ГУ на забое).

**Решения пользователя при планировании (2026-09-29):**
- `WellControl.boundary_pressure` удаляется: управление — только данные, его читают модули гидродинамики; энергия и `Simulator` берут p_wf только из `HydroResult.p_wf`.
- Замкнутое стационарное решение при управлении по дебиту — обращение квадратуры по дебиту последнего интервала (p_wf* из q_стац(p_wf*) = q_last; при недостижимом дебите — min_bhp).
- Расхождение по JT-вкладу забойной грани — отдельная запись BUG-015.

**Замер до реализации** (`vault/issues/feat-020/probes/plan_numbers.py`, управление по дебиту подставлено временной заглушкой):
- пример 14 (конфиг 12, q_k = 18·k м³ст/сут, k = 1…15, min_bhp = 1 атм): 360 подшагов без дробления, min_bhp не срабатывает, p_wf строго убывает 15.05 → 6.13 МПа, T(r_w) 350 → 345.81 К, дебит записей совпадает с расписанием точно, баланс энергии 1.2e-11;
- тест согласованности (прогон по давлению → его дебиты расписанием в прогон по дебиту): |Δp| ≤ 3.6e-3 Па, |ΔT| ≤ 1.4e-9 К, |ΔS_g| ≤ 8.8e-11;
- стационар при 270 м³ст/сут: p_wf* = 6.595 МПа против 6.130 МПа в расчёте на 15 сут — пласт при нарастающем дебите ещё не на стационаре.

**Поправка к описанию issue.** Утверждение «главный риск — температура: энергия считала бы с неверным p_wf» было неверным и исправлено в теле issue. JT-вклад забойной грани (`eq:QJT_disc`) входит с весом Φ⁺, а при добыче Φ < 0, поэтому p_wf на температуру не влияет вообще — энергии подставлялся p_wf = 1 атм вместо фактического, T побитово та же. Управление по дебиту влияет на T только через поля гидродинамики. Текст постановки (`problem_statement.tex:1697-1701, 1815-1823`) и docstring-и утверждают обратное — зарегистрировано как BUG-015 (не блокирует).
