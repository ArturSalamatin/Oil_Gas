# Ступень 4 без ограничения шага по R_s застревала на R_s = 0 — суточный останов проходил или нет по округлениям

**GitHub issue:** [#93](https://github.com/ArturSalamatin/Oil_Gas/issues/93) · план [[bug-024 stage4-rs-step-limit]]

**Наблюдение.** После [[BUG-022]] (условие сходимости по ячейке) суточный останов из развитой газовой зоны (конфиг 20: 10 сут добычи, затем 3 сут при $q_{oil} = 0$, `dt_integration` = 1 сут) перестал проходить при штатной глубине дробления `max_retries` = 9: отказ на $dt/512$ = 169 с при $t$ = 10.0781 сут. Без условия по ячейке проходил, при `max_retries` = 11 — тоже. Запись реестра и issue вывели отсюда, что виновато условие по ячейке.

**Ложный след.** Трасса итераций ступени 4 (`vault/issues/bug-024/probes/stage4_failure.py`) показала: на всех отказавших подшагах Ньютон ни разу не достигает даже глобального порога $\|F\|_\infty \le$ atol + rtol·$\|F_0\|_\infty$ — условие по ячейке до проверки не доходит. BUG-022 только сдвинул траекторию: решения шагов добычи стали другими, и к останову расчёт пришёл с другим состоянием. На коде до исправления исход 20B при 1 сут скачет без закономерности:

| условие по ячейке | 1e-5 | 1e-6 | 1e-7 | 1e-8 | 1e-9 | выкл. | выкл., atol 5e-12 |
|---|---|---|---|---|---|---|---|
| итог | ✓ | ✗ | ✓ | ✗ | ✗ | ✓ | ✗ |

Средние «37.8 итерации при лимите 40» не доказывали исчерпание лимита: при любом отказе `_newton_switching` пишет `iterations = max_iter` ([[DEBT-061]]).

**Механизм.** В `_newton_switching` давление и $S_g$ двухфазных ячеек ограничены поячеечно ($|\Delta p| \le 0.3p$, $|\Delta S_g| \le 0.2$), а $R_s$ недонасыщенных — нет: отрицательный только обрезается до 0. Замер: шаги Ньютона по $R_s$ до $\pm1.7\cdot10^{4}$ м³ст/м³ст за итерацию при самих $R_s$ 90–300; обрезание до 0 — десятки и сотни раз за решение, в том числе в сошедшихся. Два вида отказа:
- **застой** — недонасыщенная ячейка у забоя ($R_s$ 90–115 при $R_s^{sat}$ = 261) стоит на $R_s = 0$, Ньютон каждую итерацию требует $\Delta R_s \approx -45$, отсечка возвращает 0; $\|F\|/tol \approx 2\cdot10^{6}$ не меняется 30 итераций;
- **хаос** — давление итераций до 433 бар, десятки переключений фаз на итерации.

**Исправление.** $|\Delta R_s| \le 0.2\max(R_s^{sat}(p), 1)$ — аналог `ds-max` для $S_g$: та же доля допустимого диапазона $0 \le R_s \le R_s^{sat}(p)$. В перечне параметров Ньютона руководства OPM Flow 2025-10 такого ограничения нет (есть `dp-max-rel` 0.3, `ds-max` 0.2). Чувствительность на 20B: 0.1–0.5 проходит, 1.0 — нет. Отвергнуты (решение пользователя): штатный `max_retries` = 11 и лимит ступени 4 40 → 80 — сценарий проходят, причину не трогают.

| сценарий, 1 сут, `max_retries` 9 | до | после |
|---|---|---|
| 20B при порогах 1e-6…1e-9, без условия, atol 5e-12 | ✗ на 5 из 6 | ✓ все, 5–25 с |
| 19B / 21B / 20A | ✗ / ✓ 111 с / ✗ | ✓ 8 / 5 / 6 с |
| 20B при 3600 с | ✓ 188 с, 174 отказа ступени 4 | ✓ 33 с, 0 |

**Цена.** 20 примеров из 22 — побитово; 16 — на уровне допуска Ньютона ($10^{-10}$ бар); 17 — часы останова больше не дробятся (41 отказ → 0, расчёт 101 → 69 с), история сдвигается на погрешность шага ($T(r_w)$ на 16 сут −8.9 мК, на 30 сут 377.3090 → 377.3078 К). Первые сутки добычи сценария BUG-018 ($R_{s,0}$ = 500) — на один отказ и подшаг больше: там ступень 4 сходилась «через» отсечку $R_s = 0$, и так ведут себя все проверенные формы правки строки обновления. Регрессия прототипа побитово: ступень 4 в собственных расчётах прототипа выключена.

**Где в коде.** `numerical_solver/HydroSolverPrototype/Prototype_1.0.3/radial_blackoil/blackoil.py`, `RadialBlackOilModel._newton_switching` (аргумент `dr_rel`, строка обновления `xn`). Тесты: `tests/test_prototype_phase_switching.py` — `TestRsStepLimit` (ограничение и неизменность малых шагов), `TestDailyShutin` (суточный останов при `max_retries` = 9).
