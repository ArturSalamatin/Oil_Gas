## Описание

Сжимаемость породы `rock.compressibility` ($c_r$, 1/Па) в JSON-конфиге проверяется только на тип и конечность. Отрицательное значение принимается молча и уходит в прототип как есть, хотя собственный загрузчик книги прототипа $c_r < 0$ отвергает. Физически $c_r = (1/\varphi)\,d\varphi/dp \ge 0$; отрицательное значение — почти наверняка ошибка знака или путаница в определении (через объём скелета или породы вместо порового). При $c_r < 0$ коэффициент уравнения давления $C_p$ может стать отрицательным — та же некорректность, что разобрана в BUG-019.

Приоритет низкий: во всех конфигах проекта $c_r \ge 0$ (22 конфига — ноль, пример 18 — $4.5\cdot10^{-10}$ 1/Па). Задача — закрыть дыру в проверке ввода, а не исправить наблюдаемый сбой.

## Текущее состояние

- `_validate` (`io/config.py:519-523`) проверяет у породы только `porosity` ∈ (0, 1] и `permeability` > 0. `compressibility` (`:56`, по умолчанию 0.0) проходит лишь `_check_numeric_fields` (DEBT-051): тип и конечность, знак не смотрится.
- Фабрика передаёт значение прототипу без проверки: `factory.py:420-424`, `CompressibleRock(cr_per_bar = c_r·1e5)`; закон $\varphi(p) = \varphi_0\,e^{c_r(p - p_0)}$.
- Предупреждение об отрицательной сжимаемости `_warn_negative_compressibility` (`factory.py:308`, BUG-019) смотрит только флюиды: $c_{ot}$, $c_g$, $c_o$.
- Загрузчик книги прототипа отвергает: `HydroSolverPrototype/Prototype_1.0.3/radial_blackoil/input_reader.py:49`, «MODEL: Rock compressibility cr must be >= 0». Путь GPN (JSON → `load_config` → `from_config` → `CompressibleRock`) этот загрузчик не использует. Сам `CompressibleRock` (`radial_blackoil/rock.py:2-6`) знак не проверяет.
- Конвертер книги примера 18 (`examples/18_prototype_input/prototype_input.py:175`) переносит `Rock compressibility cr` без проверки знака.

**Почему это опасно.** Коэффициент при $\partial p/\partial t$ (`problem_statement.tex:603`, сводная форма `eq:Cp`):

$$C_p = \frac{\varphi}{B_g}\bigl(c_r + S_o\,c_{ot} + S_g\,c_g\bigr).$$

В недонасыщенной зоне $C_p \propto c_r + c_o$. Для недонасыщенной нефти примеров $c_o \sim 10^{-9}\ldots3\cdot10^{-9}$ 1/Па (README примеров: $3.3\cdot10^{-9}$), т. е. ошибка знака у $c_r$ того же порядка уже даёт $C_p < 0$: уравнение давления становится обратным уравнением теплопроводности — механизм BUG-019 (отказы шага, зависимость результата от $\Delta t$). При малых $|c_r|$ расчёт пройдёт молча с поровым объёмом, падающим с давлением. Условие корректности в постановке (`problem_statement.tex:605-606`) записано «при $c_r = 0$» — то есть неявно предполагает $c_r \ge 0$.

**Не замерено:** поведение решателя при $c_r < 0$ (например, конфиг примера 18 с $c_r = -4.5\cdot10^{-10}$ и $-4.5\cdot10^{-9}$ 1/Па). Утверждение «при $c_r \approx -c_o$ — отказы шага» — вывод по аналогии с BUG-019, не замер.

## Целевое состояние

- `load_config` отвергает $c_r < 0$ с `ValueError`, в тексте — имя поля `rock.compressibility`, полученное значение и определение $c_r$. $c_r = 0$ и $c_r > 0$ проходят как раньше.
- Числа всех 22 конфигов и истории примеров не меняются (проверка только отсекает ввод).
- Документы проверки ввода перечисляют новое ограничение: P8 §5 (строка `_validate`, «порода») и `json-config-schema.md` (строка «Ограничения» секции `rock`).

## Анализ вариантов решения

### Вариант 1 — отказ в `_validate` (рекомендуется)

- **Суть:** после проверок `porosity` и `permeability` — `if r.compressibility < 0: raise ValueError(...)`. NaN сюда не доходит: его раньше отсекает `_check_numeric_fields` (DEBT-051), так что сравнение `< 0` безопасно.
- **Изменения:** `config.py` (~3 строки + комментарий о физике и о прототипе), `test_config.py` (2–3 теста), P8 §5, `json-config-schema.md`.
- **Плюсы:** поведение совпадает с прототипом; отказ на этапе чтения конфига, с именем поля JSON; та же схема, что у остальных полей породы.
- **Минусы:** не покрывает конфиг, собранный в коде, и прямой вызов прототипа — но это общее свойство всех проверок `_validate` (P8 §5: «Проверки — только на пути JSON → `load_config` → `from_config`»).

### Вариант 2 — предупреждение вместо отказа

- **Суть:** запись в журнал, расчёт продолжается (как у `_warn_negative_compressibility` для флюидов).
- **Плюсы:** не ломает гипотетические конфиги с $c_r < 0$ (таких в проекте нет).
- **Минусы:** прототип такой ввод отвергает; при $c_r < -c_o$ задача некорректна ($C_p < 0$), предупреждение лишь откладывает отказ шага с непонятной причиной. Аналогия с флюидами неточна: там $c < 0$ — свойство таблицы на части диапазона давлений, здесь — одно число, заведомо ошибочное при любом знаке минус.

### Вариант 3 — проверка в `CompressibleRock` прототипа

- **Суть:** `ValueError` в конструкторе `rock.py` при `cr_per_bar < 0` (код прототипа править разрешено).
- **Плюсы:** покрывает все пути, включая прямой вызов прототипа.
- **Минусы:** срабатывает в `from_config`, позже `load_config`, и без имени поля JSON; дублирует `input_reader.py:49`. Как самостоятельное решение — хуже варианта 1; как дополнение — решить в плане.

### Вариант 4 — отказ в конвертере книги примера 18

- **Суть:** в `convert` проверка знака с именем параметра книги «Rock compressibility cr», как у прочих отвергаемых полей.
- **Плюсы:** сообщение в терминах книги.
- **Минусы:** после варианта 1 избыточно: полученный `config.json` всё равно не пройдёт `load_config`, т. е. молчаливой подмены задачи нет — а именно её ловят нынешние отказы конвертера (`:128-134`).

**Рекомендация:** вариант 1. Варианты 3 и 4 — по решению при планировании.

**Верхняя граница не нужна (проверить в плане).** При $c_r \ge 0$: $\varphi(p) \le \varphi_0 \le 1$, пока $p \le p_0$. На контуре задано $p_0$, скважина только добывает ($q \ge 0$), так что $p \le p_0$ следует из принципа максимума для параболического уравнения с $C_p \ge 0$ — и при добыче, и при останове (давление восстанавливается к $p_0$ снизу). Это рассуждение, не замер; в плане сверить $\max p \le p_0$ по историям примеров 16 и 17 (останов).

## План решения

1. **Подготовка (baseline).** Число тестов (`pytest tests/ --collect-only -q`) и быстрый уровень (`-m "not slow"`) на базе. Проба красного состояния: конфиг примера 18 с $c_r = -4.5\cdot10^{-10}$ и $-4.5\cdot10^{-9}$ 1/Па — `load_config` проходит, что делает расчёт (короткий интервал, не сотни суток); выводы — в `vault/issues/debt-068/probes/`. Проверка $\max p \le p_0$ на останове по готовым историям.
2. **Реализация.** Тесты в `TestValidationRock`: $c_r < 0$ → `ValueError` с `compressibility` в тексте; $c_r = 0$ и $c_r = 4.5\cdot10^{-10}$ проходят. Затем проверка в `_validate` с комментарием (физика $c_r$, связь с $C_p$, ссылка на `input_reader.py:49`). Документы: P8 §5, `json-config-schema.md` (включая `porosity ≤ 1`).
3. **Верификация.** Быстрый уровень зелёный, число тестов выросло на число новых; все 22 конфига проходят `load_config` (это покрывают существующие тесты примеров). Полный уровень — не обязателен: расчётный код не меняется.
