# BUG-023: эталон JT-вклада в сверке матрицы энергии — перепад давления по обе стороны грани вместо одного давления «за гранью»

## Кратко

- **Ошибка — в тесте, не в решателе.** Эталон `test_energy_matrix_examples.py` считает JT-вклад ячейки $j$ по eq:QJT_disc (`problem_statement.tex:1423-1433`):
  $$\mathcal{J}_j = \sum_\alpha\Bigl[\mu_{JT,\alpha}^{j-1/2}\,\Phi^{+}_{\alpha,j-1/2}\,(p_j - p_{j-1}) + \mu_{JT,\alpha}^{j+1/2}\,\Phi^{-}_{\alpha,j+1/2}\,(p_{j+1} - p_j)\Bigr].$$
  Вспомогательная `_ref_jt_face(f, …)` возвращает одно давление «за гранью». Для внутренней грани это `p[f]` — давление ячейки справа. Оно годится для правой грани ячейки $f-1$, но не для левой грани ячейки $f$: там эталон получает $p_j$ вместо $p_{j-1}$, `dp_left = p[j] - p[j] = 0`, и первое слагаемое теряется. Решатель (`TridiagEnergySolver.compute_jt`, `tridiag.py:389-390, 423`) берёт `p_left[j] = p[j-1]` — верно.
- **Откуда.** Внесено рефакторингом `bcbd403` (2026-09-23, «fix»): до него эталон считал `p_left = p_wf if j == 0 else p[j - 1]`, после — свёл три типа граней в `_ref_jt_face` с одним давлением. Сверка этого не заметила: на 20 примерах из 22 $\Phi^+ \equiv 0$ на внутренних гранях, и потерянное слагаемое умножается на ноль. У 16 и 17 на останове $\Phi^+ > 0$ на уровне шума Ньютона (только нефть, $Q_o$ до 1.4e-11 м³/с), потерянный вклад — до 2.7e-15 Вт, не больше 3e-5 допуска сверки (замер аудита 2026-10-10: `audit_phi_plus.py`, `audit_lost_jt.py`). Запись реестра и issue #86 («на всех 22 примерах $\Phi^+ \equiv 0$») этим уточнены.
- **Проявление.** Аудит плана [[VAL-005]]: на конфиге примера 18 шум Ньютона +2.5e-18 м³/с (от скважины) на фронте волны давления включает $\Phi^+ > 0$. Решатель даёт $d_{68}$ = 1.18e-26 Вт, эталон — 0 при нулевой сумме модулей слагаемых. Допуск равен нулю, и `test_matrix_matches_reference[18_prototype_input]` падает. Сообщение при этом указывает не туда: «max = nan в ячейке 69» (0/0 даёт `nan`, `np.argmax` берёт первый `nan`), хотя упала ячейка 68.
- **Исправление** (решение пользователя 2026-10-10 — вариант 2 + 3 + 4 issue #86):
  1. `_ref_jt_face` возвращает давления **по обе стороны** грани: $(p_{wf}, p_0)$ на забое, $(p_{f-1}, p_f)$ на внутренней, $(p_{N-1}, p_{ext})$ на контуре. `_ref_jt` для обеих граней берёт $\Delta p_f = p^{справа} - p^{слева}$;
  2. новый быстрый тест `test_ref_jt_outflow_matches_hand_formula`: синтетика $N = 4$ с $\Phi^+ > 0$, эталон и `compute_jt` против eq:QJT_disc, посчитанного вручную;
  3. сообщение сверки $d$ называет первую упавшую ячейку и её $d$, $d^{эт}$, допуск;
  4. docstring модуля и `_ref_convective` перестают утверждать, что сверка на конфигах проверяет ветки, которые конфиги не включают.
- **Замерено при планировании и аудите** (пробы `vault/issues/bug-023/probes/`; планирование — база `f99cdbe`, аудит — `031d6d8`; расчётная часть кода на них одна: DEBT-052 менял только vault, DEBT-053 — комментарии тестов и неиспользуемый параметр `Simulator(output_config)`):

### 1.2. Цепочка

1. `build_reference` (`:617-677`) зовёт `_ref_jt` (`:653-654`) с полями `hydro_result` и `p_wf` шага.
2. `_ref_jt` (`:347-413`), цикл по ячейкам `:388-411`: левая грань — `_ref_jt_face(j, …)`, правая — `_ref_jt_face(j + 1, …)`.
3. `_ref_jt_face` (`:320-344`) для $0 < f < N$ — `return p[f], …` (`:344`). Для $f = j$ это $p_j$.
4. `dp_left = p[j] - p_left` (`:399`) = 0 → `mu_Phi_left * dp_left` = 0 при любом $\Phi^+$.
5. Эталон $d^{эт}$ теряет $\sum_\alpha \mu\Phi^+\Delta p$; `_ref_d_scale` (`:597-614`) берёт $|J|$ из того же неполного $J$. При $\Phi^+ > 0$ и прочих нулевых слагаемых (дальняя зона, $\theta = T - T_{ext} = 0$, DEBT-043) допуск ноль, и любой ненулевой вклад решателя роняет сверку (`:726-730`).
6. Сообщение: `d_err / d_lim` = inf в упавшей ячейке и nan (0/0) там, где всё нулевое. `np.max` → nan, `np.argmax` → первый nan.

Забой и контур не затронуты: там значение «за гранью» одно ($p_{wf}$ — только левая грань ячейки 0, $p_{ext}$ — только правая грань ячейки $N-1$), и `_ref_jt_face` возвращает верное.

### 1.3. Целевое состояние

- `_ref_jt` совпадает с eq:QJT_disc при любых знаках $\Phi_\alpha$ на всех гранях; на синтетике — [−115, −400, −840, −2040] точно.
- На 20 примерах эталон по значению прежний: при $\Phi^+ = 0$ на внутренних гранях левый вклад нулевой и в старом, и в новом эталоне; на забое и контуре перепады те же выражения (`p[0] - p_wf`, `p_ext - p[N-1]`). У 16 и 17 новый эталон добавляет потерянный шумовой вклад: 267 и 124 вызова, до 1.4e-15 и 2.7e-15 Вт, не больше 2.6e-5 и 3.0e-5 допуска (`audit_lost_jt.out.txt`). Сверка проходит и со старым эталоном (база), и с новым (подменой: 25 passed). Ожидание — 22 из 22 passed.
- Сообщение сверки $d$ называет первую ячейку с `~(d_err <= d_lim)` и печатает $d$, $d^{эт}$, допуск. NaN в $d$ или $d^{эт}$ по-прежнему валит сверку.
- Docstring не утверждают, что сверка на конфигах проверяет ветки, которые конфиги не включают.

### 1.5. Решение о размещении теста

Тест — в `test_energy_matrix_examples.py`, сразу после `_ref_jt`: `_ref_jt` закрытая функция модуля, тест проверяет именно эталон, и рядом с функцией его найдёт тот, кто её правит. Не в разделе A (сверка на конфигах, slow): рядом с `:684-688` правят VAL-005 и [[DEBT-048]]; область `:380-450` не правит ни одна задача с готовым планом.

`compute_jt` вызывается на `TridiagEnergySolver(None, None, None)`: метод — функция полей, `self._grid`, `self._pvt`, `self._rock` в нём не читаются (`tridiag.py:361-431`). Сетка, PVT и порода только загромоздили бы тест. Если метод когда-нибудь начнёт их читать, тест упадёт громко (`AttributeError` на `None`) — это сигнал, а не тихая ошибка.

**Забойная грань с $\Phi^+_{1/2} > 0$ (аудит 2026-10-10).** Синтетика задаёт $\Phi_o[0] > 0$ — нефть идёт и через забой. Такой приток постановка не определяет (ssec:bc_disc; `_ref_convective` запрещает его assert-ом), а $\mu_{JT}$ забойной грани и решатель, и эталон берут из ячейки 0 «при любом знаке: слева ячеек нет» (`tridiag.py:392-394`). Слагаемое $\mathcal{J}_0 \ni 1\cdot1\cdot5$ закрепляет это **соглашение**, а не физику. Оставлено намеренно: пара $(p_{wf}, p_0)$ новой `_ref_jt_face` иначе не проверялась бы ничем (на пути `build_reference` $\Phi^+[0] \equiv 0$), а путь энергии с $\Phi^+_{1/2} > 0$ уже закреплён тестом `test_energy.py:1451` (`test_inflow_temperature_depends_on_hydro_pwf`). Соглашение названо в комментарии теста и в docstring `_ref_jt_face`: если постановка определит приток через забой, меняется `J_hand[0]`.

### 1.6. Подводные камни

- ✅ **Побочные эффекты.** `_ref_jt_face` вызывается только из `_ref_jt` (`:392`, `:394`; grep по `*.py` проекта). `_ref_jt` и `build_reference` — сигнатуры и возврат прежние; пробы, которые их импортируют (`val-005/probes/audit_matrix_d.py`, `debt-043/probes/audit3_planned_tests.py`, пробы FEAT-023/024 — `build_reference` без `with_scale`), не затрагиваются.
- ✅ **Граничные случаи.** $N = 1$: грани 0 и 1 = $N$, ветка внутренней грани не исполняется, `p[N - 1]` = `p[0]`. Порядок проверок в `_ref_jt_face` прежний (`f == 0`, затем `f == N`). Знаки нуля: при $\Phi^+ = 0$ новое `0.0 * dp` может дать `-0.0` вместо `0.0` — сумма с другим слагаемым и сравнения от этого не меняются.
- ✅ **Производительность.** Цикл Python тот же, один лишний элемент кортежа; сверка — внутри slow-теста, время прежнее.

**Файл:** `numerical_solver/tests/test_energy_matrix_examples.py` (существующий), быстрый уровень.
