## Описание

В модели Black Oil вязкость нефти зависит от двух независимых аргументов: $\mu_o = \mu_o(p, R_s)$. В недонасыщенной нефти ($p > p_b(R_s)$) при фиксированном $R_s$ вязкость растёт с давлением. В `StandingFullPVT` вязкость зависит только от $R_s$ (Беггс–Робинсон). Ветвь для $p \ge p_b(R_s)$ формально есть, но обе ветви `np.where` возвращают одно и то же значение `_mu_o_beggs(Rs)`, так что ветвь ничего не делает.

Нужно добавить зависимость $\mu_o(p)$ выше $p_b$ при фиксированном $R_s$.

## Мотивация

- Обнаружено 2026-10-03 при разборе подписи `pvt.png` примера 20: $B_o$ выше $p_b$ убывает по $c_o$, а $\mu_o$ остаётся горизонтальной. Подпись `pvt_plot._describe` сейчас прямо оговаривает это ограничение («$\mu_o$ от $p$ — только через $R_s$»).
- Фаза: PVT-модель / ядро.
- Приоритет: низкий, эффект в единицах процентов (оценка ниже).

## Физическое/математическое обоснование

**Корреляция-кандидат: Васкес–Беггс (1980).**

$$\mu_o(p, R_s) = \mu_{ob}(R_s)\,\left(\frac{p}{p_b(R_s)}\right)^{m}, \qquad m = 2.6\,p^{1.187}\exp\!\left(-11.513 - 8.98\cdot10^{-5}\,p\right),\quad p\ \text{в psia},$$

где $\mu_{ob}(R_s)$ — Беггс–Робинсон при том же $R_s$. Этот вид совпадает с кодом, который уже есть в базе знаний: `vault/knowledge/decisions/pvt-корреляции-стендинг.md:114-134`. Первоисточник (Vasquez M., Beggs H.D., JPT, 1980) в `Refs/` отсутствует, коэффициенты по нему не сверялись.

**Свойства на стыке $p = p_b$:**
- $\mu_o$ непрерывна: $(p_b/p_b)^m = 1$;
- $\partial\mu_o/\partial p|_{R_s}$ имеет излом: ниже $p_b$ производная равна 0, выше — $m\,\mu_{ob}/p_b$. Тот же тип излома уже есть у $B_o$ при $c_o > 0$ (`standing.py:96-100`).

**Оценка эффекта на примере 20** (проверено расчётом, $\rho_{o,ст} = 800$, $T_0 = 380$ К, $R_{s,0} = 300$):

| $p$, МПа | $m$ | $\mu_o/\mu_{ob}$ |
|---|---|---|
| $p_b = 30.29$ | 0.3695 | 1.0000 |
| $p_0 = 33$ | 0.3949 | 1.0344 |

Здесь $\mu_{ob} = 0.200$ сП, $\partial\mu_o/\partial p$ при $p_b$ равна $2.44\cdot10^{-12}$ с. Эквивалентный линейный коэффициент $c_\mu = m(p_b)/p_b = 1.22\cdot10^{-8}$ 1/Па.

Во всех остальных примерах со Стендингом $c_o = 0$, и ветвь не включается.

**⚠️ Особый случай: $p_b(R_s) \le 0$.** Корреляция Стендинга даёт $p_b < 0$ при малых $R_s$; при $R_s = 0$ получается $p_b = -0.176$ МПа. Для таких $R_s$ условие `p >= pb_local` выполняется всегда, и $(p/p_b)^m$ с нецелым $m$ даёт NaN.

Это не гипотеза. В `tests/test_pvt.py` фикстура задаёт `CO_UNDER = 5e-10`, а три теста вызывают `mu_o` при $R_s = 0$:
- `test_mu_dead_oil_formula` (стр. 198-211, $p = 2$ МПа);
- `test_mu_o_below_pb_formula[0.0]` (стр. 213-227, $p = \max(0.5\,p_b, 10^5) = 0.1$ МПа $> p_b$);
- `test_mu_o_decreases_with_Rs` (стр. 229-234, $p = 2$ МПа).

Если ветвь включается флагом $c_o > 0$ без защиты, все три упадут. Защита нужна при любом варианте: например, при $p_b \le p_{ст}$ ветвь не применять или ограничить $p_b$ снизу.

**⚠️ Расхождение с записью в реестре.** Реестр предлагает «внести уравнение в `.tex` при планировании», но `numerical_solver/doc/problem_statement.tex` намеренно не содержит корреляций (стр. 55-57, 505-507: «конкретные корреляции здесь не приводятся — они реализованы в программном модуле PVT»). Формула уже записана в `pvt-корреляции-стендинг.md`. Куда её вносить, нужно решить при планировании.

## Предлагаемый API

Всё ниже открыто к планированию, решение принимает пользователь.

**Вариант А — Васкес–Беггс под существующим флагом `co_undersaturated > 0`** (так задумано в коде, `standing.py:129-134`).
- Плюсы: конфиги не меняются, правка затрагивает только `standing.py`.
- Минусы: сжимаемость и рост вязкости с давлением — разные эффекты, а флаг у них общий. Пример 20 меняется автоматически, и числа README и тестов (DEBT-034) придётся перемерить.

**Вариант Б — Васкес–Беггс под отдельным параметром**, например `"mu_o_undersaturated": "none" | "vasquez_beggs"` в `PVTConfig`, по умолчанию `"none"`.
- Плюсы: эффекты разделены; при значении по умолчанию все примеры побитово прежние; включение в примере 20 — отдельное решение.
- Минусы: правки в `io/config.py`, `factory.py` и описании схемы JSON.

**Вариант В — линейная модель с параметром** `"c_mu_o_undersaturated"`, 1/Па, по умолчанию 0: $\mu_o = \mu_{ob}(1 + c_\mu(p - p_b))$. Так предложено в `pvt-корреляции-стендинг.md:121-129`.
- Плюсы: симметрия с $c_o$; один скаляр, который можно подогнать под лабораторные данные; при $p_b < 0$ NaN не возникает.
- Минусы: это не корреляция, значение нужно задавать. Для примера 20 эквивалент — $1.22\cdot10^{-8}$ 1/Па.

**Предварительная рекомендация: Б.** Эффекты разделяются, регрессии не будет. Лабораторных данных по вязкости нет, поэтому корреляция предпочтительнее подгоночного коэффициента.

При любом варианте:
- удалить мёртвую ветвь `standing.py:131-134`;
- удалить неиспользуемый атрибут `_mu_o_at_pb` (`standing.py:61`);
- аналитическая производная $\partial\mu_o/\partial p$ не нужна: `StandingFullPVT` наследует `FullPVT`, а не `DifferentiableHydroPVT`, и якобиан прототипа конечно-разностный.

## План реализации

1. **Проектирование.**
   - Выбрать вариант (А/Б/В) и способ включения.
   - Определить защиту при $p_b \le 0$.
   - Решить, куда вносить формулу: заметка vault или `.tex`.

2. **Ядро.** `StandingFullPVT.mu_o`: новая ветвь, удаление мёртвого кода и `_mu_o_at_pb`, ссылка на формулу в докстринге.
3. **Тесты** (`tests/test_pvt.py`):
   - непрерывность $\mu_o$ при $p = p_b$;
   - рост с $p$ при фиксированном $R_s$ выше $p_b$;

   - $R_s = 0$ ($p_b < 0$) — конечное значение без NaN;
   - выключенная ветвь — тождественно Беггс–Робинсон.
4. **Интеграция.**

   - Подпись `pvt_plot._describe` и докстринг модуля.
   - `json-config-schema.md`.
5. **Верификация.**
   - Быстрый уровень после каждого шага, полный — в конце.
   - Если ветвь по умолчанию выключена, примеры должны остаться побитово прежними.
