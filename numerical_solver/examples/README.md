# Примеры использования солвера

Десять готовых сценариев: JSON-конфиг → Factory → расчёт → графики и таблицы.
Каждая подпапка самодостаточна — конфиг, нужные CSV, `main.py` и README
с описанием физики и эталонными числами.

**Главная задача примеров** — показать, как комбинировать конкретные
реализации модулей библиотеки. Возьмите ближайший к вашей задаче пример
и меняйте конфиг.

## С какого начать

| Ваша ситуация | Пример |
|---|---|
| Первое знакомство с библиотекой | **01** — самый простой, однофазный |
| Лабораторных данных нет, есть только параметры пласта | **03** — корреляции PVT + аналитические ОФП |
| Есть полный набор лабораторных данных (PVTO + ОФП по керну) | **04** — всё из CSV |
| PVT по корреляциям, ОФП измерены на керне | **05** |
| PVT из лаборатории, ОФП неизвестны | **06** |
| Нужно оценить вклад отдельного теплового эффекта | **07 → 08 → 09** |
| Интересует сильная депрессия | **10** |

## Запуск

```powershell
cd numerical_solver
.venv\Scripts\pip install -e .        # один раз

# Один пример
.venv\Scripts\python examples\01_single_phase_no_jt\main.py

# Все десять последовательно
.venv\Scripts\python examples\run_all.py
```

`PYTHONPATH` задавать не нужно: `example_runner.py` сам подключает прототип
`radial_blackoil` через `sys.path`.

`run_all.py` не останавливается на первой ошибке — прогоняет все примеры,
печатает сводку и возвращает ненулевой код, если что-то упало.
Суммарное время всех десяти — около 45 с (каждый пример запускается
отдельным процессом, ~3 с из которых уходят на импорт numpy и matplotlib;
сам расчёт занимает 0.6–1.7 с).

### Свойства PVT — во всех примерах

`pvt.png` строится общим модулем [pvt_plot.py](pvt_plot.py) для любой
PVT-модели. Смысл тот же, что у `relperm.png`: замыкающие свойства в
штатных графиках не видны, хотя определяют результат сильнее ОФП — смена
PVT-модели в паре 03↔04 меняет дебит на 46 % и фронт разгазирования в
12 раз, а смена ОФП — почти ничего.

Для $B_o$ и $\mu_o$ рисуются до трёх кривых: насыщенная ($R_s = R_s^{eq}(p)$),
недонасыщенная ($R_s = R_{s,0}$) и **физическая** $R_s = \min(R_s^{eq}(p), R_{s,0})$
— та, что реально была в расчёте. Ветви наносятся только на «чужой»
половине от $p_b$: на «своей» их полностью перекрыла бы физическая кривая.
Ветвь, совпадающая с физической тождественно, не рисуется вовсе — у
табличного PVT выше $p_b$ это насыщенная ветвь, потому что там
$R_s^{eq} \equiv R_{s,0}$. Поэтому число линий зависит от модели: три у
Standing, две у таблицы, одна у однофазных примеров (01, 02).

У табличного PVT отмечаются узлы — видно, где таблица задана, а где
интерполирована. У примера 04 в рабочий диапазон 8.17…19.89 МПа попадает
**один** узел, и вся кривая между краями получена интерполяцией через две
точки: демонстрационные таблицы грубы, и график это показывает.

Отдельная панель $\mu_o(r)$ — вязкость **в ячейках** по последнему
состоянию. Панели $f(p)$ отвечают на вопрос «как свойство зависит от
давления», эта — «насколько узка зона, где оно меняется»: у примера 03
вся вариация вязкости укладывается в $r < 0.20$ м при радиусе дренирования
47 м. Радиус совпадает с фронтом разгазирования $r_b = 0.1996$ м не
случайно — $\mu_o$ у Стендинга зависит только от $R_s$, а $R_s$ меняется
ровно в разгазированной зоне.

**Отличие от `rs_profiles.png`.** Оба графика про $R_s$, но по разным осям
и про разное: `rs_profiles.png` даёт $R_s$ по **радиусу** — где в пласте газ
вышел из раствора, где фронт $r_b$; это про **решение задачи**. Панель $R_s$
в `pvt.png` даёт $R_s$ по **давлению** — где $p_b$, насколько груба таблица;
это про **модель**, которой задачу решали.

Ядро библиотеки содержит `plot_pvt_properties` — ту же функцию без привязки
к конфигам примеров, так что пользователь установленного пакета строит
график одной строкой:

```python
from gpn_multiphase_solver.io.output import plot_pvt_properties
plot_pvt_properties(pvt, Rs0=50.0, p_range=(8e6, 20e6))
```

### Замкнутое решение — во всех сценариях с газом

На `pressure_profiles.png` и `saturation_profiles.png` наносится решение,
в котором **из расчёта не берётся ничего** — ни дебит, ни давление, ни
насыщенность. Всё следует из двух условий стационарности: компонентные
потоки постоянны по $r$, а на контуре газ входит только растворённым,
откуда GOR $= R_{s,0}$. Это даёт алгебраическое уравнение на $S_g$

$$\frac{k_{rg}(S_g)}{k_{ro}(S_g)} = \bigl[R_{s,0}-R_s(p)\bigr]\frac{\mu_g B_g}{\mu_o B_o}$$

и дебит одной квадратурой, без итераций (радиальный аналог функции Маскета):

$$q_o = \frac{2\pi k h}{\ln(R_e/r_w)}\int_{p_{wf}}^{p_e}\frac{k_{ro}(S_g(p))}{\mu_o B_o}\,dp$$

Вывод не зависит ни от источника PVT, ни от вида ОФП, поэтому модуль
[closed_form.py](closed_form.py) подключается ко всем сценариям с
$R_{s,0}>0$:

| пример | PVT / ОФП | $q_o$ расчёт | $q_o$ аналитика | расхождение |
|---|---|---|---|---|
| 03 | Standing / Corey | $1.0866\cdot10^{-2}$ | $1.0847\cdot10^{-2}$ | 0.18 % |
| 04 | таблицы / таблицы | $5.8760\cdot10^{-3}$ | $5.8498\cdot10^{-3}$ | 0.45 % |
| 05 | Standing / таблица | $1.0909\cdot10^{-2}$ | $1.0898\cdot10^{-2}$ | 0.10 % |
| 06 | таблица / Corey | $5.7632\cdot10^{-3}$ | $5.7299\cdot10^{-3}$ | 0.58 % |
| 07–09 | таблицы / таблицы | $5.8760\cdot10^{-3}$ | $5.8498\cdot10^{-3}$ | 0.45 % |
| 10 | таблицы / таблицы | $6.5550\cdot10^{-3}$ | $6.5198\cdot10^{-3}$ | 0.54 % |

Расхождение 0.1–0.6 % — погрешность конечных объёмов на 50 ячейках; она
убывает первым порядком при измельчении сетки
([05/closed_form_convergence.py](05_standing_table_rp/closed_form_convergence.py)).

На профиле $S_g$ рисуются **две** кривые, отвечающие на разные вопросы:
кружки — $S_g$ из замыкания при *численном* давлении (проверяет решатель,
ошибка $p$ не наследуется), пунктир — полностью автономное решение
(проверяет всю конструкцию сразу).

Фронт определяется условием $p(r_b)=p_b$, а не обнулением аналитической
$S_g$. Для ОФП Кори это принципиально: у порога подвижности $S_{gc}$
требуемое отношение $k_{rg}/k_{ro}$ так мало, что корень падает ниже
порога, где $k_{rg}\equiv0$, и обращение возвращает ноль при физически
имеющемся газе — в примере 03 такой критерий занижал $r_b$ на 13 %.

### Проверка $R_s$ — во всех сценариях с газом

На `rs_profiles.png` поверх численного профиля наносятся точки

$$R_s(r) = \min\bigl(R_s^{eq}(p(r)),\ R_{s,0}\bigr),$$

и то же расхождение печатается в консоль. В модели Black Oil газосодержание
не имеет собственной динамики — ни релаксации, ни кинетики выделения: оно
алгебраически следует за давлением. Правее фронта нефть недонасыщена и
$R_s \equiv R_{s,0}$; левее — насыщена, и $R_s = R_s^{eq}(p)$.

Проверка зависит только от PVT и поля давления, поэтому применима и к
аналитическому PVT (03, 05), и к табличному (04, 06–10) — она включена
для всех сценариев с $R_{s,0} > 0$ модулем
[rs_analytics.py](rs_analytics.py):

| пример | PVT | $R_s$ диапазон | $\max\|R_s^{числ}-R_s^{равн}\|$ | ячейки $p<p_b$ = ячейки $S_g>0$ |
|---|---|---|---|---|
| 04 | таблица | 9.50 … 30 | $2.1\cdot10^{-14}$ | да (26) |
| 05 | Standing | 42.00 … 50 | $7.1\cdot10^{-15}$ | да (6) |
| 10 | таблица | 3.61 … 30 | $1.4\cdot10^{-14}$ | да (29) |

Точность машинная, потому что обе величины — одна и та же функция от
одного и того же $p$. Проверка не избыточна: расхождение означало бы либо
паразитную релаксацию в схеме (газ выделяется не мгновенно), либо
рассогласование PVT энергетического блока с PVT гидродинамики. Ни то, ни
другое не видно на профилях $p$ и $S_g$.

### Баланс энергии — во всех сценариях без исключения

Схема не должна терять и создавать энергию. Проверка суммирует по всем
ячейкам и по всем шагам то, что решатель ставит в СЛАУ, и сравнивает с
изменением запаса:

$$\Delta E = E_{\text{адиаб}} + E_{\text{конв}} + E_{\text{JT}} + E_{\text{дегаз}} + E_{\text{конд}}$$

Модуль [energy_balance.py](energy_balance.py) подключён к **каждому**
примеру, включая однофазные: там часть членов тождественно нулевая, и это
видно на графике — кривая лежит на нуле. Условного включения по признаку
конфига («этот член нужен только если $\lambda \neq 0$») здесь нет
принципиально: именно так пропуск кондуктивного члена у примера 10
скрывался за девятью примерами с $\lambda = 0$.

| пример | $\lambda$ | относительная невязка | $E_{\text{конд}}$, Дж |
|---|---|---|---|
| 01 | 0 | $5.66\cdot10^{-4}$ | 0 |
| 02 | 0 | $1.87\cdot10^{-3}$ | 0 |
| 03 | 0 | $9.65\cdot10^{-3}$ | 0 |
| 04 | 0 | $4.03\cdot10^{-3}$ | 0 |
| 05 | 0 | $9.64\cdot10^{-3}$ | 0 |
| 06 | 0 | $4.55\cdot10^{-3}$ | 0 |
| 07 | 0 | $5.76\cdot10^{-3}$ | 0 |
| 08 | 0 | $1.84\cdot10^{-3}$ | 0 |
| 09 | 0 | $2.26\cdot10^{-3}$ | 0 |
| **10** | **1.5 / 0.14 / 0.04** | $4.33\cdot10^{-3}$ | $+1.29\cdot10^{7}$ |

Остаток — ошибка **расщепления**, а не формул: гидро-шаг замораживает $T$,
тепловой шаг замораживает $p$ и $S_g$, рассогласование линейно по шагу.
Это проверяется измерением порядка
([energy_balance_convergence.py](energy_balance_convergence.py)):

| пример | 01 | 02 | 03 | 04 | 05 | 10 |
|---|---|---|---|---|---|---|
| порядок по $\Delta t$ | 1.000 | 0.999 | 0.995 | 0.967 | 0.996 | 0.980 |

Порядок важнее самой невязки. Пропущенный член почти не зависит от шага,
поэтому при измельчении $\Delta t$ он начинает доминировать над убывающей
ошибкой расщепления, и порядок падает — тогда как абсолютная невязка при
штатном шаге выглядит приемлемой. Так были найдены оба дефекта: BUG-004
(порядок $-0.006$, полка $0.2001/0.2017/0.2025$) и пропуск кондукции у
примера 10 (0.751 вместо 0.980 при невязке всего на 8.6 % выше).

Сводная проверка всех десяти одной командой:

```powershell
.venv\Scripts\python examples\check_energy_balance_all.py
```

### Стационарная асимптотика температуры — где применима

Модуль [temperature_asymptotics.py](temperature_asymptotics.py) проверяет
телескопическую формулу: в стационаре при $\lambda = 0$ температура на
грани выражается через численные $\Phi$, $J$, $R$ явно, и перепад
раскладывается на три физических вклада. Для примера 03 на стационаре:

| вклад | значение |
|---|---|
| Джоуль–Томсон | $-0.6607$ К |
| скрытая теплота | $-0.6348$ К |
| изменение $\Phi$ | $+1.3066$ К |
| **итог** | **$+0.0112$ К** |

Плоский профиль $T$ в двухфазной зоне — не слабость эффектов, а их
взаимное погашение: два охлаждающих механизма компенсируются третьим
(часть массы переходит в газ, у которого $c_p$ вдвое меньше, поэтому
$|\Phi|$ падает).

Формула требует двух условий, и оба проверяемы:

1. **$\lambda = 0$** — телескопирование не учитывает кондуктивный поток.
   У примера 10 $\lambda \neq 0$, и проверка сообщает о неприменимости
   вместо печати большого расхождения.
2. **Стационар** — на штатных 3 сутках релаксация не завершена, отсюда
   расхождение $\approx 0.39$ К. Что это именно релаксация, а не дефект
   вывода, показывает прогон на длинных временах
   ([05/check_asymptotics_relaxation.py](05_standing_table_rp/check_asymptotics_relaxation.py)):
   $3.9\cdot10^{-1}$ К на 3 сутках → $5.1\cdot10^{-2}$ на 30 →
   $1.2\cdot10^{-3}$ на 100 → $7.3\cdot10^{-11}$ на 400.

## Три вещи, которые полезно знать заранее

**1. Смена ОФП почти не видна на температуре и дебитах.**
Пары 03↔05 и 04↔06 отличаются только моделью ОФП: насыщенность меняется
на 80 %, а температура — на 0.002 К, дебит — на 0.4–2 %. Смотреть надо
`saturation_profiles.png`.

Причина видна из стационарного условия (вывод — в
[03/README](03_standing_corey/README.md), п. 2): газовый фактор равен
$R_{s,0}$ независимо от ОФП, а это фиксирует отношение подвижностей

$$k_{rg}(S_g)/k_{ro}(S_g) = [R_{s,0} - R_s(p)]\,\mu_g B_g / (\mu_o B_o).$$

Правая часть от модели ОФП не зависит вовсе. Подстраивается насыщенность:
у Кори то же отношение достигается при $S_g = 0.080$, у табличной ОФП —
при $S_g = 0.014$.

Пара 03↔05 просчитывается в одном прогоне скриптом
[05/compare_with_corey.py](05_standing_table_rp/compare_with_corey.py):
он выравнивает $\lambda$, сравнивает все поля и показывает, что само
замыкание при табличной ОФП выполняется с машинной точностью
($10^{-12}$), а у Кори ошибка растёт к фронту до 93 % — там
$k_{rg}\sim(S_g-S_{gc})^2$ вырождается у порога подвижности.

Сам закон GOR $= R_{s,0}$ не зависит ни от PVT, ни от ОФП — он следует из
постоянства компонентных потоков в стационаре:

| пример | PVT / ОФП | $R_{s,0}$ | GOR | $|{\rm GOR}-R_{s,0}|$ | $S_g^{max}$ |
|---|---|---|---|---|---|
| 03 | Standing / Corey | 50 | 50.000000 | $2.4\cdot10^{-8}$ | 0.0804 |
| 04 | таблицы / таблицы | 30 | 30.000000 | $4.5\cdot10^{-8}$ | 0.0147 |
| 05 | Standing / таблица | 50 | 50.000000 | $6.2\cdot10^{-10}$ | 0.0140 |
| 06 | таблица / Corey | 30 | 30.000000 | $1.8\cdot10^{-7}$ | 0.0811 |

Насыщенность различается в 5.5 раза, газовый фактор — ни на знак.

**2. Смена PVT меняет всё.** Пара 03↔04: и насыщенность, и температура
(0.65 К), и дебит (46 %), и положение фронта (0.20 против 2.39 м).

**3. Тепловые параметры не влияют на гидродинамику вообще.**
Следствие расщепления (operator splitting): `HydroSolver` не видит секцию
`thermal`, `EnergySolver` работает на замороженных $p$, $S_g$, $R_s$.
У сценариев 07, 08, 09 массивы $S_g$, $p$, $R_s$, $q_o$ совпадают
**побитово**.

## Общие параметры всех сценариев

| Параметр | Значение |

| $\varphi$ / $k$ | 0.2 / $10^{-13}$ м² (≈100 мД) |
| $p_0$ / $T_0$ | 20 МПа / 350 К |

| $\lambda_s$ / $\lambda_o$ / $\lambda_g$ | **0** у примеров 01–09; 1.5 / 0.14 / 0.04 Вт/(м·К) только у 10 |
| $\rho_{o,ст}$ / $\rho_{g,ст}$ | 850 / 0.85 кг/м³ |

Варьируются между сценариями только: $R_{s,0}$, $p_{wf}$, модели PVT и ОФП,
тепловые скаляры.

Теплопроводности обнулены у девяти примеров из десяти намеренно: ОДУ-аналитика
температуры выводится при $\lambda = 0$, иначе задача становится краевой
(вторая производная) и решения первого порядка не существует. Цена обнуления
измерена: на стационаре разница с физическими $\lambda$ составляет 0.0002 К на
забое при полном эффекте $\approx 4$ К
([03/check_asymptotics_long_run.py](03_standing_corey/check_asymptotics_long_run.py)).
Пример 10 оставлен с физическими $\lambda$ именно для того, чтобы
кондуктивный член кем-то проверялся.
