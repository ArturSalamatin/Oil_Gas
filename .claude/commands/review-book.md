# Обзор книги/монографии для vault

Пользователь указал файл или главу: `$ARGUMENTS`

Формат аргумента: `<файл> [глава N]` или `<файл> [с. 10-30]`.

## Инструкции

### 1. Найди и прочитай

- Файл в `Refs/` или `Refs/GORM/`. Glob если не найден.
- Книги большие – **не читай целиком**. Стратегия:
  - Если указана глава/страницы – читай только их.
  - Если не указано – читай оглавление (первые 5–10 страниц), предисловие, введение. Предложи пользователю выбрать главы для обзора.
- DJVU нечитаем – сообщи.

### 2. Проверь дубли

Проверь `vault/knowledge/literature/` – нет ли заметки на эту книгу (по автору в имени файла).

**Если краткая заметка уже есть** – перезапиши расширенной версией (формат книги), обнови `status`, перенеси из `cited-references.md` в `index-literature.md`.

### 3. Создай заметку

Имя файла: `vault/knowledge/literature/Автор Год – название книги.md`

Для книги формат отличается от статьи:

```markdown
---
author: "Автор(ы)"
year: ГГГГ
publisher: "Издательство"
tags: [literature, book, тематические-теги]
date: ГГГГ-ММ-ДД
status: расширенная
type: книга
---

# Автор Год – название книги

**Полная ссылка.** Автор. *Название*. Издательство, год. Страниц.

## Структура книги
Оглавление с аннотациями – какие главы о чём, какие релевантны проекту.

## Разобранные главы

### Глава N: Название
**Ключевые результаты:**
- формулы, утверждения, подходы

**Замечания:**
- ограничения, допущения, отличия от нашей постановки

### Глава M: Название
(аналогично)

## Значение для проекта
Какие главы применимы к модели ПЗП. Wiki-ссылки на Draft-файлы и science-заметки.
Обозначения автора vs нотация проекта (см. AGENTS.md).

## TODO
- [ ] Разобрать главу X (почему)
- [ ] Сравнить формулу Y с нашей постановкой

## Цитируется в
## Ссылается на
```

### 4. Создай краткие заметки для ключевых ссылок

Монографии содержат десятки ссылок. Не обрабатывай все – только те, что автор использует в разобранных главах.

Для каждой ссылки из разобранных глав определи категорию:

| Категория | Критерий |
|---|---|
| **A – методологическая** | Автор опирается на результат: выводит формулы, верифицирует, использует как базу |
| **B – прикладная** | Описывает задачу ПЗП, промысловые данные, температурные эффекты при фильтрации |
| **C – обзорная/справочная** | Обзоры, справочники, монографии |

Для категорий A и B, **если заметки ещё нет** – создай краткую заметку (формат см. `/review-paper`, шаг 6).
Добавь запись в `vault/knowledge/literature/cited-references.md`.

### 5. Перекрёстные ссылки и индекс

Проверь **три источника** заметок:
1. `vault/knowledge/literature/` – основная папка.
2. `vault/` (корень) – legacy-заметки `ref_*.md` (если остались).
3. LaTeX-документы (`simplefied_approaches/`, `method_of_moments/`, `method_of_moments_isotermal/`, `GORM_2/`) – Grep по `\cite{}` для связей.

Действия:
- **«Ссылается на»**: wiki-ссылки на заметки цитируемых работ.
- **«Цитируется в»** существующих заметок: обнови, если книга ссылается на уже разобранные работы.
- Обнови `vault/knowledge/literature/index-literature.md` – добавь строку в тематическую таблицу и в «Расширенные обзоры».

### 7. При повторном вызове

Если заметка на книгу уже есть – дочитай указанные главы/страницы, добавь секцию в «Разобранные главы».

### 8. Стиль

- Русский.
- Конкретные формулы с номерами уравнений.
- Расхождения в обозначениях с AGENTS.md – отметить.
- Не пересказывать – выделять применимое к задаче ПЗП.
