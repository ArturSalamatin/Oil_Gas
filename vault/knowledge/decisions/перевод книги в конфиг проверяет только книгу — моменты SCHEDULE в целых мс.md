# Перевод книги в конфиг проверяет только книгу — моменты SCHEDULE в целых мс

Книга ввода ([[книга ввода Excel версии 1 — все параметры явно, единицы фиксированы]]), прочитанная разбором ([[разбор книги xlsx сообщает тип ячейки — отказ по типу решает перевод]]), переводится в каталог: `config.json`, `oil_pvt.csv`, `gas_pvt.csv`, `relperm.csv` в СИ. Дальше — обычный `load_config` и сборка решателя: JSON остаётся каноническим форматом ([[P8-формат-ввода-json]]), проверки конфига (`_validate`) и таблиц (фабрика) работают без дублирования. Код — `numerical_solver/gpn_multiphase_solver/io/workbook_convert.py`, команда — `gpn-solver convert книга.xlsx каталог`. План и решения пользователя 1–35 — [[feat-035 workbook-to-config]].

## Интерфейс

- `convert_workbook(книга, каталог) -> Path` — путь `config.json`; каталог новый или пустой (создаётся), файлы пишутся после всех проверок — книга с ошибкой не оставляет ни файлов, ни каталога. Его вызывает расчёт по книге [[FEAT-036]] с каталогом `output/input/`.
- `workbook_to_config(book) -> (конфиг, таблицы)` — словарь JSON и `{имя CSV: (заголовок, строки)}` без записи на диск; `write_files(каталог, конфиг, таблицы)`.
- Исключения: `WorkbookContentError` (подкласс `WorkbookError` → `ValueError`, поле `errors`) — значения книги; `WorkbookError` — файл не книга `.xlsx` (разбор); `FileExistsError` — каталог непуст или это файл; `FileNotFoundError` и прочие `OSError` — файловая система. Командная строка: 0 — записано, 2 — любая из этих ошибок. Перевод не импортирует решатель, scipy и прототип.
- Внутренний код (однострочные докстринги); в публичный интерфейс (README §4) — решит FEAT-036.

## Правила

| Что | Как | Почему |
|---|---|---|
| Что проверяет перевод | листы, заголовки, ключи, единицы, типы и пределы ячеек, постоянные строки, крайние строки RELPERM, моменты SCHEDULE, $\varphi_0 \le 1$ | только то, что есть лишь в книге (решение 21); конфиг и таблицы целиком (ветви PVTO, недонасыщенный старт, ОФП) проверяет расчёт до первого шага |
| Сообщения об ошибках | все ошибки ячеек одним сообщением, в порядке листов и строк, до 30 строк и «… и ещё N»; `MODEL!C6 (Absolute permeability (k)): -1.0 — нужно число > 0` | инженер правит книгу за один заход (решение 22) |
| Нет листа, версия ≠ 1 | одна ошибка до остальных проверок | прочие ошибки книги другой версии — шум |
| Пробелы | по краям ключей, единиц, заголовков, режимов, слов grouped/sparse срезаются; регистр — точно («bhp» — отказ) | пробел из буфера обмена в ячейке не виден; как заголовки CSV фабрики |
| Тип ячейки | пусто, текст («1,5» и «1.5»), логическое, ошибка Excel, дата, формула без значения — отказ с причиной и действием; формула с сохранённым значением — число | книга с пометкой «пересчитать при открытии» (XlsxWriter) хранит у формул ложный 0 |
| Целые поля | `grid.N`, `max_retries`, `newton_max_iter`, `max_active_set_iter` — `int` (100.0 → 100, 100.5 — отказ) | Excel хранит числа вещественными; у `grid.N` проверки целого в `_validate` нет — [[DEBT-081]] |
| Составные поля | $\varphi_0 = \varphi_{ref}\,e^{c_r(p_0 - p_{ref})}$; $(\rho c_p)_s = \rho_{ma} c_{ma}$ — определение под `eq:main_rhocpeff` | порода решателя — $\varphi(p) = \varphi_0 e^{c_r(p - p_0)}$, перенос опорной точки точный; ROCK в OPM — разложение экспоненты до второго порядка (OPM Flow Reference Manual 2025-10, табл. 8.138, формула (8.97)), расхождение пренебрежимо |
| $\varphi_0 > 1$ | ошибка у ячейки $\varphi_{ref}$ с вычисленным $\varphi_0$ | ключ строки книги — путь JSON, и отказ `_validate` называет строку книги у всех полей, кроме составных; `rock.porosity` в книге нет (решение 35) |
| Пустые строки и ячейки вне таблиц | полностью пустая строка таблицы пропускается, частично заполненная — ошибка; столбцы правее таблицы, Comment и «Комментарии» не читаются | как пустая строка CSV фабрики, лишние листы, ячейки чужого режима |
| RELPERM | первая строка — $S_g = 0$, $k_{rg} = 0$; последняя — $S_g = 1$, $k_{ro} = 0$; проверяется, только если у листа нет других ошибок | защита листа снимается без пароля; строка с ошибкой в таблицу не попадает, и «первой» оказалась бы следующая |
| Каждое поле книги | пишется в `config.json` явно, умолчания `io/config.py` не подставляются; `pvt.model`, `relperm.model` = `table`, имена CSV; `output` — только `title` = имя книги без расширения | книга — все параметры явно (решение 15); листа OUTPUT нет |
| Файлы | UTF-8, «\n» (`write_text(..., newline="\n")` — без него Windows пишет «\r\n»); числа — `repr` | обратное чтение точное: ячейка → файл → то же число |

## SCHEDULE → `time.history`

Строка $k$ — момент $t_k$ и режим на $[t_k, t_{k+1}]$; последняя — только момент завершения. Моменты переводятся в **целые миллисекунды** $M_k = \mathrm{round}(t_k \cdot 86\,400\,000)$, интервал — $\Delta t_k = (M_{k+1} - M_k)/1000$ с (решение 19). Округление каждой разности, как в конвертере примера 18, при моментах вне сетки 1 мс сдвигает моменты записи на сумму ошибок: 700 интервалов по $1/7$ сут — на 0.1 с; округление моментов сдвига не накапливает. Первая строка — ровно $t = 0$; $M_{k+1} \le M_k$ — отказ. Строка BHP читает только BHP target, OIL_RATE — дебит и Minimum BHP: ячейку чужого режима `_validate_interval` отверг бы. Строка Excel $k$ (без пустых строк) — `history[k − 2]`. Книга генератора: 23 момента → 22 интервала, сумма 2 592 000 с ровно ([[временная-сетка-и-история]]).

## Последний разряд

Перевод единиц делением на точный множитель не делает числа «круглыми»: $c_r$ 4.5e-5 1/бар → 4.5000000000000005e-10 1/Па; $\mu_{JT,o}$ −0.4 К/МПа → −4.0000000000000003e-07 К/Па; $h_0$ 3.05555555555556e-05 ч → 0.11000000000000017 с (на расчёт не влияет: $h_0$ округляется вниз до $\Delta t/2^m$). Прототип получает давления и вязкости таблиц обратным переводом фабрики в бары и сП: на демо-таблицах 4 из 47 давлений и 6 из 47 вязкостей отличаются от ячейки на 1 ULP — свойство канонического JSON в СИ.

## Проверено

Сценарий книги генератора `convert` → `run`: код 0, предупреждений нет, ~30 с; 100 тестов перевода и 7 командной строки; 20 порч кода — каждую ловит тест (проба `vault/issues/feat-035/probes/plan_apply.py`).
