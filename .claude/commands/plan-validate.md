# /plan-validate — план верификационного кейса

Аргумент: `$ARGUMENTS` — идентификатор кейса (например `VAL-001`, `VAL-003`) или номер GitHub issue.

Результат: подробный, самодостаточный план в `vault/plans/`, готовый к автономной реализации в отдельной сессии без контекста.

**Рабочая директория:** код, тесты и конфиги находятся в `method_of_moments/` (не в корне проекта). Все пути к коду — от корня проекта: `method_of_moments/src/`, `method_of_moments/tests/`, `method_of_moments/configs/`. Команды pytest — из `method_of_moments/`: `cd method_of_moments && python -m pytest tests/ -v`.

## Фаза 1: Сбор контекста

### 1.1. Проверить существующий план

```
ls vault/plans/<id-lowercase>*
```
Если план уже существует — сообщи пользователю путь и спроси: обновить или создать новый.

### 1.2. Загрузить задачу

Если `$ARGUMENTS` — номер issue (`#N` или просто число):
1. `gh issue view <N> --repo ArturSalamatin/Oil_Gas` → из title извлеки ID
2. Далее работай с извлечённым ID

1. Найди запись в `vault/roadmap/валидационные кейсы.md` по ID
2. Если есть поле **GitHub:** — прочитай issue через `gh issue view <N> --repo ArturSalamatin/Oil_Gas`
3. Прочитай подробную заметку из `knowledge/validation/` (поле **Подробности**)
4. Если задачи нет в vault — предложи сначала `/issue $ARGUMENTS`

### 1.3. Определить подтип

| Подтип | Эталон | Пример |
|---|---|---|
| **Аналитический** | точное решение PDE/ODE | Формула Дюпюи для однофазного притока |
| **Сходимость** | собственные расчёты при уменьшении шага | Порядок сходимости ODE-интегратора |
| **Межсимуляторный** | результат другого решателя (OPM, КР) | Сравнение с конечно-разностной схемой |
| **Инвариантный** | физический закон (баланс масс, энергии) | Интегральный баланс = 0 по всей области |

Подтип определяет шаблон этапов на фазе 3.

### 1.4. Извлечь имя ветки

1. Из GitHub issue или vault-записи (если `/issue` уже генерировал)
2. Если нет — сгенерируй: `val/<id-lowercase>/<slug-2-5-слов>`
3. Проверь существование: `git branch --list "<имя>"`

### 1.5. Загрузить физику/математику

1. **Эталонные формулы:** найди в `moments_method.tex`, `Refs/`, vault/knowledge/science/
2. **Предельные случаи:** какие упрощения дают аналитическое решение?
3. **Нотация:** проверь соответствие с CLAUDE.md (5 таблиц символов)
4. **Литература:** обзоры статей по теме валидации

### 1.6. Исследовать код

1. **Солвер:** какой модуль/функция вычисляет то, что валидируем?
2. **Конфиги:** есть ли `method_of_moments/configs/baseline.json` или аналог? Какие параметры фиксируются?
3. **Существующие тесты:** есть ли в `method_of_moments/tests/` тесты, близкие к целевому кейсу?
4. **Визуализация:** есть ли `scripts/` для построения графиков?
5. **Формула→код:** для эталонной формулы — есть ли уже реализация?

## Фаза 2: Анализ и проработка

### 2.1. Определение эталона

Для каждого подтипа — свой подход:

#### Аналитический:
- **Формула:** точное решение из tex/литературы (выписать явно)
- **Условия применимости:** при каких p, T, Sg формула валидна
- **Параметры:** конкретные числа для теста (p0, T0, Sg0, rw, rb, t_end, ...)
- **Ожидаемый результат:** числа с единицами измерения и точностью
- **Источник:** цитата (автор, год, уравнение)

#### Сходимость:
- **Метрика ошибки:** L2-норма, max-норма, относительная ошибка
- **Последовательность шагов:** h, h/2, h/4, h/8 (минимум 4 точки)
- **Ожидаемый порядок:** p = log(e_h/e_{h/2}) / log(2)
- **Tolerance:** ±0.1 от теоретического порядка

#### Межсимуляторный:
- **Другой решатель:** OPM Flow, собственная КР-реализация, MATLAB
- **Формат входных данных:** как передать одинаковые параметры?
- **Метрика сравнения:** норма разности, графическое совпадение
- **Tolerance:** % отклонения, абсолютный порог

#### Инвариантный:
- **Закон:** какой баланс (масса, энергия, импульс)?
- **Формула проверки:** интеграл по области / контрольному объёму
- **Tolerance:** машинная точность × порядок системы

### 2.2. Сценарий

Описать полностью:
- **Физика:** какая модель (М.1–М.6), какие эффекты включены/выключены
- **Геометрия:** rw, rb, Rext
- **ГУ:** давление/расход на забое, давление на контуре
- **IC:** начальные p(r), Sg(r), T(r)
- **PVT:** какие корреляции, параметры (pb, Rs0, Bo0, ...)
- **Время:** t_end, dt, количество шагов
- **Варьируемые параметры:** что меняется между запусками

### 2.3. Метрики

| Метрика | Формула | Tolerance | Единицы |
|---|---|---|---|
| ... | ... | ... | ... |

Пример:
| L2-ошибка давления | √(∫(p_num - p_exact)² dr / ∫p_exact² dr) | < 1e-3 | — |
| Баланс массы газа | |∫ρ_g S_g φ dV - ∫q_g dt| / ∫q_g dt | < 1e-10 | — |

### 2.4. Поиск подводных камней

Чеклист. Для каждого: ✅ безопасно | ⚠️ риск, адресован | ❌ проблема

- [ ] **Условия применимости эталона:** формула работает только при определённых p, T, Sg
- [ ] **Единицы измерения:** СИ vs пластовые, согласованность
- [ ] **Начальные условия:** физически непротиворечивы?
- [ ] **Граничные условия:** корректны для выбранного эталона?
- [ ] **Tolerance:** не слишком жёсткий (нереальный) и не слишком мягкий (бесполезный)?
- [ ] **Время расчёта:** не слишком долго для CI?
- [ ] **Воспроизводимость:** детерминированный результат (без random seed проблем)?
- [ ] **Регрессия vs валидация:** тест не должен ложно зеленеть при произвольном результате

### 2.5. Обнаружение новых проблем

Блокирующие → предварительный шаг. Неблокирующие → после завершения в реестр.

## Фаза 3: Детализация плана

### 3.1. Шаблон этапов по подтипу

#### Аналитический:

1. **Подготовка** — ветка, зелёные тесты, формула зафиксирована
2. **Эталонная функция** — `reference_solution(r, t, params) -> p, Sg, T`
3. **Тесты эталона** — unit-тесты самой эталонной функции (известные значения)
4. **Конфиг сценария** — параметры, совместимые с условиями эталона
5. **Запуск и сравнение** — integration-тест: прогон ODE + сравнение с эталоном
6. **Визуализация** — p(r), Sg(r), T(r): numerical vs analytical
7. **Документация** — vault-заметка с результатами

#### Сходимость:

1. **Подготовка** — ветка, зелёные тесты
2. **Серия запусков** — h, h/2, h/4, h/8 (в тесте, не вручную)
3. **Вычисление ошибок** — норма разности для каждого шага
4. **Вычисление порядка** — log-log регрессия
5. **Тест-assert** — порядок = ожидаемый ± tolerance
6. **Визуализация** — log(h) vs log(error), наклон = порядок

#### Межсимуляторный:

1. **Подготовка** — ветка, зелёные тесты
2. **Эталонные данные** — запуск другого решателя, сохранение результатов
3. **Конфиг Oil_Gas** — те же параметры
4. **Сравнение** — тест: загрузка эталона + прогон + норма разности
5. **Визуализация** — наложение кривых

#### Инвариантный:

1. **Подготовка** — ветка, зелёные тесты
2. **Функция баланса** — вычисление интеграла по области
3. **Тест** — баланс < tolerance после полного прогона
4. **Покадровый тест** — баланс на каждом шаге по времени

```

- `@pytest.mark.validation` — для всех валидационных тестов
- `@pytest.mark.slow` — если время > 10 секунд
