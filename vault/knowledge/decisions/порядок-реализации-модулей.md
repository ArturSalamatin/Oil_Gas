# Порядок реализации модулей

## Принцип

Снизу вверх по графу зависимостей: сначала модули без зависимостей, потом — зависящие от готовых.

## Граф зависимостей

```
SimulatorFactory
    └── Simulator
            ├── HydroSolver ──┬── Grid
            │                 ├── HydroPVT
            │                 ├── RelPermModel
            │                 ├── fluxes ──┬── Grid, PVT, ОФП
            │                 └── bc ──────── WellControl (ABC)
            ├── EnergySolver ─┬── Grid
            │                 ├── FullPVT
            │                 ├── RockConfig
            │                 └── fluxes (для Q_o, Q_g)
            ├── TimeSchedule ── HistoryInterval + WellControl
            ├── BoundaryConditions
            ├── SimulationState
            └── log (user_log, dev_log)

config.py (чтение JSON) ── используется всеми через Factory
fluxes.py ── общая логика upstream + вычисление G, Q, u, m
bc.py ── ABC WellControl + PressureControl
log.py ── настройка logging (user + dev уровни)
```

## Фазы реализации

### Фаза 0. Каркас проекта
- `pyproject.toml`
- Структура директорий `gpn_multiphase_solver/`, `tests/`, `configs/`
- `conftest.py` с fixtures
- Пустые `__init__.py`

**Результат:** `pytest` запускается (0 тестов, 0 ошибок).

### Фаза 1. Grid (без зависимостей)
- `gpn_multiphase_solver/grid/base.py` — ABC Grid
- `gpn_multiphase_solver/grid/log_radial.py` — LogRadialGrid

**Результат:** Grid создаётся, grани/центры/объёмы/проводимости вычислены и протестированы.

### Фаза 2. PVT + ОФП (без зависимостей)
- `gpn_multiphase_solver/pvt/base.py` — ABC HydroPVT, FullPVT, RelPermModel
- `gpn_multiphase_solver/pvt/standing.py` — StandingFullPVT (корреляции + скалярные тепловые)
- `gpn_multiphase_solver/pvt/prototype_adapter.py` — PrototypePVTAdapter (обёртка BlackOilPVT → HydroPVT)
- `gpn_multiphase_solver/pvt/table_full.py` — TableFullPVT (табличные гидро + скалярные тепловые)
- `gpn_multiphase_solver/pvt/relperm.py` — CoreyRP, PrototypeRPAdapter
- `tests/test_pvt.py` — unit-тесты
- `tests/test_relperm.py` — unit-тесты

**Результат:** ABC определены, StandingFullPVT и PrototypePVTAdapter протестированы, vectorized.

### Фаза 3. Инфраструктура: state, config, bc, log, fluxes
- `gpn_multiphase_solver/state.py` — SimulationState, WellData, HydroResult, EnergyResult, BoundaryConditions, SimulationHistory
  - HydroResult: 11 массивов [N+1] — G_o, G_g, G_free_gas, Q_o, Q_g, u_o, u_g, m_o, m_g, Gm_o, Gm_g
  - SimulationHistory: контейнер times + states + hydro_results + well_data (контракт Simulator→I/O)
- `gpn_multiphase_solver/bc.py` — ABC WellControl, PressureControl
- `gpn_multiphase_solver/log.py` — setup_logging, user_log, dev_log
- `gpn_multiphase_solver/fluxes.py` — compute_fluxes (G, Q, u, m, Gm + upstream)
- `gpn_multiphase_solver/io/config.py` — dataclasses + load_config
- `configs/baseline.json` — эталонный конфиг
- `tests/test_config.py` — чтение, валидация
- `tests/test_fluxes.py` — потоки на стационарном профиле давления

**Результат:** JSON читается, потоки вычисляются, логирование работает.

### Фаза 4. HydroSolver — ABC + аналитическая заглушка
- `gpn_multiphase_solver/hydro/base.py` — ABC HydroSolver
- `gpn_multiphase_solver/hydro/analytical.py` — AnalyticalHydroSolver (использует fluxes.py)
- `tests/test_hydro.py` — unit-тесты для заглушки

Конкретный Newton-солвер **не реализуем** — ожидаем модуль коллеги. Для тестирования EnergySolver и Simulator нужна заглушка, возвращающая аналитические поля p(r), Sg(r), u_o(r), u_g(r).

AnalyticalHydroSolver — упрощённая реализация:
- p(r) = логарифмический профиль (стационарный однофазный поток)
- Sg(r) = 0 (без дегазации) или заданный профиль
- u_o(r) из закона Дарси при известном p(r)
- u_g = 0 (однофазный) или пропорционален krg/mu_g · dp/dr

Этого достаточно, чтобы:
1. Протестировать EnergySolver на реалистичных полях
2. Протестировать Simulator (полный цикл)
3. Валидировать T(r) при известном аналитическом p(r) (VAL-001)

Модуль коллеги (Prototype_1.0.3) уже поступил. Фаза 4a — интеграция.

**Результат:** ABC определён, заглушка работает, можно тестировать остальные модули.

### Фаза 4a. Интеграция прототипа коллеги
- `gpn_multiphase_solver/hydro/prototype_adapter.py` — PrototypeHydroAdapter (декоратор единиц + A-retry)
- `gpn_multiphase_solver/pvt/prototype_adapter.py` — PrototypePVTAdapter (BlackOilPVT бар→Па)
- `gpn_multiphase_solver/pvt/table_full.py` — TableFullPVT (табличные гидро + скалярные тепловые)
- `gpn_multiphase_solver/pvt/relperm.py` — PrototypeRPAdapter
- Конвертер TimeSchedule → Schedule прототипа (в factory.py)
- `tests/test_prototype_adapter.py` — конвертация, знаки, баланс масс

Подробности: [[P1-адаптер-единицы]], [[P2-знаки-потоков-прототип]], [[P4-адаптивный-шаг]], [[P5-pvt-архитектура]], [[P8-формат-ввода-json]].

**Результат:** полный гидро-шаг через прототип, потоки в SI, согласованные PVT.

### Фаза 5. EnergySolver
- `gpn_multiphase_solver/energy/base.py` — ABC EnergySolver
- `gpn_multiphase_solver/energy/tridiag.py` — TridiagEnergySolver
- `tests/test_energy.py` — unit + интеграционные

Подзадачи:
1. Вычисление конвективных потоков (upstream по фазе)
2. Кондуктивные потоки (гармоническое среднее)
3. JT-вклад, адиабатика, дегазация
4. Сборка трёхдиагональной СЛАУ
5. Решение (scipy.linalg.solve_banded)
6. Граничные условия

**Результат:** температура решается при известных p, Sg, Rs.

### Фаза 6. Simulator + Factory
- `gpn_multiphase_solver/simulator.py` — Simulator (цикл по времени, адаптация dt)
- `gpn_multiphase_solver/factory.py` — SimulatorFactory.from_json
- `tests/test_simulator.py` — интеграционные

**Результат:** полная симуляция из JSON-конфига.

### Фаза 7. I/O + визуализация
- `gpn_multiphase_solver/io/output.py` — save_npz, save_csv, plot_profiles, plot_wellbore_dynamics, plot_well_rate, plot_2d_map
- Эталонный запуск с baseline.json → результаты в `results/`

**Результат:** полный pipeline JSON → расчёт → графики.

### Фаза 8. Валидация
- VAL-001: однофазный стационарный поток (аналитическое решение)
- VAL-003: Buckley-Leverett (при наличии двухфазного гидро-солвера)

## Оценка трудоёмкости

| Фаза | Модуль | Оценка |
|---|---|---|
| 0 | Каркас | 0.5 сессии |
| 1 | Grid (единая, immutable) | 1 сессия |
| 2 | PVT + ОФП (ABC + Standing + адаптеры прототипа) | 2 сессии |
| 3 | State + config + bc + log + fluxes | 2 сессии |
| 4 | HydroSolver ABC + аналитическая заглушка | 1 сессия |
| 4a | Интеграция прототипа (Adapter + декоратор единиц + A-retry) | 2 сессии |
| 5 | EnergySolver | 2 сессии |
| 6 | Simulator + Factory (включая конвертер TimeSchedule→Schedule) | 1 сессия |
| 7 | I/O + визуализация | 1 сессия |
| 8 | Валидация (VAL-001 как минимум) | 1 сессия |

**Итого до получения внешнего модуля:** ~11-12 сессий.
**С Newton-реализацией (если понадобится):** +3-4 сессии.

## Отложенные задачи (не блокируют реализацию)

- Checkpoint/restart — при расчётах > 1 часа
- Сериализация SimulationState — вместе с checkpoint
- Именование CellArray/FaceArray type aliases — при реализации fluxes.py
- Изменить формулу центров ячеек в прототипе (√ → центр масс кольца eq. 12) — средний приоритет
- Передача единого Grid в прототип через конструктор (вместо внутреннего RadialGrid) — низкий приоритет
