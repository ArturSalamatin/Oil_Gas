## Суть

**A-retry.** Если Newton прототипа не сходится на шаге $dt$, адаптер `PrototypeHydroAdapter.solve` повторяет шаг с $2^{a}$ равными подшагами, $a = 0, 1, \dots$. Попытки идут, пока $a$ не превысит `numerics.max_retries`, потом выдаётся `RuntimeError` (`numerical_solver/gpn_multiphase_solver/hydro/prototype_adapter.py:105-108, 190-198`). Если дробление понадобилось, симулятор проходит интервал заново $n_{sub}$ подшагами (BUG-010). Каждый такой подшаг снова идёт через `hydro.solve` с тем же лимитом (`numerical_solver/gpn_multiphase_solver/simulator.py:229-242`).

**Почему одного прогона при умолчании хватает.** Первая сошедшаяся попытка $a$ от лимита не зависит. Поэтому при лимите $m$ прогон идёт побитно как при умолчании 9, пока какому-то вызову не понадобится $a > m$. На этом вызове прогон падает. Отсюда минимально достаточный лимит: $k = \max\log_2 n_{substeps}$ по всем вызовам `hydro.solve` одного прогона при умолчании. Контроль: прогон с $k-1$ должен упасть, прогон с $k$ должен дать конечное $p$, побитно равное умолчанию.

**Что устарело.**
1. README 03 приводит при $p_{wf} = 0.5$ МПа минимум 9 удвоений; на текущем коде нужно 4. Остальные точки таблицы верны.
2. Умолчание 9 обосновано в трёх местах кода как «измеренный порог»: пример 03 при $N = 75$, $p_{wf} = 6$ МПа; пример 04a; «03 при 2 и 0.5 МПа — порог 9». После BUG-014 и BUG-016 ни один из этих сценариев 9 не требует. Об этом прямо пишут соседние docstring тех же тестов. Само значение 9 не меняется: это запас, и обоснование нужно переписать соответственно.
