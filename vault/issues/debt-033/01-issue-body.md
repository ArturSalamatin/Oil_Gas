## Описание

Конечно-разностный якобиан прототипа занимает 72–76 % времени расчёта примеров. При $N = 350$ больше половины всего времени расчёта уходит не на вычисление невязок, а на учёт вокруг них: цикл Python по ячейкам при раскраске столбцов и перевод плотной матрицы $2N \times 2N$ в разреженную. Задача — убрать эти накладные расходы, **не меняя численного метода**: якобиан должен совпасть с нынешним побитово, последовательность итераций Ньютона — остаться прежней.

Аналитический якобиан в задачу не входит (обоснование — в разделе «Анализ вариантов», вариант 4).

## Текущее состояние

`finite_difference_jacobian_grouped` собирает якобиан с раскраской столбцов (Кертис — Пауэлл — Рид, 1974). Невязки ячейки $i$ зависят только от ячеек $i-1, i, i+1$, поэтому ячейки $i, i+3, i+6, \dots$ возмущаются одновременно: 3 цвета × 2 блока переменных ($p$ и $S_g$/$R_s$) = 6 вычислений невязки на якобиан вместо $2N$. Это минимум для трёхточечного шаблона: $p$ и $S_g$ одной ячейки меняют одни и те же строки и в один цвет не совмещаются.

Сами 6 вычислений невязки векторизованы, а учёт вокруг них — нет:

- на каждый цвет — цикл Python по ячейкам (`blackoil.py:209-215`): `_pressure_fd_step` для одной ячейки (`:179-196`, `np.searchsorted` по скаляру), `np.arange` и запись трёх строк в плотную матрицу. При $N = 350$ это 2100 итераций на якобиан, 243 якобиана за расчёт примера 20;
- результат — плотная матрица `np.zeros((2n, 2n))` (`:205`);
- `_linear_solve` (`:219-220`) переводит её в разреженную: `csc_matrix(J)` просматривает все $4N^2$ элементов.

Замер 2026-10-03 (HEAD `00af963`, без профилировщика; проба `vault/issues/debt-033/probes/time_jacobian.py`):

| пример | $N$ | PVT | всего | якобиан | невязки в якобиане | учёт раскраски | перевод в разреженную | LU |
|---|---|---|---|---|---|---|---|---|
| 20_rs500_cooling | 350 | Стендинг | 5.93 с | 4.44 с (75 %) | 1.20 с | 3.24 с (55 %) | 0.68 с (11 %) | 0.15 с |

Доля учёта растёт с $N$: цикл длиной $O(N)$ на каждый цвет и плотная матрица $O(N^2)$. При $N = 50$ время якобиана определяют сами невязки, и векторизация там почти ничего не даст.

## Целевое состояние

- Шаги возмущения и запись столбцов — операциями над массивами, без цикла Python по ячейкам.
- Якобиан собирается сразу в разреженном виде (4 трёхдиагональных блока), без плотной матрицы $2N \times 2N$.
- Якобиан побитово равен нынешнему; шаги `advance` и истории примеров — побитово прежние.
- Оценка (не замер): пример 20 — с 5.9 до ~2.1–2.8 с, пример 03 — ×1.6–1.7, пример 04 — ×1.1. На подробных сетках ($N \ge 500$) выигрыш больше, и снимается квадратичный рост памяти: плотная матрица при $N = 2000$ — 128 МБ на итерацию.

## Анализ вариантов решения

### Вариант 1. Векторизация учёта, плотная матрица остаётся

- **Суть.** Шаги для всех ячеек сразу: векторный аналог `_pressure_fd_step` (`np.searchsorted` по массиву, `np.where` для выбора $\pm h$; поэлементно та же арифметика → те же $h$ побитово). Для каждого цвета — запись трёх диагоналей каждого блока срезами массивов. Деление `df / h` сохранить (не умножение на `1 / h`) — для побитового совпадения.
- **Изменения.** `blackoil.py:179-216`.
- **Плюсы.** Интерфейс не меняется, тесты не трогаются; побитовость проверяется `np.array_equal` против нынешней реализации. Снимает 55 % времени примера 20.
- **Минусы.** Остаётся $O(N^2)$: перевод в разреженную (11 % при $N = 350$, растёт квадратично) и память плотной матрицы.

### Вариант 2. Вариант 1 + сборка сразу в разреженном виде

- **Суть.** `finite_difference_jacobian_grouped` возвращает `csc_matrix`, собранную из трёх диагоналей четырёх блоков. Перед `splu` — `eliminate_zeros()`: `csc_matrix(dense)` отбрасывает нули, в том числе внутри полосы (например, $\partial k_{rg}/\partial S_g = 0$ ниже $S_{gc}$). Явные нули меняют шаблон разреженности, SuperLU выбирает другую перестановку столбцов, и решение расходится с нынешним на уровне округления. `linear_solver='dense'` — через `.toarray()`.
- **Изменения.** Вариант 1 + `blackoil.py:219-221`; `test_grouped_jacobian.py` (`.toarray()`).
- **Плюсы.** $O(N)$ по времени и памяти; ещё −11 % при $N = 350$, больше на подробных сетках.
- **Минусы.** Меняется тип результата `finite_difference_jacobian` — правка тестов прототипа; пробы в `vault/issues/`, читающие J как `ndarray`, перестанут работать (исторические, не поддерживаются). Риск расхождения шаблона разреженности — закрывается `eliminate_zeros()` и побитовой проверкой шагов.

### Вариант 3. Вариант 1 + быстрый перевод в разреженную внутри `_linear_solve`

- **Суть.** Якобиан остаётся плотным (интерфейс прежний), `_linear_solve` собирает `csc` только из известных четырёх трёхдиагональных блоков.
- **Плюсы.** Интерфейс не меняется; перевод — $O(N)$.
- **Минусы.** Плотная матрица и её обнуление — по-прежнему $O(N^2)$ по памяти; знание о шаблоне дублируется в двух местах (сборка и решение). Половинчатое решение.

### Вариант 4. Аналитический якобиан — не входит

Обсуждено 2026-10-03. При $N = 350$ невязки в якобиане — 1.2 с из 5.9; аналитика сэкономила бы часть этой секунды, а цена — производные корреляций Стендинга и Беггза — Робинсона по $p$ и $R_s$, двумерной таблицы PVTO, табличных ОФП, трёх ветвей скважины и цепное правило $dR_s/dp$ в двухфазных ячейках. Точность конечных разностей (~$10^{-6}$ относительной: $h_p = \max(10^{-4}$ бар$, 10^{-6} p)$, $h_{S_g} = 10^{-7}$) сходимость не ограничивает: зарегистрированные отказы Ньютона (BUG-003, BUG-008, BUG-014, BUG-016, BUG-018, BUG-019, DEBT-025) связаны с негладкостью, начальным приближением, линейным поиском. На полках и в изломах ОФП аналитическая производная несёт ту же информацию. Пересмотреть, если после этой задачи скорости не хватит или проверка якобиана в BUG-019 (тест Тейлора вдоль направления Ньютона) покажет, что якобиан не согласован с невязкой. При малых $N$ на табличном PVT (пример 04) невязки — основная доля якобиана, но абсолютное время — 1.4 с.

### Вариант 5. JIT-компиляция (numba)

- **Минусы.** Новая зависимость ради цикла, который векторизуется средствами numpy. Не рекомендуется.

**Рекомендация:** вариант 2, двумя шагами в одной ветке — сначала вариант 1 (побитовая проверка якобиана на плотной матрице), затем разреженная сборка (побитовая проверка шагов `advance`).

   - Замер пробой `time_jacobian.py` на примерах 20, 03, 04 на базе.
   - Эталонные якобианы в `.npz` на замороженных состояниях: однофазные ячейки, смешанный набор фаз, ячейки у узлов PVTO (табличный PVT), управление по дебиту, ветвь скважины `shut`.
   - Эталонные истории ($p$, $S_g$, $R_s$, $T$ по времени) всех примеров для побитового сравнения.
   - Тесты: `tests/` (полный), тесты прототипа (80 passed), регрессия прототипа — зафиксировать набор FAIL (DEBT-029).
2. **Реализация.**
   - Векторный расчёт шагов возмущения; тест: равенство скалярному `_pressure_fd_step` на массиве давлений, включая точки у узлов (сценарии `test_pvt_kink_jacobian.py`).
   - Векторная запись столбцов, плотная матрица (вариант 1); тест: `np.array_equal` с эталонными якобианами.
   - Разреженная сборка + `eliminate_zeros()` (вариант 2), `_linear_solve` принимает разреженную матрицу, `dense` — через `.toarray()`; `test_grouped_jacobian.py` — сравнение через `.toarray()`.
3. **Верификация.**
   - Якобианы побитово равны эталонным; шаги `advance` и истории всех примеров — побитово прежние.
   - Тесты прототипа 80 passed; регрессия прототипа — тот же набор FAIL с теми же числами; полный `tests/` зелёный.
   - Повторный замер пробой: зафиксировать ускорение в реестре.
