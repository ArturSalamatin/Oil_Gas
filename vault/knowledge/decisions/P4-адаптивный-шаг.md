# P4. Адаптивный шаг по времени

## Принцип

Гидродинамический модуль — **чёрный ящик**. Получает (state_n, dt, BC), возвращает (state_{n+1}, потоки). Что он делает внутри (подшаги, Newton, active-set) — его дело.

EnergySolver использует:
- p^{n+1}, Sg^{n+1}, Rs^{n+1} — из HydroResult (замороженные коэффициенты)
- p^n, Rs^n — из state_prev
- dt — внешний шаг (от Simulator)
- Потоки — мгновенные при state^{n+1}

EnergySolver **не знает** о внутренних подшагах гидро.

## Решение: A-retry

Adapter при расходимости **сам уменьшает dt** и выполняет подшаги. Снаружи возвращает единый HydroResult на конец исходного dt.

### Алгоритм

```python
def solve(self, state, dt, bc) -> HydroResult:
    """Чёрный ящик: state_n → state_{n+1} за dt.
    
    При расходимости — автоматический retry с уменьшением шага.
    """
    max_retries = 5
    
    for attempt in range(max_retries + 1):
        n_sub = 2 ** attempt           # 1, 2, 4, 8, 16, 32
        dt_sub = dt / n_sub
        
        dev_log.debug(
            f"Hydro attempt {attempt+1}/{max_retries+1}: "
            f"{n_sub} substep(s), dt_sub={dt_sub:.2e} s")
        
        success = True
        current = state
        
        for step in range(n_sub):
            # Конвертировать → advance → конвертировать обратно
            proto_state = self._to_proto(current, bc)
            new_proto, report = self._model.advance(proto_state, dt_sub)
            
            if not report.converged:
                dev_log.debug(
                    f"  Substep {step+1}/{n_sub} failed: "
                    f"iters={report.iterations}, res={report.residual_inf:.2e}")
                success = False
                break
            
            current = self._from_proto(new_proto, current, dt_sub)
        
        if success:
            if attempt > 0:
                user_log.info(
                    f"Hydro: converged after {n_sub} substeps "
                    f"(dt_sub={dt_sub:.2e} s)")
            
            # Потоки — мгновенные при итоговом state
            fluxes = self._model.face_component_fluxes_sm3s(new_proto)
            return self._build_result(current, new_proto, fluxes, bc)
    
    raise RuntimeError(
        f"HydroSolver не сошёлся после {2**max_retries} подшагов "
        f"(dt_sub={dt/2**max_retries:.2e} s). "
        f"Уменьшите dt_integration в JSON.")
```

### Параметры

| Параметр | Значение | Смысл |
|---|---|---|
| `max_retries` | 5 | Максимум удвоений числа подшагов |
| `n_sub` | 2^attempt | 1, 2, 4, 8, 16, 32 |
| `dt_sub` | dt / n_sub | Шаг подшага |
| Минимальный dt_sub | dt / 32 | При dt=3600 с → 112.5 с |

### Пример

dt = 3600 с:
- Попытка 1: 1 шаг × 3600 с → расходимость
- Попытка 2: 2 шага × 1800 с → расходимость на 2-м
- Попытка 3: 4 шага × 900 с → все сошлись → возврат state после 4-го шага

## Что возвращается

### Состояние

State после **последнего подшага** — это state на момент t_{n+1} = t_n + dt. Не промежуточные.

### Потоки

`face_component_fluxes_sm3s(final_state)` — мгновенные потоки при p^{n+1}, Sg^{n+1}. Это то, что нужно EnergySolver для конвекции (неявная схема: потоки на уровне n+1).

### Δp/Δt и ΔRs/Δt для EnergySolver

EnergySolver вычисляет:
```
Q_ad ∝ (p^{n+1} - p^n) / dt          # адиабатический эффект
ṁ   ∝ (Rs^{n+1} - Rs^n) / dt         # темп дегазации (временная часть)
```

Здесь dt — **внешний** шаг (от Simulator), p^n — из state_prev, p^{n+1} — из HydroResult. Это конечная разность через весь интервал, не через подшаги.

Физически: средняя скорость изменения давления за интервал. Приближение первого порядка по времени — совместимо с первым порядком неявной схемы.

При достаточно малом dt_integration (из JSON) ошибка пренебрежима. Если dt_integration слишком велик — ошибка в температуре (не в гидродинамике).

## Взаимодействие с TimeSchedule

Simulator определяет dt_actual = dt_hist / n_sub (из TimeSchedule). Adapter получает этот dt. Если Adapter справился без retry — один вызов advance. Если с retry — несколько внутренних подшагов, но снаружи один вызов solve().

TimeSchedule не знает о retry. Simulator не знает о retry. Только Adapter и логи.

## Проверенные нюансы

### Перезапуск с state_n на каждой попытке

При каждой попытке retry все подшаги начинаются с исходного state_n. Ранее вычисленные подшаги не переиспользуются. Неэффективно (максимум 32 вызова advance вместо ~6 при smart retry), но просто и корректно. Оптимизировать при необходимости.

### Управление скважиной при retry

`set_bhp_control` / `set_oil_rate_control` вызывается перед каждым подшагом (идемпотентно). Дебит (OIL_RATE) — постоянный во времени, суммарная добыча за dt пропорциональна dt. Корректно.

### Roundoff при конвертации Па→бар→Па

При retry подшаги 2..n_sub конвертируют state обратно из Па в бар. Float64 roundoff ~1e-15. Не проблема.

### Первый подшаг всегда расходится

Если при dt/32 Newton не сходится — задача слишком жёсткая. RuntimeError с информативным сообщением. Пользователь уменьшает dt_integration.

### Режимы (gas_active) между подшагами

При retry подшаг k передаёт state с обновлённым regime в подшаг k+1. advance использует gas_active как starting guess и сам определяет правильный mask через active-set. Корректно.
