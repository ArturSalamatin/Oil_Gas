# 07 — Разгазирование: только адиабатический эффект

**Опорная точка семейства 07–09.** От неё отсчитываются вклады остальных
тепловых эффектов.

## Описание

Гидродинамика полностью совпадает с примером [04](../04_table_table/):
табличные PVT и ОФП, $R_{s,0} = 30$, $p_{wf} = 8$ МПа, разгазирование есть.

Отличие — **все тепловые коэффициенты обнулены**: $\mu_{JT,o} = \mu_{JT,g} = 0$,
$L = 0$. Остаётся единственный источник изменения температуры —
адиабатический член:

$$Q_{ad} = \varphi \sum_\alpha S_\alpha \left(1 + \rho_\alpha c_{p,\alpha} \mu_{JT,\alpha}\right) \frac{dp}{dt}$$

При $\mu_{JT} = 0$ он сводится к $\varphi \, dp/dt$ — работе сжатия/расширения
скелета порового пространства.

## Комбинация модулей (B: Table + Table)

| Модуль | Класс | Ключ конфига |
|---|---|---|
| Сетка | `LogRadialGrid` | `grid.N = 50` |
| PVT (гидро) | `TableFullPVT` | `pvt.model = "table"` |
| PVT (термо) | скаляры `thermal` | **все нули** |
| ОФП | `PrototypeRPAdapter` | `relperm.model = "table"` |
| Гидродинамика | `PrototypeHydroAdapter` | (единственный) |
| Энергия | `TridiagEnergySolver` | (единственный) |

```json
"thermal": {
    "c_p_oil": 2000.0,
    "c_p_gas": 1000.0,
    "mu_JT_oil": 0.0,        ← выключен
    "mu_JT_gas": 0.0,        ← выключен
    "L_degas": 0.0           ← выключена
}
```

$c_{p,o}$ и $c_{p,g}$ остаются положительными — они стоят в знаменателе
уравнения энергии, обнулить их нельзя.

## Ожидаемое поведение

| Величина | Значение |
|---|---|
| $T(r_w)$ финал | **352.77 К** — нагрев на +2.77 К |
| $S_g^{max}$ | 0.0147 |
| $R_s^{min}$ | 9.5 м³ст/м³ст |
| $q_o$ финал | $5.876 \times 10^{-3}$ м³ст/с |
| фронт $r_b$ | 2.39 м |

### ⚠️ Почему нагрев, а не охлаждение

Интуиция подсказывает, что при падении давления флюид должен охлаждаться.
Здесь наоборот: $T$ растёт на 2.77 К. Это **не ошибка знака**.

При $\mu_{JT} = 0$ адиабатический член описывает работу сжатия породы,
а не дросселирование флюида. Охлаждение при падении давления даёт
эффект Джоуля–Томсона, который в этом сценарии отключён (см. пример 08),
и скрытая теплота дегазации (пример 09).

Именно поэтому 07 — опорная точка: он показывает, что остаётся,
когда «настоящих» механизмов охлаждения нет.

## Место в семействе 07–09

Три сценария отличаются **только** секцией `thermal`:

| Сценарий | $\mu_{JT}$ | $L$ | $T(r_w)$, К | вклад относительно 07 |
|---|---|---|---|---|
| **07** (этот) | 0 | 0 | 352.770 | — (опора) |
| [08](../08_degassing_jt/) | > 0 | 0 | 348.558 | $-4.212$ К (JT) |
| [09](../09_degassing_latent_heat/) | 0 | > 0 | 351.083 | $-1.687$ К (дегазация) |
| [04](../04_table_table/) | > 0 | > 0 | 346.871 | $-5.899$ К (оба) |

**Суперпозиция выполняется точно:**
$(-4.212) + (-1.687) = -5.899$ К, что в точности равно полному эффекту
$T_{04} - T_{07}$. Невязка — $4 \times 10^{-13}$ К, то есть машинная точность.
Эффекты складываются линейно.

**Гидродинамика во всех четырёх сценариях идентична побитово.**
Проверено: массивы $S_g$, $p$, $R_s$, $q_o(t)$ совпадают точно
(`np.array_equal` → `True`). Это следствие расщепления (operator splitting):
`HydroSolver` не видит тепловых коэффициентов, `EnergySolver` работает
на замороженных $p$, $S_g$, $R_s$.

## Как увеличить газонасыщенность

$S_g^{max} = 1.5\,\%$ — свойство демонстрационной таблицы ОФП, не ошибка.
Главный рычаг — заменить `relperm` на модель Кори с крутой кривой:

```json
"relperm": {"model": "corey", "S_or": 0.2, "S_gc": 0.05,
            "n_o": 2.0, "n_g": 3.0, "kro_max": 1.0, "krg_max": 0.3}
```

даст $S_g^{max} = 0.165$ вместо 0.015. Подробный разбор с числами
и объяснением, почему **менее** подвижный газ даёт бо́льшую насыщенность —
в README примера [04](../04_table_table/).

Что не помогает: увеличение длительности (стационар за 8–12 ч),
расширение $R_e$ (двигает фронт, не насыщенность).

## Как модифицировать

### Что менять безопасно

| Параметр | Секция JSON | Эффект |
|---|---|---|
| тепловые скаляры | `thermal` | только $T$; гидродинамика не меняется вовсе |
| $R_e$ | `geometry.R_ext` | шире область; фронт $r_b$ растёт |
| $h$, $k$, $\varphi$ | `geometry`, `rock` | дебит; ⚠️ $\varphi$ входит и в адиабатический член |
| $N$ | `grid.N` | детальность профилей |
| длительность | `time.history[].dt` | ⚠️ стационар за 8–12 ч |
| `save_every` | `output.save_every` | 1 → 73 шага (0.22 МБ), 6 → 13, 24 → 4 |

Полезный эксперимент: включить по одному коэффициенту и сравнить $T(r_w)$
с таблицей выше — так проверяется линейность вкладов на своих данных.

### Что требует осторожности — $p_{wf}$

**Сверху:** при $p_{wf} > p_b = 15$ МПа разгазирования не будет ($S_g \equiv 0$).

**Снизу:** табличный PVT устойчив в диапазоне 14…3 МПа.
При отказе `RuntimeError: HydroSolver не сошёлся после 32 подшагов`
помогает `"dt_integration": 600` в секции `time` (DEBT-007).

### Не трогать

`grid.type` и `output.format` — объявлены в `io/config.py`, но не читаются.
