## Описание

Поле `pvt.co_undersaturated` (сжимаемость недонасыщенной нефти $c_o$, 1/Па) работает только в PVT Стендинга. При `pvt.model = "table"` оно молча игнорируется: ни `_validate`, ни фабрика не отказывают и не предупреждают. Соседнее поле той же группы «для Стендинга», `mu_o_undersaturated`, в том же случае даёт `ValueError` (FEAT-027). Пользователь, который задал $c_o$ при табличном PVT, считает сжимаемость нефти учтённой, а расчёт идёт по таблице.

Попутно: знак `co_undersaturated` не проверяется. $c_o < 0$ в PVT Стендинга даёт только предупреждение фабрики (BUG-019), хотя у `rock.compressibility` при $c_r < 0$ — отказ (DEBT-068).

## Текущее состояние

**Табличный PVT.** `create_pvt` (`factory.py:105`) передаёт `co_undersaturated` только в ветвь `"standing"` → `StandingFullPVT` (`factory.py:117`), где при $p \ge p_b(R_s)$
$B_o = B_o(p_b)\,e^{-c_o (p - p_b)}$ (`pvt/standing.py:106-111`). В ветви `"table"` (`factory.py:125-162`) $B_o$ выше $p_b$ задают недонасыщенные ветви PVTO, поле не читается. Для `mu_o_undersaturated` в начале той же ветви стоит отказ (`factory.py:126-131`, комментарий «молча игнорировать опцию нельзя»), для `co_undersaturated` — нет.

Замер (`vault/issues/debt-078/probes/co_undersaturated.py`, `co_undersaturated.out.txt`, на `130b88d`): конфиг примера 04 (`pvt.model = "table"`), $c_o = 0$ и $3.3\cdot10^{-9}$ 1/Па. `create_pvt` и `SimulatorFactory.from_config` проходят без отказа и без предупреждений (перехвачены и `warnings`, и журнал `logging`). $B_o$ на ветви $R_s = R_{s,0} = 30$ от $p_b$ до $p_0$ совпадает побитово: $\max|\Delta B_o| = 0$.

**Знак $c_o$.** `_validate` (`io/config.py:499`) проверяет у `co_undersaturated` только тип и конечность (`_check_numeric_fields`, DEBT-051). Та же проба, пример 03 (Стендинг), $c_o = -10^{-9}$ 1/Па: `load_config` принимает, фабрика пишет в журнал одно предупреждение `_warn_negative_compressibility` (`factory.py:354-396`): «PVT несогласована: отрицательная сжимаемость недонасыщенной нефти … Расчёт продолжается». $B_o$ выше $p_b$ растёт с $p$: 1.1672 → 1.1796 на 9.4–20 МПа.

Предупреждение вместо отказа — решение BUG-019 (по образцу ECLIPSE, «Negative Compressibility Found»). Но принималось оно для $c_{ot} < 0$ насыщенной нефти, которая возникает из корреляций при большом $R_{s,0}$, то есть для свойства PVT-данных. Отрицательное число, введённое в конфигурацию напрямую, — другой случай.

Физически: $c_o = -(1/B_o)\,\partial B_o/\partial p\,|_{R_s}$ — сжимаемость жидкости при постоянном составе. Условие механической устойчивости $(\partial p/\partial V)_T < 0$ (Ландау, Лифшиц, т. V, §21) требует $c_o > 0$; $c_o = 0$ — предел несжимаемой нефти и значение по умолчанию. В недонасыщенной зоне коэффициент уравнения давления $C_p \propto \phi\,(c_r + c_o)$ (`eq:Cp` в `problem_statement.tex`). При $c_o < -c_r$ получается $C_p < 0$ и некорректная задача (механизм BUG-019). При $c_r > |c_o|$ расчёт пройдёт, но с неверным знаком сжимаемости нефти.

**Документация.** `numerical_solver/README.md:132-133` (п. 3.1) называет оба поля «для корреляций Стендинга»; у `mu_o_undersaturated` добавлено «При табличном PVT допустимо только `"none"`», у `co_undersaturated` такой оговорки нет. Перечень проверок `P8-формат-ввода-json.md` §5 (`:219`, `:221-222`) не упоминает ни отказ FEAT-027 в `create_pvt`, ни проверку $c_o$.

**Кого затронет.** Ни один табличный конфиг (`examples/`, `configs/`, `tests/data/`) поле не задаёт. Задают его только конфиги Стендинга: 17, 20 (`3.3e-9`), `tests/data/bug020_rs300` (`3.3e-9`), `configs/val001.json` (`0.0`). Тесты, которые меняют поле в коде (`test_examples.py:1403`, `test_energy.py`, `test_pvt.py` и др.), работают со Стендингом и с $c_o \ge 0$. Книга ввода Excel (FEAT-033) поле не задаёт: `NOT_FROM_WORKBOOK["pvt.co_undersaturated"] = "только Стендинг"` (план FEAT-033) — значение по умолчанию 0 пройдёт любую из проверок ниже.

## Целевое состояние

- `co_undersaturated != 0` при `pvt.model = "table"` — отказ с объяснением (как у `mu_o_undersaturated`): у табличного PVT $B_o$ выше $p_b$ задают недонасыщенные ветви таблицы.
- `co_undersaturated < 0` — решение при планировании: отказ в `_validate` по образцу DEBT-068 или прежнее предупреждение фабрики.
- README п. 3.1 и P8 §5 описывают обе проверки и отказ FEAT-027.

## Анализ вариантов решения

**Вариант 1 — отказ в `create_pvt` (ветвь `"table"`) при `co_undersaturated != 0`.**
- Суть: рядом с проверкой `mu_o_undersaturated` (`factory.py:128`) — второй `ValueError`: «`co_undersaturated` — только для `model = 'standing'`; у табличного PVT $B_o$ выше $p_b$ задают недонасыщенные ветви таблицы».
- Изменения: `factory.py` (+5 строк), `test_factory_standing_hydro.py` (+1 тест по образцу `test_beal_with_table_raises`).
- Плюсы: одно правило для двух полей группы «для Стендинга»; пользователь узнаёт, что значение не используется; ни один конфиг проекта не ломается.
- Минусы: конфиг, переведённый со Стендинга на таблицу заменой одной строки `model`, потребует удалить `co_undersaturated` — это и есть цель. Явный `0` при таблице проходит молча: отличить «задано 0» от умолчания dataclass не может, вреда нет (как `"none"` у `mu_o_undersaturated`).

**Вариант 2 — предупреждение в журнал вместо отказа.**
- Суть: `user_log.warning` в той же ветви.
- Плюсы: расчёт не останавливается — значение и правда результат не портит.
- Минусы: два поля одной группы по-прежнему ведут себя по-разному. Предупреждение теряется в журнале длинного расчёта, а ошибка ввода остаётся.

**Вариант 3 — отказ в `_validate` при `co_undersaturated < 0`.**
- Суть: по образцу DEBT-068 (`io/config.py:546-550`): «`pvt.co_undersaturated` = … 1/Па < 0: сжимаемость недонасыщенной нефти должна быть ≥ 0 — объём нефти с ростом давления не растёт (вероятно, ошибка знака)». Проверка от модели не зависит: при таблице вариант 1 отвергнет любое ненулевое значение, но сообщение о знаке точнее.
- Изменения: `io/config.py` (+комментарий с замером и проверка), `test_config.py` (параметризованный отказ при $c_o < 0$ и приём при $c_o \in \{0, 3.3\cdot10^{-9}\}$).
- Плюсы: введённое число с неверным знаком отвергается при загрузке, а не после сборки PVT. Правило для $c_o$ то же, что для $c_r$.
- Минусы: на пути Стендинга недонасыщенная ветвь предупреждения BUG-019 при $c_o \ge 0$ больше не сработает. Код предупреждения остаётся: для таблиц $c_o$ берётся из ветвей PVTO, и отрицательная сжимаемость там — свойство данных, предупреждение уместно.

**Рекомендация:** варианты 1 + 3. Отказ при таблице — рядом с `mu_o_undersaturated` в `create_pvt`, чтобы правило «опция только для Стендинга» жило в одном месте. Знак — в `_validate`, рядом с DEBT-068. Перенос обеих табличных проверок (`mu_o`, `c_o`) в `_validate` — возможная альтернатива размещения, решить при планировании.
