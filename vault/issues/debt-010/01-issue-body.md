## Описание

Ссылки «формула → код» в докстрингах и комментариях `numerical_solver/` частью записаны **абсолютными номерами** уравнений `doc/problem_statement.tex` (`eq. 8`, `Eq. 10-13`, `Eq. 51`), частью — **номерами строк** `.tex` (`problem_statement.tex:1334`). Номера уехали при правках постановки: **ни одна из 27 числовых ссылок не указывает на своё уравнение, ни одна из 3 ссылок на строки — на свою строку.**

Правило «связь формула → код» (CLAUDE.md) по таким ссылкам не работает: при правке формулы в `.tex` соответствующую функцию по ссылке не найти. Ошибка уже вышла за пределы кода — запись FEAT-017 унаследовала «eq. 51» из `pvt/base.py:69`.

На расчёт не влияет — только на сопровождение.

## Сверка соответствий по существу

Все 22 ссылки ядра сверены с формулами под правильными метками: формулы кода совпадают с постановкой (знак перепада $p_j - p_{j+1}$ в `eq:flux_oil`/`eq:flux_gas`, логарифм отношения **центров** в `eq:transmissibility`, `geomspace` = `eq:log_grid`). Два уточнения:

1. **$Q_{ad}$.** Код (`tridiag.compute_adiabatic`, `balance.py:234`) реализует `eq:Qad_disc` — дискретную форму при $c_r = 0$. Непрерывная `eq:main_Qad_muJT` содержит ещё член $c_r\,(p + (\rho c_p)_s T)$. Ссылаться нужно на `eq:Qad_disc`.
2. **$\Phi_\alpha$** собственного номера не имеет — определена в тексте после `eq:energy_conv_face`. Варианты: ссылка «определение под `eq:energy_conv_face`» или собственная метка определения (правка `.tex`).

## Попутные наблюдения (вне задачи, не зарегистрированы)

- **«Центр масс» кольцевого слоя** (`problem_statement.tex:938`, `grid/log_radial.py:8`, `:22`, `:25`, словарь) — неточное название. Формула `eq:cell_center` даёт $r_j = \exp\langle \ln r\rangle$ — среднее по площади слоя от $\ln r$, то есть точку, где логарифмический профиль давления равен своему среднему по ячейке. Центр масс кольца — $\langle r\rangle = \tfrac{2}{3}\,(r_{j+1/2}^3 - r_{j-1/2}^3)/(r_{j+1/2}^2 - r_{j-1/2}^2)$; при $r_{j-1/2} = 1$, $r_{j+1/2} = 2$: 1.528 против 1.556. Сама формула для конечных объёмов разумна, неверно только название.
- **$c_r \ne 0$.** Гидродинамика прототипа берёт $c_r$ из `rock.compressibility` (`factory.py:414`), а энергия считает $Q_{ad}$ при $c_r = 0$ (`eq:Qad_disc`) и нигде $c_r$ не использует. Во всех конфигах $c_r = 0$ (план DEBT-008), поэтому сейчас расхождения нет; при $c_r \ne 0$ энергия и гидродинамика станут несогласованными без предупреждения.

## Анализ вариантов решения

### Вариант 1. Только 22 ссылки ядра (объём записи реестра)

- **Суть:** заменить номера на метки в 6 файлах ядра по таблице выше.
- **Плюсы:** минимальная правка.
- **Минусы:** тесты, примеры, ссылки на строки и словарь vault остаются с номерами; при следующем чтении словаря номера снова попадут в код. Повторение ничем не ловится.

### Вариант 2. Весь `numerical_solver/` + словарь + CLAUDE.md

- **Суть:** 22 + 5 числовых ссылок и 3 ссылки на строки → метки; 41 номер в `словарь-код-физика.md` → метки; правило «меткой, не номером» в CLAUDE.md.
- **Плюсы:** код и справочник согласованы; закрыт вероятный первоисточник.
- **Минусы:** 41 правка в заметке vault; проектные заметки `модули-*.md` остаются с номерами (они исторические); формулировку правки CLAUDE.md надо согласовать.

### Вариант 3. Вариант 2 + тест-сторож

- **Суть:** новый тест, который (а) запрещает в `.py` под `gpn_multiphase_solver/`, `tests/`, `examples/` ссылки `eq. <число>` и `problem_statement.tex:<строка>`; (б) проверяет, что каждая метка `eq:*` из `.py` есть среди `\label{}` в `doc/problem_statement.tex`.
- **Плюсы:** (б) ловит то, чего номера в принципе не ловят, — переименование или удаление метки в `.tex`. Разбор текста, доли секунды, не `slow`.
- **Минусы:** тесты читают `doc/problem_statement.tex` — привязка к документу; шаблон (а) может сработать на ссылку на уравнение чужой статьи (сейчас таких в `.py` нет — все 27 совпадений относятся к постановке).

**Рекомендация:** вариант 3. Объём правок vault (только словарь или ещё `модули-*.md`) и способ ссылки на $\Phi_\alpha$ — решить в `/plan-improve`.
