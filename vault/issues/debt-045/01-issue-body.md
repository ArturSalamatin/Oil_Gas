## Описание

Таблица баланса энергии в сводном README примеров (`numerical_solver/examples/README.md`, раздел «Баланс энергии — во всех сценариях без исключения») приводит для примера 14 кондуктивный член $E_{\text{конд}} = -1.41\cdot10^{8}$ Дж. Расчёт `examples\energy_balance.py 14` даёт $-9.9742\cdot10^{8}$ Дж, то есть число в таблице занижено в 7 раз. Результат одинаков на базовом коде (`79603bc`) и в ветке DEBT-043, значит расхождение появилось раньше DEBT-043.

Таблица — документация для заказчика и для сверки. Из-за устаревшего числа роль теплопроводности в 14 выглядит в 7 раз меньше, чем на самом деле. На расчёт это не влияет, приоритет низкий.

## Анализ вариантов решения

### Вариант 1. Ручной пересчёт по `energy_balance.py`

- **Суть:** 11 запусков `examples\energy_balance.py <N>`, числа переносятся в README вручную.
- **Изменения:** только README.
- **Плюсы:** без кода; штатный инструмент.
- **Минусы:** 11 отдельных прогонов с рисунками (пример 14 — 360 сут на $N = 350$); замер не сохраняется — через месяц не восстановить, откуда число; от повторения не защищает.

### Вариант 2. Проба в `vault/issues/debt-045/probes/`

- **Суть:** один скрипт обходит примеры с $\lambda \ne 0$, считает баланс (`compute_balance`) без рисунков и печатает строки таблицы в формате README ($\pm a.bc\cdot10^{k}$) вместе с невязкой и перегревом ячейки у контура над $T_{ext}$ для абзаца. Вывод сохраняется в `.out.txt` рядом.
- **Изменения:** новая проба; README по её выводу.
- **Плюсы:** воспроизводимо; замер остаётся в vault; код пакета и примеров не меняется.
- **Минусы:** от повторения не защищает.

### Вариант 3. Столбец $E_{\text{конд}}$ в `check_energy_balance_all.py`

- **Суть:** штатный обход печатает `cum_cond[-1]` рядом с невязкой — таблица README воспроизводится одной командой.
- **Изменения:** `check_energy_balance_all.py` (возврат `check_one` и печать, ~5 строк); README.
- **Плюсы:** следующий пересчёт — одна команда; инструмент уже упомянут в README.
- **Минусы:** правка существующего скрипта; рассинхронизацию не ловит — нужно помнить про запуск.

### Вариант 4. Сверка README с расчётом в тестах

- **Суть:** медленный тест на фикстуре `results` (примеры уже посчитаны в сессии) разбирает таблицу README и сверяет $E_{\text{конд}}$ с `cum_cond[-1]` с допуском округления до трёх значащих цифр (относительный $5\cdot10^{-3}$); невязку — только порогом (на уровне $10^{-16}$ это шум, совпадения цифр не будет).
- **Изменения:** `tests/test_examples.py` (+1 тест, медленный уровень); README.
- **Плюсы:** устраняет корень проблемы — рассинхронизация ловится автоматически (третий случай подряд).
- **Минусы:** связывает документацию с тестами: любая правка конфига с $\lambda \ne 0$ краснит медленный уровень до правки README; разбор markdown-таблицы хрупок к форматированию; требует полного прогона (~10 мин) для верификации.

### Рекомендация

**Вариант 2** — пересчёт с сохранённым замером, без правки кода. **Вариант 4** — решение пользователя на этапе плана: он закрывает причину повторений, но добавляет связь «документ ↔ тест». Вариант 3 — облегчённая альтернатива 4, если тест не нужен.
