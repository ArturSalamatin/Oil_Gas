# Каталог вывода очищается переименованием — занятый каталог не удаляется частично

`run_case` (`numerical_solver/gpn_multiphase_solver/report/pipeline.py`) очищал каталог вывода прямым `shutil.rmtree`. На Windows файл, открытый в другой программе без права удаления (так открывает Excel), не удаляется: `rmtree` падает WinError 32, успев удалить часть файлов; если каталог — текущий у консоли, `rmtree` удаляет **все** файлы и только потом падает на самом каталоге. У конфига очистка идёт после расчёта (решение 2026-10-13, [[пример — это конфиг и README, штатный набор рисунков и проверок даёт команда пакета]]) — трассировка, код 1, расчёт потерян. План — [[debt-082 locked-output-dir]].

## Правило

Переименование каталога — неразрушающая проверка «каталог удаляется целиком»: Windows отказывает, если в каталоге открыт файл без права удаления или каталог — текущий у процесса, и при этом ничего не трогает.

- `_check_output_free(output_dir)` — до расчёта по конфигу: переименование в `<имя>.check-<pid>` и обратно. Отказ — `CaseConfigError`, код 2, «каталог вывода … не удаётся очистить (<причина ОС>): файл в нём открыт в другой программе … или каталог — текущий в консоли …». Каталог не изменён.
- `_clear_output(output_dir)` — очистка: переименование в `<имя>.old-<pid>`, затем `rmtree` переименованного. Переименование — точка невозврата: не прошло — `OSError`, ни один файл не тронут.
- После расчёта по конфигу `_clear_output` отказал (файл открыли во время расчёта) — результаты в соседний `<имя>_<ГГГГ-ММ-ДД>_<чч-мм-сс>`, прежний каталог не тронут, `[WARNING]` с обоими путями, код 0; `CaseResult.output_dir` — новый каталог. Примеры 01, 02, 05, 18 дописывают рисунки в `r.output_dir`.
- У книги ([[расчёт по книге очищает каталог вывода до перевода — input и результаты от одного запуска]]) очистка до расчёта — той же `_clear_output`; отказ — `CaseConfigError` с тем же текстом.
- Корень диска как каталог вывода — `CaseConfigError` до любого действия (прежде `rmtree` пытался бы стереть диск).
- Имена соседних каталогов — от `os.path.abspath`, не `resolve()`: на диске `subst` и сетевом `resolve()` подменяет букву диска реальным путём.
- `_check_output_path(output_dir)` ([[DEBT-083]]) — до проверки занятости, у конфига после `_check_inputs_outside`, у книги до её чтения: первый существующий путь среди каталога вывода и его предков должен быть каталогом. Путь — файл (`--output well_history.csv`), путь через файл (`well_history.csv\sub`) или нет диска — `CaseConfigError`, код 2, ничего не создаётся. Прежде у конфига `mkdir(parents=True, exist_ok=True)` после расчёта падал `FileExistsError` (`exist_ok` не спасает, если по пути файл) — трассировка, код 1, расчёт потерян; у книги — код 2 с текстом ОС без причины. Не ловит недопустимое имя и нет прав на запись ([[DEBT-084]]): там первый существующий предок — обычный каталог.

Решения пользователя 2026-10-18: файл открыли во время расчёта — соседний каталог и код 0 (отклонены: отказ без записи — расчёт теряется; ожидание закрытия с повторами — блокирует пакетные запуски); очистка у книги — той же функцией.

## Пробы (`vault/issues/debt-082/probes/`)

| Что держит каталог | `os.rename` | `shutil.rmtree` |
|---|---|---|
| файл открыт без права удаления (`open()` Python; настоящий Excel через COM — то же) | отказ WinError 5, всё цело | отказ WinError 32, часть файлов удалена |
| файл открыт с правом удаления | отказ WinError 5 | прошло |
| дескриптор самого каталога (наблюдение Проводника) | прошло | прошло |
| текущий каталог другого процесса (консоль) | отказ WinError 32, всё цело | отказ, **все файлы удалены** |

Вторая строка — ложный отказ проверки: принят как отказ с запасом, сообщение верно. На POSIX переименование проходит, как и `rmtree`, — проверка ничего не меняет.
