# 04 — Разгазирование: табличные PVT + табличные ОФП (комбинация B)

**Начинать отсюда, если есть полный набор лабораторных данных** —
PVTO-таблицы и кривые ОФП по керну.

## Описание

Тот же физический режим, что в примере [03](../03_standing_corey/):
двухфазное течение с разгазированием при $p_{wf} = 8$ МПа, полная термика.
Отличие — **все свойства читаются из CSV**, ни одна корреляция не вызывается.

## Комбинация модулей (B: Table + Table)

| Модуль | Класс | Ключ конфига | Внешние файлы |
|---|---|---|---|
| Сетка | `LogRadialGrid` | `grid.N = 50` | — |
| PVT (гидро) | `TableFullPVT` | `pvt.model = "table"` | `oil_pvt.csv`, `gas_pvt.csv` |
| ОФП | `PrototypeRPAdapter` | `relperm.model = "table"` | `relperm.csv` |
| Гидродинамика | `PrototypeHydroAdapter` | (единственный) | — |
| Энергия | `TridiagEnergySolver` | (единственный) | — |
| Управление | `PressureControl` | `control = "pressure"` | — |

Как это задаётся:

```json
"pvt": {"model": "table", "rho_o_std": 850.0, "rho_g_std": 0.85,
        "oil_pvt_file": "oil_pvt.csv", "gas_pvt_file": "gas_pvt.csv"},
"relperm": {"model": "table", "file": "relperm.csv"}
```

Пути к CSV — **относительно самого JSON**, поэтому файлы лежат
в этой же папке. Формат:

| Файл | Столбцы |
|---|---|
| `oil_pvt.csv` | `Rs_sm3_sm3, pressure_Pa, Bo, mu_o_Pa_s` |
| `gas_pvt.csv` | `pressure_Pa, Bg, mu_g_Pa_s` |
| `relperm.csv` | `Sg, kro, krg` |

`oil_pvt.csv` — таблица PVTO: строки сгруппированы по веткам $R_s$.
В демонстрационном файле только две ветки: $R_s \in \{0, 30\}$.

Все три таблицы интерполируются **линейно** (`np.interp`), поэтому
свойства — кусочно-линейные функции, а узлы таблиц дают изломы
подвижности. Для ОФП это видно на `output/relperm.png` (строится
автоматически для всех примеров модулем
[examples/relperm_plot.py](../relperm_plot.py)), для PVT — на
`output/pvt.png` (модуль [examples/pvt_plot.py](../pvt_plot.py)); там же
отмечены узлы таблиц, и видно, что в рабочий диапазон 8.17…19.89 МПа
попадает **один** узел ($p_b = 15$ МПа), а $B_g$ выходит кусочно-линейной
вместо гиперболы:

| $S_g$ | 0.00 | 0.10 | 0.20 | 0.40 | 0.60 | 0.80 |
|---|---|---|---|---|---|---|
| $k_{ro}$ | 1.00 | 0.80 | 0.60 | 0.30 | 0.10 | 0.00 |
| $k_{rg}$ | 0.00 | 0.01 | 0.05 | 0.20 | 0.50 | 0.80 |

⚠️ **Расчёт не выходит за первый отрезок.** $S_g^{max} = 0.0147$, а
первый узел после нуля — $S_g = 0.1$: строки 0.2, 0.4, 0.6, 0.8
не задействованы вовсе, и вся ОФП сводится к двум точкам.
Рабочие значения: $k_{ro} = 0.9706$, $k_{rg} = 1.47\times10^{-3}$.
Для реальных расчётов первый отрезок надо сгущать.

## Ключевые параметры

| Параметр | Значение | Смысл |
|---|---|---|
| $R_{s,0}$ | **30** м³ст/м³ст | ограничен таблицей (ветки только 0 и 30) |
| $p_b$ | **15 МПа** | первая строка ветки $R_s = 30$ в `oil_pvt.csv` |
| $p_0$ / $p_{wf}$ | 20 / 8 МПа | $p_{wf} < p_b$ → разгазирование |
| $\mu_{JT,o}$ / $\mu_{JT,g}$ | $4\times10^{-7}$ / $-4\times10^{-6}$ К/Па | |
| $L$ | 168000 Дж/кг | |
| $\lambda_{\text{тв}}$, $\lambda_o$, $\lambda_g$ | **0** | теплопроводность отключена, см. ниже |

### Почему теплопроводность равна нулю

При $\lambda = 0$ кондуктивная проводимость граней обращается в ноль,
и уравнение энергии становится **обыкновенным дифференциальным уравнением
первого порядка** — краевая задача вырождается в задачу Коши. Это позволяет
построить для $T(r)$ такую же аналитику, как для $p$ и $S_g$
(см. [temperature_ode.py](temperature_ode.py)).

Те же нули стоят в примерах [06](../06_table_corey_rp/),
[07](../07_degassing_adiabatic_only/), [08](../08_degassing_jt/),
[09](../09_degassing_latent_heat/) — все они сравниваются с этим расчётом,
а сравнение имеет смысл только при одинаковой теплопроводности: иначе
у пары различался бы не один параметр, а два.

Побочный выигрыш: суперпозиция вкладов JT и скрытой теплоты стала точной
до четвёртого знака ($-4.215 - 1.687 = -5.902$ К), тогда как при
$\lambda \ne 0$ оставалась невязка $5\times10^{-3}$ К — она и была
вкладом теплопроводности.

### Аналитические кривые на графиках

Все четыре профильных графика несут наложенную аналитику:

| График | Аналитика | Точность |
|---|---|---|
| `pressure_profiles.png` | квадратура из $G^o = \text{const}$, замыкание GOR $= R_{s,0}$ | $q_o$ 0.45 %, профиль 28 кПа |
| `saturation_profiles.png` | кружки — $S_g$ из замыкания при численном $p$; пунктир — автономно $S_g(p_{\text{ана}}(r))$ | 0.0026 % и 0.10 % |
| `rs_profiles.png` | $R_s = \min(R_s^{sat}(p),\ R_{s,0})$ — равновесие без кинетики | $2\times10^{-14}$ |
| `temperature_profiles.png` | ОДУ первого порядка ($\lambda = 0$) | 0.017 К |

Проверка по $R_s$ **независима от GOR-замыкания**: она использует только
PVT-таблицу и численное давление. Совпадение на уровне машинного нуля
означает, что растворённый газ следует за давлением мгновенно — никакой
кинетики выделения в модели нет, и решатель не вносит в $R_s$ посторонней
динамики.

На графике насыщенности две проверки отвечают на разные вопросы:
кружки — выполняется ли само замыкание (используют численное $p$),
пунктир — точна ли вся конструкция целиком (не использует ничего
из расчёта, поэтому наследует ошибку давления).

Скрипты: [pressure_gor_closure.py](pressure_gor_closure.py),
[temperature_ode.py](temperature_ode.py). Каждый запускается автономно
и печатает сверку с расчётом.

### ⚠️ Гидродинамика и температура стационарны в разное время

Расхождение на два порядка, и это меняет смысл слова «стационар»:

| Поле | Выход на стационар | Значение на 3 сутках |
|---|---|---|
| $p$, $S_g$ | 8–12 ч (дальше max\|$\Delta p$\| **строго** 0) | стационарное |
| $T$ | ~150 суток | 346.867 К против предельных **346.657 К** |

Причина — полная теплоёмкость области $\approx 1.0\times10^{11}$ Дж/К:
тепловой фронт медленнее барического на порядки. Дрейф на 3 сутках
составляет $-0.024$ К/сут и убывает медленно.

Практически: конфиг задаёт 3 суток, чего достаточно для $p$ и $S_g$,
но **не** для $T$. Аналитика в `temperature_ode.py` это учитывает —
она воспроизводит переходный процесс шаг за шагом, а не предельное
состояние, поэтому сравнение корректно на любом шаге.

Отличие от примера 03 (тот же режим, но корреляции Стендинга):

| | 03 (Standing) | 04 (Table) |
|---|---|---|
| $p_b$ | 9.43 МПа | 15 МПа |
| $S_g^{max}$ | 0.0804 | 0.0147 |
| $r_b$ | 0.20 м | **2.39 м** |
| $q_o$ | $1.09\times10^{-2}$ | $5.88\times10^{-3}$ |
| $T(r_w)$ | 346.22 К | 346.87 К |
| $\lambda_{\text{тв}}$ | 1.5 | **0** |

Смена PVT-модели меняет **всё**: и насыщенность, и температуру, и дебит,
и положение фронта (в 12 раз). Сравните с парой 04↔06, где меняется
только ОФП и почти ничего не двигается.

⚠️ Строка $T(r_w)$ в этой таблице сравнивает расчёты с **разной**
теплопроводностью (в 04 она обнулена ради ОДУ-аналитики), поэтому
0.65 К включают и вклад $\lambda$. Различие по $p_b$, $S_g$, $r_b$
и $q_o$ от этого не зависит — гидродинамика и энергия расщеплены.

⚠️ **Сравнение с примером [06](../06_table_corey_rp/).** Пример 06 —
тот же расчёт с ОФП Кори вместо таблицы; **единственное** различие
конфигов — модель ОФП, теплопроводность у обоих нулевая.

| Величина | 04 (таблица) | 06 (Кори) | Разница |
|---|---|---|---|
| $S_g^{max}$ | 0.0147 | 0.0811 | **в 5.5 раза** |
| $T(r_w)$, К | 346.867 | 346.865 | 0.002 К |
| $q_o$, м³ст/с | $5.876\times10^{-3}$ | $5.763\times10^{-3}$ | 1.9 % |
| $r_b$, м | 2.386 | 2.386 | совпадает |

Насыщенность различается в 5.5 раза, температура — на 0.002 К. Это
**не перепутанные конфиги**: ОФП управляет распределением фаз, а на
тепловую задачу влияет ничтожно. Смотреть надо `saturation_profiles.png`.

Причина видна из замыкания (см. ниже): условие GOR $= R_{s,0}$ фиксирует
не сами кривые, а их отношение $k_{rg}/k_{ro}$, и правая часть этого
условия от модели ОФП не зависит вовсе. Подстраивается насыщенность —
у Кори то же отношение достигается при $S_g = 0.081$, у таблицы при 0.015.

## Как увеличить газонасыщенность

$S_g^{max} \approx 1.5\,\%$ — значение малое, и график $S_g(r)$ выглядит
скромно. Это **не ошибка расчёта**, а свойство демонстрационных данных.

### Почему $S_g$ мала

В стационаре работает баланс «сколько газа выделилось — столько унесено».
На контуре свободного газа нет ($S_g = 0$), весь газ приходит растворённым,
поэтому газовый фактор жёстко закреплён: $\text{GOR} = R_{s,0} = 30$.

Подставив это в отношение компонентных потоков $G^g/G^o$, видим, что общий
множитель сокращается, и остаётся **алгебраическое** уравнение на $S_g$:

$$R_s(p) + \frac{k_{rg}(S_g)}{k_{ro}(S_g)}\cdot\frac{\mu_o B_o}{\mu_g B_g} = R_{s,0}$$

Дефицит $R_{s,0} - R_s(p)$ левее фронта компенсируется потоком свободного
газа; отношение $k_{rg}/k_{ro}$ монотонно растёт по $S_g$, поэтому корень
единственный. Отсюда все свойства профиля насыщенности:

- **$S_g$ зависит только от $p$**, локально. Пространственный профиль —
  это композиция $S_g(p(r))$, а не самостоятельная динамика.
- **$k$, $\varphi$, $h$, $q_o$ в уравнение не входят** — отсюда нули
  в таблице выше.
- **Фронт разгазирования — это изобара $p = p_b$**, и ничего больше.

Насыщенность мала потому, что `relperm.csv` даёт $k_{rg} = 0.01$ уже при
$S_g = 0.1$: газ «слишком текучий», и малого $S_g$ хватает, чтобы
отношение подвижностей достигло нужного значения.

Термодинамический потолок при $p = 8$ МПа составил бы $S_g = 0.239$
(если бы весь выделившийся газ остался в ячейке) — фактическое значение
в 16 раз меньше, разница уходит в вынос потоком.

### Что НЕ помогает (проверено прогонами)

| Изменение | $S_g^{max}$ | Комментарий |
|---|---|---|
| базовый (3 суток) | 0.0147 | |
| 30 суток | 0.0147 | **без изменений** — стационар за 8–12 ч |
| $R_e = 500$ м | 0.0148 | фронт шире, $S_g$ практически та же |
| $k/10$ | 0.0147 | **вообще не меняется**; дебит падает в 10 раз |
| $\varphi = 0.05$ | 0.0147 | **вообще не меняется** |

Полная нечувствительность к $k$ и $\varphi$ — не совпадение, а прямое
следствие GOR-замыкания (см. ниже): уравнение на $S_g$ не содержит ни
проницаемости, ни пористости, ни дебита. Проницаемость меняет $q_o$
(в 10 раз), но $S_g$ при том же давлении — нет.

### Что помогает

**Рычаг 1 — подвижность газа (решающий, до ×25).** Заменить секцию `relperm`
на аналитическую модель Кори с крутой кривой:

```json
"relperm": {"model": "corey", "S_or": 0.2, "S_gc": 0.05,
            "n_o": 2.0, "n_g": 3.0, "kro_max": 1.0, "krg_max": 0.3}
```

| ОФП | $S_g^{max}$ | $T^{min}$, К |
|---|---|---|
| табличная (текущая) | 0.0147 | 346.87 |
| Кори $n_g = 2$, $k_{rg}^{max} = 0.8$ | 0.0811 | 346.86 |
| Кори $n_g = 3$, $k_{rg}^{max} = 0.3$ | **0.1647** | 346.86 |
| Кори $n_g = 4$, $k_{rg}^{max} = 0.1$, $S_{gc} = 0.1$ | **0.3055** | 346.99 |

Контринтуитивно: **менее подвижный газ даёт бо́льшую насыщенность**, потому
что для выноса того же расхода нужно накопить больше газовой фазы.

Обратите внимание на столбец $T^{min}$: насыщенность выросла в 20 раз,
а температура не сдвинулась. ОФП управляет распределением фаз, но почти
не влияет на тепловую задачу — та же закономерность, что в паре 04↔06.

**Рычаг 2 — газосодержание $R_{s,0}$:** 10 → 0.0005, 20 → 0.0077, 30 → 0.0147.
Выше 30 не задать: в `oil_pvt.csv` есть только ветки $R_s \in \{0, 30\}$.
Для больших $R_s$ нужна своя PVTO-таблица.

**Рычаг 3 — депрессия $p_{wf}$ (слабый):** 14 МПа → 0.0018, 8 МПа → 0.0147,
4 МПа → 0.0219.

⚠️ При крутой ОФП и/или низком $p_{wf}$ возможен отказ
`RuntimeError: HydroSolver не сошёлся после N подшагов`.
Лечится увеличением `"max_retries"` в секции `numerics` (по умолчанию 9).
Подробности — DEBT-007.

## Как модифицировать

### Что менять безопасно

| Параметр | Секция JSON | Эффект |
|---|---|---|
| $R_e$ | `geometry.R_ext` | шире область; фронт $r_b$ растёт |
| $h$, $k$, $\varphi$ | `geometry`, `rock` | дебит; фронт почти не двигается |
| $N$ | `grid.N` | детальность профилей |
| длительность | `time.history[].dt` | ⚠️ $p$, $S_g$ — стационар за 8–12 ч; $T$ — только за ~150 суток (см. ниже) |
| частота записи | `time.history[]` | число интервалов = число записей; 72 по 3600 с → 73 шага |
| тепловые скаляры | `thermal` | только $T$; гидродинамика не меняется (расщепление) |
| содержимое CSV | `oil_pvt.csv` и др. | своя лаборатория — главный сценарий использования |

### Что требует осторожности — $p_{wf}$

**Сверху:** при $p_{wf} > p_b = 15$ МПа разгазирования не будет
($S_g \equiv 0$), расчёт пройдёт молча.

**Снизу:** табличный путь устойчив в диапазоне 14…3 МПа — в отличие от
Стендинга (пример 03), где есть провалы сходимости.

### Не трогать

`grid.type` и `output.format` — объявлены в `io/config.py`, но не читаются.

## Запуск

```powershell
cd numerical_solver
.venv\Scripts\python examples\04_table_table\main.py
```

Расчёт с наложенной аналитикой на всех трёх профильных графиках.
Вспомогательные скрипты запускаются автономно и печатают сверку:

```powershell
.venv\Scripts\python examples\04_table_table\pressure_gor_closure.py
.venv\Scripts\python examples\04_table_table\temperature_ode.py
```

| Скрипт | Что делает |
|---|---|
| `pressure_gor_closure.py` | замыкание GOR: $S_g(p)$, дебит квадратурой; overlay для $p$ и $S_g$ |
| `temperature_ode.py` | ОДУ первого порядка для $T$; overlay для $T$; контроль вклада JT и дегазации |

График ОФП (`output/relperm.png`) строится сам при запуске `main.py` —
общим модулем [relperm_plot.py](../relperm_plot.py) для всех примеров.
Так же строится график PVT (`output/pvt.png`) — общим модулем
[pvt_plot.py](../pvt_plot.py).
