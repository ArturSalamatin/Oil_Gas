# Отчёт и сводка раунда

Сохрани `vault/issues/<id-lowercase>/audit-r<N>.md`. Отчёт содержит ID и тип задачи, номер и фокус раунда, путь и SHA-256 полного файла плана, состояние рабочей копии, проверенные источники и команды, находки с основаниями, непроверенные области, вопросы пользователю и вердикт. Явно запиши число блокирующих, существенных и уточняющих находок и число вопросов. У каждой находки укажи степень, место, свидетельство, последствие, рекомендацию и состояние. Для вопросов укажи, блокируют ли они продолжение.

Субагент завершает работу тремя строками без дополнительного текста:

```text
round: <N> | verdict: <готов/условно/не готов> | next-round: <да/нет>
found: blocking <N> | significant <N> | minor <N> | decisions <N>
report: <путь> | plan-sha256: <64 шестнадцатеричных символа>
```

Счётчики и вердикт относятся только к текущему раунду и согласуются с отчётом. Хеш соответствует байтам плана до правок основного агента. «Готов» означает выполненные обязательные проверки и отсутствие блокирующих замечаний. «Условно» содержит неблокирующие ограничения. «Не готов» обозначает блокирующую находку либо невыполненную обязательную проверку.

Поле `report` может содержать обычный путь или ссылку Markdown на локальный файл. Основной агент извлекает целевой путь, сопоставляет его с ожидаемым путём текущего раунда и читает файл. Отсутствие файла или несовпадение пути не заменяются догадкой по подписи ссылки.
