# DEBT-076: проверка знака плотностей при стандартных условиях

**GitHub issue:** [#129](https://github.com/ArturSalamatin/Oil_Gas/issues/129)

> **Подтип:** проверка входа (`_validate`), инфраструктура ввода. Новых формул нет. **База — не раньше влития [[FEAT-033]]** (решение пользователя 2026-10-17, раздел 0, п. 5): тест FEAT-033 `test_excel_not_stricter_than_program` фиксирует множество «книга строже программы» = {`pvt.rho_o_std`, `pvt.rho_g_std`}; эта задача делает его пустым и сама правит тест. **FEAT-033 влит 2026-10-17 (`7036854`); база плана после аудита 1 — `0f8074d`: 2116 тестов, быстрый уровень 1840.**
>
> **Параллельная [[DEBT-078]]** (#130, план `debt-078 co-undersaturated-table-check` готов к реализации) правит те же места: `_validate` сразу после $c_r$, класс тестов между `TestValidationRock` и `TestValidationInitial`, докстринг модуля `test_config.py`, комментарии `PVTConfig`, строку `_validate` и абзац после «Порода» в P8 §5, таблицу `pvt` в `json-config-schema.md`. Шаги 1 и 3 написаны для обоих порядков влития — см. «Если DEBT-078 влита раньше» в каждом шаге.

## 2. Контекст

### 2.1. Текущее состояние (на `8ddb08d`; FEAT-033 эти файлы не менял — номера строк сверены на `0f8074d`)

- `_validate` (`io/config.py:499`) секцию `pvt` не проверяет вовсе: в функции нет ни одного обращения к `cfg.pvt`. У плотностей — только тип и конечность: цикл `_check_numeric_fields` по `_NUMERIC_SECTIONS` в начале `_validate` (`:508-509`, [[DEBT-051]]). Пределы есть у `porosity`, `permeability`, `compressibility` ([[DEBT-068]]), `skin` ([[DEBT-056]]), `rho_cp_solid`, `c_p_oil`, `c_p_gas`, $\lambda$ ([[DEBT-047]]), `p0`, `T0`, `Rs0` — у плотностей нет.
- Фабрика передаёт плотности в PVT без проверки: `create_pvt` (`factory.py:105`) → `StandingFullPVT(rho_o_std=…, rho_g_std=…)` (`:111-124`) или `PrototypePVTAdapter(proto_pvt, pc.rho_o_std, pc.rho_g_std)` (`:154`) → `TableFullPVT`.
- Куда входят плотности:

  | путь PVT | где | что |
  |---|---|---|
  | оба | `pvt/base.py:70`, `:74` | $\rho_o = (\rho_{o,ст} + R_s\rho_{g,ст})/B_o$ (`eq:rho_oil`), $\rho_g = \rho_{g,ст}/B_g$ — теплоёмкость флюида в энергии |
  | оба | `fluxes.py:100-101`, `simulator.py:249-250` | массовые потоки фаз, массовые дебиты на забое |
  | оба | `energy/tridiag.py:545-570` | интенсивность разгазирования $\dot m$ (`eq:mdot`) — источник $Q_{deg} = -L\dot m$ |
  | Стендинг | `pvt/standing.py:20-24`, `:58-60` | $\gamma_{API} = 141.5/(\rho_{o,ст}/\rho_w) - 131.5$, $\gamma_g = \rho_{g,ст}/\rho_{возд}$ — вход корреляций $R_s$, $B_o$, $\mu_o$ |

- Гидродинамика табличного пути плотностей не видит (прототип работает в стандартных объёмах) — на этом пути отказа нет нигде.

## 3. Варианты (решено: 1)

| | суть | плюсы | минусы |
|---|---|---|---|
| **1 ✅** | отказ в `_validate` при ≤ 0 | как у остальных физических полей; один предел с книгой; отказ с именем поля до фабрики на обоих путях | правдоподобную ошибку (850 → 85) не ловит |

Почему отдельный блок, а не цикл тепловых параметров (`config.py`, цикл `0 < v < inf` для `rock.rho_cp_solid`, `thermal.c_p_*`): плотности — свойства флюида, не тепловые параметры; у цикла свой комментарий (DEBT-047) и текст «должна быть конечной и > 0» без единиц и смысла поля — для плотности главное подсказать, что нужна плотность при стандартных, а не пластовых условиях.
