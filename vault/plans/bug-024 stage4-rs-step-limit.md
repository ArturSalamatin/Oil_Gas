## 1. Контекст и диагностика

### 1.1 Симптом

Запись реестра: 10 суточных интервалов добычи конфига `20_rs300_cooling` при $p_{wf}$ примера, затем 3 сут останова при $q_{oil} = 0$, `min_bhp` = 1 атм; `dt_integration` = 86400 с, `max_retries` = 9:

```
HydroSolver не сошёлся при дроблении шага до dt/512 = 1.69e+02 с на подшаге с t = 10.0781 сут:
двухфазных ячеек 183 из 350, max S_g = 0.199.
```

До BUG-022 (база `9a4669e`) тот же расчёт проходил. Расчёт с `cell_tol = None` проходит побитово как до BUG-022, а с `max_retries` = 11 тоже проходит. Отсюда реестр и issue вывели, что отказы вносит условие по ячейке. Диагностика ниже это опровергла.

### 1.2 Условие по ячейке ни при чём — Ньютон ступени 4 не сходится и глобально

Проба `vault/issues/bug-024/probes/stage4_failure.py` оборачивает методы модели: `_newton_switching`, `finite_difference_jacobian`, `_switch_phases`, `_linear_solve`. Для каждого решения ступени 4 она записывает причину отказа и трассу итераций: $\|F\|_\infty/tol$, условие по ячейке, переключения фаз, зафиксированные грани. Выводы: `diag_20B_86400_ct1e-8_all.out.txt`, `diag_20B_86400_ct1e-8_rs0.out.txt`.

- Все 11 отказов ступени 4 — по лимиту: построено 41 якобиан.
- **Ни в одном отказе** $\|F\|_\infty$ не опускается до глобального порога `atol + rtol·‖F₀‖` («$\|F\| \le tol$ — 0 раз»). Условие по ячейке до проверки ни разу не доходит.
- В двух сошедшихся решениях условие по ячейке задержало приём на 1 итерацию. Это вся его роль.

Гипотеза issue (а) «не хватает 40 итераций, чтобы довести невязку до условия по ячейке» опровергнута.

Отдельно: `_newton_switching` при любом отказе пишет `iterations = max_iter` (`blackoil.py:578`), в том числе при досрочном `break`. Поэтому «в среднем 37.8 итерации» из записи реестра ничего не доказывало: 11 × 40 + 89 = 529. Это зарегистрировано как [[DEBT-061]] (2.7).

### 1.3 Механизм: шаг $R_s$ недонасыщенных ячеек ничем не ограничен

Обновление в `_newton_switching` (`blackoil.py:570-573`):

```python
x=z[n:]; lim=dp_rel*np.maximum(p,1.0)
pn=np.maximum(p+np.clip(dz[:n],-lim,lim),1.0+1e-6)
xn=np.where(mask,x+np.clip(dz[n:],-ds_max,ds_max),np.maximum(x+dz[n:],0.0))
```

Давление ограничено ($|\Delta p| \le 0.3p$, как `dp-max-rel` OPM Flow), $S_g$ двухфазных тоже ($|\Delta S_g| \le 0.2$, как `ds-max`). А $R_s$ недонасыщенных ячеек (второе неизвестное у них) **не ограничен**, отрицательный $R_s$ просто обрезается до 0. Замер (`diag_20B_86400_ct1e-8_rs0.out.txt`):
- шаги Ньютона по $R_s$ — до $+1.7\cdot10^{4}$ и $-1.8\cdot10^{3}$ м³ст/м³ст за итерацию, при самих $R_s$ около 90–300;
- обрезание до $R_s = 0$ случается десятки и сотни раз за решение: 738 раз в решении на 1 сут, 47–82 раза даже в сошедшихся решениях;
- обрезания формулой выхода из двухфазных (`_switch_phases`) — 0. Все нули дала строка обновления.

Два вида отказа на подшаге $t$ = 10.0781 сут:
- **застой** (h = 675 и 337.5 с). Недонасыщенная ячейка у забоя (3 или 11; в старом состоянии $R_s$ = 89.75 / 114.4 при $R_s^{sat}$ = 261) стоит на $R_s = 0$. Ньютон каждую итерацию требует $\Delta R_s \approx -45$, отсечка возвращает 0. Переключений фаз нет, $\|F\|/tol$ замер на $\approx 2\cdot10^{6}$ на 30 итераций, условие по ячейке — около 2.3 (230 % порового объёма в строке нефти);
- **хаос** (h = 168.75 с и все длинные подшаги). Давление итераций скачет до 433 бар, на каждой итерации переключаются десятки ячеек, $R_s$ сбрасывается в 0 сотни раз.

Ограничение шага по $R_s$ — прямой аналог `ds-max` для $S_g$. Допустимый диапазон $R_s$ недонасыщенной ячейки — $[0, R_s^{sat}(p)]$: выше ячейка переключается в двухфазный набор. Шаг $0.2\,R_s^{sat}(p)$ — та же доля диапазона, что $0.2$ для $S_g \in [0, 1]$. В руководстве OPM Flow 2025-10 (`Refs/incoming/OPM_Flow_Reference_Manual_2025-10_Rev-0_compressed.pdf`, с. 91 PDF) из ограничений приращений Ньютона есть `--dp-max-rel` = 0.3 и `--ds-max` = 0.2. Отдельного ограничения на $R_s$ в перечне параметров нет (поиск `dr-max`, `drMaxRel` — пусто). Поэтому это ограничение — решение проекта, а не перенос из OPM.

## 2. Анализ

### 2.1 Воспроизведение

- Проба: `.venv\Scripts\python ..\vault\issues\bug-024\probes\red_state.py code` — ✗ на 10.0781 сут.
- Тест-воспроизводитель (шаг 2): `tests/test_prototype_phase_switching.py::TestDailyShutin::test_daily_shutin_passes_default_retries`. На коде базы — `RuntimeError` на $dt/512$; проверено подменой `base` (`plan_tests/test_bug024_plan.py`: 2 failed — тест ограничения и этот).
- Тест ограничения (шаг 1): `TestRsStepLimit::test_large_rs_step_is_limited` — на коде базы $R_s$ всех недонасыщенных ячеек после одного обновления = 0.

### 2.2 Цепочка причин

1. **Вход.** Останов после 10 сут добычи с развитой газовой зоной. У забоя недонасыщенная нефть с низким $R_s$ (90–130) при давлении, быстро растущем к 270 бар ($R_s^{sat}$ = 261). Ступени 1–3 отказывают (BUG-020), шаг решает ступень 4.
2. **Ошибка.** `blackoil.py:573`: `np.maximum(x+dz[n:],0.0)` для недонасыщенных ячеек. Направление Ньютона по $R_s$ — до $10^{4}$; обрезание до 0 переводит итерацию в состояние, далёкое от корня.
3. **Распространение.** На $R_s = 0$ Ньютон тянет $R_s$ ниже нуля, отсечка возвращает 0 — застой. Или скачки давления до 433 бар и массовые переключения фаз — хаос. Лимит 40 итераций исчерпан, решение отказывает.
4. **Проявление.** `Simulator._advance` делит подшаг. Отказывают все подшаги от $dt$ до $dt/512$, и выходит `RuntimeError` «не сошёлся при дроблении шага до dt/512». Сходятся ли мелкие подшаги, зависит от состояния, к которому расчёт пришёл, то есть от округлений всех предыдущих шагов (1.4).

### 2.3 Целевое состояние

- Шаг Ньютона ступени 4 по $R_s$ недонасыщенной ячейки не больше $0.2\,\max(R_s^{sat}(p), 1)$; $R_s \ge 0$ — как прежде.
- 20B, 19B, 21B, 20A при 1 сут и `max_retries` = 9 проходят (1.6).

### 2.4 Варианты решения

**А. Ограничение шага $R_s$ в `_newton_switching` — выбран.** Строка обновления (`blackoil.py:573`):


Новый аргумент `dr_rel=0.2` — последним в сигнатуре, чтобы пробы, подменяющие `__defaults__` по индексам 0 и 2 (`max_iter`, `atol_sm3s`), не сдвинулись.
- Плюсы: устраняет причину; все сценарии 1.6; 17 быстрее в 1.5 раза, 20B 3600 с — в 5.7 раза.

```python
# E. BUG-024: шаг R_s недонасыщенных ячеек в ступени 4 ограничен
# ═══════════════════════════════════════════════════════════

def _first_update(model, ps, drs, monkeypatch):
    """z до и после одного обновления _newton_switching при подменённом направлении Ньютона.

    Направление: dp = 0, dS_g = 0, dR_s = drs у недонасыщенных ячеек (подмена
    _linear_solve). Второй вызов якобиана получает обновлённое z; на нём расчёт
    обрывается исключением _Stop. Двухфазные ячейки не меняются, давление тоже —
    переключений фаз при dR_s < 0 нет (активация требует R_s > R_s^sat).
    """
    n = model.grid.n
    mask = ps.gas_active.copy()
    zs = []
    orig_jac = model.finite_difference_jacobian

    def jac(z, *a, **kw):
        zs.append(z.copy())
        if len(zs) == 2:
            raise _Stop
        return orig_jac(z, *a, **kw)

    def lin(J, b):
        dz = np.zeros(2 * n)
        dz[n:][~mask] = drs
        return dz

    monkeypatch.setattr(model, "finite_difference_jacobian", jac)
    monkeypatch.setattr(model, "_linear_solve", lin)
    with pytest.raises(_Stop):
```

```python
    def test_daily_shutin_passes_default_retries(self):

        Ловит: возврат к неограниченному шагу R_s в ступени 4 (BUG-024).
        """
        cfg = load_config(RS300)
        cfg.output.log_level = "ERROR"
        hist = list(cfg.time.history)
        for _ in range(3):
            x = copy.deepcopy(hist[0])
            x.control, x.p_wf, x.q_oil, x.min_bhp = "rate", None, 0.0, 101325.0
            hist.append(x)

        assert cfg.time.dt_integration == DAY and cfg.numerics.max_retries == 9

        calls = []
        orig = sim._hydro.solve

        def solve(state, dt, bc):
            shut = state.t >= 10 * DAY - 1e-6
            try:
                r = orig(state, dt, bc)
            except HydroConvergenceError:
                if shut:
                    calls.append((dt, False))
                raise
            if shut:
                calls.append((dt, True))
            return r

        sim._hydro.solve = solve
        st = sim.run(init).states[-1]
        ok = [dt for dt, conv in calls if conv]
        failed = [dt for dt, conv in calls if not conv]
        assert len(ok) == 10 and len(failed) == 7
        assert sum(ok) == pytest.approx(3 * DAY, rel=1e-12)   # трое суток пройдены ровно один раз
        assert min(ok) == 5400.0

        assert st.T[0] == pytest.approx(375.3667, abs=1e-3)
```
