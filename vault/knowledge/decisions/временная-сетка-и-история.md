# Временная сетка и история

**GitHub issue:** [#50](https://github.com/ArturSalamatin/Oil_Gas/issues/50) — FEAT-018, неравномерное расписание с блочной записью

## Структура

Аналог InjectorGPN: `t_major_step` (шаги истории) + `t_minor_step` (шаг интегрирования).

Два уровня:
1. **Интервалы истории (major steps)** — задаются пользователем в JSON. Каждый интервал: длительность `dt` + забойное давление `p_wf`. На интервале p_wf = const.
2. **Подшаги интегрирования (minor steps)** — внутри каждого интервала. Шаг dt_actual ≤ dt_integration. Число подшагов подбирается так, чтобы целое число подшагов точно покрывало интервал.

## JSON-формат

```json
"time": {
    "dt_integration": 3600,
    "history": [
        {"dt": 86400,  "control": "pressure", "p_wf": 15000000},
        {"dt": 172800, "control": "pressure", "p_wf": 12000000},
        {"dt": 604800, "control": "rate", "q_oil": 0.001, "min_bhp": 5000000}
    ]
}
```

- время отсчитывается от начала истории, $t = 0$ (`start_day` удалён, [[DEBT-008]])
- `dt_integration` — шаг интегрирования, с (= dt_initial для гидро-прототипа)
- `control` — тип управления: `"pressure"` или `"rate"` (по умолчанию `"pressure"`)
- `dt_min`, `dt_max` удалены ([[DEBT-008]]): шаг — `dt_integration`, дробление — `numerics.max_retries`

### Краткие формы (FEAT-018)

Повторы и неравномерный шаг записи задаются блоками; парсер (`io/config.py`, `_expand_history`) разворачивает их в те же интервалы, решатель о блоках не знает:

```json
"history": [
    {"duration": 3600,  "dt_out": 300,  "control": "pressure", "p_wf": 8000000},
    {"duration": 18000, "dt_out": 3600, "control": "pressure", "p_wf": 8000000},
    {"dt": 3600, "repeat": 66, "control": "pressure", "p_wf": 8000000}
]
```

Первый час — 12 записей по 300 с, следующие 5 ч — 5 записей по 3600 с, затем 66 часовых интервалов. Правила и ограничения — [[json-config-schema]], секция `time`.

## Алгоритм подгонки шага

Для интервала k с длительностью Δt_hist:

```python
n_sub = ceil(Δt_hist / dt_integration)
n_sub = max(n_sub, 1)
dt_actual = Δt_hist / n_sub
```

**Пример:**
- dt_integration = 3600 с (1 час)
- Δt_hist = 10000 с
- n_sub = ceil(10000/3600) = 3
- dt_actual = 10000/3 ≈ 3333.3 с

Гарантии:
- dt_actual ≤ dt_integration (точность не хуже заданной)
- n_sub · dt_actual = Δt_hist **точно** (нет накопления ошибки)
- Конец каждого интервала достигается ровно

## Двухуровневый цикл

```python
for k, interval in enumerate(schedule.history):
    p_wf = interval.p_wf
    n_sub, dt = schedule.substeps(k)

    for step in range(n_sub):
        # шаг интегрирования: hydro + energy
        ...

    # сохранить результат на конце интервала
    history.append(state, well_data)
```

## Что сохраняется

Результаты сохраняются **только на концах интервалов истории**. Промежуточные подшаги не сохраняются.

Число записей в history = len(history_intervals) + 1 (начальное состояние).

Это соответствует физике: пользователь задаёт расписание эксплуатации (режимы работы скважины по интервалам), и хочет видеть состояние на конец каждого режима.

## Отличие от предыдущей схемы

Ранее (до уточнения 2026-08-25) предполагалась адаптивная схема с dt_growth_factor, dt_cut_factor, dt_min, dt_max. Теперь:
- **Нет** адаптивного шага — dt_actual фиксирован внутри интервала
- **Нет** dt_min, dt_max, growth/cut — шаг определяется пользователем
- **Нет** разрезания шага на границе интервала — подгонка гарантирует попадание

Это проще, предсказуемее, и соответствует подходу InjectorGPN.

Если в будущем потребуется адаптивный шаг (для Ньютона с плохой сходимостью) — это ответственность HydroSolver, не Simulator. HydroSolver может внутри себя делить dt_actual на подшаги при расходимости. Simulator видит только один вызов `hydro.solve(state, dt, p_wf, ...)`.

## Связь с InjectorGPN

В InjectorGPN:
- `t_minor_step`: 1 (в единицах t_unit, обычно сутки)
- `t_major_step`: [1.0, 1.0, ...] — массив длительностей интервалов
- `well_rate`, `pressure`, `inlet_temperature` — параметры на каждом интервале

У нас упрощённо: один параметр на интервал (p_wf). В будущем можно расширить до нескольких (температура притока, дебит и т.д.).
