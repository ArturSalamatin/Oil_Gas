## Описание

Собрать комплект поставки заказчику: решатель гидродинамики и температуры `gpn-multiphase-solver`, прототип `radial-blackoil`, примеры, тесты, постановку задачи. Решение пользователя 2026-10-10: отдел разработки заказчика правит исходный код и развивает проект, инженеры и аналитики запускают расчёты.

Состав комплекта:

1. **Исходный код** — отдельный репозиторий или архив: пакет `gpn_multiphase_solver`, прототип, тесты, примеры, постановка (`numerical_solver/doc/problem_statement.tex` и PDF). Репозиторий `Oil_Gas` целиком не передаётся: в нём `vault/` (внутренние заметки), `method_of_moments/`, LaTeX других подходов.
2. **Дистрибутивы** обоих пакетов — для установки без исходного кода.
3. **Инструкции.** Разработчикам: установка с правкой исходников (`pip install -e`), тесты и их уровни, регрессия прототипа. Инженерам: установка, команда расчёта (FEAT-030), формат конфига, что показывают рисунки и проверки.
4. **Приёмочная проверка** скриптом, который повторяется на машине заказчика: новое виртуальное окружение → установка из комплекта → тесты → расчёт примера из постороннего каталога → совпадение с эталонным выводом.
5. **Версии и журнал изменений** обоих пакетов.

## Мотивация

Последняя задача цепочки поставки DEBT-059 (#94) → DEBT-011 (#91) → FEAT-030 (#104) → FEAT-031. Первые три влиты: прототип — отдельный устанавливаемый дистрибутив, диагностика примеров — в пакете, расчёт по конфигу — команда `gpn-solver run` / `python -m gpn_multiphase_solver run`. Чего нет: самого комплекта, инструкций в базовой ветке, согласованных номеров версий и воспроизводимой приёмки на чужой машине.

## Анализ вариантов решения

### Сверка с эталоном на машине заказчика

- **Побайтно (как в пробе FEAT-030).** Работает только при тех же версиях numpy/scipy/matplotlib, той же сборке BLAS и ОС. На другой машине последние биты CSV и PNG расходятся — ложный отказ приёмки. Годится лишь при установке строго из колёс комплекта на той же платформе.
- **Числа с допуском + наличие рисунков.** Истории и профили (CSV) сравниваются с эталоном с относительным допуском; PNG/SVG — только наличие и число файлов. Не зависит от сборки BLAS и версии matplotlib. Допуск выбрать по замеру разброса между версиями зависимостей.
- **Рекомендация:** второй вариант; в комплект — файл ограничений версий (`constraints.txt`), на которых получен эталон, чтобы расхождение сверх допуска указывало на ошибку, а не на версию библиотеки.

### Исходный код

- **Срез без истории** (`git archive HEAD:numerical_solver`): просто, воспроизводимо, только отслеживаемые файлы. Минус — заказчик не видит, почему код такой.
- **Отдельный репозиторий с историей каталога** (`git subtree split --prefix numerical_solver`): история сохраняется, но сообщения коммитов ссылаются на `vault/`, которого у заказчика нет.
- Решает пользователь (открытый вопрос реестра).

### Где живут сборка и приёмка

- **Скрипты в `numerical_solver/`** (каталог — при планировании): сборка комплекта (срез, колёса, PDF постановки, эталон, манифест SHA256, архив) и приёмка входят в исходный код — разработчики заказчика соберут следующую версию сами.
- **Команда пакета** (`gpn-solver selftest`): эталон 23 примеров попадает в колесо и раздувает его; для инженеров удобнее, но тянет в пакет то, что нужно один раз. Не рекомендуется.

## План реализации

1. **Проектирование.** Решения пользователя по открытым вопросам: версия Python и ОС у заказчика; доступ к PyPI или установка без сети (тогда в комплект — колёса numpy, scipy, matplotlib, XlsxWriter под их Python); точные или нижние границы версий; история git или срез; авторство и условия использования кода прототипа и решателя; Inkscape для EMF в инструкции; входит ли `CONTEXT_HANDOFF_1.0.3.md`; способ сверки с эталоном; номер версии решателя.
2. **Версии и журналы.** `gpn.2` прототипа; `__version__` решателя и тест; `CHANGELOG.md` решателя; раздел `gpn.2` в журнале прототипа; манифест SHA256 прототипа.
3. **Инструкции.** README пакета — в git, $h_0$ после BUG-026, число тестов, команды проверены в чистом окружении; раздел для разработчиков (уровни тестов, регрессия прототипа); пояснение про ссылки на внутренние задачи.
4. **Сборка комплекта.** Скрипт: срез исходного кода, колёса обоих пакетов (и зависимостей — при установке без сети), PDF постановки, эталон примеров, `constraints.txt`, манифест SHA256 комплекта, архив.
5. **Приёмка.** Скрипт на основе `clean_env_command.py`: новое venv → установка из комплекта без сети → тесты (уровень — решить) → расчёт примеров из постороннего каталога → сверка с эталоном.
6. **Верификация.** Приёмка на собранном комплекте в чистом окружении (по возможности — на второй машине или другой версии Python из диапазона `>=3.10`); полный прогон тестов; `test_packaging.py` зелёный.
