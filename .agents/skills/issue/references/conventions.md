# Соглашения и правила для задач (issue)

Документ фиксирует правила именования, сопоставления меток и адресации реестров проекта для навыка `issue`.

## 1. Реестры задач в vault

| Префикс ID | Тип задачи | Файл реестра в vault |
|---|---|---|
| `BUG-` | Ошибка / дефект | `vault/roadmap/известные баги и технический долг.md` |
| `DEBT-` | Технический долг / рефакторинг | `vault/roadmap/известные баги и технический долг.md` |
| `FEAT-` | Новая функциональность | `vault/roadmap/планируемые фичи.md` |
| `VAL-` | Валидационный расчет / кейс | `vault/roadmap/валидационные кейсы.md` |

## 2. Формирование имени ветки git

Формат: `<prefix>/<id-lowercase>/<slug>`

| Префикс ID | Префикс ветки | Пример ID | Пример ветки |
|---|---|---|---|
| `BUG-*` | `fix` | `BUG-001` | `fix/bug-001/pvt-negative-viscosity` |
| `DEBT-*` | `refactor` | `DEBT-001` | `refactor/debt-001/split-pvt-module` |
| `FEAT-*` | `feat` | `FEAT-001` | `feat/feat-001/standing-pvt` |
| `VAL-*` | `val` | `VAL-001` | `val/val-001/dupuit-steady-state` |

### Требования к части slug:
- От 2 до 5 слов на латинице в нижнем регистре (lowercase), разделенных дефисом.
- Отражает существо решаемой задачи, а не ее номер.
- Не содержит артиклей и предлогов.

## 3. Назначение меток (labels) на GitHub

Базовые метки по типу:
- `BUG-*` → `bug`
- `DEBT-*` → `enhancement`
- `FEAT-*` → `feature`
- `VAL-*` → `validation`

Дополнительные метки по контексту:
- Метку `critical` добавлять при явно указанной критичности; 🔴 в статусе открытой задачи сам по себе критичности не означает
- Если статус содержит 🟡 (наличие обходного решения) → добавить метку `workaround`
- Если поле **Блокирует** заполнено → добавить метку `blocking`

## 4. Хранение артефактов issue

Все текстовые заготовки перед публикацией сохраняются в каталоге `vault/issues/<id-lowercase>/`:
- `00-draft.md` – контекст регистрации, если черновик существует.
- `01-issue-body.md` – тело задачи для GitHub.
- `02-comment-open.md` – комментарий «Контекст при открытии».

Категорически запрещено использовать временные каталоги ОС или scratchpad. Хранение в репозитории обеспечивает версионируемость и воспроизводимость истории задачи без запросов к внешнему API GitHub.
