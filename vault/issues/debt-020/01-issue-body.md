## Описание

Кондуктивная проводимость грани $\mathcal{Q}_T$ в `energy/tridiag.py` хранится не так, как остальные величины на гранях: внутренние грани — массив $[N-1]$ со сдвигом индекса, контурная — отдельный скаляр, забойной нет вовсе. Все прочие грань-величины модуля ($\Phi^\pm$, $\Phi_o$, $\Phi_g$) — массивы $[N+1]$, индексируемые номером грани напрямую. В результате в одной строке сборки соседствуют две конвенции индексации. Дефекта в результатах нет; задача снижает риск ошибки индексации ровно в том члене, где она уже была ([BUG-002](#19): двойной $\ln$, [BUG-027](#97): тот же дефект в постановке).

Запись реестра составлена 2026-09-20. Ниже — состояние кода на `d7528d4` (2026-10-11): часть мотивации с тех пор закрыта (см. «Что уже сделано»).

## Текущее состояние

| грань | где лежит | тип |
|---|---|---|
| $f = 0$ (забой) | нигде | — |
| $f = 1 \ldots N-1$ | `Q_T_internal[f-1]` | массив $[N-1]$, **индексация со сдвигом** |
| $f = N$ (контур) | `Q_T_ext` | скаляр, отдельный аргумент |

Сборка внутренней строки (`TridiagEnergySolver.assemble_tridiag`):

```python
Q_T_L = Q_T_internal[j - 1]     # грань j   — со сдвигом
Q_T_R = Q_T_internal[j]         # грань j+1 — со сдвигом
...
b[j] = cap[j] + Q_T_L + Q_T_R + Phi_plus[j] - Phi_minus[j + 1]
#                               ↑ грань j    ↑ грань j+1 — без сдвига
```

Постановка такого разделения не делает: `eq:tridiag_a`–`eq:tridiag_c` пишут $Q^T_{\lambda,j\mp 1/2}$ для всех $j$, а ГУ Неймана у забоя (`ssec:bc_disc`) — это просто $Q^T_{\lambda,1/2} = 0$.

Что плохо:

1. **Две конвенции индексации в одном выражении** — главное. `_ref_assemble` эталона [DEBT-016](#33) (`tests/test_energy_matrix_examples.py`) повторяет ту же структуру, поэтому ошибку сдвига, внесённую в обе сборки одинаково, сверка матрицы не увидит.
2. **Разнотипная сигнатура.** `compute_conductive_transmissibility` возвращает пару `(Q_T_internal, Q_T_ext)`, `assemble_tridiag` принимает их двумя аргументами — кондуктивный член выбивается из общего контракта модуля.
3. **Особые случаи из-за хранения.** `if N > 1 … else np.empty(0)` в `compute_conductive_transmissibility` и явная ветвь `if N == 1` в `assemble_tridiag`: при $N = 1$ блоки «забой» и «контур» пишут в один элемент, и второй затирал бы первый.

### Что уже сделано после регистрации

- [BUG-012](#36) (`4f8220e`, 2026-09-22) выделил $N = 1$ явной ветвью в `assemble_tridiag` и `_ref_assemble` и добавил `test_energy.py::TestAdvectiveFormDetectors::test_single_cell_boundary_contribution_counted_once`. Мотивация записи «четыре непокрытых ветвления `if N > 1`, теста с $N = 1$ нет» и пункт «сопутствующий тест $N = 1$ написать до правки» **устарели**: тест есть, он же исполняет ветвь `np.empty(0)`.
- [DEBT-010](#92) заменил ссылки `balance.py` → `tridiag.py:NNN` ссылками по имени метода. Устаревшими остались две ссылки на номера строк (см. таблицу).

## Целевое состояние

Единый массив `Q_T` длины $[N+1]$, индексируемый номером грани, как `Phi_plus`/`Phi_minus`:

- `Q_T[0] = 0.0` — следствие ГУ Неймана $\partial T/\partial r|_{r_w} = 0$ (`ssec:bc_disc`): вклад $\mathcal{Q}_T[0]\,(T_{-1} - T_0) \equiv 0$ при любой $T_{-1}$;
- `Q_T[1..N-1]` — внутренние грани, без сдвига индекса;
- `Q_T[N]` — контурная, вместо скаляра `Q_T_ext`.

`balance.py` по-прежнему получает проводимость **от решателя** (`add_substep(Q_T_ext=Q_T[N])`), а не пересчитывает её: иначе повторятся [BUG-004](#21) и BUG-002.

**Численный результат не меняется ни на бит** — добавляется нулевой элемент, меняется индексация, арифметика внутри грани та же. Проверка — побитовым сравнением поля $T$ (утилита `tests/baseline_vectorization_check.py`, эталон снимается до правки).

**Чего правка не даёт.** Забойный ноль и контурная проводимость разнородны по смыслу (Нейман против Дирихле): у $\mathcal{Q}_T[N]$ есть парный член $\mathcal{Q}_T[N]\,T_{ext}$ в правой части `d[N-1]`, у забойного нуля — нет. Граничные строки останутся особыми и в варианте 2; уходит двойная индексация, а не граничные условия.

## Анализ вариантов решения

### Вариант 1 — только хранение (как в записи реестра)

- **Суть:** `Q_T` $[N+1]$; цикл по внутренним ячейкам, блоки «забой»/«контур» и ветвь `if N == 1` остаются, меняются только индексы (`Q_T[j]`, `Q_T[j+1]`, `Q_T[N]`).
- **Плюсы:** минимальный дифф; побитовость очевидна.
- **Минусы:** ветвь $N = 1$ и раздельные граничные блоки остаются — их причина не хранение, а то, что блоки **присваивают** строку целиком.

### Вариант 2 — единый массив + сборка по формулам постановки на всех строках

- **Суть:** при `Q_T[0] = 0` формулы `eq:tridiag_a`–`eq:tridiag_c` верны для **всех** $j$, включая граничные и $N = 1$:
  - `b = cap + Q_T[:-1] + Q_T[1:] + Phi_plus_w[:-1] - Phi_minus[1:]`, где `Phi_plus_w` — `Phi_plus` с занулённой гранью 0 (забойная грань конвективного вклада не даёт, как сейчас);
  - `a = -Q_T[:-1] - Phi_plus_w[:-1]`, `a[0] = 0.0`; `c = -Q_T[1:] + Phi_minus[1:]`, `c[N-1] = 0.0`;
  - `d = cap*T_old + J_jt + V*(Q_ad + Q_deg)`, затем `d[N-1]` — полной формулой контура в прежнем порядке слагаемых.

  Ветвь `if N == 1` и цикл исчезают: граничные поправки точечные и не затирают друг друга.
- **Побитовость (проверено выкладкой, не прогоном):** `b[0]` = `((cap + 0.0) + Q_T[1] + 0.0) - Φ⁻[1]` — прибавление точного нуля не меняет ни бита; порядок сложения в `b[N-1]` совпадает с нынешним; `d[N-1]` собирается в прежнем порядке. Подтвердить утилитой обязательно.
- **Плюсы:** код повторяет запись постановки; уходят цикл, ветвь $N = 1$ и обе конвенции индексации.
- **Минусы:** правка тела сборки больше, чем в варианте 1; `_ref_assemble` остаётся циклом — это даже полезно (эталон и решатель собраны по-разному).

### Эталон DEBT-016 — отдельно от ядра

`_ref_conductive` считает проводимость **другим путём** (взвешенное среднее $\lambda_{face}$ и $\ln(r_{c,f}/r_{c,f-1})$) — в независимости вывода ценность эталона. Менять только **способ хранения результата** (или оставить пару и сравнивать `Q_T[1:N]`, `Q_T[N]`), не способ вычисления; отдельным шагом от правки ядра, чтобы сверка матрицы на шаге ядра шла против нетронутого эталона.

**Рекомендация:** вариант 2. Если план покажет, что векторная сборка теряет побитовость, — откат к варианту 1, он тоже закрывает мотивации 1 и 2.

## План решения

1. **Базовый вариант.** Быстрый уровень тестов на `numerical_scheme/implementation`; эталон $T$ утилитой `baseline_vectorization_check.py` (`BASELINE_WRITE=1`) — до любой правки. Проверить, что утилита работает на текущем API (написана под DEBT-017/018); при необходимости добавить в неё пример останова (16).
2. **Ядро.** `compute_conductive_transmissibility` → `Q_T` $[N+1]$; `assemble_tridiag` по выбранному варианту; `solve` передаёт `Q_T` и `Q_T[N]` в накопитель. Тесты-вызовы — механически. Побитовая сверка утилитой; `test_energy_matrix_examples.py` против нетронутого эталона.
3. **Эталон DEBT-016.** Хранение результата `_ref_conductive`/`_ref_assemble` — отдельным шагом; путь вычисления не трогать. Сверка матрицы зелёная.
4. **Ссылки.** `test_examples.py:752`, `examples/02_single_phase_jt/main.py:143` → ссылки по имени метода.
5. **Верификация.** Полный прогон; побитовая сверка $T$; тест $N = 1$ проходит без изменений смысла (меняется только распаковка).
