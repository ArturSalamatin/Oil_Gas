# JSON-конфиг numerical_solver — структура и соглашения

> **SUPERSEDED** частично. Актуальная структура JSON: [[P8-формат-ввода-json]]. Эта заметка содержит полезные детали по валидации и описанию отдельных секций, но структура секций обновлена в P8.

## Принципы

1. **Всё в SI**: Па, К, м, с, кг. Конвертация единиц — на входе, не внутри кода.
2. **Группировка по физике**: geometry, grid, rock, pvt, relperm, thermal, initial_conditions, boundary_conditions, numerics, output.
3. **Без дублирования**: PVT-параметры задаются один раз. Разделение на «гидро-PVT» и «тепловой PVT» — ответственность кода.
4. **Валидация при чтении**: dataclasses в Python, проверка в конструкторах.

## Секции

### geometry

| Поле | Тип | Ед. | Описание |
|---|---|---|---|
| `r_well` | float | м | Радиус скважины r_w |
| `R_ext` | float | м | Радиус контура питания R_ext |
| `h` | float | м | Мощность пласта |

Ограничения: `r_well > 0`, `R_ext > r_well`, `h > 0`.

### grid

| Поле | Тип | Описание |
|---|---|---|
| `N` | int | Число ячеек |
| `type` | str | `"log_radial"` — единственный пока |

Ограничения: `N >= 1` (обновлено, см. P8).

### rock

| Поле | Тип | Ед. | Описание |
|---|---|---|---|
| `porosity` | float | — | Пористость φ |
| `permeability` | float | м² | Абсолютная проницаемость k |
| `rho_cp_solid` | float | Дж/(м³·К) | Объёмная теплоёмкость скелета |
| `lambda_solid` | float | Вт/(м·К) | Теплопроводность скелета |
| `lambda_oil` | float | Вт/(м·К) | Теплопроводность нефтяной фазы |
| `lambda_gas` | float | Вт/(м·К) | Теплопроводность газовой фазы |

Ограничения: `0 < porosity < 1`, `permeability > 0`, все λ > 0.

### pvt

| Поле | Тип | Описание |
|---|---|---|
| `model` | str | `"standing"`, `"table"`, `"custom"` |
| `rho_o_std` | float | Плотность нефтяного компонента при ст. условиях, кг/м³ |
| `rho_g_std` | float | Плотность газового компонента при ст. условиях, кг/м³ |

Для `"standing"`: параметры корреляции (gamma_o, gamma_g, ...).
Для `"table"`: пути к CSV-файлам с колонками p, Bo, Bg, mu_o, mu_g, Rs_eq.
Для `"custom"`: `module_path` + `class_name` (importlib).

### relperm

| Поле | Тип | Описание |
|---|---|---|
| `model` | str | `"corey"`, `"table"`, `"brooks_corey"`, `"LET"` |

Для Corey:

| Поле | Тип | Описание |
|---|---|---|
| `S_or` | float | Остаточная нефтенасыщенность |
| `S_gc` | float | Критическая газонасыщенность |
| `n_o` | float | Показатель Кори для нефти |
| `n_g` | float | Показатель Кори для газа |
| `kro_max` | float | Максимум kro |
| `krg_max` | float | Максимум krg |

Ограничения: `0 ≤ S_or < 1`, `0 ≤ S_gc < 1`, `S_or + S_gc < 1`, `n > 0`, `0 < k_max ≤ 1`.

Для `"table"`: `file` — путь к CSV (Sg, kro, krg).

### thermal

| Поле | Тип | Ед. | Описание |
|---|---|---|---|
| `mu_JT_oil` | float | К/Па | Коэффициент Джоуля-Томсона нефти |
| `mu_JT_gas` | float | К/Па | Коэффициент Джоуля-Томсона газа |
| `L_degas` | float | Дж/кг | Удельная теплота дегазации |
| `c_p_oil` | float | Дж/(кг·К) | Теплоёмкость нефти |
| `c_p_gas` | float | Дж/(кг·К) | Теплоёмкость газа |

Все — постоянные скаляры (п. 1.2 задания). ABC принимает (p, T) для расширяемости; скалярная реализация игнорирует аргументы.

### initial_conditions

| Поле | Тип | Ед. | Описание |
|---|---|---|---|
| `p0` | float | Па | Начальное пластовое давление |
| `T0` | float | К | Начальная температура |
| `Rs0` | float | м³ст/м³ст | Начальное газосодержание (обязательно) |

Начальное состояние однофазное ($S_g = 0$), поэтому нефть на старте недонасыщенная: `Rs0 <= Rs_eq(p0)` (то есть `p0 >= pb(Rs0)`), допуск $10^{-5}$ м³ст/м³ст. Для табличной PVT `Rs0` должен лежать в диапазоне веток `oil_pvt.csv`. Обе проверки — `SimulatorFactory.from_config`, нарушение — `ValueError` (BUG-017). Выход начального давления за газовую таблицу или ветки нефти — предупреждение в журнале.

### time (история + шаг интегрирования)

Аналог InjectorGPN: `t_minor_step` (шаг интегрирования) + `t_major_step` (шаги истории).

```json
"time": {
  "dt_integration": 3600,
  "history": [
    {"dt": 86400, "p_wf": 15000000},
    {"dt": 172800, "p_wf": 12000000},
    {"dt": 604800, "p_wf": 10000000}
  ]
}
```

| Поле | Тип | Ед. | Описание |
|---|---|---|---|
| `dt_integration` | float | с | Желаемый шаг интегрирования |
| `history` | list | — | Массив интервалов истории |
| `history[k].dt` | float | с | Длительность k-го интервала (шаг истории) |
| `history[k].p_wf` | float | Па | Забойное давление на k-м интервале |

**Алгоритм подгонки шага:**
Для каждого интервала истории k с длительностью Δt_hist:
1. n_sub = ceil(Δt_hist / dt_integration) — число подшагов
2. dt_actual = Δt_hist / n_sub — фактический шаг (≤ dt_integration)
3. Выполнить n_sub шагов интегрирования с постоянным p_wf
4. Сохранить результат на конце интервала

Гарантии:
- dt_actual ≤ dt_integration (точность не хуже заданной)
- n_sub · dt_actual = Δt_hist ровно (нет накопления ошибки)
- Результаты на концах интервалов истории (не на каждом подшаге)

Ограничения: `dt_integration > 0`, `history` не пуст, `dt > 0`, `p_wf > 0` для каждого элемента.

### output

| Поле | Тип | Описание |
|---|---|---|
| `fields` | list[str] | `["p", "T", "Sg", "Rs", "u_o", "u_g"]` |
| `format` | str | `"npz"` (по умолчанию) или `"csv"` |

⚠️ Поле `save_every` **удалено** (DEBT-013). Частоту записи задаёт только
структура `time.history`: число интервалов = число записей. Конфиг с этим
полем отвергается с `ValueError` — молчаливое игнорирование изменило бы
состав вывода без предупреждения. См. [[временная-сетка-и-история]].

## Реализация в Python

`config.py`:
- `json.load()` → dict
- Каждая секция → dataclass с `__post_init__` валидацией
- Верхний класс `SimulationConfig` агрегирует все секции
- При ошибке валидации — `ValueError` с понятным сообщением

## Расширяемость PVT

Три модели:
1. **standing** — встроенные корреляции Стендинга, Бэггса-Робинсона
2. **table** — CSV-таблицы (как в InjectorGPN для газа)
3. **custom** — пользовательский Python-класс, наследующий FullPVT

Для custom: `"module_path": "path/to/my_pvt.py"`, `"class_name": "MyPVT"`. Фабрика делает `importlib.import_module` + `getattr` + проверку `isinstance(obj, HydroPVT)`.
