# Сдвиг матрицы энергии на 1 ULP не меняет записанных T — побитовая проверка ведётся по хешам a, b, c, d

**Замер** (план [[debt-020 unified-face-conductance]], `vault/issues/debt-020/probes/plan_negative_control.py`, код `d7528d4`). Обёртка над `TridiagEnergySolver.assemble_tridiag` сдвигает `b[N-1]` на одну единицу последнего разряда (`np.nextafter`) на **каждом** вызове. Проба `bits_capture.py` сравнивает с нетронутым кодом:

| | матрица $a, b, c, d$ (sha256 на вызов) | записанные поля $T$ |
|---|---|---|
| синтетика, 800 случаев | расходится с вызова 0 | — |
| 07, 10, 11, 14, 16 | расходится с вызова 0 | **побитово прежние** |

**Почему.** СЛАУ решается в отклонениях $\theta = T - T_{ext}$ ([[невязку баланса энергии задавало решение СЛАУ в абсолютной температуре]], DEBT-043); $|\theta|$ — единицы–десятки К, а в историю пишется $T = \theta + T_{ref}$ с $T_{ref} \approx 350$ К. Сдвиг $\theta$ на относительную величину $\sim\varepsilon$ меньше половины ULP числа 350 и при сложении исчезает. Поэтому совпадение записанных $T$ до бита **не доказывает**, что схема не изменилась.

**Следствие для проверок.**
- «Побитово прежний» рефакторинг `energy/` проверяется по хешам $a, b, c, d$ через `matrix_probe` на каждом вызове `solve` плюс поля $T$; образец — `vault/issues/debt-020/probes/bits_capture.py` (снимок ~30 с: синтетика $N = 1, 2, 3, 10$ с $T_{ext} \ne 0$ и $\Phi^+_0 > 0$; примеры 07, 10, 11, 14, 16).
- Нужен отрицательный контроль: проба обязана видеть сдвиг в 1 ULP, иначе «совпало» ничего не значит.
- Утилита `tests/baseline_vectorization_check.py` (DEBT-018) сравнивает только последнее поле $T$ — для таких правок недостаточна.

**Применение — DEBT-020.** Проводимость грани переведена в массив $[N+1]$, сборка СЛАУ — на операции над массивами без цикла и ветви $N = 1$. Хеши матрицы совпали с базой на всех вызовах после каждого шага кода (`bits_compare.out.txt`); при планировании кандидатная сборка сверена с прежней на каждом вызове всех 23 примеров (`plan_vector_assembly.out.txt`).
