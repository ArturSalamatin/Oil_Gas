# 07 — Разгазирование: только адиабатический эффект

## Описание

Двухфазный сценарий с разгазированием: табличные PVT и ОФП,
$R_{s,0} = 30$, $p_{wf} = 8$ МПа.

**Все тепловые коэффициенты секции `thermal` обнулены**: $\mu_{JT,o} = \mu_{JT,g} = 0$,
$L = 0$. Остаётся единственный источник изменения температуры —
адиабатический член:

$$Q_{ad} = \varphi \sum_\alpha S_\alpha \left(1 + \rho_\alpha c_{p,\alpha} \mu_{JT,\alpha}\right) \frac{dp}{dt}$$

При $\mu_{JT} = 0$ он сводится к $\varphi \, dp/dt$: множитель
$1 + \rho c_p \mu_{JT}$ равен $\alpha T$ фазы, и нулевой $\mu_{JT}$ означает
$\alpha T = 1$.

## Комбинация модулей (B: Table + Table)

| Модуль | Класс | Ключ конфига |
|---|---|---|
| Сетка | `LogRadialGrid` | `grid.N = 50` |
| PVT (гидро) | `TableFullPVT` | `pvt.model = "table"` |
| PVT (термо) | скаляры `thermal` | **все нули** |
| ОФП | `PrototypeRPAdapter` | `relperm.model = "table"` |
| Гидродинамика | `PrototypeHydroAdapter` | (единственный) |
| Энергия | `TridiagEnergySolver` | (единственный) |

```json
"thermal": {
    "c_p_oil": 2000.0,
    "c_p_gas": 1000.0,
    "mu_JT_oil": 0.0,        ← выключен
    "mu_JT_gas": 0.0,        ← выключен
    "L_degas": 0.0           ← выключена
}
```

$c_{p,o}$ и $c_{p,g}$ остаются положительными — они стоят в знаменателе
уравнения энергии, обнулить их нельзя.

Теплопроводность — 1.5 / 0.14 / 0.04 Вт/(м·К). Источником она не является:
это перенос тепла, как и конвекция. Без неё $T(r_w)$ за 3 суток была бы
ниже на 0.001 К.

| $S_g^{max}$ | 0.0147 |

| фронт $r_b$ | 2.63 м |

### Откуда охлаждение

При $\mu_{JT} = 0$ множитель адиабатического члена равен единице
($\alpha T = 1$ для обеих фаз), и $Q_{ad} = \varphi\,dp/dt$. Давление
падает, $dp/dt < 0$ — поровое пространство теряет энергию на работу
расширения, забой охлаждается на 0.47 К. Эффект Джоуля–Томсона и скрытая
теплота дегазации в этом сценарии выключены.

Гидродинамика от тепловых коэффициентов не зависит — следствие
расщепления (operator splitting): `HydroSolver` не видит секцию `thermal`,
`EnergySolver` работает на замороженных $p$, $S_g$, $R_s$.

## Как увеличить газонасыщенность

$S_g^{max} = 1.5\,\%$ — свойство демонстрационной таблицы ОФП, не ошибка:
`relperm.csv` даёт $k_{rg} = 0.01$ уже при $S_g = 0.1$, газ подвижен и
выносится потоком, не накапливаясь. Главный рычаг — заменить `relperm` на
модель Кори с крутой кривой:

```json
"relperm": {"model": "corey", "S_or": 0.2, "S_gc": 0.05,
            "n_o": 2.0, "n_g": 3.0, "kro_max": 1.0, "krg_max": 0.3}
```

даст $S_g^{max} = 0.165$ вместо 0.015: чем **менее** подвижен газ, тем
бо́льшая насыщенность нужна, чтобы вынести тот же поток.

Что не помогает: увеличение длительности (стационар за 8–12 ч),
расширение $R_e$ (двигает фронт, не насыщенность).

## Как модифицировать

### Что менять безопасно

| Параметр | Секция JSON | Эффект |
|---|---|---|
| тепловые скаляры | `thermal` | только $T$; гидродинамика не меняется вовсе |
| $R_e$ | `geometry.R_ext` | шире область; фронт $r_b$ растёт |
| $h$, $k$, $\varphi$ | `geometry`, `rock` | дебит; ⚠️ $\varphi$ входит и в адиабатический член |
| $N$ | `grid.N` | детальность профилей |
| длительность | `time.history[0].duration` | ⚠️ стационар за 8–12 ч |
| частота записи | `time.history[0].dt_out` | запись раз в `dt_out` на этапе `duration`: 259 200 / 3600 → 72 интервала, 73 шага; `duration` должна делиться на `dt_out` |

### Что требует осторожности — $p_{wf}$

**Сверху:** при $p_{wf} > p_b = 15$ МПа разгазирования не будет ($S_g \equiv 0$).

**Снизу:** табличный PVT устойчив в диапазоне 14…3 МПа.
При отказе `RuntimeError: HydroSolver не сошёлся при дроблении шага до dt/N …`
помогает увеличение `"max_retries"` в секции `numerics` (по умолчанию 9).

### Не трогать

`grid.type` и `output.format` — объявлены в `io/config.py`, но не читаются.
