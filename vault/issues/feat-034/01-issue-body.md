## Описание

Вторая задача цепочки ввода книгой Excel: FEAT-033 (формат, шаблон, влит, #128) → **FEAT-034** (разбор ячеек) → FEAT-035 (перевод книги в `config.json` и CSV) → FEAT-036 (`gpn-solver run книга.xlsx`).

Нужен модуль пакета `gpn_multiphase_solver`, который читает книгу `.xlsx` средствами стандартной библиотеки (`zipfile`, `xml.etree.ElementTree`) и для каждой ячейки отдаёт лист, адрес (A1), значение и тип: число, строка, логическое, ошибка, пусто. Отдельно — признак даты по формату ячейки (`styles.xml`) и признак формулы с отметкой, есть ли у неё сохранённое значение.

Разбор только сообщает тип. Отказы по типам (дата, логическое, число строкой «1,5», формула без значения в числовом поле) применяет FEAT-035: только он знает, какое поле ждёт число. Файл не zip (в том числе `.xls`) — отказ с подсказкой «сохраните как .xlsx».

## Мотивация

Поставка заказчику (FEAT-031, #114): инженеры задают параметры расчёта книгой. Перевод (FEAT-035) должен отказывать с листом и ячейкой на каждую ошибку ввода, которую Excel допускает молча. Главная из них: в Excel с русскими региональными настройками «1.5» превращается в 1 мая, и в XML ячейки лежит число 46143 с форматом даты. Сейчас в пакете читать книгу нечем:

- `radial_blackoil.xlsxio.read_workbook_tables` (прототип, 52 строки) дату отдаёт числом, `TRUE` — числом 1.0, формулу без значения — как пустую ячейку; адресов нет. Кроме того, это внутренний модуль другого дистрибутива;
- `tests/_xlsx.py` (FEAT-033) — средство тестов генератора: стили, проверки данных, защита; типы ячеек не различает, в его заголовке прямо сказано «не разборщик книги для пользователя».

## Физическое/математическое обоснование

Формул нет. Решения пользователя (черновик плана, раздел 0):

1. Стандартная библиотека, без `openpyxl` (2026-10-14): новая зависимость поставки ради чтения нескольких листов не нужна. Кроме того, `openpyxl` за одно чтение «формулу без значения» тоже не отличает: с `data_only=True` она приходит как `None`, как и пустая ячейка.
2. Свой модуль в пакете, не `radial_blackoil.xlsxio` (подтвердить на планировании).
3. Формула с сохранённым значением допустима (FEAT-033, решение 26): разбор отдаёт значение и признак формулы.
4. Скрытые листы и строки читаются как обычные.
5. Защита листов, выпадающие списки и проверки данных Excel разбору безразличны: проверку данных обходит вставка из буфера обмена, поэтому все проверки повторяет FEAT-035.

## Предлагаемый API

Имена предварительные, утверждаются при `/plan-feature`.

```python
# gpn_multiphase_solver/io/xlsx_reader.py
class WorkbookReadError(ValueError): ...      # не zip, нет частей книги, .xlsb, Strict OOXML, битый XML

@dataclass(frozen=True)
class Cell:
    address: str                  # "C5"
    row: int                      # с 1
    col: int                      # с 1
    kind: str                     # "number" | "string" | "bool" | "error" | "empty"
    value: float | str | bool | None
    is_date: bool                 # число с форматом даты или времени
    formula: str | None           # текст <f>; None — не формула
    number_format: str            # код формата — для сообщений FEAT-035

@dataclass(frozen=True)
class Sheet:
    name: str
    cells: dict                   # (row, col) → Cell, только ячейки из XML
    def cell(self, address: str) -> Cell: ...   # отсутствующая — kind="empty"

def read_workbook(path) -> dict[str, Sheet]   # порядок листов — как в книге
```

Формула без сохранённого значения — `formula is not None and kind == "empty"`. Число строкой — `kind == "string"`; строку разбор не толкует.

## Найдено при открытии (пробы на `e480af7`)

Книги в git записаны тремя разными программами, у каждой свой XML:

1. **Книги прототипа** (`INPUT_TEMPLATE.xlsx`, `regression/inputs/T*.xlsx`, 19 книг): теги с префиксом пространства имён (`<x:c>`, `<x:v>`), текст — `t="str"` без формулы (так обычно помечают строковый результат формулы), общих строк нет, `calcPr` нет. `t="str"` без `<f>` — обычная строка. Разбор регулярными выражениями по `<c>` на них ломается, разбор `ElementTree` с полными именами тегов — нет.
2. **Книги IMEX `*_rates.xlsx`** (сохранены Microsoft Excel): формулы `DATE(2026,1,1) + TIME(0,1,0)` с сохранёнными значениями (46023.000694444447) и пользовательский формат 164 `\y\y\y\y\-\m\m\m\-\d\d\ \h\h\:\m\m\:\s\s`, где все буквы экранированы `\`. По правилам кода формата экранированный символ — литерал, то есть по формату это не дата, хотя значения — даты. Готовый тест на правило признака даты; что считать датой, решить при планировании.
3. **Книга генератора** (XlsxWriter): `<calcPr fullCalcOnLoad="1"/>`. XlsxWriter у формулы записывает сохранённое значение 0, если значение не передали, и просит Excel пересчитать книгу при открытии. Пока книгу не открыли и не сохранили в Excel, сохранённые значения формул могут быть ложными, и нуль от настоящего не отличить. В книге генератора формул нет. Но если инженер правит книгу программой, такой случай возможен. Предложение: разбор отдаёт признак `fullCalcOnLoad`, решение (отказ формулам в такой книге?) — за FEAT-035.
4. **Стилизованные пустые ячейки** — в черновике руководителя на THERMAL 7, SCHEDULE 16, COMMENTS 57 ячеек `<c s="…"/>` без значения. Тип — «пусто», как у отсутствующей ячейки.
5. **Не zip — не только `.xls`.** Книга с паролем на открытие — составной файл OLE, как `.xls`. Подсказка «сохраните как .xlsx» должна упоминать и пароль. Zip, но не та книга: `.xlsb` (`xl/workbook.bin`) и Strict Open XML (пространство имён `http://purl.oclc.org/ooxml/spreadsheetml/main` — пустой разбор без ошибки, если его не проверить). На каждый случай — свой отказ с подсказкой.
6. **Тест на черновике руководителя** (запись реестра: «черновик читается, значения совпадают с `xlsxio`») в чистом дереве и у заказчика не запустится: черновика в git нет. Сверку с `xlsxio` предлагается вести на 45 книгах прототипа в git (строки, числа, пустые ячейки — там, где `xlsxio` прав), черновик — пробой в `vault/issues/feat-034/probes/`.
7. **LibreOffice в окружении разработки нет** (вопрос 3 черновика плана). Книга, сохранённая LibreOffice, — только закоммиченным файлом, если она нужна.

## Анализ вариантов решения

**Вариант A — свой модуль на `zipfile` + `ElementTree` (рекомендуется).**
- Суть: новый модуль в `io/`, типизированные ячейки, признак даты по `numFmtId` (встроенные 14–22, 45–47 и пользовательские коды с d/m/y/h/s вне кавычек, `[…]` и `\x`), признак формулы, отказы чтения с подсказками.
- Плюсы: без зависимостей; формат ввода не связан с прототипом; разбор под требования FEAT-035.
- Минусы: правила XML (общие строки с `<rPh>`, `t="d"`, относительные и абсолютные пути частей, ячейки без `r`) — на нас; нужен корпус тестов.

**Вариант B — расширить `radial_blackoil.xlsxio`.**
- Суть: добавить в модуль прототипа типы и адреса.
- Минусы: им пользуется `input_reader.py` прототипа: смена возвращаемых значений ломает прототип, а параллельная функция — два разбора в одном файле. Ввод решателя зависит от внутреннего модуля другого дистрибутива. Отклонён решением 2.

**Вариант C — `openpyxl`.**
- Минусы: новая зависимость поставки (отклонено решением 1). Формулу без значения за одно чтение тоже не отличает: нужно два чтения книги, с `data_only=True` и без.

## План реализации

1. **Проектирование** (`/plan-feature`): имя модуля и структуры ячейки; правило признака даты (встроенные форматы, разбор пользовательского кода, формат 164 IMEX); `t="d"`; признак `fullCalcOnLoad` и кому решать; набор отказов чтения и тексты подсказок; путь книги из `_rels/.rels` или постоянный `xl/workbook.xml`.
2. **Ядро**: чтение частей книги (порядок и имена листов из `workbook.xml` + `_rels/workbook.xml.rels`, общие строки, стили), ячейки с типами, отказы чтения.
3. **Тесты**:
   - книги-ловушки XlsxWriter: дата (встроенный и пользовательский формат), логическое, число строкой «1,5», формула с сохранённым значением, ошибка `#DIV/0!`, неровные строки, пустые хвостовые строки, общие и встроенные строки (пишет ли XlsxWriter встроенные строки и `t="e"` у формулы — проверить пробой);
   - формула без сохранённого значения, Strict OOXML, ячейка без `r` — правкой XML в тесте;
   - не zip, `.xlsb`, книга без `workbook.xml` — отказ с подсказкой;
   - корпус: 45 книг прототипа в git — совпадение с `xlsxio` на строках, числах и пустых ячейках; книга генератора — совпадение значений с `tests/_xlsx.py`; книги IMEX — формулы и формат 164.
4. **Верификация**: быстрый уровень зелёный; `test_packaging.py` без новых зависимостей; проба на черновике руководителя.
