# P1. Адаптер единиц: прототип (бар) ↔ наша библиотека (Па)

## Суть проблемы

Прототип коллеги (`RadialBlackOilModel`) работает с давлением в **барах**, вязкостью в **сП**, проницаемостью в **мД**. Наша библиотека — в **SI** (Па, Па·с, м²).

Прототип **не модифицируем** — он валидирован, имеет 79 тестов и 12 регрессий vs IMEX.

Решение: Adapter на границе, прототип остаётся нетронутым.

## Полная ревизия единиц в прототипе

### Что хранится в прототипе и в каких единицах

| Объект | Поле | Единицы прототипа | Единицы SI |
|---|---|---|---|
| **BlackOilState** | `pressure_bar` | бар | Па |
| | `rs_sm3_sm3` | м³ст/м³ст | м³ст/м³ст (совпадает) |
| | `sg` | безразмерное | безразмерное (совпадает) |
| | `gas_active` | bool | bool (совпадает) |
| **RadialGrid** | `rw_m`, `re_m`, `h_m` | м | м (совпадает) |
| | `permeability_md` | мД | м² |
| | `faces_m`, `centers_m` | м | м (совпадает) |
| | `bulk_volumes_m3` | м³ | м³ (совпадает) |
| | `internal_transmissibility_m3` | м³ | м³ (совпадает*) |
| | `outer_transmissibility_m3` | м³ | м³ (совпадает*) |
| **RadialBlackOilModel** | `p_bhp_bar` | бар | Па |
| | `p_outer_bar` | бар | Па |
| | `outer_rs` | м³ст/м³ст | совпадает |
| | `skin` | безразмерный | совпадает |
| | `oil_rate_target_sm3_day` | м³ст/сут | м³ст/с |
| | `min_bhp_bar` | бар | Па |
| | `_last_effective_bhp_bar` | бар | Па |
| **BlackOilPVT** | `pb` (массив) | бар | Па |
| | `rs_values` | м³ст/м³ст | совпадает |
| | `bo_sat`, `mu_sat` | м³пл/м³ст, сП | м³пл/м³ст, Па·с |
| | `gp` (газ p) | бар | Па |
| | `gbg`, `gmu` | м³пл/м³ст, сП | м³пл/м³ст, Па·с |
| **TabulatedRelPerm** | `sg`, `kro_tab`, `krg_tab` | безразмерные | совпадает |
| **CompressibleRock** | `phi_ref` | безразмерный | совпадает |
| | `p_ref_bar` | бар | Па |
| | `cr_per_bar` | 1/бар | 1/Па |
| **Schedule** | `time_day` | сут | с |
| | `bhp_bar` | бар | Па |
| | `oil_rate_sm3_day` | м³ст/сут | м³ст/с |
| | `min_bhp_bar` | бар | Па |

*Transmissibility в м³ — это T = 2πkh/ln(...), единицы [м²·м] = [м³]. Формула потока: q = T · mob · Δp · BAR_TO_PA. Mob = kro/(μ_cP · CP_TO_PA_S · Bo), единицы 1/(Па·с). Итого q [м³/с]. Корректно.

### Что возвращает прототип и в каких единицах

| Метод | Возвращает | Единицы |
|---|---|---|
| `model.advance(state, dt_s)` | `(new_state, report)` | state в бар; dt в **секундах** |
| `model.face_component_fluxes_sm3s(state)` | dict потоков | **м³ст/с** (SI) |
| `model.well_rates(state)` | dict дебитов | oil/gas в **м³ст/с**, bhp в **бар**, GOR безразм. |
| `model.component_inventories(state)` | (oil_inv, gas_inv) | **м³ст** (SI) |

Ключевое наблюдение: **потоки и дебиты уже в м³ст/с** (SI). Конвертация BAR_TO_PA и CP_TO_PA_S происходит **внутри** формул прототипа. Наружу выходят м³ст/с.

### Что нужно конвертировать

| Величина | Направление | Конвертация |
|---|---|---|
| **pressure** | наша → прототип | Па → бар: `/BAR_TO_PA` (`/1e5`) |
| **pressure** | прототип → наша | бар → Па: `*BAR_TO_PA` (`*1e5`) |
| **bhp (забойное)** | наша → прототип | Па → бар |
| **bhp** | прототип → наша | бар → Па |
| **p_ext (контур)** | наша → прототип | Па → бар |
| Rs, Sg | — | **не конвертировать** (совпадает) |
| потоки G_o, G_g | прототип → наша | **не конвертировать** (уже м³ст/с) |
| dt | наша → прототип | **не конвертировать** (оба в секундах) |
| gas_active → regime | прототип → наша | `regime = np.where(gas_active, 1, 2)` |
| oil_rate | наша → прототип | **м³ст/с → м³ст/сут**: `*DAY_TO_S` |
| min_bhp | наша → прототип | Па → бар |

### Что НЕ нужно конвертировать

| Величина | Почему |
|---|---|
| Rs | м³ст/м³ст — одинаково |
| Sg | безразмерно |
| Потоки (G_o, G_g) | Уже в м³ст/с внутри прототипа |
| dt | Оба в секундах |
| Объёмы ячеек | м³ — одинаково |
| Сетка (r_w, R_ext, h) | м — одинаково |

## Архитектура Adapter

### Класс PrototypeHydroAdapter

```python
class PrototypeHydroAdapter(HydroSolver):
    """Adapter между RadialBlackOilModel (бар) и нашей библиотекой (Па).

    Конвертирует:
    - давление: Па ↔ бар (на входе и выходе)
    - режим: gas_active ↔ regime
    - управление: WellControl → set_bhp_control/set_oil_rate_control

    НЕ конвертирует:
    - Rs, Sg (безразмерные)
    - Потоки (м³ст/с — уже SI)
    - dt (секунды — уже SI)
    """
```

### Конструктор

```python
class PrototypeHydroAdapter(HydroSolver):
    def __init__(self, model: RadialBlackOilModel, grid: Grid,
                 pvt: HydroPVT):
        """
        model — готовый RadialBlackOilModel, уже сконфигурированный
        grid  — наш Grid (LogRadialGrid), для вычисления u, Gm
        pvt   — наш HydroPVT (PrototypePVTAdapter, обёртка над тем же BlackOilPVT)
                Используется для вычисления Bo, Bg, ρ при расчёте Q, u, m, Gm.
                Factory гарантирует, что pvt._pvt is model.pvt — один и тот же
                объект BlackOilPVT под капотом.
        """
        self._model = model
        self._grid = grid
        self._pvt = pvt
```

**Принцип:** Adapter **не обращается** к `model.pvt` напрямую для вычисления Q, u, m.
Вместо этого использует `self._pvt` (наш HydroPVT, полученный через конструктор).
Это гарантирует единый PVT для всех модулей: и гидро (внутри прототипа), и вычисление
производных величин (Q, u, m в Adapter), и энергия (EnergySolver).

Factory создаёт оба объекта из одного BlackOilPVT:
```python
proto_pvt = BlackOilPVT(...)
model = RadialBlackOilModel(..., pvt=proto_pvt, ...)
our_pvt = PrototypePVTAdapter(proto_pvt, rho_o_std, rho_g_std)
adapter = PrototypeHydroAdapter(model, grid, our_pvt)
energy = EnergySolver(grid, our_pvt, ...)   # тот же our_pvt
```

> ⚠️ **DEBT-006 (2026-10):** фабрика передаёт адаптеру не `PrototypePVTAdapter`, а сам `FullPVT` (`TableFullPVT` или `StandingFullPVT`) — тот же объект, что решателю энергии, как и задумано здесь («тот же our_pvt»). До DEBT-006 табличный путь разворачивал `TableFullPVT` до `PrototypePVTAdapter`; числа от этого не зависели.

### Метод solve: пошаговый алгоритм

> ⚠️ **DEBT-028 (2026-10-03):** шаг 7 (Q, u, m, Gm из G) вынесен в
> `fluxes.phase_fluxes_from_components` — общий для адаптера и `compute_fluxes`.
> Ячейка выше по потоку выбирается по перепаду давления (как в прототипе,
> `blackoil.py`: `left = dp >= 0`), а не по знаку `G_o`: при $k_{ro} = 0$
> в ячейке выше по потоку $G^o = 0$, и правило ниже брало ячейку ниже по потоку.
> Код ниже — история проектирования, не текущая реализация шага 7.

```python
def solve(self, state: SimulationState, dt: float,
          bc: BoundaryConditions) -> HydroResult:
    """
    Вход:
        state — SimulationState в SI (p в Па, Rs, Sg, T, regime)
        dt — шаг в секундах
        bc — BoundaryConditions (bc.well — WellControl, p_wf в Па)

    Выход:
        HydroResult в SI (p в Па, потоки в м³ст/с, u в м/с и т.д.)
    """

    # ──────────────────────────────────────────────
    # ШАГ 1. Применить управление скважиной
    # ──────────────────────────────────────────────
    # Конвертировать WellControl → вызов set_bhp_control / set_oil_rate_control
    # Единицы: Па → бар, м³ст/с → м³ст/сут

    well = bc.well
    if isinstance(well, PressureControl):
        self._model.set_bhp_control(well.p_wf / BAR_TO_PA)
    elif isinstance(well, RateControl):
        # Дебит НЕФТИ: прототип умеет только OIL_RATE (FEAT-020).
        # Имя TotalRateControl/q_total здесь было ошибкой проекта —
        # вызов set_oil_rate_control суммарного расхода не задаёт.
        # Реализовано 2026-09-30: min_bhp обязателен (валидация конфига и
        # RateControl), поэтому ветки min_bhp = None в коде нет.
        self._model.set_oil_rate_control(well.q_oil * DAY_TO_S,   # м³ст/с → м³ст/сут
                                         well.min_bhp / BAR_TO_PA)  # Па → бар

    # ──────────────────────────────────────────────
    # ШАГ 2. Конвертировать SimulationState → BlackOilState
    # ──────────────────────────────────────────────
    # pressure: Па → бар
    # Rs, Sg: без изменений
    # regime → gas_active: regime==1 → True, regime==2 → False

    from radial_blackoil.state import BlackOilState

    proto_state = BlackOilState(
        pressure_bar = state.p / BAR_TO_PA,
        rs_sm3_sm3   = state.Rs.copy(),
        sg           = state.Sg.copy(),
        gas_active   = (state.regime == 1)
    )

    # ──────────────────────────────────────────────
    # ШАГ 3. Вызвать model.advance()
    # ──────────────────────────────────────────────
    # dt уже в секундах — прототип принимает dt_s

    new_proto, report = self._model.advance(proto_state, dt)

    if not report.converged:
        raise RuntimeError(
            f"HydroSolver не сошёлся: {report.iterations} итераций, "
            f"residual={report.residual_inf:.2e}, "
            f"active_set={report.active_set_iterations}, "
            f"switches={report.phase_switches}")

    # ──────────────────────────────────────────────
    # ШАГ 4. Конвертировать BlackOilState → SimulationState
    # ──────────────────────────────────────────────
    # pressure: бар → Па
    # Rs, Sg: без изменений
    # gas_active → regime: True → 1, False → 2
    # T: копируем из входного state (гидро не меняет T)

    new_state = SimulationState(
        p      = new_proto.pressure_bar * BAR_TO_PA,
        Sg     = new_proto.sg.copy(),
        Rs     = new_proto.rs_sm3_sm3.copy(),
        T      = state.T.copy(),   # гидро не трогает T
        regime = np.where(new_proto.gas_active, 1, 2),
        t      = state.t + dt
    )

    # ──────────────────────────────────────────────
    # ШАГ 5. Извлечь потоки из прототипа
    # ──────────────────────────────────────────────
    # face_component_fluxes_sm3s возвращает м³ст/с — конвертация НЕ нужна
    # НО: конвенция знаков прототипа (G>0=к скважине) противоположна нашей!
    # Инверсия знаков — ответственность P2, здесь только извлечение.

    fluxes = self._model.face_component_fluxes_sm3s(new_proto)

    # Собрать массивы потоков [N+1]:
    # fluxes['oil_well'] — скаляр (забой, грань f=0)
    # fluxes['oil_internal'] — массив [N-1] (внутренние грани f=1..N-1)
    # fluxes['oil_outer'] — скаляр (контур, грань f=N)

    N = self._grid.N

    # ──────────────────────────────────────────────
    # ШАГ 5+6. Извлечь потоки + согласование знаков
    # ──────────────────────────────────────────────
    #
    # ВНИМАНИЕ: конвенция знаков в прототипе НЕОДНОРОДНА:
    #
    # - well:     qow > 0 = outflow из ячейки (к скважине)
    #             → наша конвенция: G < 0 (к скважине)
    #             → G_o[0] = -qow
    #
    # - internal: qoi > 0 = поток вправо (от скважины)
    #             → наша конвенция: G > 0 (от скважины)
    #             → G_o[f] = +qoi — БЕЗ инверсии
    #
    # - outer:    qoo > 0 = outflow из пласта (от скважины)
    #             → наша конвенция: G > 0 (от скважины)
    #             → G_o[N] = +qoo — БЕЗ инверсии
    #
    # Проверка: при типичном потоке к скважине все G < 0.
    #   qow > 0 → G_o[0] = -qow < 0 ✓
    #   qoi < 0 (dp<0) → G_o[f] = qoi < 0 ✓
    #   qoo < 0 (dpo<0) → G_o[N] = qoo < 0 ✓

    G_o = np.empty(N + 1)
    G_o[0]    = -fluxes['oil_well']          # инверсия ТОЛЬКО для well
    G_o[1:N]  =  fluxes['oil_internal']      # без инверсии
    G_o[N]    =  fluxes['oil_outer']         # без инверсии

    G_g = np.empty(N + 1)
    G_g[0]    = -fluxes['gas_component_well']
    G_g[1:N]  =  fluxes['gas_component_internal']
    G_g[N]    =  fluxes['gas_component_outer']

    # ──────────────────────────────────────────────
    # ШАГ 7. Вычислить расходы фаз Q, скорости u, массовые расходы m
    # ──────────────────────────────────────────────
    # Q_o[f] = G_o[f] * Bo_up  (обратная связь: G = Q/Bo, Q = G*Bo)
    # u_o[f] = Q_o[f] / (2πh·r_face[f])
    # m_o[f] = ρ_o_up · Q_o[f]
    # Gm_o = ρ_o_ст · G_o, Gm_g = ρ_g_ст · G_g
    #
    # Bo_up, ρ_o_up — из upstream ячейки.
    # Используем self._pvt (наш единый HydroPVT), а НЕ model.pvt напрямую.
    # Factory гарантирует, что self._pvt обёртывает тот же BlackOilPVT,
    # что и model.pvt → результат идентичен, но архитектура чистая:
    # Adapter не лезет внутрь прототипа за PVT.

    p_new = new_state.p  # Па
    Rs_new = new_state.Rs

    # PVT в центрах ячеек — через наш единый HydroPVT (SI, Па)
    Bo_cells = self._pvt.Bo(p_new, Rs_new)       # [N]
    Bg_cells = self._pvt.Bg(p_new)                # [N]
    rho_o_cells = self._pvt.rho_o(p_new, Rs_new)  # [N], кг/м³
    rho_g_cells = self._pvt.rho_g(p_new)           # [N], кг/м³

    # Upstream: определяется знаком G_o (наша конвенция: G<0 = к скважине)
    # Для внутренних граней f=1..N-1:
    #   G_o[f] < 0 → поток к скважине → upstream = ячейка f (правая)
    #   G_o[f] > 0 → поток от скважины → upstream = ячейка f-1 (левая)

    Q_o = np.empty(N + 1)
    Q_g = np.empty(N + 1)
    u_o = np.empty(N + 1)
    u_g = np.empty(N + 1)
    m_o = np.empty(N + 1)
    m_g = np.empty(N + 1)

    # Извлечь потоки свободного газа (для Q_g — расход газовой ФАЗЫ)
    # Та же логика знаков: инверсия только для well
    G_free_gas = np.empty(N + 1)
    G_free_gas[0]    = -fluxes['free_gas_well']       # инверсия для well
    G_free_gas[1:N]  =  fluxes['free_gas_internal']   # без инверсии
    G_free_gas[N]    =  fluxes['free_gas_outer']      # без инверсии

    # Внутренние грани (f = 1..N-1)
    for f in range(1, N):
        if G_o[f] < 0:  # к скважине → upstream = ячейка f (правая)
            up = f
        else:           # от скважины → upstream = ячейка f-1 (левая)
            up = f - 1
        Q_o[f] = G_o[f] * Bo_cells[up]
        Q_g[f] = G_free_gas[f] * Bg_cells[up]   # расход газовой ФАЗЫ = G_free_gas * Bg
        u_o[f] = Q_o[f] / (2 * np.pi * self._grid.h * self._grid.r_faces[f])
        u_g[f] = Q_g[f] / (2 * np.pi * self._grid.h * self._grid.r_faces[f])
        m_o[f] = rho_o_cells[up] * Q_o[f]
        m_g[f] = rho_g_cells[up] * Q_g[f]

    # Забой (f = 0): upstream = ячейка 0
    # Прототип — producer-only: при p_wf >= p[0] скважина shut-in (q=0),
    # upstream не влияет на результат (Q=0). Ячейка 0 — безопасный выбор.
    Q_o[0] = G_o[0] * Bo_cells[0]
    Q_g[0] = G_free_gas[0] * Bg_cells[0]
    u_o[0] = Q_o[0] / (2 * np.pi * self._grid.h * self._grid.r_faces[0])
    u_g[0] = Q_g[0] / (2 * np.pi * self._grid.h * self._grid.r_faces[0])
    m_o[0] = rho_o_cells[0] * Q_o[0]
    m_g[0] = rho_g_cells[0] * Q_g[0]

    # Контур (f = N): upstream зависит от направления потока
    if G_o[N] < 0:
        # Типичный приток из контура → upstream = контур
        p_ext_arr = np.array([bc.p_ext])
        Rs_ext_arr = np.array([bc.Rs_ext])
        Bo_up_N = self._pvt.Bo(p_ext_arr, Rs_ext_arr)[0]
        Bg_up_N = self._pvt.Bg(p_ext_arr)[0]
        rho_o_up_N = self._pvt.rho_o(p_ext_arr, Rs_ext_arr)[0]
        rho_g_up_N = self._pvt.rho_g(p_ext_arr)[0]
    else:
        # Нетипичный отток из пласта → upstream = ячейка N-1
        Bo_up_N = Bo_cells[N-1]
        Bg_up_N = Bg_cells[N-1]
        rho_o_up_N = rho_o_cells[N-1]
        rho_g_up_N = rho_g_cells[N-1]

    Q_o[N] = G_o[N] * float(Bo_up_N)
    Q_g[N] = G_free_gas[N] * float(Bg_up_N)
    u_o[N] = Q_o[N] / (2 * np.pi * self._grid.h * self._grid.r_faces[N])
    u_g[N] = Q_g[N] / (2 * np.pi * self._grid.h * self._grid.r_faces[N])
    m_o[N] = float(rho_o_up_N) * Q_o[N]
    m_g[N] = float(rho_g_up_N) * Q_g[N]

    # ──────────────────────────────────────────────
    # ШАГ 8. Сформировать HydroResult
    # ──────────────────────────────────────────────
    # ШАГ 9 (FEAT-020, 2026-09-30): фактическое давление на забойной грани.
    # Результат шага при любом управлении — при OIL_RATE выражено из
    # уравнения притока, при BHP и p[0] <= уставки (закрытие) равно p[0].
    # well_rates считает на том же new_proto, что и потоки выше.
    # В код HydroResult добавлено поле p_wf=p_wf (Па).
    p_wf = self._model.well_rates(new_proto)['bhp_bar'] * BAR_TO_PA

    return HydroResult(
        state = new_state,
        G_o = G_o,    # [N+1], м³ст/с, >0 = от скважины
        G_g = G_g,            # [N+1], м³ст/с
        G_free_gas = G_free_gas,  # [N+1], м³ст/с
        Q_o = Q_o,            # [N+1], м³пл/с
        Q_g = Q_g,            # [N+1], м³пл/с
        u_o = u_o,            # [N+1], м/с
        u_g = u_g,            # [N+1], м/с
        m_o = m_o,            # [N+1], кг/с
        m_g = m_g,            # [N+1], кг/с
        Gm_o = self._pvt.rho_o_std * G_o,  # [N+1], кг/с
        Gm_g = self._pvt.rho_g_std * G_g,  # [N+1], кг/с
    )
```

## Замечания и ловушки

### 1. Внутренние потоки прототипа — массив длины N-1, не N+1

`fluxes['oil_internal']` имеет длину **N-1** (между ячейками 0–1, 1–2, ..., (N-2)–(N-1)). В нашем массиве G_o[N+1] это грани f=1..N-1. Присваивание: `G_o[1:N] = fluxes['oil_internal']`.

### 2. gas_component vs free_gas

Прототип различает:
- `gas_component_well` = Rs · q_oil + q_free_gas (полный газовый компонент)
- `free_gas_well` = только свободный газ

Наш G_g — это **полный поток газового компонента** (растворённый + свободный). Нужно брать `gas_component_*`, не `free_gas_*`.

### 3. Q_o = G_o · Bo_up — точная формула. Q_g — через free_gas

G_o — поток нефтяного компонента при ст. условиях. G_o = Q_o / Bo_up. Значит Q_o = G_o · Bo_up. Точно.

Для газа: G_g = Rs_up · G_o + G_free_gas — полный газовый компонент. Q_g (расход газовой **фазы** в пластовых условиях) = G_free_gas · Bg_up. Нельзя писать Q_g = G_g · Bg — это физически бессмысленно (часть газа растворена в нефти, не занимает объём газовой фазы).

**Решение (уже исправлено в шаге 7):** использовать `fluxes['free_gas_*']` для Q_g:

```python
Q_g[f] = G_free_gas[f] * Bg_up
```

### 3a. Upstream на контуре — не ячейка N-1

При типичном притоке (p_ext > p[N-1]) жидкость течёт **из контура в пласт**. Upstream = контур: свойства (Bo, Bg, ρ) берутся при p_ext, Rs_ext, Sg=0.

В исходной версии заметки было написано «upstream = ячейка N-1» — **неверно**. Прототип (blackoil.py, строка 122) правильно выбирает upstream по знаку dpo:

```python
p_up = p[-1] if dpo >= 0 else self.p_outer_bar
```

В Adapter исправлено: Bo_ext, Bg_ext, ρ_ext вычисляются при (p_ext, Rs_ext).

### 4. PVT для вычисления Bo, Bg, ρ в Adapter — РЕШЕНО

**Решение:** Adapter получает наш единый `HydroPVT` через конструктор (`self._pvt`). Factory передаёт в `self._pvt` тот же объект `FullPVT`, что решателю энергии и `Simulator` (DEBT-006; до него — развёрнутый `PrototypePVTAdapter`); у табличного PVT под ним — тот же объект `BlackOilPVT`, что и `model.pvt`. Результат идентичен прямому вызову `model.pvt.bo()`, но Adapter не нарушает инкапсуляцию прототипа.

Все модули (Adapter, EnergySolver) получают один объект HydroPVT → Bo, Bg, ρ согласованы везде.

Массовые расходы m_o, m_g, покомпонентные Gm_o, Gm_g вычисляются через `self._pvt.rho_o()`, `self._pvt.rho_g()`, `self._pvt.rho_o_std`, `self._pvt.rho_g_std`.

### 5. Зависимости Adapter

Adapter нуждается в:
- `model` (RadialBlackOilModel) — для advance() и face_component_fluxes_sm3s()
- `grid` (наш Grid) — для r_faces, h при вычислении u
- `pvt` (наш HydroPVT) — для Bo, Bg, ρ при пересчёте G→Q, вычислении m, Gm

Adapter **не обращается** к `model.pvt` напрямую. PVT — только через `self._pvt`.
Factory гарантирует согласованность: `self._pvt` обёртывает тот же `BlackOilPVT`.

### 6. Обработка расходимости

Адаптер не дробит шаг: при `report.converged == False` — `HydroConvergenceError`
(`hydro/base.py`), состояние не меняется. Дробит `Simulator` — локально, не
глубже `numerics.max_retries` (по умолчанию 9, наименьший подшаг dt/512).
См. [[P4-адаптивный-шаг]], DEBT-015. До DEBT-015 здесь было равномерное
A-retry (2, 4, 8, … равных подшагов).

Текст `HydroConvergenceError` (DEBT-054): прежний (dt, t, итерации, невязка) и хвост
из отчёта Ньютона — допуск, мера ячеек с порогом `numerics.newton_cell_tol`, причина
выхода, невыполненное условие, чьи числа (ступень 1 после подмены DEBT-030 или
ступень 4 по памяти). Пример — отказ первых суток BUG-018 при $N$ = 350:
«… итераций 4, невязка 6.51e-15 (допуск 5.35e-07), мера ячеек 2.60e-08 (порог
numerics.newton_cell_tol = 1e-08), выход: линейный поиск не принял ни одной точки —
не выполнено только условие по ячейке; числа — Ньютона ступени 1».

### 7. Выбор ячейки выше по потоку — по $\Delta p$, не по знаку $G^o$ (DEBT-028)

При $k_{ro} = 0$ в ячейке выше по потоку прототип отдаёт $G^o = 0$, и знак $G^o$
направление не различает; правило «по знаку $G^o$» брало ячейку ниже по потоку
($\mathcal{Q}_g, u_g$ с $B_g$ не той ячейки). Правило — как в прототипе, по перепаду
давления; код — `fluxes.phase_fluxes_from_components`, см. [[debt-028 compute-fluxes-shutin-upwind]].

## Тестирование Adapter

### Тест 1: конвертация давления туда-обратно

```python
p_pa = 250e5  # 250 бар
p_bar = p_pa / BAR_TO_PA
assert abs(p_bar - 250.0) < 1e-10
p_back = p_bar * BAR_TO_PA
assert abs(p_back - p_pa) < 1e-6
```

### Тест 2: знак потоков

При p_wf < p0 (типичная добыча):
- Прототип: G_o_well > 0 (к скважине)
- После инверсии: G_o[0] < 0 (наша конвенция)
- Дебит: q_o = -G_o[0] > 0 ✓

### Тест 3: материальный баланс через Adapter

Запустить один шаг через Adapter, проверить:
- `Σ(V·φ·Δ(So/Bo)) + dt·(G_o[N] - G_o[0]) ≈ 0` (с точностью до roundoff)

### Тест 4: стационарный поток

Однофазный стационар (p > pb всюду): G_o[f] = const для всех f.
